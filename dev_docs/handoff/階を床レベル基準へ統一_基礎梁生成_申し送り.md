# 階を床レベル基準へ統一・基礎梁の生成 申し送り

## 発端

利用者からの 2 件の不具合報告。

1. 架構作成ウィザードが**基礎梁を作らない**
2. ウィザードで作った階を**伏図で選んでも部材が表示されない**

調査の結果、どちらも「`Story` が層と床のどちらなのか」が定まっていないことに起因していた。
2 件を個別に直すと不整合が残るため、`Story` の意味を床レベルに統一する作業として一括で
対応した。

## 決めたこと

### 階は床、層は階の間

**不変条件: `model.stories[0].elevation == model.base_elevation()`**

`Model::stories` は基部の床から屋根の床までの床レベル列であり、先頭は必ず基部。
層（法規上の「i 階」）は隣り合う階の間で、層数は `stories.len() - 1`。

層の一覧は `Model::layers() -> Vec<Layer>` が唯一の入口。`Layer` は導出値で保持しない
（保持すると `Story::node_ids` と同種の同期ずれを 1 つ増やす）。
**層を数える処理が `model.stories` を直接走査してはならない。**

層と床の対応は実務の慣行どおり。

| 層 i の量 | 由来 |
| --- | --- |
| 名前 | `stories[i]`（下端床。法令の「i 階」は下の床の呼び名） |
| 階高 | `stories[i+1].elevation - stories[i].elevation` |
| 重量・所属節点・階種別・構造種別 | `stories[i+1]`（上端床） |

重量が上端床なのは `Q1 = C1·(W1+W2+…)` が成り立つため（基部の重量は地盤が直接受ける）。
`level_kind`・`weight_override` も重量と同じ上端床に置いた。名前だけが下端床という
1 つの例外に集約し、属性が 2 か所へ散らばるのを避けている。

### 帰属区間

最下階（基部の床）だけ**下端を含む点区間** `[base, base]`。他は従来どおり `(下端, 上端]`。
これがないと基部の区間が空集合になり、柱脚・基礎梁がどの階にも属さず伏図・数量から落ちる。

`story_at` は二分探索に変更した（伏図が毎フレーム全節点に対して呼ぶため）。
`story_spans` は不変条件により `base_elevation()` を呼ばなくなり `O(階数)` になった。

### `base_elevation()` は変更していない

節点の最小 Z のまま。不変条件が成立していれば `stories[0].elevation` と一致するが、
**階生成が不変条件を作る側**なので、そのブートストラップに階へ依らない基部が要る。
`stories[0].elevation` を返すように変えると、旧形式の階列から生成するときに基部を
最下層の上端と誤認して生成結果が壊れる。

### 基部の剛床

基部の床にも剛床を作る。代表節点の拘束は `master_restraint` がスレーブの可動性から決める。

- 全スレーブがその方向へ拘束されている（柱脚が固定・ピン）→ マスターも拘束
  拘束済みのスレーブ自由度には従属行が張られない（`constraint.rs` の `dofmap.active`
  ガード）ため、自由なままだと剛性ゼロの独立自由度が残り**特異行列になる**
- 支点ばねで水平に動ける → 自由のまま。基礎の質量が地盤ばねと連成して応答に効く

質量は常に与える。水平拘束された基部では該当自由度が系から除かれるので影響しない。
場合分けが不要になる。

**可動性の判定対象は構造節点（`squid_n_core::dof::structural_nodes`）に限る。**
`Node::restraint` だけで判定すると、床の境界・小梁の支持点のように要素が接続しない
節点を「動ける」と数えてしまう。これらは `DofMap::build` が解析自由度から外すため、
拘束が無くてもマスターへ剛性を写さない。判定に混ぜるとマスターの Ux・Uy が剛性ゼロの
独立自由度として残り、上と同じ**特異行列**になる。

これは実際に踏んだ。1FL が基部にある ST-Bridge 取り込みモデル（柱脚ピン・1FL の床に
小梁あり）で、基部の剛床のスレーブが「水平拘束された柱脚 12 節点」と「拘束の無い小梁
支持点 16 節点」の混在になり、線形静解析・固有値・地震静解析のすべてが解析準備の段階で
止まった。回帰テストは `story_gen::tests::test_base_master_ignores_non_structural_slaves`
（拘束マスクの単体）と
`squid-n-app` の `test_analysis_runs_with_non_structural_nodes_on_base_floor`
（準備計算から解析まで通ること）。

### 後方互換は取らない

移行コード・二形式の吸収・`validate` の追加はいずれも入れていない。
代わりに**階生成が不変条件を作る**（`generate.rs`。基部レベルの階が無ければ先頭に補う）。
旧ファイルを開いても、解析に必要な準備計算を通した時点で床基準に直る。

補完がないと `Model::layers` が最下層を見落とし、層間変形角・層せん断力から 1 層分が
**例外も警告もなく**落ちる。回帰テスト
`story_gen::tests::test_layer_quantities_match_between_legacy_and_floor_based_stories`
がこれを固定している。

### 不変条件のガード

- `SetStoryLevel`: 基部の階は階名だけ変え、標高は据え置く
- `DeleteStory`: 基部の階は Noop
- 階の定義表: 基部行の標高欄は表示のみ、削除ボタンは無効、階種別欄は「—」
  （階種別は層の属性で上端の階が持つため、基部の階は設定しない）

### 伏図は幾何から引く

`build_story_frame` を `Node::story` 参照から `Model::node_stories()`（帰属区間による
幾何判定）へ切り替えた。`story.rs` の「UI の表示もこれを用いる」という宣言と実装が
一致した。柱の救済（上端節点がその階に属する柱を含める）も同じ `node_stories` を情報源に
した。

`Node::story` は準備計算だけが埋める派生値であり、ウィザード直後・`AddNode` 直後・
`SetNodeCoord` 直後は空または古い。伏図は描画対象の絞り込みのみで構造計算に用いないため、
幾何から引いてよい。

情報源の割れは生じない。階生成は `node_story` を全 `None` から作り直し既存値を参照しない
ので、2 つのキャッシュ（`Node::story` / `Story::node_ids`）はどちらも同じ幾何規則から
機械的に導かれる。

### ウィザード

- **基礎梁は常に生成**（オプションなし、`with_girders` に依存しない）。日本の RC・S 造では
  基礎梁を必ず設けるため、生成しないウィザードのモデルは出発点として不正だった。
  仕様変更ではなく**不具合修正**
- 「基礎梁」という部材属性は追加していない。数量積算が幾何から自動分類する
  （`quantity/mod.rs` の `MemberCategory::FoundationGirder`）
- 基部レベルにも床を張る（`with_slabs` を基部にも適用）
- `story_names` は床ごとなので `story_heights` より 1 つ多い（先頭が基部の床）
- 柱脚の既定はピンのまま。回転拘束は基礎梁が担うので支点に重ねない

### 階名

`default_story_name` を `index + 2` → `index + 1` に変更（`1F` 始まり）。
ST-Bridge の階（`1F` の height が GL）と意味が一致し、
`階と剛床の分離_申し送り.md` の「両者で階名が 1 つずれる」残課題が解消した。

**層の表示名は下端の階名**（法令・構造計算書の「i 階」）。従来は上端の階名を層の行名に
使っており、計算書の慣行と 1 つずれていた。

## 直した既存の不具合

統一に付随して、以下の既存バグが解消した。

1. **最下層の下端変位を 0 と決め打ちしていた**（`summary.rs` / `stiffness_ratio.rs` /
   `pushover/response.rs`）。支点ばねで基礎が動くモデルで最下層の層間変位を過大に
   見積もっていた。基部の階の実変位を使うようになった
2. **最下層の下端標高の定義が 4 通りに割れていた**（`Model::base_elevation` / 全節点 min Z /
   GL / 絶対 0）。`Layer::height` に一本化
3. **時刻歴が基部節点を誤認していた**（`history.rs` の
   `find(|n| n.story.is_none())`）。階数が減って不活性化した剛床代表節点も `story: None`
   で残るため、それを基部と誤認して層間変形角を誤る可能性があった。`Layer` 経由に変更
4. **ST-Bridge の標高 0 階で最下層の階高が `1e-9` になっていた**。`story_spans` の先頭が
   `(0, 0]` の空区間になるため。層が階の対になったので消えた
5. **崩壊機構のヒンジ帰属が節点ベースだった**（`mechanism.rs`）。部材ベース
   （材端節点のうち高い側の所属階を上端とする層）へ変更した。2 階柱の脚部ヒンジは
   2 層目に属するのが正しい

## 意図的に変わる挙動（PR の「影響・注意事項」）

- **基礎梁が付くことで柱脚に回転拘束が生じる**。1 層目の柱に柱脚モーメントが入り、
  層間変形角が小さくなる。実挙動に近づく変化だが、既存モデルとの比較では差が出る
- **基部レベルにも床が張られる**。基部の床の自重・積載は基礎梁へ分配される
- **層の表示名が 1 つずれる**（従来 `2F` と出ていた最下層の行が `1F` になる）
- **剛床代表節点が 1 つ増える**（基部の床の分）。節点数・`generated_masters` が増える

## 残課題

### 層間変位 δ の再定義（中間節点対応）— 対応済み

`secondary::story_columns` に柱列挙の単一情報源を集約した。
上端階の床レベル上の節点から鉛直材を下へ辿り、下端階の床レベルに達する連なりを
1 本の柱とする。`stiffness_ratio` の `column_drifts`、`eccentricity_analysis` の
`for_each_story_column`、D 値法略算の `eccentricity::column_stiffnesses` がこれを共用する。
δg（`cog_horizontal_disp`）は床レベル節点の質量加重平均であり、柱の連なりとは別である。

### 床面が非構造節点だけの上階でマスターが無言で拘束される — 対応済み

`master_restraint` を構造節点だけで判定するようにした副作用。**基部以外の階でも、床面の
スレーブが全て非構造節点ならマスターが水平拘束される**。その階へ配る水平力は
`distribute_seismic_forces` がマスターへ載せるため、拘束された自由度へ入って無言で消える。

成立条件は「その階の床レベルに部材が 1 本も取り付かない」かつ「帰属区間の中に重量を持つ
構造節点がある」で、宙に浮いた床を張った壊れたモデルに限られる。実際に確認した範囲では、
床面が非構造節点だけの階は重量も 0 になり、消える水平力も 0 だった
（柱を分割していない架構＋宙に浮いた小梁で確認）。

変更前はこの状況が特異行列（loud failure）になっていた。無言の過小評価（危険側）へ
変わっているので、precheck に「基部以外で剛床マスターが水平拘束され、かつ階の
地震用重量が 0 でない」をエラーとして追加した（`precheck.rs::model_issues`）。

### ST-Bridge の `StbNodeIdList` 由来の `Node::story` が解析に効いていない — 未着手

`assemble.rs` が `StbStory/StbNodeIdList` から `Node::story` を埋めるが、準備計算の階生成が
`node_story` を全 `None` から作り直すため上書きされる。ファイルの明示的な割り当ては
解析に一切効いていない。今回のスコープ外。
