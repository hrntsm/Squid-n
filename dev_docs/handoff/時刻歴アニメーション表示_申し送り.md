# 時刻歴アニメーション表示 申し送り

2026-07 実施。3D ビューアに時刻歴応答解析（`ThRecording`）のアニメーション再生
表示モードと、部材クリックでの荷重変形履歴ループ・簡易断面検定ウィンドウを追加。

## 背景

`ResultsBundle.time_history: Option<ResponseResult>` の `recording:
Option<ThRecording>`（フレームごとの全節点変位・部材内力、全ステップの
部材内力包絡）は既存の解析側実装で用意されていたが、3D ビュー側の表示が
なかった。地震応答の変形の様子をアニメーションで確認し、任意部材の
荷重変形履歴・最大応力に対する検定を見られるようにした。

## 実施内容（squid-n-app のみ、solver/element 側は変更なし）

### 1. `ViewMode::TimeHistory`（`viewer/mod.rs`）

- `recording` がある場合のみ表示モード選択肢に「時刻歴」を出す
  （`has_th_recording` を `viewer_panel` 冒頭で判定）。
- フレーム制御 UI（スライダー・再生/一時停止・速度 ×0.25〜×2）を追加。
  再生中は `ctx.input(|i| i.stable_dt)` を積算した再生経過時刻
  `App::th_play_time` を、`advance_play_time`/`frame_at_time`（純関数、単体
  テスト付き）でフレーム番号 `App::th_frame` へ写像する。末尾はループ
  （`f64::rem_euclid`）。
- 変形描画は `ViewMode::Deformed` と同じ経路を流用（`disp` の match 分岐に
  `TimeHistory` アームを追加し、`recording.node_disp[th_frame]` を渡すだけ）。
  変形倍率スライダー・内部たわみトグルも `show_deform_options` の対象に
  `TimeHistory` を追加して共用。
- 床・二次部材の変形追従（`interpolate_unreferenced_disp`）は Deformed と
  完全に共通の経路（同じ `display_disp` 呼び出し）なので、追加の判断は不要
  だった（実装内容の想定どおり流用できた）。

### 2. 部材クリックの履歴・検定ウィンドウ（`viewer/th_detail.rs`、新規）

`ViewMode::Hinge` のクリック処理（`app.hinge_detail_elem = Some(id)`）に倣い、
`TimeHistory` モードでのクリックで `app.th_detail_elem = Some(id)` をセット。
`hinge::show_hinge_detail_window` と同様の `egui::Window` + `egui_plot`。

- **荷重変形履歴ループ**: 要素種別で 2 分類。
  - 軸力系（`Brace`/`Damper`/`Isolator`/`NodalSpring`）: N-δ。
    δ は両端変位差を材軸方向へ射影（`axial_relative_disp`、微小変形近似）。
  - 梁・柱（`Beam`/`Fiber`/`MultiSpring`）: M-θ（強軸/弱軸切替、i端/j端重ね
    表示）。θ は squid-n-solver の増分解析
    （`nonlinear::pushover::member_response::record_member_step`）と同じ式
    （弦回転を節点回転の局所成分から差し引く）を複製（`beam_end_rotations`）。
  - 壁・シェル・パネルゾーンはループ表示非対応の旨を案内。
  - 内力が 1 フレームも記録されていない要素（`elem_has_force_recording` が
    false）は「記録されていません」と案内してループを描かない。
- **最大応力検定**: `ThRecording::peak_member_forces`（全ステップ包絡）から
  `MemberForcesAt` を組み、断面形状・材料名で RC/Steel/SRC/CFT の
  `DesignCheck` へ振り分けて短期検定（`app::actions::run_design_check` と
  同じ振り分けロジックだが、当該関数は `app` モジュール内の非公開関数
  （`is_steel`/`member_kind_of` 等）に依存しビューア側から呼べないため、
  必要分だけ `th_detail.rs` 内へ複製）。

## 簡略化した点（意図的な判断。フル実装は別タスクで検討）

- **検定コンテキストが簡易**: 座屈長さ lk_y/lk_z は自動算定せず部材長
  （K=1 相当）を使う。鋼継手・スカラップの欠損率、一本部材グループの応力
  合成、地震時短期 QD の長期内力割増、BRB 属性による検定式差し替えは
  いずれも `run_design_check` にはあるが本ウィンドウには含めていない。
  ウィンドウ内に「簡易検定です」の注記を表示している。
- **長期重ね合わせの注記は現在の設定値ベース**: `ResponseResult` 自体には
  「線形/非線形のどちらで解析したか」「長期荷重を初期載荷したか」の情報が
  残っていないため、注記は `AnalysisSettings::th_nonlinear` /
  `th_apply_long_term`（解析タブの**現在の設定値**）を参照している。解析後に
  設定を変更してから結果を見た場合、注記が実際の解析条件と食い違う可能性が
  ある。正確を期すなら `ResponseResult`/`ThRecording` に解析時のフラグを
  残す改修が必要（solver 側の変更が要るため見送った）。

  **解消済み（追記、2026-07）**: `ResponseResult` に `nonlinear: bool`・
  `applied_long_term: bool`（いずれも `#[serde(default)]`）を追加し、解析時の
  条件をそのまま記録するようにした（線形・HHT-α は常に `false, false`、非線形は
  `nonlinear=true`・`applied_long_term` は `NonlinearThCfg::apply_long_term` の値）。
  `viewer/th_detail.rs::draw_long_term_note` は `AnalysisSettings` の参照をやめ、
  この 2 フラグを引数で受け取るよう変更した。解析後に解析タブの設定を変更しても、
  詳細ウィンドウの注記は解析実行時の条件のまま変わらない
  （詳細は `dev_docs/handoff/時刻歴応答_詳細記録と長期荷重初期化_申し送り.md`
  「追記3」参照）。
- **免震・ダンパー要素は内力が記録されない**: `IsolatorElement` /
  `MaxwellDamperElement` / `HystereticDamperElement` は
  `ElementBehavior::recover_forces`/`state_member_forces` を実装しておらず
  （デフォルトで `None`）、`ThRecording::member_forces` が常に `None` になる。
  そのため軸力系ループは免震・ダンパー要素では常に「記録されていません」と
  表示される。`NodalSpring` は `recover_forces`（線形）のみ実装しており、
  非線形時刻歴では同様に記録されない。N-δ ループを実際に確認できるのは
  現状 `Brace`（トラス要素）が中心。内力を記録したい場合は squid-n-element
  側に `recover_forces`/`state_member_forces` の実装追加が必要（別タスク）。

  **解消済み（追記、2026-07）**: 免震支承（`IsolatorElement`）・マクスウェル
  ダンパー（`MaxwellDamperElement`）・履歴型ダンパー（`HystereticDamperElement`）・
  節点ばね（`NodalSpring`）のいずれも `state_member_forces` を実装し、現在の
  要素状態（軸力・軸方向相対変位相当の内力）を返すようにした
  （`crates/squid-n-element/src/springs/{isolator.rs, damper/maxwell.rs,
  damper/hysteretic.rs, spring.rs}`）。符号規約は節点ばねの `recover_forces`
  （軸力は引張を正）に統一している。これにより、これらの要素種別でも
  3D ビューの時刻歴詳細ウィンドウで N-δ 履歴ループが表示できるようになった。
- **M-θ の曲げ軸既定値**: `hinge.rs` の M-θ カーブは最終ステップの
  強軸/弱軸のうち絶対値が大きい方を自動選択するが、本ウィンドウでは
  自動選択をせず既定を強軸（Mz）固定＋手動トグルにした（時刻歴は全フレーム
  を通じて優勢な軸が変わりうるため、単純な自動判定が適切とは限らないと
  判断）。

## 2026-07-28 コードレビュー対応（ビューア・表示部分）

直前のコミット（ソルバ側: 層応答ピーク `peak_story_shear`/`peak_floor_accel`/
`peak_floor_vel`/`peak_floor_disp` の全ステップ追加、フレーム記録の部材内力を
両端 2 点へ間引き）を受けて、ビューア・表示側のコードレビュー指摘を解消した。

- **M-θ ループの i端モーメント符号規約統一**（`viewer/th_detail.rs::end_moments`）:
  `MemberForces::at` の ξ=0（i端）断面値は squid-n-element の「断面内力」規約
  （切断法で連続にするため節点モーメントを符号反転して格納）だが、
  ヒンジ詳細（`viewer/hinge.rs`）・増分解析の応答抽出
  （`nonlinear::pushover::member_response`）は「節点端モーメント」規約
  （反転なし）で θ と対にしている。両者の規約が食い違ったまま M-θ ループを
  描いていたため、i端のみ符号を再反転して節点端モーメント規約へ統一した
  （My/Mz とも）。単体テスト
  `flexural_points_i_end_slope_is_positive_for_elastic_cantilever` で、
  弾性片持ち梁相当の変位（理論たわみ曲線 \\(v_j=PL^3/3EI\\)・
  \\(\theta_j=PL^2/2EI\\) を `BeamElement::recover_forces` で内力復元）を
  与えたときに i端の M-θ 勾配が正になることを検証している
  （修正前はこのテストが失敗することを確認済み）。
- **時刻歴アニメーションの変形倍率を記録全体のピークから 1 回だけ算定**
  （`viewer/mod.rs::time_history_deform_scale`／`TimeHistoryScaleCache`）:
  通常の変形図（`deform_display_scale`）は現在フレームの変位から自動倍率を
  算定するため、時刻歴アニメーションにそのまま使うと振幅の小さいフレームで
  倍率が発散し、無変形フレームでは 0 になって表示が消えていた。
  `ResponseResult::peak_disp`（全ステップ間引きなしの並進成分絶対値最大）を
  仮想的な変位配列として `deform_display_scale` に与え、結果を
  `App::th_scale_cache`（フレーム数・ピーク変位・モデルサイズ・内部たわみ
  表示 ON/OFF が変わらない限り再利用）にキャッシュする。手動倍率係数
  （スライダー）はキャッシュ後に別途掛け合わせるため、フレーム切替を伴わず
  スライダー操作だけなら再計算なしに反映される。
- **モデル編集後の添字ずれ対策**（`viewer/mod.rs`・`viewer/th_detail.rs`）:
  `app.staleness.results_stale`（他タブの「⚠ モデルが編集されました」表示と
  同じ判定条件）が立っている間は、時刻歴モードの変形アニメーション・部材
  クリックを無効化し「モデルが編集されています。解析を再実行してください」
  と案内する。開いている部材の履歴・検定ウィンドウ（`th_detail.rs`）でも
  同様にプロット・検定を隠して同じ案内を出す。モデル編集で部材の並び
  （`elem_idx`）が変わり、別部材の記録を誤って表示する事態を防ぐ。
- **零長要素（免震・節点ばね）の N-δ ループ**（`viewer/th_detail.rs`）:
  部材長がほぼ 0 の要素は材軸方向が定まらず、従来の材軸射影
  （`axial_relative_disp`）は常に 0 を返していた。要素種別ごとの実際の
  零長時ローカル軸規約（`IsolatorElement::new`＝軸=鉛直・せん断=水平、
  `NodalSpringElement::new`＝単位回転）を複製した
  `zero_length_local_frame`/`zero_length_relative_disp` で成分別
  （軸／せん断y／せん断z）の相対変位を求め、成分切替 UI（`AxialComponent`）
  を追加した。免震支承は水平せん断（Qy-δy）を既定表示にする
  （`default_axial_component`）。通常長の要素（ブレース・ダンパー等）は
  従来どおり軸方向 N-δ のみで、切替 UI は出さない。
- **検定の成分非同時性の注記**（`viewer/th_detail.rs::draw_peak_check`）:
  既存の「簡易検定です」注記に、各成分（軸力・せん断力・曲げモーメント）の
  最大値が全ステップ包絡のため同一時刻に生じたとは限らない旨を追記した。
- **層応答最大値を全ステップピークへ切替**（`time_history_view.rs`・
  `summary.rs`・`story_response.rs`）: 層応答分布グラフ・レポート CSV の
  層せん断力・階加速度・階速度・階変位を、間引きフレームからの
  `story_absmax` 集計ではなく、`StoryResponse::peak_story_shear`／
  `peak_floor_accel`／`peak_floor_vel`／`peak_floor_disp`（全ステップ更新、
  間引きなし）を直接使うよう変更した。層せん断力係数は従来どおり
  `peak_shear_coeff` のまま。`story_absmax` 自体は純関数として残しているが、
  呼び出し元はなくなった。
- **時刻歴の詳細記録の保存方針**（当初は .scz から常時除外としたが、その後の
  ユーザー指示「結果を制限のために捨てるのは違う」を受けて以下へ変更）:
  - `.scz` 読込の 1 エントリ展開上限を 512 MiB → **4 GiB** に引き上げ
    （`squid_n_io::scz::MAX_ENTRY_UNCOMPRESSED`）。単層 deflate の展開率は
    理論上約 1032 倍が上限のため、絶対サイズ上限がメモリ保護として機能する。
    展開率ベースの検知は、ゼロ成分の多い正当な解析結果でも高圧縮になり
    誤検知しうるため不採用とした。
  - 詳細記録は**既定で保存に含める**。解析結果の直列化サイズが 512 MB
    （`app/actions.rs::SAVE_RECORDING_CONFIRM_BYTES`）を超え、かつ詳細記録を
    含む場合のみ、保存時に確認ダイアログ（含めて保存／除外して保存／
    キャンセル。`App::pending_save_recording`）を表示する。除外時は `take()` →
    直列化 → 書き戻しで、メモリ上の記録は保持される
    （`save_project_without_recording`）。
- **階名を添字ではなく `StoryId` で突き合わせ**（`story_response.rs::
  story_display_names`、`time_history_view.rs`・`summary.rs` から利用）:
  解析後にモデルの階が編集（追加・削除・並び替え）されても、記録済みの
  `StoryId` で現在のモデルの階を探すため、別の階の名前を誤って表示しない。
  該当する階が見つからない場合は「(削除済み階)」と表示する。
- **非線形 ON 時の積分法 UI**（`app/panels.rs`）: Newmark-β は選択状態のまま
  常に有効表示にし（非線形時刻歴は常に Newmark-β 相当で解くため選択自体を
  無効化する理由がない）、HHT-α のみ無効化して hover に理由
  （「非線形時刻歴は Newmark-β 固定です」）を表示するよう UI 構造を変更した
  （実際の解析挙動は変更なし。`th_integrator` は非線形時は元々無視される）。
