# 時刻歴アニメーション表示 申し送り

2026-07 実施。3D ビューアに時刻歴応答解析（`ThRecording`）のアニメーション再生
表示モードと、部材クリックでの荷重変形履歴ループ・簡易断面検定ウィンドウを追加。

## 背景

`ResultsBundle.time_history: Option<ResponseResult>` の `recording:
Option<ThRecording>`（フレームごとの全節点変位・部材内力、全ステップの
部材内力包絡）は既存の解析側実装で用意されていたが、3D ビュー側の表示が
無かった。地震応答の変形の様子をアニメーションで確認し、任意部材の
荷重変形履歴・最大応力に対する検定を見られるようにした。

## 実施内容（squid-n-app のみ、solver/element 側は変更なし）

### 1. `ViewMode::TimeHistory`（`viewer/mod.rs`）

- `recording` がある場合のみ表示モード選択肢に「時刻歴」を出す
  （`has_th_recording` を `viewer_panel` 冒頭で判定）。
- フレーム制御 UI（スライダー・再生/一時停止・速度 ×0.25〜×2）を追加。
  再生中は `ctx.input(|i| i.stable_dt)` を積算した再生経過時刻
  `App::th_play_time` を、`advance_play_time`/`frame_at_time`（純関数、単体
  テスト付き）でフレーム番号 `App::th_frame` へ写像する。末尾はループ
  （`f64::rem_euclid`）。
- 変形描画は `ViewMode::Deformed` と同じ経路を流用（`disp` の match 分岐に
  `TimeHistory` アームを追加し、`recording.node_disp[th_frame]` を渡すだけ）。
  変形倍率スライダー・内部たわみトグルも `show_deform_options` の対象に
  `TimeHistory` を追加して共用。
- 床・二次部材の変形追従（`interpolate_unreferenced_disp`）は Deformed と
  完全に共通の経路（同じ `display_disp` 呼び出し）なので、追加の判断は不要
  だった（実装内容の想定どおり流用できた）。

### 2. 部材クリックの履歴・検定ウィンドウ（`viewer/th_detail.rs`、新規）

`ViewMode::Hinge` のクリック処理（`app.hinge_detail_elem = Some(id)`）に倣い、
`TimeHistory` モードでのクリックで `app.th_detail_elem = Some(id)` をセット。
`hinge::show_hinge_detail_window` と同様の `egui::Window` + `egui_plot`。

- **荷重変形履歴ループ**: 要素種別で 2 分類。
  - 軸力系（`Brace`/`Damper`/`Isolator`/`NodalSpring`）: N-δ。
    δ は両端変位差を材軸方向へ射影（`axial_relative_disp`、微小変形近似）。
  - 梁・柱（`Beam`/`Fiber`/`MultiSpring`）: M-θ（強軸/弱軸切替、i端/j端重ね
    表示）。θ は squid-n-solver の増分解析
    （`nonlinear::pushover::member_response::record_member_step`）と同じ式
    （弦回転を節点回転の局所成分から差し引く）を複製（`beam_end_rotations`）。
  - 壁・シェル・パネルゾーンはループ表示非対応の旨を案内。
  - 内力が 1 フレームも記録されていない要素（`elem_has_force_recording` が
    false）は「記録されていません」と案内してループを描かない。
- **最大応力検定**: `ThRecording::peak_member_forces`（全ステップ包絡）から
  `MemberForcesAt` を組み、断面形状・材料名で RC/Steel/SRC/CFT の
  `DesignCheck` へ振り分けて短期検定（`app::actions::run_design_check` と
  同じ振り分けロジックだが、当該関数は `app` モジュール内の非公開関数
  （`is_steel`/`member_kind_of` 等）に依存しビューア側から呼べないため、
  必要分だけ `th_detail.rs` 内へ複製）。

## 簡略化した点（意図的な判断。フル実装は別タスクで検討）

- **検定コンテキストが簡易**: 座屈長さ lk_y/lk_z は自動算定せず部材長
  （K=1 相当）を使う。鋼継手・スカラップの欠損率、一本部材グループの応力
  合成、地震時短期 QD の長期内力割増、BRB 属性による検定式差し替えは
  いずれも `run_design_check` にはあるが本ウィンドウには含めていない。
  ウィンドウ内に「簡易検定です」の注記を表示している。
- **長期重ね合わせの注記は現在の設定値ベース**: `ResponseResult` 自体には
  「線形/非線形のどちらで解析したか」「長期荷重を初期載荷したか」の情報が
  残っていないため、注記は `AnalysisSettings::th_nonlinear` /
  `th_apply_long_term`（解析タブの**現在の設定値**）を参照している。解析後に
  設定を変更してから結果を見た場合、注記が実際の解析条件と食い違う可能性が
  ある。正確を期すなら `ResponseResult`/`ThRecording` に解析時のフラグを
  残す改修が必要（solver 側の変更が要るため見送った）。
- **免震・ダンパー要素は内力が記録されない**: `IsolatorElement` /
  `MaxwellDamperElement` / `HystereticDamperElement` は
  `ElementBehavior::recover_forces`/`state_member_forces` を実装しておらず
  （デフォルトで `None`）、`ThRecording::member_forces` が常に `None` になる。
  そのため軸力系ループは免震・ダンパー要素では常に「記録されていません」と
  表示される。`NodalSpring` は `recover_forces`（線形）のみ実装しており、
  非線形時刻歴では同様に記録されない。N-δ ループを実際に確認できるのは
  現状 `Brace`（トラス要素）が中心。内力を記録したい場合は squid-n-element
  側に `recover_forces`/`state_member_forces` の実装追加が必要（別タスク）。
- **M-θ の曲げ軸既定値**: `hinge.rs` の M-θ カーブは最終ステップの
  強軸/弱軸のうち絶対値が大きい方を自動選択するが、本ウィンドウでは
  自動選択をせず既定を強軸（Mz）固定＋手動トグルにした（時刻歴は全フレーム
  を通じて優勢な軸が変わりうるため、単純な自動判定が適切とは限らないと
  判断）。

## テスト

`crates/squid-n-app/src/viewer/th_detail.rs`・`viewer/mod.rs` に純関数の単体
テストを追加（`cargo test -p squid-n-app --lib --features gui`）。

- `axial_relative_disp` / `beam_end_rotations`: 剛体並進・弦回転一致・純回転の
  各ケース。
- `loop_kind_of` / `is_steel_material`: 分類の境界確認。
- `advance_play_time` / `frame_at_time`: 再生時刻の周回・フレーム写像。

`cargo clippy -p squid-n-app --all-targets --features gui -- -D warnings` は、
本改修と無関係な `time_history_view.rs`（未変更ファイル）の
`clippy::type_complexity` 警告 1 件（2 箇所）により失敗する。当該ファイルは
今回のタスクの編集許可範囲外のため対応していない。
