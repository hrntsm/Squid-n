# 仕口パネル: 対象接合部の判定とオフセットの出所の見直し 申し送り

関連文書: [仕口パネル_申し送り.md](仕口パネル_申し送り.md)、
[仕口パネル_定式化と検証_2026-07.md](../v_and_v/仕口パネル_定式化と検証_2026-07.md)

PR #153 でパネルのモデル化を導入したあと、利用者から次の 2 点の指摘を受けて着手した。

1. モデル化図で、材端集中ばね・ファイバー断面の記号がパネルの内側（節点位置）に描かれる
2. RC 梁 ＋ S 柱の接合部にもパネルが生成され、寸法が RC 梁基準になっている

## 1. 何が問題だったか

### 1.1 オフセットの所在が `factory` の中だけだった

パネル分のオフセット（部材がパネル面で接合するための剛体アーム）は、
`panel_offset::resolve` が要素の組み立て時に `ElementData` を複製して剛域長へ
折り込んでいた。モデルに保存された `rigid_zone.length_i/j` は 0 のままだったため、
**`rigid_zone` を直接読む側はオフセットを見落としていた**。

| 箇所 | 用途 | 状態 |
|---|---|---|
| `app/viewer/modeling.rs` | 可撓区間・材端記号の位置 | 見落とし（**指摘 1 の原因**） |
| `solver/nonlinear/pushover/geom.rs` | 幾何剛性の剛域変換 | 見落とし（弾性剛性と剛域長が食い違う） |
| `solver/nonlinear/pushover/shear_yield.rs` | せん断降伏の `h0` | 見落とし |
| `design-jp/steel/buckling.rs` | 剛度比 `G` の材長 `L'` | 見落とし |

指摘 1 は**描画の問題**で、解析（要素剛性）は正しかった。

### 1.2 オフセットが危険断面位置に相乗りしていた

オフセットの大きさに `RigidZone::face_i/face_j` を使っていた。これは
**断面算定の既定の危険断面位置**でもあり、利用者から「危険断面位置は将来任意位置へ
拡張する」との方針が示されたため、そのままでは危険断面位置を動かすとパネルの接合位置が
一緒に動いてしまう。

加えて `face_i` は「概ね直交する**全**部材の最大せい/2」であり、はりにとっては直交する
**はり**も候補に入る。直交ばりのほうがせいが大きい接合部では、はりの接合位置が
そのばりのフェースになり、資料の「柱フェースで接合」から外れていた。

### 1.3 梁の構造種別を見ていなかった

`panel_gen::panel_at` は梁を「鉛直成分が小さい・断面が割当済み」でしか判定せず、
S 造かを見ていなかった。RC 梁でも `has_beam` が立ち、`beam_panel_depth` の
`0.9 × せい` フォールバックが RC 梁せいを `db` に持ち込んでいた（**指摘 2 の原因**）。

一方、**断面検定側は `is_steel(材料名)` で S 梁だけを抽出しており**、モデル化側だけが
規則から外れていた。ただし検定側の材料名前方一致（`SS`/`SN`/`SM`/`STK`/`ST`/`SA`/`BC`）も
脆く、独自名の鋼材を取りこぼす。

### 1.4 柱の選択が要素の並び順に依存していた

柱が複数取り付く節点では「諸元を解決できた**最初の 1 本**」から `dc`・`tp` を取っていた。
下階 RC 柱・上階 S 柱の切替階では RC 柱が読み飛ばされて S 柱側の諸元だけでパネルが
作られ、S 柱同士でも断面が違えば要素配列の順序で結果が変わった。

## 2. どう直したか

### 2.1 構造種別の判定を `squid_n_core::structure_kind` へ一元化

`squid-n-element/frame/beam/rigid_zone.rs` の private `MemberKind` を
`squid_n_core::structure_kind::StructureKind` として core へ移した。判定順（断面形状 →
無ければ材料の `fc`/`fy` → どちらも無ければ RC/SRC）はそのまま。

これを剛域算定・パネルのモデル化・パネルの断面検定の 3 者が共有するため、
「剛域長 0 になる S 接合部 ＝ パネルを設ける接合部」の対応がコード上も一致する。

### 2.2 対象接合部の判定を `squid_n_core::panel_zone::resolve_panel_joint` へ集約

モデル化と断面検定が**同じ関数**を通る。規則は次のとおり。

- 柱が 1 本以上・はりが 1 本以上取り付く
- 取り付く**柱・はりがすべて S/CFT 系**（1 本でも RC/SRC が混じれば対象外）
- 諸元を解決できる柱があり `Ve` が正
- 柱が複数なら **`Ve` が最小になる柱**の諸元を採る（決定的かつ安全側）

斜材は資料が接合位置・ζ を定めておらずパネルと連成しないため、種別判定の対象にもしない。

モデル化だけが追加で `PanelJoint::has_filled_column`（CFT を含むか）を見る。

**検定の網羅性が下がる点に注意。**従来は S 柱＋S 梁が 1 本でもあれば検定していたが、
RC/SRC が混じる接合部は検定しなくなった。利用者確認済みの判断で、`docs` にも明記した。

### 2.3 オフセットを危険断面位置から切り離した

`squid_n_core::panel_zone::panel_half_extent` が接合部の物理的な半寸法を返す。

| 部材 | オフセット |
|---|---|
| はり | 取り付く柱せいの最大値 / 2 |
| 柱 | 取り付く梁せいの最大値 / 2 |

柱・はりを明示的に区別するので、1.2 の「直交ばりを拾う」穴も同時に塞がる。
`face_i/face_j` は一切参照しない。回帰テストで独立性を押さえてある
（`test_resolve_is_independent_of_face_distance` / `test_panel_half_extent_is_independent_of_face_distance`）。

### 2.4 オフセットをモデルの剛域長へ書き込むようにした

`panel_gen::apply_auto_panel_zones` の末尾で `rigid_zone.length_i/j` へ
`max(現在値, オフセット)` を書き込む。これで 1.1 の 4 箇所がすべて同じ値を見る。

`panel_offset::resolve` は**剛域長を触らなくなり**、戻り値も
`Option<[Option<PanelEnd>; 2]>`（接合面の ζ だけ）へ縮んだ。

書き込みは `ZoneSource` に依らず行う。オフセットは「部材が節点ではなくパネル面で接合する」
という幾何的事実で、剛域長の設計的な調整量とは性質が違うため。`max` を取るので手動指定が
オフセットより大きければ残る。

剛域の自動算定はパネル生成より前に走って `Auto` 端を再算定するので、パネルを OFF に
すれば書き込みは消え、繰り返し適用しても増えない。

## 3. 既存挙動への影響

### 3.1 軸剛性・ねじり剛性は変わらない

`beam/stiffness.rs::local_stiffness_flex` が剛域のある部材で断面性能を
`A·(L'/L)`・`J·(L'/L)` に補正しており、`EA/L`・`GJ/L`（節点間長基準）へ揃う。
剛域変換 `Tr` も軸・回転自由度に作用しない。剛域長が増えても軸・ねじりは影響を受けない。

### 3.2 座屈長さは直接は変わらない

`lk_y = K_y × 節点間長さ`（`actions.rs`）であり、`buckling.rs::clear_length` が使われるのは
**剛度比 `G` の材長**のみ。パネル分が入ると柱側・梁側の `L'` が両方短くなるため、
`G` は比として打ち消し合い、`K` の変化は小さい。横座屈長さ `lb` は剛域を見ないので無関係。

### 3.3 幾何剛性・せん断降伏 `h0` が変わる

こちらは実害のあった不整合の解消。パネルを設けた S 接合部で、P-Δ の幾何剛性と
せん断降伏の内法高さが弾性剛性と同じ可撓長を用いるようになった。

### 3.4 RC/SRC 混在接合部のパネルが消える

指摘 2 のとおり、これらの接合部にはパネルが生成されなくなり、S パネルゾーンの検定も
行われなくなる。既存モデルで該当する接合部があれば、解析結果と検定件数の双方が変わる。

## 4. 残課題

[仕口パネル_申し送り.md](仕口パネル_申し送り.md) §4 に挙げたものは、次を除いて残っている。

- 「柱が複数取り付く節点で最初の 1 本を採る」は `Ve` 最小の柱を採る規則で解消した
- 「`face_i` への相乗り」は解消した

新たに残るもの。

- **`db` の非 H 形フォールバック**（`0.9 × せい`）は S 梁にのみ効くようになったが、
  角形・円形の梁せいからフランジ中心間距離を推定する根拠は依然として弱い
- **`resolve_panel_joint` が全要素を走査する**。呼び出し側が隣接マップを渡せる形には
  してあるが、`panel_gen` と検定配線は `&model.elements` をそのまま渡している。
  大規模モデルでは隣接マップの事前構築へ寄せる余地がある

## 5. テストの入口

| 対象 | 場所 |
|---|---|
| 構造種別の判定 | `squid-n-core/src/structure_kind.rs` の `tests` |
| 対象接合部の判定・`Ve` 最小柱の選択 | `squid-n-core/src/panel_zone.rs` の `tests` |
| 接合部の半寸法と危険断面位置の独立性 | 同上 |
| オフセットの剛域長への書き込み・冪等性 | `squid-n-element/src/springs/panel_gen.rs` の `tests` |
| RC 梁・混在接合部の除外 | 同上 |
| `resolve` が `face` に依存しないこと | `squid-n-element/src/frame/panel_offset.rs` の `tests` |
| モデル化図の四角形寸法 | `squid-n-app/src/viewer/modeling.rs` の `tests`（`--features gui`） |
| 系レベル（解析解照合・釣り合い） | `squid-n-solver/tests/panel_zone.rs` |

`squid-n-solver/tests/panel_zone.rs` のモデルは、パネル要素を手組みせず
`apply_auto_panel_zones` で生成するようにした。パネル要素の追加とオフセットの
書き込みが一体の処理なので、手組みすると実際のモデル化と食い違うためである。
