# 時刻歴ソルバの重複統合と HHT-α の削除 — 申し送り

作成日: 2026-09-02
対象コード: `crates/squid-n-solver/src/dynamic/timehistory/`、`crates/squid-n-app/src/viewer/`

この申し送りでは、時刻歴応答解析の積分器から重複を抜いた経緯と、HHT-α 法を廃止した判断を記録します。
あわせて、同じ波で行った `viewer_panel` の分割も記録します。

## 背景

コードベース全体を見渡して、リファクタリングの対象を選ぶところから始めました。
候補として挙がったのは、124 フィールドの `App` 構造体の分離、時刻歴ソルバの重複統合、1447 行の `viewer_panel` の分解の 3 つです。

このうち `App` の分離は本ブランチでは扱いません。
gui フィーチャ配下の 76 フィールドを別型へ移すと書き換え箇所が 889 か所になり、検証の大半がコンパイラ頼みになるためです。
GUI の挙動退行はテストで拾いきれないため、専用ブランチで一括して行うのが妥当だと判断しました。

対象に選んだのは、時刻歴ソルバの重複と `viewer_panel` の 2 つです。
数値計算コアの重複は、この一貫プログラムでもっとも高くつく種類の負債だからです。
実際に [`実装レビューと重複統合_申し送り.md`](実装レビューと重複統合_申し送り.md) には、その実害が記録されています。
RC 側で直したせん断スパン比の規約が、コピーされた SRC 側では旧仕様（割増を最大化する非保守側）のまま残っていました。

時刻歴には次の重複がありました。

| 重複していたもの | コピー数 | 備考 |
| --- | --- | --- |
| Newmark 係数 c1〜c6 | 3 | HHT は β・γ を α から導く点だけが違う |
| 毎ステップの地動外力 `p = −M·r·ẍg` | 3 | ホットループ内。逐語一致 |
| 初期地動外力 `p(0)` | 3 | 逐語一致 |
| 時間刻みの解決と正値チェック | 3 | エラー文言まで一致 |
| 独立自由度が 0 のときの空応答 | 3 | 解析種別を示す 2 フィールドだけが違う |
| `use_kg` 未対応のエラー | 2 | 文言まで一致 |
| behaviors 構築・行列組立・縮約・減衰 | 2 | 約 30 行が逐語一致 |
| 縮約空間の初期変位・初期速度 | 2 | 逐語一致 |

## 変更内容

### HHT-α 法の削除

線形時刻歴の積分法から HHT-α を落としました。
削除したのは `hht.rs`（478 行）、`HhtCfg`、`ThIntegrator`、`Analysis::time_history_hht`、`squid-n-job` の分岐、解析パネルの「積分法」ラジオ、テスト 7 件（ソルバ 6・app 1）です。
利用者向けの計算根拠からも §5.5.2 を落とし、後続の節番号を繰り上げました。

HHT-α は死んだコードではなく、解析パネルから選べる現役の機能でした。
ですが、非線形時刻歴では選択できず線形時刻歴限定の選択肢であり、2 つの積分法を持ち続ける実務上の理由がないため、廃止を選んでいます。

`th_integrator` は `AnalysisSettings` のフィールドで、`.scz` の `analysis_settings.msgpack` へ含まれていました。
`rmp_serde::to_vec` は構造体を配列（フィールド名なし）で書くため、フィールドを 1 つ落とすと以降の並びがずれます。
そのため、**この変更より前に保存した `.scz` は解析タブの設定値を失います**。

失われ方は確認済みです。
ずれた位置では `bool` を読む場所に旧 `ThIntegrator` の列挙子（整数）が来るため、`rmp_serde` は型エラーを返します。
`decode_on_load` はこれを捕まえて「保存された解析タブの設定値を読み込めませんでした（再実行が必要です）」と通知し、既定値へ落とします。
黙って別の値として読むことはありません。
ですが、同じエントリに入っている波形ライブラリの選択（`wave_name`・`wave_sha256`）も一緒に失われるため、波形を選び直す必要があります。
モデル・準備計算・解析結果は別エントリのため影響を受けません。

数値減衰を持つ積分法が要るようになった場合は、`linear.rs` の `LinearSetup` を α 対応へ広げる形で復活させてください。
HHT-α は α=0 で平均加速度 Newmark に一致するため、有効剛性の重み付けと有効荷重の前ステップ項を足すだけで足ります。

### 時刻歴の前処理と地動外力の集約

上表の重複を [`timehistory/common.rs`](../../crates/squid-n-solver/src/dynamic/timehistory/common.rs) へ集約しました。
追加したのは `resolve_dt`・`NewmarkCoeffs`・`GroundInfluence`・`empty_response`・`reduced_vec_from` の 5 つです。

`GroundInfluence` は影響ベクトル `M·r_x`・`M·r_y`・`M·r_θ` の 3 本を束ねた型です。
3 本は常にまとめて使われ、等価地震力 `p = −M·r·ẍg` の構築も同じ式だったため、束と式を 1 か所に置いています。
ホットループは `force_at_into` でバッファへ書き込む形にし、ループ外の 1 回きりの用途には `force_at` を使い分けます。

線形側は、初回実行とチェックポイント再開が同じ前処理を 2 度書いていました。
これを `LinearSetup` へまとめ、`run_steps` の引数を 25 個から 11 個へ減らしています。
引数が 25 個あるということは、本来 1 つの型であるべきものが解けたまま渡されているという合図です。

数値はビット一致を保っています。
式そのものと演算順序を変えず、置き場所だけを移したためです。
地動加速度の取得は `wave.accel_x[n]` の直接添字から `get(n).unwrap_or(0.0)` へ変わります。
ですが、どちらの積分器もループの範囲を `accel_x.len()` で決めているため、到達しうる添字では同じ値を返します。

行数は `linear.rs` が 622 行から 534 行、`nonlinear.rs` が 1020 行から 974 行になりました。
`common.rs` は 148 行から 288 行へ増えています。

### `viewer_panel` の分割

`viewer_panel` は 1447 行あり、操作 UI・視点操作・クリック処理・描画が 1 つの関数に同居していました。
[`app_viewerハブ薄化_申し送り.md`](app_viewerハブ薄化_申し送り.md) で描画の実体は兄弟ファイルへ移してありますが、入口の関数そのものは太いままでした。

次の 2 ファイルへ切り出しています。

```
viewer/
  controls.rs — 表示モード・応力図成分・検定比フィルタ・時刻歴再生・変形表示の操作 UI
  input.rs    — カメラ操作、ViewCube、描画領域のクリック処理
```

`viewer_panel` は 1447 行から 809 行になり、`mod.rs` は 2316 行から 1679 行になりました。
残しているのは、投影文脈の構築と、モードごとの描画の振り分けです。
どちらも `proj` と `pts` を共有するため、切り出すと引数のバケツリレーが増えるだけになります。

`input.rs` の並びは、処理が走る順に合わせています。
視点（`interact_camera`・`interact_viewcube`）は投影より前に確定させる必要があります。
一方、クリック処理（`handle_click`）は投影後の点列が要ります。
ホバー時の強調表示は描画と一体のため、`viewer_panel` 側に残しました。

## 設計判断

- **線形と HHT の統合ではなく、HHT の削除を選ぶ。** α=0 で一致するため 1 実装へまとめることもできるが、チェックポイント再開 API を HHT 側へも広げることになり、利用者から見た解析種別の輪郭も薄れる
- **式は共有し、係数の選択は呼び出し側に残す。** `NewmarkCoeffs` は β・γ を受け取るだけで、平均加速度法か線形加速度法かは呼び出し側が決める
- **`GroundInfluence` に書き込み版と確保版の両方を置く。** ホットループでの確保を避けつつ、1 回きりの初期外力では読みやすさを取る
- **`viewer_panel` の入口は 1 つのままにする。** 表示モードごとにファイルを切ると、モード追加のたびに階層が増える

## 意図的にやらないこと（残課題）

- `AppCore` / `UiState` への型分離。専用ブランチで一括して行う（[`実装レビューと重複統合_申し送り.md`](実装レビューと重複統合_申し送り.md) §2.2）
- `viewer_panel` に残る 809 行の描画振り分け。投影文脈を共有するため、切ると引数が増えるだけになる
- 巨大テストファイルの分割。`app/tests.rs` は 8148 行ある
