# モデル化図・解析対象外節点の表示修正 申し送り

作成日: 2026-07-25
対象コード:
`crates/squid-n-app/src/viewer/mod.rs`、`crates/squid-n-app/src/viewer/modeling.rs`、
`crates/squid-n-core/src/dof.rs`、`crates/squid-n-element/src/factory/springs.rs`、
`crates/squid-n-element/src/frame/fiber/mod.rs`、
`crates/squid-n-element/src/frame/multi_spring.rs`、
`docs/result_view.md`、`docs/calc_basis/04_要素剛性/09_非線形梁要素のモデル化.md`

3D ビューアの表示について、次の 4 点を修正した。

## 1. 「床・二次部材」OFF で解析対象外の節点が浮いて残る

### 症状（変更前）

「床・二次部材」トグルを OFF にするとスラブ・小梁・二次部材の線は消えるが、
節点はモデルの全節点を無条件に描いていたため、**二次部材・床だけが参照する節点が
空中に浮いて残っていた**。実在しない構造点があるように見え、主架構の確認を妨げる。

### 対応（変更後）

節点の表示可否を「構造節点（解析自由度を持つ節点）か、または『床・二次部材』が
表示中か」で判定する（`viewer_panel` の `node_visible`）。構造節点の判定は解析
（`DofMap::build`）と同じ規則で、後述のとおり `squid_n_core::dof::structural_nodes`
へ一元化した。

非表示の節点は `pick_nearest_node` のピック対象からも外す（引数に可視フラグを追加）。
見えない節点が梁・壁・スラブ作成モードで選ばれてしまうのを防ぐため。

## 2. 剛域と弾性材の表示が近く区別できない

### 症状（変更前）

剛域バーは `translucent(GRAY_900, 150)` の 6px 線だった。ビュー背景（`VIEW_BG`
= `#F0F2F5`）と混色すると実効色は約 `#6D7078` となり、弾性材の `GRAY_600`
（`#4B5563`）とほぼ同じ明度になる。太さの違いしか手掛かりがなく、静解析（全部材が
グレー）の表示では剛域が判別できなかった。

### 対応（変更後）

`draw_rigid_zone` を「太さと色が違う線」から「**ハッチング入りのブロック**」へ
変えた。材軸に沿った矩形の輪郭（±4px の平行線 2 本＋両端キャップ）と、その内部の
斜めハッチ（間隔 4px、長い区間は本数を頭打ちにして間隔を広げる）で描く。
線材とは**図形の種類そのものが違う**ため、色や太さの微差に頼らずに区別できる。
両端のキャップがそのまま剛域フェイスの位置を示す。

白などで下地を塗り潰す案は採らなかった。要素ごとに逐次描画するため、接合部で
後続部材のケーシングが先行部材の記号を消し、描画順に依存した白い抜けが出るため。

壁エレメントの上下剛梁も同じ `draw_rigid_zone` を使うよう統一した（従来は同じ
半透明色をインラインで指定していた）。凡例のスウォッチも `draw_rigid_zone` を
呼んで実物と一致させている。

弾性材の色（`GRAY_600`）は TONMANUAL の「弾性＝降伏を考えない中立色」の規定に
従いそのままとした。

## 3. ファイバー要素のファイバー位置が表示されない

### 症状（変更前）

モデル化図は、`plastic_zone` が**指定されている場合だけ**端部 Lp 区間を太線にし、
未指定なら「可とう長全体を分布塑性」としてファイバー色一色で描いていた。
しかし要素生成（`factory::build_fiber`）は **`plastic_zone` の指定有無に依らず常に**
`FiberBeam::with_plastic_zone` を用いており、未指定時は Lp = 断面せいの 0.5 倍が
既定として入る。つまり実際の解析は常に「材端 2 断面のファイバー＋中央弾性」で、
表示の「可とう長全体を分布塑性」は解析と食い違っていた。さらにファイバー断面の
位置（積分点）そのものは描かれていなかった。

### 対応（変更後）

`FiberBeam::build_plastic_zone` の定式化どおりに描く。

- **端部 Lp 区間**（積分点 ξ=∓1 の積分重み）を部材色の太線、
  **中央 [Lp, L−Lp]** を弾性色の細線で描く。
- **ファイバー断面の位置**（ξ=∓1 = 材端）に断面記号（材軸直交の短バー＋3 点）を
  描く（`draw_fiber_section_marker`）。接合部で複数部材の記号が重ならないよう、
  材軸方向へ 8px 内側へ寄せる（他の材端記号と同じ描画上のオフセット規約）。
- Lp は要素生成と同じ既定・同じクランプで解決する（下記 5 を参照）。
- MS 要素（`ElementKind::MultiSpring`）も実体は `FiberBeam::build_plastic_zone`
  （ファイバ分割が粗いだけ）なので同じ描き方とし、材端回転ばねではないため
  塑性ヒンジ（●）は描かない。分類（`ModelClass`）は従来どおり「材端集中塑性」の
  ままで、判定は `is_end_plastic_zone_model` が要素種別と分類から行う。

### 剛域の扱い

本作業の時点では `FiberBeam` が剛域変換を持たず、積分点は節点位置だった。
その後の追補（本書「6. 追補」）で `FiberBeam` に剛域を実装したため、現在は
可撓部の材端（剛域フェイス）が積分点である。表示もそれに追従している。

`end_cond`（ピン・半剛の材端解放）も同様に未対応だったが、「7. 追補」で実装した。
モデル化図の ○／□ は要素の挙動と一致している。

## 4. 剛床代表点の点線が二次部材の節点まで伸びる

### 症状（変更前）

「剛床代表点」トグル ON で代表点からスレーブ節点へ点線を引く際、
`Constraint::RigidDiaphragm::slaves` をそのまま辿っていた。階の生成
（`squid-n-load` の `story_gen`）は当該レベルの**全節点**をスレーブに登録するため、
スラブ境界・小梁支持点・二次部材の節点（解析自由度を持たない節点）も含まれ、
解析対象外の節点まで剛床に所属しているように見えていた。

### 対応（変更後）

点線を引く相手を構造節点に限定した。解析上もこれらの節点は剛床の縮約対象では
ない（`DofMap` が全自由度を不活性にし、拘束行列の生成
（`solver/common/constraint.rs`）も `dofmap.active` が `None` を返す自由度を
素通りする）ため、表示を解析の実態に合わせた形になる。

モデルデータ側（`slaves` の中身）は変更していない。`slaves` から解析対象外の節点を
除くと、`precheck` の孤立節点チェック（要素・拘束・床・二次部材のいずれからも
参照されない節点を弾く）の判定が変わり、従来通っていたモデルが弾かれる可能性が
あるため、表示側の対応にとどめた。

## 5. 判定・既定値の一元化（重複解消）

同じ規則が複数箇所に写経されていたため、次の 2 つを共有関数へ集約した。

- **構造節点の判定**: `squid_n_core::dof::structural_nodes(model) -> Vec<bool>` を
  新設し、`DofMap::build` と、ビューアの `interpolate_unreferenced_disp` /
  節点表示 / 剛床点線が共有する。
- **塑性化域長 Lp の既定**: `squid_n_element::factory::plastic_zone_length`
  （`plastic_zone` 指定値、未指定は断面せいの 0.5 倍、断面不明は 200mm 仮定）と
  `squid_n_element::fiber::clamp_plastic_zone`（部材長に対する
  `[1e-6·L, 0.45·L]` クランプ）を公開し、`build_fiber` / `MultiSpringElement::new` /
  `FiberBeam::build_plastic_zone` / モデル化図が同じ値を使う。

これにより「表示の Lp」と「解析の Lp」が原理的に一致する。

## テスト

- `viewer/modeling.rs`（`--features gui`）:
  - `端部塑性化域モデルの判定は増分解析のファイバーとmsのみ`
  - `塑性化域長は要素生成の既定と一致する`（既定 0.5D・指定値優先・45% クランプ）
- 既存の分類テスト（静解析＝弾性／regime 別振り分け／MS の解析種別別分類／壁の
  耐震壁・雑壁）はそのまま維持。

## 既知の制約

- 「床・二次部材」OFF で非表示になるのは**解析自由度を持たない節点**であり、
  主架構の部材が 1 本でも接続する節点は常に表示される（床にしか使っていない節点でも
  主架構に接続していれば表示される）。
- ファイバー断面記号は材軸方向へ 8px 内側へ寄せて描くため、極端にズームアウトした

## 6. 追補: FiberBeam の剛域対応

対象コード: `crates/squid-n-element/src/frame/rigid_arm.rs`（新規）、
`frame/fiber/mod.rs`、`frame/beam/stiffness.rs`、`frame/beam/behavior.rs`、
`crates/squid-n-app/src/viewer/modeling.rs`、
`docs/calc_basis/04_要素剛性/01_ティモシェンコ梁要素.md`、
`docs/calc_basis/04_要素剛性/09_非線形梁要素のモデル化.md`、`docs/result_view.md`

上記「3. 剛域を考慮しない件」で残課題としていた、`FiberBeam`（ファイバー要素・
MS 要素）の剛域未対応を解消した。

### 実装

剛体アームの運動学を `frame/rigid_arm.rs` へ切り出し、弾性梁とファイバー梁で共有する。

| 関数 | 内容 |
| --- | --- |
| `to_flex_disp` | `u_flex = Tr·u_node` |
| `to_node_force` | `f_node = Trᵀ·f_flex` |
| `transform_stiffness` | `K_node = Trᵀ·K_flex·Tr` |
| `resolve_lengths` | 剛域長を可撓長が正に残る範囲へ解決（負値は 0、合計が部材長以上なら剛域なし） |

`FiberBeam` は `rigid_i` / `rigid_j` / `flex_length` を保持し、次をすべて**可撓長基準**に変えた。

- せん断変形係数 φ（`FiberBeam::new`）
- 一定せん断ひずみ場の剛性 `k_shear`
- ひずみ－変位行列 `compute_b_matrix` の基準長
- 塑性化域考慮モデルの端部積分点重み `2Lp/L'`・中央弾性部 `k_mid`・Lp のクランプ
- 接線剛性・内力・幾何剛性・`ductility_probe`

断面ひずみは `flex_disp()`（＝ `Tr·trial_disp`）から評価し、接線剛性は `Trᵀ K Tr`、
内力は `Trᵀ f` で節点自由度へ写す。これにより**積分点 ξ=∓1 は剛域フェイス**に位置し、
塑性ヒンジが節点位置ではなく部材フェイスに形成される。

`MultiSpringElement` は `FiberBeam::build_plastic_zone` に委譲しているため自動的に追従する。

### 軸方向の扱い（設計判断）

弾性梁（4.1.4）は軸断面積を `A·(L'/L)` に補正して軸剛性を `EA/L`（節点間長基準）へ
戻し、剛域を曲げのみに効かせる。**ファイバー要素ではこの補正を行わない**（軸剛性は
`EA/L'`）。

理由: ファイバー断面の積分は軸ひずみと曲率から各ファイバーのひずみを決め、応力を
積分して `(N, My, Mz)` を同時に返す。軸成分だけを別の基準長へ補正すると、断面が返す
軸力が断面のひずみ状態と整合せず、N-M 相関（ファイバーモデルの要点）が崩れる。
単一の積分領域をもつ変位法要素で「軸だけ全長・曲げだけ可撓長」を対称かつ厳密な
勾配整合のまま実現することはできない。したがって軸方向は剛体アームの運動学に
そのまま従わせ、その帰結（軸剛性が L/L' 倍）を仕様として明記した（4.9.5）。

ねじりは断面積分と連成しない独立項なので、弾性梁と同じ節点間長基準 `GJ/L` のまま
（剛体アーム変換もねじり自由度には作用しない）。

### 弾性梁側の変更（副次）

`BeamElement` の `apply_rigid_zone_transform` を `rigid_arm::transform_stiffness` への
委譲に置き換え、剛域長の解決に `rigid_arm::resolve_lengths` を用いるようにした。
これにより、剛域長の合計が部材長以上の病的な入力で従来は**剛性ゼロの退化要素**
（特異行列の原因）になっていたのが、剛域なしへフォールバックするようになる。
実務モデルでは発生しない条件だが、ファイバー梁と規則を揃えるための変更である。

### 表示（モデル化図）

`FiberBeam` が剛域を考慮するようになったため、「剛域（この要素では未考慮）」の破線
ブロック表示（`draw_ignored_rigid_zone`）と対応する凡例・ツールチップ注記を削除した。
ファイバー／MS 要素も他の線材と同じハッチ入り剛域ブロックを描き、Lp 区間・断面記号は
可撓区間（剛域フェイス間）のパラメータで置く。`flexible_span` も
`rigid_arm::resolve_lengths` を使い、表示と解析の剛域解決を一致させている。

### V&V

`fiber/tests.rs`（新規 6 件）:

- `剛域ありの弾性剛性は軸以外が弾性梁と厳密一致する` — 剛域つき `BeamElement` と
  12×12 を比較し、軸自由度（0, 6）以外が `1e-9·max|K|` 以内で一致すること、軸は
  ファイバー `EA/L'`・弾性梁 `EA/L`、ねじりは両者 `GJ/L` であることを検証
- `剛域は片持ち先端の曲げ剛性を増大させる`
- `剛域ありでも剛体回転で内力が生じない`（客観性。剛体アームの符号検証）
- `剛域ありでも接線剛性が内力の勾配と一致する`（差分近似との照合。剛性側と内力側の
  変換整合）
- `剛域ありの塑性化域は可撓長基準になる`（積分点 ξ=∓1・重み 2Lp/L'）
- `可撓長が残らない剛域は無視される`

`rigid_arm.rs`（新規 3 件）: 恒等性・剛体回転の運動学・剛性変換の対称性。

`viewer/modeling.rs`: `可とう区間は要素側の剛域解決と一致する` を追加。

## 7. 追補: FiberBeam の材端解放（ピン・半剛）対応と系レベル V&V

対象コード: `crates/squid-n-element/src/frame/fiber/mod.rs`、`frame/rigid_arm.rs`、
`crates/squid-n-solver/src/nonlinear/pushover/{geom,hinge,member_response}.rs`、
`crates/squid-n-solver/src/nonlinear/strength_loss/mod.rs`、
`crates/squid-n-design-jp/tests/vnv_rigid_zone_ds.rs`（新規）、
`dev_docs/v_and_v/剛域_保有水平耐力_系レベル検証.md`（新規）、
`docs/calc_basis/04_要素剛性/09_非線形梁要素のモデル化.md`、
`docs/calc_basis/05_構造解析/{07_プッシュオーバー解析,08_段階的耐力喪失解析}.md`

「6. 追補」で残課題としていた 2 件（材端解放の未対応、系レベル V&V）に対応した。

### 7.1 材端解放（`end_cond`）の実装

`FiberBeam` は `EndCondition::Pinned` / `SemiRigid` を無視していた（常に剛接扱い）。
弾性梁 `BeamElement::condense_end_springs` と同じ定式化で実装した。

- 解放する回転自由度を `EndRelease { dof, spring }` として保持する
  （`resolve_end_releases`）。ピンは `spring = 0`、半剛は `k_theta`。
  **ねじり剛性がない部材（J≤0）の rx は解放しない**（縮約行列 `Kbb` の対角が
  ゼロになり特異化するだけで意味がないため）。
- 解放した要素端回転を内部自由度 `trial_int` として保持し、各 `update_state` で
  内部釣合い `f_elem[dof] + k_s·(u_int − u_flex[dof]) = 0` を要素内 Newton で解く
  （`solve_internal_dofs`）。弾性域は線形のため 1 反復で厳密。**降伏後もピン端の
  モーメントゼロが保たれる**のがこの内部反復の要点。
- 接線剛性は 12+n 元系を組んで静縮約（`condense_releases`）。組立順は
  「可撓長で要素剛性 → 材端解放の静縮約 → 剛体アーム変換 → 全体座標変換」で弾性梁と同一。
- 内部自由度は snapshot / restore / commit / revert / チェックポイントに含める。
  チェックポイントは旧形式（内部自由度なし）も読めるようフォールバックを持つ。

要素レベル V&V（`fiber/tests.rs` 新規 8 件）: ピン端の剛性が弾性梁と（軸を除き）厳密一致、
ピン端のモーメントがゼロ、半剛が剛接とピンの中間かつ両極限へ漸近、剛域併用でも
接線＝内力の勾配、剛体回転の客観性、降伏後もモーメント解放が保たれる、
J=0 で rx を解放しない、内部自由度のチェックポイント往復。

### 7.2 系レベル V&V と、そこで判明した経路上の不整合

検証記録は [dev_docs/v_and_v/剛域_保有水平耐力_系レベル検証.md](../v_and_v/剛域_保有水平耐力_系レベル検証.md)。
門形フレーム（柱 100×100・はり 300×300 で柱の崩壊機構に固定）で剛域あり／なしを比較し、
崩壊荷重比が可撓長基準の理論値 H/L' に一致することを確認した（実測 1.234 / 理論 1.250）。

検証の過程で 3 件の不整合が判明し、いずれも是正した。**剛域を要素へ実装しただけでは
崩壊機構・Ds まで正しく伝わらない**類のもので、系レベルで測って初めて表面化した。

1. **曲げヒンジ判定が節点位置のモーメントを使っていた** → 剛域を与えても崩壊荷重が
   全く変わらなかった（比 1.0000）。危険断面＝剛域フェイスの材端力で判定するよう
   是正（`geom.rs::member_end_forces_at_face` / `rigid_arm::to_flex_force`）。
   終局時の設計用曲げ（`member_response.rs`）も同基準へ揃えた。局所成分を使うことで、
   材軸まわりのねじりを曲げと取り違えていた丸めも解消。
2. **崩壊機構の運動学的ゲートが部材あたり 1 ヒンジしか数えていなかった** → 柱両端が
   降伏しても `Partial` 判定。ヒンジを材端ごとに記録するよう是正。崩壊機構種別は
   `story_ds` の機構補正へ直結するため Ds への影響が大きい。
3. **段階的耐力喪失解析でファイバー部材のピン化が効いていなかった** → 7.1 の実装で解消。
   副作用として、除去が正しく効くと対称フレームでは残存構造が機構化して再載荷が
   解けなくなるため、`staged_strength_loss` は 2 パス目以降の分解失敗を**解析の正常終了**
   として扱うようにした（1 パス目の失敗は元モデルの問題としてエラー）。

系レベル V&V テスト: `squid-n-solver` `pushover/tests.rs` 3 件（崩壊荷重・崩壊機構・層剛性）、
`squid-n-design-jp` `tests/vnv_rigid_zone_ds.rs` 3 件（機構 → Ds の経路、保有水平耐力）。

### 7.3 残課題

- 系レベル V&V は単一層・単一スパンの門形フレームによる。多層モデルの層崩壊
  （`MechanismType::StoryCollapse`）判定に剛域が与える影響は未検証。
- 崩壊荷重の観測は荷重ステップの量子化誤差（本検証で約 1.3%）を含む。弧長法・変位制御
  による plateau の直接同定は未実施。
- Ds のもう一方の入口である部材ランク（せん断余裕度）→ Ds の系レベル通し検証は未実施。
- `FiberBeam` の軸剛性は剛域を軸方向にも剛として扱う（EA/L'）ため弾性梁（EA/L）と
  一致しない（4.9.5）。軸変形が支配的な架構での影響は未評価。
