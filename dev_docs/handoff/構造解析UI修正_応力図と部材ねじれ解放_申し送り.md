## 1. 上部ツールバーの「荷重: 長期/短期」を削除

### 指摘

「上部の長期と短期の選択は何に使っていますか？ 使っていないように感じています。」

### 調査結果（指摘は妥当）

`App::design_term` は断面検定（`run_design_check`）が参照する実データだが、値は
**表示対象の荷重ケース／組合せから自動判定**される
（`actions.rs::select_displayed_result` → `squid_n_load::combo::is_short_term_combo`）。
自動判定は「一括解析の完了時」「表示対象の切替時」「断面検定の再実行時」の 3 箇所で
走るため、ツールバーで手動切替しても次の操作で必ず上書きされていた。すなわち
**設定としては機能しておらず、現在の区分の表示以上の意味を持たなかった**。

### 変更

- ツールバーの `selectable_label`（長期/短期）を削除。`design_term` フィールドと
  自動判定は従来どおり維持する。
- 情報が失われないよう、設計タブの「対象荷重」の右へ読み取り専用の
  「許容応力度: 長期／短期」ラベルを追加（ホバーで判定規則を表示）。
- `docs/calc_basis/06_一次設計/README.md` に区分の決定規則を明記。

## 2. N 図・Q 図・M 図を「応力図」へ統合し、6 成分の同時表示にする

`ViewMode::{N, Q, M}` を `ViewMode::Force` の 1 モードへ統合し、成分は
`ForceComponent::{N, Qy, Qz, Mx, My, Mz}`（内力ベクトル `[N,Qy,Qz,Mx,My,Mz]` と
**列挙順＝添字**）のチェックボックス集合 `ForceComponents`（`App::force_components`）で
個別に ON/OFF する。**選んだ成分はすべて同時に描く**。

- **プリセット**: N図={N}／Q図={Qy,Qz}／M図={My,Mz}。既定は M 図プリセット。
- **張り出し面**: 強軸側（N・Qy・Mx・Mz）は局所 ey 面、弱軸側（Qz・My）は局所 ez 面
  （`ForceComponent::plane`）。曲げ・せん断の対が同じ面に出るため、6 成分同時でも
  直交 2 面に分かれる。`diagram_offset_dir` に `DiagramPlane` 引数を追加した
  （CMQ 図は常に `Ey`）。
- **成分固定色**: 凡例・塗り・輪郭線・数値ラベルで共通（`ForceComponent::color`）。
  コンター表示中も輪郭線は成分色のままなので判別できる。
- **正規化はすべて成分ごとに独立**。N[N] と M[N·mm] は単位も桁も違うため、
  1 つの max を共有できない。凡例は成分ごとに「色見本＋成分名＋max」を 1 行ずつ並べ、
  コンター時は各行の下にその成分のカラーバーを付ける。
- **表示単位は kN・kN·m**（`display_scale`／`unit`）。凡例・数値ラベル共通。
- **「値を表示」トグル**（`App::diagram_values`）: 各部材の ξ=0・0.5・1.0 の値を図の
  輪郭上へ成分色で描く。小数 1 桁で、その成分のモデル全体最大の 1% 未満は描かない。

### My の張り出し符号（要注意）

断面力の符号規約は `Qy = dMz/dx`・**`Qz = −dMy/dx`** で My だけせん断との関係が
反転している（`docs/calc_basis/05_構造解析/02_線形静解析.md`）。応力図は
「正のモーメントを引張側へ張り出す」規約のため、**My だけ張り出しの符号を反転**する
（`ForceComponent::plot_sign`）。単位行列軸の梁で j 端に +y／+z のたわみを与えて
材端モーメントの符号を実測し、Mz と My が逆符号になることを確認したうえで決めた
（`test_beam_i_end_torsion_released_by_default` と同じ要領の一時テストで確認、削除済み）。
エルミート補間の勾配源も対で持たせている（Mz→Qy、My→Qz。`moment_gradient_source`）。
数値ラベルとコンター色は張り出し値ではなく内力値そのものを使う。

## 3. 増分解析の「factor: NotPositiveDefinite」

### 根本原因

`newton_converge`（`pushover/driver.rs`）が**接線剛性の分解失敗を `Err` として
上位へ返し、解析全体を中止**していた。弾塑性の接線剛性は降伏の進行（崩壊機構の形成・
耐力劣化）で正定値性を失い得るため、これは「増分が大きすぎるときの非収束」と同じ
扱いにすべきものである。実際、変位制御フェーズと弧長法フェーズは同じ失敗を
**増分半減へ回して**おり、長期載荷・荷重制御フェーズだけ扱いが揃っていなかった。

加えて、`elastic_roof_slope` が初期接線剛性の分解失敗を `.ok()?` で握り潰して
固定 λ 刻みへフォールバックしていたため、**初めから特異なモデル**でも最初に出る
メッセージが `factor: NotPositiveDefinite` になり、原因（どの自由度に剛性が無いか）が
利用者にまったく伝わらなかった。

なお PR #149（`増分解析_時刻歴_解析不能バグ修正_申し送り.md`）で修正した CSC 組立
キャッシュのパターン誤判定は別の原因であり、そちらは修正済みのまま本件と独立。

### 変更

1. **分解・求解の失敗を非収束として扱う**: `newton_converge` の戻り型を
   `Result<Option<Vec<f64>>, String>` → `Option<Vec<f64>>` へ変更し、
   `factorize`／`solve_into` の失敗は `None`（非収束）を返す。呼び出し側は既存の
   増分半減（5 回）→ フェーズ打ち切り → 次フェーズ（変位制御）へ引き継ぐ経路に乗る。
2. **初期接線剛性のチェック**: 解析冒頭（要素生成後・長期載荷前）に初期接線剛性を
   一度分解し、失敗したら診断メッセージで停止する。初めから特異なモデルは増分を
   刻んでも解けないため、ここで止めるのが正しい。
3. **診断メッセージ（新規 `pushover/diagnosis.rs`）**: 自由 DOF 空間の接線剛性
   `k_free` の対角を走査し、
   - 剛性がほぼ 0（行列の対角最大値に対する相対 `1e-12`）の自由度があれば
     **節点 ID と成分名（Ux…Rz）を名指し**して「剛性がありません」と案内する。
   - 対角が負の自由度があれば耐力劣化・崩壊機構として案内する。
   - いずれも無ければ拘束不足・機構の可能性として案内する（静解析の
     `singular_diagnosis` 相当）。
   さらに `nonconvergence_detail` は「分解できるか」で案内を分け、**剛性は健全で
   Newton 反復が収束しないだけ**の場合に拘束不足を疑わせないようにした。
4. **空の結果を返さない**: 1 ステップも確定しなかった場合は `Ok`（Qu=0 の空の
   性能曲線）ではなく診断付きエラーを返す。空の結果は保有水平耐力 0 と誤認され得る
   （危険側）ため。

### 併せて修正した潜在不具合

`BeamElement::condense_end_springs`（弾性梁）は、ねじり剛性を持たない部材
（\\( J \le 0 \\)・\\( G \le 0 \\)）でも端条件がピン・半剛なら rx を解放していた。
縮約行列 `Kbb` の対角がゼロになり、`invert_small` がゼロピボットを 1.0 へ置換する
ため**無意味な値で静縮約が進む**。ファイバー梁（`resolve_end_releases`）は同じ
ガードを既に持っていたので、規則を揃えた。

### 検証

- 回帰テスト（`pushover/tests.rs`）:
  `test_pushover_singular_tangent_reports_dof_diagnosis`（自由度を名指しした診断で
  停止し、`NotPositiveDefinite` を露出しない）、
  `test_pushover_unconverged_load_control_reports_reason`（非収束は空の結果ではなく
  理由付きエラー）。`diagnosis.rs` に対角走査の単体テスト 2 件。
- 再現調査: 3×3 スパン 5 層 S 造フレームに対し、断面形状の有無・剛域自動算定の有無・
  PH 階の有無・剛床の有無・J=0 断面・大梁両端ピン・大梁の中間節点・地震用重量倍率
  （×1〜×50）・終了目標（1/150〜1/30）を組み合わせて掃引したが、**利用者環境の
  NotPositiveDefinite は再現しなかった**（`examples/repro_pushover.rs` として一時
  作成し、調査後に削除）。特異化を再現できたのは「大梁を中間節点で分割 ×（J=0 断面
  または大梁両端ピン）」の 2 ケースで、いずれも静解析でも特異になるモデルである。
  本件の修正は「どのモデルでも中止せず、止まる場合は原因を名指しする」ことで
  再現の有無に依らず利用者側で原因に到達できるようにする方針とした。

### 申し送り

- 非線形時刻歴（`dynamic/timehistory/nonlinear.rs`）にも同じ
  `format!("factor: {:?}")` が 2 箇所残っている。K_eff は質量項を含むため正定値性を
  失いにくく、失敗は真の異常である可能性が高いので今回は変更していない。同種の
  報告があれば同じ診断へ寄せるとよい。

## 4. 断面表示で「床・二次部材」非表示中も小梁が描かれる

`solid::draw_section_solids` が `model.secondary_members` を**常に**押し出して
いたため、「床・二次部材」トグル OFF でも、また主架構の図である CMQ 図でも、
断面表示にすると小梁・間柱のソリッドだけが現れていた（中心線側は
`app.show_floor_secondary` に従っていた）。

判定を `viewer_panel` のローカル変数 `show_secondary`
（`mode != Cmq && app.show_floor_secondary`）へ集約し、スラブ・小梁の描画、
断面ソリッド（新引数 `show_secondary`）、二次部材の中心線が同じ値を参照するように
した。非表示時は「断面未定義の部材 n 本」の集計からも除く。

## 5. 部材（梁・柱）の i 端ねじれを既定でピンに

### 設計

日本の一貫計算では床と一体の大梁のねじり剛性を期待しないため、**線材（梁要素。柱を
含む）の i 端のねじれ（rx）を既定で解放**する。実装は既存の端部ばね静縮約
（\( k_s = 0 \)）にねじり自由度を追加するだけで、曲げの端条件（`end_cond`）とは
独立に効く。i 端のみの解放でも直列経路が切れるため、ねじりモーメントは部材全長で 0。

データモデルへ**部材ごとの**フィールドを足すと `ElementData` の構造体リテラル
249 箇所を書き換えることになるため、次の構成にした。

- `Model::beam_torsion: BeamTorsionMode`（`ReleaseIEnd`(既定) / `Keep`）を建物一律の
  設定として追加（msgpack の位置ベース直列化に合わせ `dof_map` の直前＝末尾へ追加。
  `#[serde(default)]` で旧 `.scz` は既定へ補完）。
- 部材ごとの適用可否は `beam::i_end_torsion_release(data, model)` が幾何・トポロジから
  判定する（モデル化の自動判定。剛域自動算定・側柱の面内ピンと同じ位置づけ）。
  理由付きは `i_end_torsion_release_skip` → `TorsionReleaseSkip`。
- `BeamElement::torsion_release: [bool; 2]`（`BeamElement` のリテラルは 7 箇所のみ）。

### UI（準備計算）

準備計算パネルに新セクション「**部材のモデル化**」を設け、チェックボックス
「**部材 i 端のねじりをピン（梁・柱）**」（既定 ON）を置いた。設定は
`squid_n_edit::SetBeamTorsion`（新規コマンド）で `Model::beam_torsion` を**即時に**
書き換え、`staleness.mark_edited()` で結果を陳腐化させる。質量方式のように
「準備計算の実行時にモデルへ反映」とすると、②解析タブから直接解析した場合に旧設定の
まま解かれる事故が起こり得るため、剛性を変える設定は即時反映とした。

準備計算の結果タブに「**ねじり解放**」タブを追加し、対象外部材（部材 ID・種別・
原因節点・理由）を一覧する（`PrepTorsionSkipRow`）。載せるのは
`TorsionReleaseSkip::UnrestrainedRotation`（＝ねじり剛性が残る部材）だけで、
ねじり剛性をもともと持たない部材（J≤0・G≤0）は設計上の影響が無いため除外する。
設定 OFF のときは表の代わりに「全部材で保持中」の注記を出す。

### 特異化の回避（重要）

ねじりを解放した部材は材軸まわり回転に剛性を持たないため、**その回転を他に拘束する
ものが無い節点では全体剛性行列が特異になる**。両端節点それぞれについて、材軸まわりの
回転が「非平行な線材の曲げ」「線材以外の要素」「支点拘束」「支点ばねの回転成分」の
いずれかで拘束されることを確かめ、確かめられない部材は解放しない。
典型的に解放されないのは、大梁・柱を中間で分割した「一直線に並ぶ線材だけが集まる
節点」を含む部材、片持ち梁の先端を持つ部材、柱脚がピン支点で基礎梁の無い柱。

**剛床は判定に含めない**。剛床が拘束するのは面内 3 成分で、スレーブの Rz は
マスターへ集約されるだけである。「柱 1 本だけが載る剛床」ではマスターの Rz を止めるのが
その柱のねじりだけになるため、剛床を「拘束あり」とみなすと特異化を見逃す。

判定は部材生成ごとに全要素を走査する O(n) で、`BeamElement::new` 全体としては
O(n²)。同関数は既に `collect_misc_walls`（同じく O(n)）を呼んでおり、要素生成は
解析 1 回につき 1 度なので許容した（数千部材規模で問題が出れば、モデル単位で
`Vec<bool>` を前計算して渡す形へ寄せる）。

### 床小梁の格子解析は常に `Keep`

`floor_grillage::build_slab_grillage` が組む床サブモデルは `BeamTorsionMode::Keep` を
明示する。**交差する小梁はそれぞれ両端を大梁にねじれ止めされた一本材**（支点の
`Dof6Mask` は主曲げ回転だけを解放し、ねじり回転は拘束している）であり、交点での分割は
格子解析上の都合にすぎないため、材端ねじりピンの対象ではない。実際、この扱いをやめて
設定に追従させると、交点でのねじり連続が切れて剛接十字（`pinned_onto = None`）が
ピン受けと同一結果になり、フレーミング指定が結果に効かなくなる（既存テスト
`test_pin_vs_rigid_cross_differ` が「剛接とピンで曲げが完全一致」で落ちる）。

### 影響

3×3 スパン 5 層 S 造フレームの増分解析で Qu の変化は 0.1% 未満（ねじり寄与は小さい）。
既存テストはすべて通過。

### 検証

`frame/beam/tests.rs`（梁・柱の解放、中間節点での不適用、`Keep`、J=0 両端ピンの有限性）、
`app/tests.rs`（準備計算の対象外一覧・設定 OFF・undo/redo）、
`viewer/diagram.rs`（成分の添字・単位・張り出し面・My の符号・プリセット・選択列挙）。
