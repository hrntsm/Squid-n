# 利用者ドキュメント（`docs/`）から過去との差分記述を除去した件 申し送り

## 1. 方針

`docs/` は**利用者向けの計算根拠**であり、[AGENTS.md](../../AGENTS.md) のとおり
**開発経緯・過去との差分（変更前後の比較、実装のビフォーアフター、履歴的な言及）を
書いてはいけない**。現在の仕様・計算根拠のみを、それ単体で完結する形で記述する。

この方針に反していた記述を洗い出して整理した。開発経緯として残す価値のある内容は
本ディレクトリ（`dev_docs/`）側へ移してある。

## 2. 直した記述

### 2.1 「従来どおり」の削除

「従来どおり」は過去のある時点との差分を前提にした表現で、その時点を知らない利用者
には意味が取れない。単に現在の挙動を述べる形へ直した。

| ファイル | 箇所 |
|---|---|
| `docs/calc_basis/04_要素剛性/01_ティモシェンコ梁要素.md` | 剛域なしのときの幾何剛性 |
| `docs/calc_basis/04_要素剛性/06_パネルゾーン.md` | RC/SRC 接合部の剛域評価、斜材の接合 |
| `docs/calc_basis/05_構造解析/01_線形代数ソルバ.md` | AUTO 対象外の系で疎 LU を使う旨 |
| `docs/calc_basis/10_免震制振/02_制振ダンパー.md` | リリーフ速度未指定時の扱い |
| `docs/result_view/06_検定比の表示.md` | 検定表セルの 3 段階着色 |
| `docs/result_view/08_応力図の曲線補間.md` | N 図・Q 図を直線で描く旨、断面検定が評価断面のみを使う旨 |

### 2.2 「〜が変わります」というビフォーアフター表現

`docs/calc_basis/04_要素剛性/06_パネルゾーン.md` と `docs/preparation/06_仕口パネル.md`
の断面算定の節で、設計用パネルモーメント \\( {}_p M \\) の求め方を「変わります」と
書いていた。モデル化の有無による**現在の場合分け**として書き直した。

### 2.3 モデル間比較の段落を削除

`docs/preparation/06_仕口パネル.md`「モデル化の影響」の末尾にあった
「接合部の有限寸法を無視した従来のモデルと比べると、全体としては硬くなる」という
段落を削除した。これは旧モデルとの比較そのもので、`docs/` の役割から外れる。

同じ内容は本ディレクトリの
[仕口パネル_申し送り.md](仕口パネル_申し送り.md) §3.1 に記載済みで、失われていない。
`docs/` には「せん断変形で柔らかくなる／オフセットが剛域として働き硬くなる」という
**現在のモデルの性質**だけを残した。

### 2.4 旧スキーマとの互換の記述を移設

`docs/calc_basis/01_荷重/07_自重の長期応力解析への接続.md` から次の 2 点を削除した。

- 「DL ケースがない**旧構成**のモデルでは**従来どおり**密度から直接算入します」
  → 「DL ケースがないモデルでは、階の生成で密度から自重を直接算入します」へ書き換え
  （挙動の記述としては同じで、過去への言及だけを落とした）
- 「**旧スキーマとの互換**：旧来の自動生成ケース「自重(自動)」「床荷重(自動)」は、
  モデル読込時に「DL」へ移行（改名・統合）されます」→ 削除

後者の実装は残っている。**`Model::migrate_legacy_auto_load_cases` はモデル読込時に
旧名の自動生成ケース「自重(自動)」「床荷重(自動)」を「DL」へ改名・統合する**。
挙動を確認・変更する場合はこの関数を参照すること。

### 2.5 「互換用に残しています」の削除

`docs/calc_basis/06_一次設計/03_鋼構造_断面検定.md` の座屈長さの節で、方向を区別
しない簡略版を「互換維持のための簡略化」「互換用に残しています」と書いていた。
簡略版は縮退軸のフォールバックとして現在も使われる経路なので、由来への言及を落とし、
何をする版なのかだけを述べる形へ直した。

## 3. 残したもの

次は過去への言及ではないため、そのままにしてある。

- `docs/model_io/01_プロジェクト形式_scz.md` の「本ソフトはリリース前で後方互換を
  持たないため、現行スキーマ版（`1`）以外は拒否します」— 現在の受け入れ条件の説明
- `docs/model_io/02_ST-Bridge_形式.md` の「対応バージョン」— 外部フォーマット側の
  版であって本ソフトの履歴ではない
- 数式・処理の説明中の「置き換える」— 計算手順そのものの記述

## 4. 今後

`docs/` を書くときは、次の語が入っていないか確認する。入っている場合はたいてい
過去との差分を書いている。

```
従来 / これまで / 以前 / かつて / 旧 / レガシー / 互換 / 移行 / 廃止
〜に変わりました / 〜するようになりました / 〜を追加しました
```

差分そのものを残したい場合は `dev_docs/handoff/` か `dev_docs/v_and_v/` へ書く。
