# 増分解析グラフの均等刻み化とヒンジ可視化 申し送り

2026-07 実施。増分解析（プッシュオーバー）の結果グラフと可視化に関する 3 点の改善。

## 背景（ユーザー指摘）

- 性能曲線（層間変位−層せん断力）の点が「最初は非常に細かく、その後が荒い」。
  原因は増分制御の構造: 荷重制御が λ=1 までを `push_steps`（既定 50）分割で刻む
  （弾性域なので変位はほとんど進まない）のに対し、変位制御は残りの全変位を
  固定 10 分割で刻んでいた。剛性変化が起こらない弾性域こそ粗くてよく、
  降伏が進む後半こそ細かくすべきで、既定は変位軸で均等が望ましい。
- グラフ下部の「● は計算で釣合いを求めた増分ステップの点、点間の線は補間です。」
  の注記は不要。
- ヒンジがどこに発生したかを 3D モデル図で確認したい。さらにヒンジをクリックしたら
  その状態（N-M 相関、ファイバー断面の塑性化、M-θ カーブ）を確認したい。

## 実施内容

### 1. 均等変位刻み制御（squid-n-solver）

`nonlinear/pushover/driver.rs`:

- 押込み上限 roof_bound（目標変位と目標層間変形角×Σ階高の小さい方）を関数冒頭で
  算定し、目標刻み `du_uniform = roof_bound / n_steps` を導入（段階制御＋上限有限時のみ）。
- 荷重制御の λ 増分を「頂部変位が du_uniform 進む見込みの量」へ適応制御。勾配は
  初回が初期接線剛性の弾性解（`elastic_roof_slope`、K·δu=q を 1 回解く）、以降は
  直近確定ステップ間の実勾配。λ=1 で従来どおり変位制御へ引き継ぐ。
- 変位制御の押込み刻みも同じ du_uniform（従来の固定 10 分割はフォールバック時のみ）。
- 弾性勾配が推定できない場合（頂部 DOF 不明・特異等）は従来の固定刻みへフォールバック。
  「荷重増分のみ」（LoadOnly）は比較検証用のため従来の等分割 λ 刻みを維持。
- 記録ステップ番号を「確定順の通し番号」（`step_no`）へ変更。従来は
  荷重制御=スケジュール添字／変位制御=`n_steps+1+step`／弧長法=`n_steps+1+step` で、
  変位制御と弧長法の番号が衝突し得た。テスト 2 件が「step > n_steps」でフェーズを
  識別していたため、荷重係数 λ>1 での識別へ更新（tests.rs）。
- 収束失敗時の挙動: 均等刻みでは増分半減済みのため打ち切って変位制御へ引き継ぐ
  （固定刻み λ≦1 の「スキップして次の刻み」は従来どおり）。

### 2. ヒンジ詳細図用の記録（squid-n-solver / squid-n-element）

クリック詳細図（N-M 相関の応答経路・M-θ カーブ・ファイバー断面塑性化）の
データ源として、解析中の記録を追加。

- `PushoverResult::member_history`（`#[serde(default)]`）: ヒンジまたはせん断降伏が
  記録された部材のみ、確定ステップごとの端応答（軸力・剛域フェイスの局所曲げ
  My/Mz・弦からの材端回転 ry/rz、f32）を steps と同並びで保持。
  算定は `member_response.rs::record_member_step`。
- `PushoverResult::fiber_states`（`#[serde(default)]`）: 終局時のファイバー断面状態。
  `ElementBehavior::fiber_section_states`（新規、既定 None）を FiberBeam が実装し、
  全ガウス点×全ファイバーの位置・ひずみ・降伏比（|ε|/εref）・材料区分
  （0=母材格子/1=主筋）を返す（一般化ひずみの復元規則は ductility_probe と同一）。
- `strength_loss::truncate_result` は member_history の records も steps に揃えて切り詰める。

### 3. GUI（squid-n-app）

- 性能曲線グラフ下部の注記 1 行を削除（マーカー表示自体は維持）。
- ビューアに表示モード「ヒンジ」（`ViewMode::Hinge`、`viewer/hinge.rs`）を追加。
  ヒンジ発生位置を材端 10% 内側にレベル別色分けマーカー
  （ひび割れ/降伏/終局）で表示し、凡例・ホバーツールチップを持つ。
  ヒンジ履歴はステップ重複を含むため (部材, 端) で集約し最高レベルを表示。
- ヒンジ図でヒンジ部材をクリックすると詳細ウィンドウ（`viewer/hinge.rs`）を表示:
  - M-θ カーブ: member_history から採用曲げ面（最終レコードで強軸/弱軸の大きい方）の
    材端回転と端モーメントを i端/j端の 2 系列で描画
  - N-M 相関図: 軸力部材（鉛直材またはファイバー系）に表示。断面のファイバー分割
    （`mn_surface::plastic_fibers` + `build_surface`、材料強度割増を反映）から
    N-M 経線（正曲げ・負曲げ）を抽出し、応答経路を重ねる。App 側に部材単位の
    キャッシュ（`hinge_mn_cache`）
  - ファイバー断面塑性化マップ: fiber_states からヒンジ端に近いガウス点断面を選び、
    ファイバーを降伏状態（未降伏=灰/引張降伏=赤/圧縮降伏=青、主筋は強調）で散布図表示

## 残課題・注意

- ステップ番号が通し番号になったため、外部で「step > n_steps ＝変位制御」の
  識別をしている箇所があれば λ による識別へ変更が必要（リポジトリ内は対応済み）。
- member_history / fiber_states は旧プロジェクトファイルにないフィールド
  （読込時は空で補完）。古い結果を読み込んだ場合、ヒンジ詳細図の応答経路・
  断面塑性化は表示できない（再解析が必要）。
- 均等刻みの目標刻みは押込み上限基準のため、目標到達より手前で解析が
  終わる場合（層間変形角が先に成立）は実際の点数がステップ数設定より少なくなる。

## 2026-07 追加改善（ユーザー指摘 4 件への対応）

ヒンジ詳細ウィンドウの表示品質と増分解析設定について、以下を実施。

### 1. M-θ・N-M・ファイバーマップの `egui_plot` ID を部材ID込みへ変更

`Plot::new("hinge_m_theta")` のように固定文字列 ID を使うと、egui_plot は
ズーム／パン状態（`PlotMemory`）を ID のみで永続化するため、ある部材の
グラフを操作（ドラッグ／スクロールでのズーム）した後に別の部材のヒンジ詳細を
開くと、直前の操作で確定した表示範囲を新しい部材のデータへそのまま流用して
しまい「カーブが描画領域の一部にしか収まらない・余白が過大」に見える不具合が
あった。`hinge_m_theta_{elem_id}` / `hinge_mn_{elem_id}` /
`hinge_fiber_{i|j}_{elem_id}` のように部材IDを ID に含めることで、選択部材の
切替時は必ず新規の `PlotMemory`（既定=自動フィット）から始まるようにした。

### 2. ファイバー断面塑性化マップの材料別色分け

`FiberStateSample::material` の区分（0=コンクリート／1=主筋／2=鋼材。本改修と
並行してソルバ側で鋼材区分=2を追加）に応じて、コンクリート=グレー系・
主筋=赤系・鋼材=青系の3色で描画するよう変更（従来は降伏状態のみで色分けし、
材料の区別がなかった）。降伏状態は明度と形状に載せ替え: 未降伏=材料色の淡色、
降伏=材料色そのまま＋外周リング、さらに引張降伏=丸／圧縮降伏=ひし形で区別する。

### 3. N-M 相関図の 3D 化と応答経路の原点前置

N-M 相関図に、`mn_view.rs`（断面詳細ビュー）と同じ考え方の 3D ワイヤーフレーム
（N-My-Mz 曲面＋ 3D 応答経路、`viewer::CameraState` によるターンテーブル
カメラ）を追加し、従来の 2D スライスをその下段に残した。`mn_view.rs` 自体は
変更していない（3D 描画・投影は正規化基準が用途ごとに異なり共通化しにくいため、
`hinge.rs` 内に自己完結で再実装した）。

応答経路（2D・3D 共通）は、記録点列の先頭に原点 [0,0]（無載荷状態）を前置する
よう変更した。従来は最初の記録ステップから経路が始まり、始点が無載荷状態から
どれだけ離れているか分からなかった。長期荷重の初期載荷（本節 4）が実装されると
最初の記録ステップは長期荷重時点になるが、原点前置のままで
「無載荷→長期荷重→水平力」の経路として正しく表示される。

### 4. 長期荷重初期載荷のチェックボックス

`AnalysisSettings::push_apply_long_term`（既定 `true`）を追加し、解析タブの
増分解析設定に「長期荷重を初期載荷」チェックボックスを追加した。ソルバ側
（`pushover_analysis_recording` への `apply_long_term` 引数追加、並行実装）と
組み合わせて、長期荷重ケース（固定・積載等）を水平力増分の前に載荷し、その
応力状態を初期条件とする。長期荷重ケースがないモデルでは無視される。
