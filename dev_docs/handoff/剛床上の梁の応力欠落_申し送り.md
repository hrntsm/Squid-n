# 剛床に載る梁の応力・検定が欠落する不具合の修正 申し送り

作成日: 2026-07-25
対象コード: `crates/squid-n-element/src/factory/mod.rs`（`build_behavior`）、
`crates/squid-n-element/src/factory/springs.rs`

## 1. 症状

3D ビューの応力図（N/Q/M 図）と検定比図で、**柱と最下レベルの RC 基礎梁だけに結果が
表示され、各階の梁（鉄骨大梁）には図も検定比も一切表示されない**。

検定比図では当該梁が未検定（無着色）となり、検定位置マーカー・数値ラベルも出ない。
応力表・検定表でも同じ梁の行が欠落する。

## 2. 原因

線形弾性解析の要素生成 `factory::build_behavior` が、`ForceRegime::Auto` の
トポロジ判定（`resolve_force_regime`）に従って **材端集中ばね梁
（`ConcentratedSpringBeam`）** を組んでいた。

`resolve_force_regime` の `Auto` 判定は「**剛床に所属する非鉛直材（＝各階の梁）
→ 材端集中ばね**、それ以外（柱などの鉛直材）→ ファイバー」である。したがって

- 各階の梁 … 剛床に載る水平材 → 材端集中ばね（`ConcentratedSpringBeam`）
- 柱 … 鉛直材 → ファイバー判定だが線形パスでは弾性 `BeamElement`
- 最下レベルの基礎梁 … 基部レベルは階に含まれず剛床に載らない → 弾性 `BeamElement`

という振り分けになる。ここで `ConcentratedSpringBeam` は `ElementBehavior::recover_forces`
（節点変位からの部材内力復元）を実装しておらず、トレイト既定の `None` を返す。
線形静解析（`statics/linear` と `statics/analysis`）は

```rust
if let Some(mut forces) = behavior.recover_forces(&u_elem) {
    member_forces.push((elem.id, forces));
}
```

と `None` を黙って読み飛ばすため、**剛床に載る梁だけが `member_forces` から丸ごと
欠落**していた。応力図・検定・接合部検定・QD 算定はすべて `member_forces` を入力に
するため、下流の表示・検定が一括で失われる（＝症状そのもの）。

つまり不具合の分岐点は「鉄骨かどうか」ではなく「**剛床に載る梁かどうか**」であり、
基礎梁だけが残ったのは RC だからではなく剛床に載っていないためである。

### 併発していた剛性の誤り

材端集中ばねの初期剛性は `k_rot = 6EI/l_eff`（塑性ヒンジ骨格の初期剛性）である。
これが弾性梁の端部回転剛性（両端固定で 4EI/l 相当）に**直列**で入るため、
剛床に載る梁の端部回転剛性は 2.4EI/l 程度（約 6 割）まで低下していた。
一次設計の応力・層間変形・剛性率・偏心率・固有周期（Ai 分布）が
実際より柔らかい側に評価されていたことになる。

### 仕様との不整合

計算根拠 4.9.4「モデルの自動選択（ForceRegime）」は
**「線形弾性解析は常に弾性 `BeamElement` を用い、非線形解析でのみ非線形要素を構築する」**
と明記しており、モデル化確認ビュー（`viewer/modeling.rs` の `classify`）も
静解析＝一律「弾性材」と表示していた。実装だけが仕様から外れていた
（ビューの表示と実際の解析モデルも食い違っていた）。

## 3. 対応

`build_behavior`（線形弾性用ファクトリ）から `ForceRegime` による振り分けを外し、
線材は常に弾性 `BeamElement` を組むようにした。

- `ElementKind::Beam` … 常に弾性 `BeamElement`
- `ElementKind::MultiSpring` … 常に弾性 `BeamElement`（従来は `MultiSpringElement`
  を組んでおり、同じく `recover_forces` を持たないため線形解析で内力が欠落していた）
- `ElementKind::Fiber` … 従来どおり弾性 `BeamElement`
- 唯一の例外として、耐震壁の側柱（`InPlaneReleasedColumn`）は従来どおり残す。
  これは降伏ではなくトポロジ由来の面内端部解放であり、線形・非線形の双方に効く。

非線形解析（プッシュオーバー・時刻歴応答）の `build_nonlinear_behavior` は
`ElementKind::Beam` / `MultiSpring` を自分で処理しており、`build_behavior` への
フォールバックは `PanelZone` / `Shell` / `NodalSpring` などに限られるため、
本変更の影響を受けない（材端集中ばね・ファイバーの振り分けはそのまま）。

線形パス専用だった `springs::build_rotational_springs` は参照元がなくなったため削除した
（非線形用の `build_flexural_springs` / `rotational_spring_params` は存置）。

## 4. 影響（既存モデルの結果が変わる点）

剛床を持つモデルでは、各階の梁の弾性剛性が上がる方向へ**結果が変わる**。

- 応力図・検定比図・応力表・検定表に、これまで欠落していた各階の梁が出るようになる。
- 梁の端部回転剛性が 2.4EI/l 相当 → 4EI/l 相当へ戻るため、層間変形角・剛性率・
  偏心率・固有周期（およびそれに依る Ai 分布・地震力）が変化する。従来値の方が
  柔らかい側の評価だったので、変化は概ね変形が小さくなる方向。
- 柱・基礎梁（剛床に載らない部材）の要素種別は従来から変わらない。

    （応力図・検定比図の元データが揃う）ことの一気通貫確認。

## 6. 残課題への対応（追補）

初版で挙げた 3 件の残課題に対応した。

### 6.1 非線形解析の部材内力取得 API（対応済み）

`ElementBehavior::state_member_forces(&state, &ctx) -> Option<MemberForces>` を追加した。
**接線剛性 × 全変位ではなく、履歴状態から求めた端部復元力を材軸方向へ釣合いで分配**
するため、降伏後も正しい内力を返す。

- 分配式は線形の内力回収と共有する（`beam::member_forces_from_end_forces` として
  `BeamElement::recover_forces` から切り出し、側柱 `InPlaneReleasedColumn` の
  重複実装も置き換えた）。
- 実装したのは `FiberBeam`（各積分点の断面応答＝ファイバーの履歴状態から算定）、
  `MultiSpringElement`（実体のファイバー要素へ委譲）、`BeamElement`・
  `InPlaneReleasedColumn`・`TrussElement`（弾性材のため trial 変位から復元）。
- 評価断面を線形解析と揃えるため、危険断面位置の算定を
  `beam::eval_sections_of` として共有し、`FiberBeam` にも `eval_sections` を持たせた
  （従来 `BeamElement::new` にしかなく、`app/mod.rs::design_positions` と合わせて
  3 箇所に同じ規則が散っていた）。
- `ConcentratedSpringBeam` は**実装しない**（既定の `None`）。復元力が
  接線剛性 × 全変位であり、ばね変形量も節点回転そのものを用いているため、
  状態から内力を正しく取り出せない。理由をコード doc に明記し、是正案を
  [`dev_docs/v_and_v/材端集中ばね梁_定式化レビュー_2026-07.md`](../v_and_v/材端集中ばね梁_定式化レビュー_2026-07.md)
  §2 に記録した。

なお本 API の消費側（非線形解析結果の応力表示 UI）はまだない。

### 6.2 内力欠落の検出（対応済み）

線形静解析が `recover_forces` の `None` を黙って読み飛ばす点を、
`statics::linear::ensure_line_member_forces` で検出して解析エラーにした
（`linear_static_once` と `Analysis::solve_and_recover` の両経路に適用）。
線材（`Beam` / `Fiber` / `MultiSpring` / `Brace`）が `member_forces` に現れない
のは要素実装の不備であり、そのまま続けると応力図・断面検定から当該部材が
無言で欠落するため、部材 ID を挙げて止める。

`prepare` の事前診断（`precheck_model`）ではなく解析後の検査にしたのは、
内力を回収できるかどうかが実際に要素を組んでみるまで分からないため。

### 6.3 `compute_kstar` の組み立て（対応済み）

弾性梁から可撓部剛性 `BeamElement::local_stiffness_flex()`（可撓長で生剛性を組み、
端部条件を静縮約したところまで。剛域変換の手前）を切り出して共有し、
`compute_kstar` は「`local_stiffness_flex` → 材端塑性ばねの静縮約 → 剛域変換」で
組むようにした。これで剛域の可撓長と `end_cond`（ピン・半剛）が
材端集中ばね梁にも反映される。

この精査中に、**材端ばねが弱軸曲げ面（局所 `ry`）に入っていた**という別の欠陥も
見つかったため併せて是正した（強軸 `rz` へ）。平面架構では梁の弱軸回転がほぼ
生じないため材端ヒンジが事実上形成されず、保有水平耐力を過大評価していた
（危険側）。詳細と残る定式化課題は上記 V&V ドキュメントを参照。

**影響**: 保有水平耐力計算・時刻歴応答解析の結果が変わる（材端ヒンジが実際に
形成されるようになるため、Qu は下がる方向）。プッシュオーバーの再 V&V が必要
（V&V ドキュメント §2.3）。
