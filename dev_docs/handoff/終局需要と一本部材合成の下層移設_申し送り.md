# 終局需要組み立てと一本部材合成の下層移設 — 申し送り

作成日: 2026-08-12
対象コード:
`crates/squid-n-design-jp/src/beam_group.rs`、
`crates/squid-n-job/src/ultimate_demand.rs`、
`crates/squid-n-app/src/app/actions/design/{check,ultimate}.rs`、
`crates/squid-n-mcp/src/job/ultimate.rs`

`app_actions設計塊分割_申し送り.md` の残課題「設計入口を squid-n-job へ寄せる」のうち、
**実体のある二重**だけを先に潰した。許容の薄いラッパは作っていない
（`run_member_design_checks` がすでに共通のため）。

## 背景

許容応力度検定の本体はすでに `design-jp::run_member_design_checks` にあり、
終局の `collect_*` も design-jp にある。残っていたのは次の二つだった。

- 一本部材グループの検定文脈合成（`beam_group_overrides`）が app にだけあった
- 終局の部材需要組み立てが app と MCP で別実装だった（MCP は QL/Q0 なし）

内力や解析結果の取得元（app はキャッシュ、MCP は都度再解析）は入口ごとに残し、
**揃ったあとの変換だけ**を下層へ移した。MCP の数値は QL/Q0 を渡さないことで維持する。

## 変更内容

### `beam_group_overrides` → `squid-n-design-jp`

型 `BeamGroupContextOverride` と同じクレートへ移し、`pub fn beam_group_overrides` とした。
手計算照合テストは `beam_group.rs` 内に置き、app からは削除した。
app の許容検定はこれを呼ぶ。MCP は従来どおり overrides を渡さない。

### 終局需要ビルダ → `squid-n-job`

- `q_long_map_from_member_forces` — 静的内力 → QL マップ（呼び出し側が明示渡す用）
- `member_demand_from_static_forces` — 静的内力 → `MemberDemand`
- `member_demand_from_pushover` — 増分応答 → `MemberDemand`（空なら `None`）

QL / Q0 はいずれも独立した `Option`。一方の有無が他方の埋込を切り替えない。
静的 GUI は `q_long_map_from_member_forces` で QL を作り、Q0 マップと併せて明示渡す。
MCP は両方 `None`（数値不変）。

app は重力ケース選択・pushover 優先分岐を残したまま、組み立て本体だけ委譲する。
MCP 終局はインライン組み立てをやめ、静的ビルダを `None, None` で呼ぶ。

## 意図的にやらないこと

- 許容の job 薄いラッパ（別名化になるだけのため）
- MCP に QL/Q0・一本部材・床検定・保有水平耐力を足すこと（数値・仕様変更になる）
- `design_seismic_period` の移設
- 壁幾何など別系統の式統合
