# ヒンジ詳細の表示値と解析値の乖離 申し送り

作成日: 2026-09-06。コメント整理のレビューで発覚した、ヒンジ詳細表示の値と解析本体の値の不一致。
更新日: 2026-09-17。Issue #286 で方針を決定・実装し、残課題を解消した（下記「対応」）。

## 背景（ユーザー指摘）

ヒンジ詳細ウィンドウの M-N 相関曲面・M-θ カーブは、解析に使われていない値で描いている。
計算に使われない値を表示しても意味がなく、知りたいのは計算に使われる値である。

## 現状の事実

ヒンジ詳細の表示は 2 種類の値を混ぜている（`result_view/09_ヒンジ図の表示.md`）。

- 応答経路の折れ線: 増分解析の各ステップの実応答。計算値である。
- M-N 相関曲面・M-θ カーブ: `squid_n_section::mn_surface` の 3 モデル（単純降伏バネ・M-N 相関用マルチスプリング・M-N 相関用マルチファイバー）で描く表示用の値（`squid-n-app/src/mn_view.rs:410-414,458-464`）。

解析本体が使うのは別系統である（`docs/calc_basis/02_材料/02_部材履歴則.md` §2.2.4 の使い分け）。

- 材端集中ばね梁: `MemberSkeleton`（`squid-n-skeleton` の RC トリリニア骨格または略算式）と履歴則。
- ファイバー梁要素: `squid-n-element` のファイバ定式化（配置規則 `plastic_fibers_at` のみ `mn_surface` と共用。曲面・カーブの値は使わない）。
- MS モデル: `MultiSpringElement`（断面内 y 軸上の 1 次元バネ配置）。

3 者は塑性化域の集約規則が異なるため、同じ部材でも骨格は一致しない。
応答経路が表示用の曲面・カーブに一致しない・はみ出すことがあり、画面上では区別できない。

## 修正方向の選択肢

1. 解析に使った骨格で表示する（集中ばねなら `MemberSkeleton`、ファイバーなら要素定式化の M-φ、MS なら MS 骨格）。
2. 最低限、曲面・カーブが参考表示である旨を画面に明示する。
3. 現状の 3 モデル比較表示を V&V 参照用と位置づけ直すか（利用者向けに残すか）を決める。

いずれも未着手だった。2026-09-17 の「対応」で選択肢 1 を実装済み。

## 対応（2026-09-17、Issue #286）

「解析に使った値で表示する」方針（選択肢 1）を採り、表示を解析要素と同じ計算経路へ一本化した。

- `squid_n_element::factory::build_hinge_view` を読み取り専用の単一情報源として追加した。解析と同じパラメータ解決（強度基準・履歴則・ファイバー生成）を通り、表示側に式・既定値・配置を複製しない。
- **材端集中ばね**: `build_flexural_springs` が解析用材料を組む際の特徴点（初期＋降伏＋降伏後枝。履歴則によりバイリニア／トリリニア／座屈考慮の 5 点等）を M-θ 骨格として返す。これは初期載荷の包絡線であり、除荷・再載荷の履歴ループそのものではない。N-M は `with_mn_interaction` と同じ線形相関 \\( M = M\_{y0}\\,(1 - |N|/N\_{\text{許容}}) \\) を返す。非線形ばねは強軸（局所 z, Mz）のみに作用するため表示も強軸に固定し、`use_mn=false` の履歴材料（武田型等）では相関を表示しない。
- **ファイバー / マルチスプリング**: 解析が実際に生成する `FiberSection` のファイバ配置（断面形状が未定義・壁断面のときはファイバー 12×20、MS 2×5。形状ありは形状に応じた板・円環分割）に、解析と同じ解決経路の実効降伏強度を与えて既存の支持点法で全塑性曲面を再算定する。解析本体はファイバー積分で応答を決めるため、曲面はその可視化であり解析の全塑性挙動そのものではない（硬化を無視するぶん初期耐力としては安全側。劣化は考慮しないため、劣化後の耐力はこの曲面より低下しうる）。固定骨格を持たない M-θ は応答経路のみを表示する。
- ヒンジ詳細にステップセレクタ（確定ステップ列、既定=最終）を追加し、選択ステップの軸力（圧縮正）を集中ばねの骨格・N-M 相関へ反映して選択点をマーカー強調する。
- キャッシュを `hinge_view_cache`（キー: 要素 ID／選択 step／結果世代 `last_run`＋`results_stale`／断面・材料・履歴則の指紋）へ再設計した。`step_count` 単独に依存しない。
- GUI は `squid_n_section::mn_surface` の曲面構築を直接呼ばない。旧 `MnCurveCache`・`build_mn_curve_cache`・`ensure_mn_cache`・`is_axial_bending_member` は廃止し、`UiModelScoped` に `hinge_step`・`hinge_view_cache` を追加した。

## 残課題

- なし（選択肢 1 の実装で解消）。
