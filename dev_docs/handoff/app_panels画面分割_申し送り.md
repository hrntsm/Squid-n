# app `panels` の画面単位分割 — 申し送り

作成日: 2026-08-13
対象コード: `crates/squid-n-app/src/app/panels/`

この申し送りでは、GUI のパネル描画を画面単位のファイルへ分けた経緯を記録します。

`panels.rs` は 3000 行あり、ナビ、準備計算、解析実行、結果、インスペクタ、ステータスバーが 1 ファイルに同居していました。
画面ごとの変更理由が混ざるため、レビューの単位も、後からファイルを移す単位も読みにくくなっていました。

後続で `viewer` の親モジュールと `actions` の解析ジョブを分ける予定があったため、先に画面の境界だけを切り出しました。
描画の内容と挙動は変えていません。

## 背景

`actions` は 2026-08-12 に、解析種別や入出力といった機能の境界で分割済みです。
詳細は [`app_actions設計塊分割_申し送り.md`](app_actions設計塊分割_申し送り.md) を参照してください。
`panels` は未着手のままだったため、同じ波の GUI 側として画面境界を先に作りました。

分割の単位は公開型 1 つにつき 1 ファイルではなく、利用者から見た画面を 1 ファイルにします。
`actions` は解析の種別で切るため、`panels` と軸は揃えません。
解析実行 UI の静的、固有値、増分、時刻歴は、同じ「② 解析」画面の節なので切りません。

## 変更内容

`panels.rs` をディレクトリ化し、次の構成にしました。

```
panels/
  mod.rs          — ファイルダイアログ、薄いタブスイッチャー、
                    ①②切替、結果表示対象の選択肢収集
  navigator.rs    — 左ドック ナビ
  draw_tools.rs   — 左ドック 作成パレット
  preparation.rs  — 右ドック ①準備計算
  analysis.rs     — 右ドック ②解析（実行 UI。節は切らない）
  results.rs      — 結果タブ（スイッチャー、増分結果、質点系）
  inspector.rs    — 右ドック インスペクタ
  status_bar.rs   — ステータスバー
```

メソッド本体は移動のみで、シグネチャと描画内容は変えていません。
可視性の引き上げは不要でした。
`right_panel_switcher` と `result_display_options` は親モジュールの private メソッドとして、子から見えます。
`toggle_dock_icon` は `status_bar` だけが使うため、同じファイルの private 関数にしました。

`app/mod.rs` の `mod panels;` は、ファイルがディレクトリになってもそのまま解決します。

## 設計判断

- **実体のある画面だけファイル化する。** `model_tab` / `design_tab` / `report_tab` は、本体が `tables/` や `design_view` などへの委譲
- **結果タブの子ビューは `results.rs` に同居する。** 増分結果と質点系は、結果画面の表示モード
- **ファイルダイアログは親に残す。** 画面ではなく、入出力の薄い UI 入口

`model_tab` などは 40〜70 行程度のスイッチャーです。
1 関数 1 ファイルにすると、メソッドの場所がかえって追いづらくなるため、親に残しました。
増分結果と質点系を結果タブへ同居させたのは、解析実行画面の節を切らない判断と揃えるためです。

## 意図的にやらないこと（残課題）

本波（GUI のファイル分割）の残りは、次の 1 点です。

- `actions/mod.rs` に残る解析ジョブの分割（共有基盤は親、静的・固有値・増分・時刻歴は兄弟ファイル。`design/` と同じ型）

`viewer/mod.rs` の親モジュール分割は
[`app_viewerハブ薄化_申し送り.md`](app_viewerハブ薄化_申し送り.md) で実施しました。

本波の対象外は、次のとおりです。

- `AppCore` / `UiState` への型分離（専用ブランチ）
- app／MCP の設計入口を `squid-n-job` へ寄せること（機能統合）
- 巨大テストファイルの分割
- 単一機能の厚い計算コア（`wall_panel.rs` など）の行数分割

## まとめ

画面の境界をファイルへ出したことで、後続の `viewer` と `actions` の分割単位が読みやすくなります。
短いスイッチャーまで切っていないため、親には委譲だけが残ります。
