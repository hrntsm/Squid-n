# 診断と解析前チェックの判定共通化 申し送り

作成日: 2026-08-05
対象コード:
`crates/squid-n-solver/src/statics/analysis/precheck.rs`、
`crates/squid-n-solver/src/statics/analysis/mod.rs`、
`crates/squid-n-app/src/app/actions.rs`、
`docs/preparation/README.md`、`docs/calc_basis/05_構造解析/02_線形静解析.md`、
`dev_docs/specs/UI設計.md`

`仕口パネル要素のUI混入_申し送り.md` の残課題「診断は `section` のみを見ており
`material` の未割当を警告しない」への対応。調べたところ乖離は材料だけではなかったため、
判定そのものを共通化した。

## 変更前の乖離

`run_diagnostics`（app）と `precheck_model`（solver）が別々に検査を持っており、
解析前チェックにあって診断に無い項目が次のとおり 5 つあった。いずれも解析を止める。

| 検査 | 解析前チェック | 診断（変更前） |
| --- | --- | --- |
| 節点・部材が 1 つも無い | エラー | 無し |
| 拘束（支点）が 1 つも無い | エラー | エラー（別メッセージで二重に実装） |
| 断面が未割当 | エラー | **警告** |
| 材料が未割当 | エラー | **無し** |
| シェル断面の板厚が無い | エラー | 無し |
| 線材の As が 0 | エラー | 無し |
| 耐震壁と周辺架構の種別食い違い | エラー | 無し |
| 存在しない節点への参照・孤立節点 | エラー | 無し |

利用者から見ると「診断は E0/W0 なのに解析だけが止まる」ことになる。

## 対応

判定を `precheck::model_issues(&Model) -> Vec<ModelIssue>` へ集約し、解析前チェックと
診断の両方がこれを呼ぶ形にした。`precheck_model` は先頭 1 件をエラーにする薄いラッパで、
診断は全件を対象単位の行へ展開する。以後どちらか一方に検査を足しても乖離しない。

```rust
pub struct ModelIssue {
    /// 対象 ID と是正方法を含む、単体で完結する説明文（解析前チェックのメッセージ）。
    pub message: String,
    /// 対象 1 件ごとに添える短い説明（診断の行。例: 「断面が未割当です」）。
    pub short: String,
    pub targets: IssueTargets,   // Model / Members(Vec<ElemId>) / Nodes(Vec<NodeId>)
}
```

### 断面と材料を別々の不備へ分けた

変更前は 1 つの検査で `section.is_none() || material.is_none()` を見ており、メッセージも
「断面または材料が未割当の部材があります」だった。診断の行がそのままでは
「断面または材料が未割当です」となり、どちらを直せばよいか伝わらない。検査を 2 つに分け、
解析前チェックのメッセージも「断面が未割当」「材料が未割当」と具体化した。

### 重要度をエラーへ揃えた

診断の断面未割当は変更前まで警告だった。`PreparationResult::is_ready` は
`diag_errors == 0` で、右パネルはエラーがあるときだけ「⛔ 解析前に解消してください」を
出す。つまりエラー＝解析前に解消すべき不備という規約なのに、確実に解析が止まる不備が
警告に置かれ、「✅ 準備計算 済（警告 42 件）」と表示されてから解析が失敗していた。
`model_issues` 由来の不備はすべてエラーとし、警告・情報は解析が通る指摘に限定した
（規約は `dev_docs/specs/UI設計.md` §1.4 に明記）。

### 節点を対象とする診断行

`DiagTarget::Node` は UI 側にクリック処理があるだけで、これまで生成する経路が無かった。
孤立節点・ダングリング参照が節点単位の行として出るようになり、クリックで 3D 選択へ飛ぶ。

## 変更前の挙動を保った点・変えた点

- `model_issues` の並び順は変更前の `precheck_model` の早期 return と同じ順にした。
  先頭 1 件をエラーにするため、同じモデルに対するエラーメッセージは断面・材料の分割を
  除いて変わらない。
- 変更前は早期 return で後続の検査を行わなかったが、`model_issues` は全件を集める。
  部材が 1 つも無いモデルでは全節点が孤立になるため、そこだけは「部材がありません」で
  同じことを言っているとみなして孤立節点の検査を飛ばす（節点数だけ行が並ぶのを防ぐ）。
- 孤立節点の判定は `referenced[n.id.index()]` の直接添字をやめ、
  `get(..).unwrap_or(true)` にした。診断は `Model::validate` が失敗するモデルでも動くため、
  「id == 添字」が崩れていると添字で panic する。引けない節点は孤立と決めつけない。
- app が持っていた独自の支点なし判定（「支点が定義されていません（解析すると剛体移動
  します）」）は削除し、共通判定のメッセージへ寄せた。

## 回帰テスト

| テスト | 内容 |
| --- | --- |
| `analysis::tests::test_prepare_missing_material_gives_diagnostic` | 材料だけ未割当でも解析が止まる |
| `analysis::tests::test_model_issues_collects_every_issue` | 先頭 1 件で打ち切らず全件集める・対象 ID を持つ |
| `analysis::tests::test_model_issues_skips_isolated_nodes_without_elements` | 部材なしのとき孤立節点を並べない |
| `app::tests::test_run_diagnostics_flags_unassigned_material` | 材料未割当が部材単位のエラーになる |
| `app::tests::test_diagnostics_errors_agree_with_analysis_precheck` | 診断エラーの有無と解析前チェックの成否が一致する |

`test_diagnostics_errors_agree_with_analysis_precheck` は健全なモデルと 4 種の不備
（断面・材料・As=0・支点なし）について、診断のエラー件数と `Analysis::prepare` の成否が
両方向で一致することを確かめる。今回の乖離そのものを塞ぐテスト。

## 残課題

- 診断は依然として O(部材数) の検査に限る想定である。`model_issues` に重い検査
  （解析・断面算定を伴うもの）を足すと診断タブを開くたびに走るため、足す前に
  遅延評価の粒度を見直すこと。
- 耐震壁と周辺架構の種別食い違いは壁 1 枚ごとに 1 行出る。壁が多いモデルで
  同じ原因の行が並ぶ可能性があるが、メッセージが相手部材まで名指しするため
  まとめずに残している。
