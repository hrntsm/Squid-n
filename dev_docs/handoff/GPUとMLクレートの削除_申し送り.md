# squid-n-gpu（P10）と squid-n-ml（P11）を削除した件 申し送り

**作成日:** 2026-08-31

## 1. 方針

`squid-n-gpu` と `squid-n-ml` は、どちらも実装が入らないまま置かれていた予約クレートでした。
[AGENTS.md](../../AGENTS.md) の「現在の要件を完全に満たすもっともシンプルな実装を選ぶ」に従い、
クレート本体・機能フラグ・レイヤ表・仕様書をまとめて整理しました。

削除前の状態は次のとおりです。

- どちらのクレートも、ワークスペースのどのクレートからも依存されていない（`Cargo.toml` に記載なし）
- `squid-n-ml` は `placeholder()` 1 関数だけの空クレート
- `squid-n-gpu` の GPU 経路は未実装で、`GpuSpMv::spmv` は `unimplemented!`、`PcgGpu::solve` は必ず `SolveError::Backend` を返す
- 実際に動く実装は `CpuSpMv`（CSC → CSR 変換と f32 の疎行列ベクトル積）だけで、これも呼び出し元がない

GPU 高速化（P10）は**恒久的に実装しません**（利用者判断）。
ML 断面提案（P11）は方針としては取り下げていませんが、当分着手しないため、空クレートを置き続けるより
着手時に作り直すほうが実体と文書が食い違わないと判断しました。

## 2. 削除したもの

### 2.1 コード

| 対象 | パス |
|---|---|
| GPU クレート一式 | `crates/squid-n-gpu/`（`lib.rs`・`spmv.rs`・`pcg.rs`・`gpu_context.rs`） |
| ML クレート一式 | `crates/squid-n-ml/`（`lib.rs`） |
| ワークスペースメンバ | ルート `Cargo.toml` の `members` から 2 行 |
| レイヤ定義 | `xtask/src/main.rs` の `check-deps` レイヤ表（Layer 0 の ml、Layer 1 の gpu） |
| 機能フラグ | `gpu`・`ml`（`CONTRIBUTING.md` の機能フラグ表） |

クレート数は 16 から 14 になりました。

### 2.2 依存関係と Cargo.lock

`wgpu 29`・`cubecl 0.3`・`cubecl-runtime` は `squid-n-gpu` の任意依存だったため、`Cargo.lock` から
関連するエントリ 712 行が消えました。

もともと `gpu` フィーチャは既定で無効だったので、通常のビルド時間は変わりません。
変わるのは cargo-deny と cargo-audit の走査対象です。
特に `cubecl-wgpu` が引いていた `wgpu 22.1.0` が消え、eframe 由来の `wgpu 29.0.3` だけが残りました。
`deny.toml` は `multiple-versions = "warn"` なので、wgpu の重複はこれで警告されなくなります。

`deny.toml` の `ignore` リストは変更していません。
現在除外している勧告は `bincode`（直接依存）・`paste`（faer → gemm 経由）・`ttf-parser` と `quick-xml`
（eframe 経由）で、どれも削除したクレート由来ではないためです。

### 2.3 仕様書

`dev_docs/specs/P10_GPU高速化.md` は削除しました。
GPU は恒久的に実装しないので、この仕様書を残すと果たされない約束になります。

`dev_docs/specs/P11_ML断面提案.md` は残しました。
着手する可能性があるので、冒頭に「クレートは撤去済み・着手時に §2 に従って作り直す」ことを注記しています。
本文にあった P10 への参照（burn のバックエンドを P10 と共有する記述、GPU 概算 → CPU 確定の比喩）は、
参照先が消えたため落としました。

なお P11 の backend にある `wgpu`・`cuda` は burn 自身のバックエンドで、削除した `squid-n-gpu` とは無関係です。

## 3. 残したもの

### 3.1 squid-n-math の PCG

`squid_n_math::pcg::PcgSolver` は残しています。
`PcgGpu` が内部で呼んでいたため GPU 専用に見えますが、実体は CPU の反復ソルバです。
`SolverBackend::IterativePcg` と `squid_n_math::auto` の自動選択から使われており、消すと超大規模モデルの
経路がなくなります。

あわせて、設計書のコメントにあった「大規模・GPU 向け」「反復法は GPU 経路と超大規模用」という位置づけは、
GPU 経路が消えたため「超大規模向け」へ書き換えました。

### 3.2 3D ビューアの wgpu

GUI の 3D ビューアが使う `wgpu` は eframe / egui-wgpu 経由で、`squid-n-gpu` とは別系統です。
今回の削除の影響を受けません。
`dev_docs/specs/UI設計.md` の「3D は `wgpu = "29"`」という前提もそのまま有効です。

### 3.3 CpuSpMv の実装

`CpuSpMv`（CSC → CSR 変換と f32 SpMV）は、削除したクレートで唯一動いていた実装です。
呼び出し元がないため復元先を用意していません。
必要になった場合は git 履歴から取り出せますが、現在の `squid_n_math::sparse` の型に合わせ直すほうが早いはずです。

## 4. 過去の判断との関係

`squid-n-ml` は、[実装レビューと重複統合_申し送り.md](実装レビューと重複統合_申し送り.md) §2.1 で
**予約地として存置**すると決着していました。
今回はその判断を覆しています。

存置の理由は「レイヤ表での位置決め」でしたが、実際にはレイヤ表・機能フラグ表・アーキテクチャ図・
利用者向けドキュメントの 4 か所に、中身のないクレートを載せ続けるコストが残っていました。
[AGENTS.md](../../AGENTS.md) は後方互換性を維持しない方針なので、着手時に作り直すほうが素直だと判断しています。

`squid-n-gpu` の `PcgGpu::solve` を明示エラー化した経緯（[申し送り.md](申し送り.md) 2.1-6）も、
今回クレートごと消えたことで役目を終えました。
過去の記録としてはそのまま残しています。

## 6. 今後

GPU 高速化を再検討する場合は、`P10_GPU高速化.md` を git 履歴から復元できます。
ただし `wgpu` と `cubecl` の API は版ごとに変わるため、仕様書の前提環境（`wgpu = "29"` / `cubecl 0.3`）は
そのまま使えません。

特に `cubecl` は、`default-features = false` にしても `cubecl-runtime` の `tune/tuner.rs` が
`async_channel` を無条件に使うため、`cubecl-runtime` を直接依存に足して `channel-mpsc` をフィーチャ統合で
有効にする必要がありました。
この回避策は削除した `crates/squid-n-gpu/Cargo.toml` のコメントに書いてありましたが、GPU を実装しない
方針のため、どこにも移していません。
必要になったら git 履歴から拾ってください。

ML 断面提案に着手する場合は、`P11_ML断面提案.md` §2 に従ってクレートを新設してください。
そのとき `xtask/src/main.rs` のレイヤ表への追加を忘れると、依存方向チェックの対象外のまま進みます。
