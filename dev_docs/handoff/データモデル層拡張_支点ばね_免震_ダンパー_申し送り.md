# データモデル層拡張（支点ばね・免震配置・ダンパープリセット・リリーフ特性）申し送り

**起票:** 2026-07-28

## 概要

データモデル層（`squid-n-core`/`squid-n-element`/`squid-n-edit`）へ以下 4 点を追加した。
UI（`squid-n-app`）側の入力フォーム・一覧画面は未実装であり、後続エージェントの対応事項。

1. 節点への支点ばね直接指定（`Node::support_spring`）
2. 支点への免震装置の配置コマンド（`PlaceSupportIsolator`）
3. 制振ダンパー定義（プリセット）ライブラリ（`Model::damper_defs`）
4. マクスウェルダンパーのリリーフ特性（`DamperProps::relief_velocity`/`c2_ratio`）

## 1. 支点ばね（`Node::support_spring`）

- `Node::support_spring: Option<[f64; 6]>`（全体座標系、並進 [N/mm]・回転 [N·mm/rad]）。
  `restraint` で固定されている自由度の値は無視する（固定支持を優先）。
- **単位系についての設計判断**: タスク指示書では `[N/m, N·m/rad]`（SI 基本単位）と
  記載されていたが、本コードベースは座標 [mm]・剛性 [N/mm]・[N·mm/rad] で一貫している
  （`NodalSpring::spring`、`IsolatorProps::k1/k2`、`DamperProps::kd` など、全て mm 系）。
  支点ばねだけ m 系にすると単位混在で重大なバグを誘発するため、**既存の mm 系に統一した**。
  UI 実装時は他の剛性入力（例: 節点バネ）と同じ桁感覚で扱ってよい。
- 線形経路: `squid_n_solver::common::assemble::assemble_global_k` の対角へ加算
  （`support_spring_terms` ヘルパで `(active DOF, k)` を列挙し、線形・非線形の両方から共用）。
- 非線形経路（プッシュオーバー）: `nonlinear::pushover::assembly::assemble_k` の対角へ
  同じ `support_spring_terms` を加算するのに加え、新関数 `add_support_spring_f_int` で
  内力側 `k・u` も明示的に加算する必要があった。理由: `compute_f_int` は要素
  （`ElementBehavior`）が自ら保持するトライアル変位から内力を求める契約だが、支点ばねは
  要素を介さない節点属性のため、現在の試行変位を呼び出し側（`driver.rs`）から渡す必要が
  ある。K だけに加算し内力側を忘れると、Newton は「支点ばねが存在しない残差方程式」の根へ
  収束してしまい、支点ばねが解析結果に一切効かなくなる（K は効くが残差計算に効かない
  不整合）。この対応のため `driver.rs`（`newton_converge` のシグネチャ変更、荷重制御・
  変位制御・弧長法の各フェーズでの呼び出し追加）にも波及した。
- テスト: `squid-n-solver/src/common/assemble.rs`（線形 K の対角加算・restraint 固定時の
  無視・孤立節点の非対象）、`squid-n-solver/src/nonlinear/pushover/tests.rs`
  （`test_pushover_support_spring_affects_k_and_f_int`。要素ばね kx と支点ばね ks の
  合成剛性 kx/(kx+ks) が非線形経路の終点変位比に正しく現れることを検証）。

## 2. 免震装置の配置（`PlaceSupportIsolator`）

- `crates/squid-n-edit/src/node_member.rs` に `AddIsolator`（`AddDamper` と同型の原子的
  追加コマンド）と `PlaceSupportIsolator`（複合的な設置コマンド）を追加。
- **`PlaceSupportIsolator` の構成**: 対象節点と同一座標に接地節点（`restraint=FIXED`）を
  新規作成し、その2節点間に零長 `ElementKind::Isolator` 要素＋`IsolatorAttr` を追加した上で、
  対象節点自身の `restraint` を `FREE` に変更する（免震装置を介して支持されるため）。
  要素の節点順は `[接地節点, 対象節点]`（i端=接地/下端、j端=対象/上端）。
  `element/src/springs/isolator.rs` の零長特例（2 節点が同一座標の場合、局所 x 軸＝全体
  座標系の鉛直方向、節点0→節点1 の向き）に整合させるため。
- undo は生成した接地節点・Isolator 要素（＋属性）を**要素→節点の順**で削除し
  （`node_in_use` が要素参照中の節点削除を拒否するため）、対象節点の `restraint` を
  元へ戻す。redo は同一パラメータで `PlaceSupportIsolator` を再適用するだけでよい
  （LIFO の undo/redo 前提の下、生成される ID は元と同じ値に戻るため）。単一コマンドとして
  実装し `CompositeCommand` は使っていない（子コマンドの生成順序・ID 依存関係が複雑になる
  ため、専用の逆コマンド `UndoPlaceSupportIsolator` を持たせる方が単純だった）。
- テスト: `squid-n-edit/src/tests.rs`
  （`test_add_isolator_creates_element_and_attr_roundtrip`、
  `test_place_support_isolator_roundtrip`、`test_place_support_isolator_invalid_node_is_noop`）。

## 3. ダンパー定義ライブラリ（`Model::damper_defs`）

- `DamperDef { name: String, props: DamperProps }`（`squid-n-core/src/model/wall.rs`）。
  `Model::damper_defs: Vec<DamperDef>` を追加（`ElemId` への参照を持たないため、要素の
  追加・削除に伴う ID シフト（`shift_elem_attr_refs` 等）の対象外。`eq_ignoring_dofmap`
  には追加済み）。
- 割当は値コピー設計（`AddDamper`/`SetDamperProps` で `DamperProps` を複製して
  `Model::damper_attrs` へ入れる）のため、`DamperDef` を更新・削除しても既存の割当済み
  部材は壊れない（`squid-n-edit/src/tests.rs::test_damper_def_removal_does_not_affect_assigned_member`
  で確認）。
- 編集コマンド `AddDamperDef`/`UpdateDamperDef`/`RemoveDamperDef`（+ 内部の逆操作
  `InsertDamperDef`）を `crates/squid-n-edit/src/section_material/damper_def.rs` に追加
  （`section.rs` の `AddSection`/`DeleteSection` と同型）。

## 4. マクスウェルダンパーのリリーフ特性

- `DamperProps` に `relief_velocity: Option<f64>`（リリーフ速度 Vr [mm/s]）と
  `c2_ratio: Option<f64>`（リリーフ後の減衰係数比 C2/C1）を追加。
- **力則の式**（`element/src/springs/damper/maxwell.rs` の `dashpot` 関数）:
  - `|V| ≤ Vr`: 従来どおり `Fc = C0・sign(V)・|V|^α`。
  - `|V| > Vr`: `Fc = sign(V)・(C0・Vr^α + C2・(|V|−Vr))`、
    `C2 = c2_ratio・C1`、`C1 = C0・α・Vr^(α−1)`（リリーフ点 Vr における
    リリーフ前の接線減衰係数）。
  - この定義により、リリーフ点で力は連続（両式とも `C0・Vr^α` に一致）、勾配は
    `C1 → C2` へ不連続に低下する折れ線となる（実オイルダンパーのバイパス弁による
    頭打ち特性の近似）。`relief_velocity=None`（既定）は従来どおり全域で線形則。
  - Newton 法（`solve_ud`）・整合接線（`axial_tangent`）の両方を `dashpot` 経由に統一した
    ため、リリーフ有効時は α=1 でも閉形式を使わず必ず反復で解く
    （閉形式は線形粘性のみに厳密なため）。
- テスト: `test_relief_dashpot_continuous_and_slope_matches_c2`（連続性・勾配の照合）、
  `test_relief_matches_baseline_below_relief_velocity`（Vr 以下では従来と完全一致の
  回帰確認）、`test_relief_caps_force_growth_at_high_velocity`（高速域での頭打ち効果の
  要素レベル確認）。

## 5. コードレビュー指摘対応（2026-07 追記）

コアモデル・編集コマンド・テーブル UI について実施したコードレビューで見つかった問題点への
対応。対象は `squid-n-core`/`squid-n-edit`/`squid-n-app`（`tables/` と
`damper_def_editor.rs`）。

### 5-1. `Model::damper_defs` の構造体内位置（msgpack 後方互換の落とし穴）

- `damper_defs` フィールドは元々 `damper_attrs` の直後（`member_detail_attrs` の手前）に
  宣言されていた。msgpack（`rmp_serde::to_vec`、.scz の実直列化形式）は構造体を**位置ベースの
  配列**として直列化するため、`#[serde(default)]` による欠損フィールド補完は**構造体の末尾に
  限って**有効であり、途中への挿入は後続フィールド（`member_detail_attrs`・`secondary_members`・
  `beam_groups`）の値がずれて読み込まれる形で壊れる（JSON なら壊れないが、.scz は壊れる）。
- 対応: `damper_defs` を `beam_groups` の後・`dof_map`（`#[serde(skip)]`）の手前という
  **構造体の実質末尾**へ移動した。`Model` 構造体のドキュメントコメントに「msgpack 後方互換の
  ため新フィールドは必ず構造体末尾へ追加する」旨を明記した。
- `squid-n-core/src/model/tests.rs` の `test_node_support_spring_msgpack_backward_compat` に
  付いていた「rmp-serde は self-describing 形式のため…」というコメントは誤り（実際は
  位置ベース配列であり、self-describing ではない）だったため訂正した。
- 本件は「今後の新規フィールドは末尾に追加する」運用改善であり、既に世に出た .scz
  ファイルの救済（マイグレーション）は対象外（本アプリはリリース前段階のため）。

### 5-2. ダンパー定義削除時の index ずれ（`damper_def_editor.rs`／`tables/members.rs`）

- `DamperDefDraft.edit_index`（一覧の「✏」で読み込んだ編集対象の `damper_defs` 内
  インデックス）は、削除位置より後ろの定義を編集中に別の定義を削除すると、ずれた
  インデックスのまま残ってしまい、「選択定義へ適用」が別定義を上書きしてしまう不具合が
  あった。対応:
  - 削除時に `edit_index > 削除位置` なら 1 減算、`edit_index == 削除位置` なら
    クリア（新規作成扱いへ戻す）。
  - `DamperDefDraft` に `edit_target_name: Option<String>`（編集開始時点の定義名）を追加し、
    「選択定義へ適用」の直前に現在その位置にある定義名と一致するか確認する
    （undo/redo で並びが変わり、index は範囲内でも別定義を指してしまうケースを検知）。
    不一致ならエラーメッセージへフォールバックし、上書きせず編集状態をクリアする。
  - 描画のたびに `edit_index >= damper_defs.len()` なら編集状態をクリアする（undo/redo で
    定義数が変わった場合の保険）。
  - 上記の補正ロジックは `remap_edit_index_after_delete`/`edit_target_still_matches` として
    純関数に切り出し、`damper_def_editor.rs` 内でユニットテストしている。
  - `tables/members.rs` の「制振ダンパーの定義から選択」（`damper_def_sel`、部材追加フォーム）
    も同種の問題があったため、選択インデックスと選択時点の定義名の組を egui 一時メモリに
    保持し、`resolve_damper_def_selection`（純関数、ユニットテスト付き）で毎フレーム
    名前ベースに追従させるよう修正した。

### 5-3. 支点免震要素の単体削除でゴミが残る（`node_member.rs`／`tables/members.rs`・`tables/nodes.rs`）

- `PlaceSupportIsolator` が生成する「対象節点＋接地節点＋零長 Isolator 要素」の組は、免震
  一覧から通常の `DeleteMember` で免震要素だけを削除すると、接地節点（`restraint=FIXED`の
  孤立節点）が孤児として残ってしまっていた。
- 対応: `squid-n-edit::node_member` に `RemoveSupportIsolator { node: NodeId }` を追加した。
  - 判定には `Model::support_isolator_ends(elem) -> Option<(上部節点, 接地節点)>`
    （`squid-n-core/src/model/aggregate.rs`）を新設し、「零長・片方が
    `restraint=FIXED`かつこの要素以外から参照されていない（孤立）」を支点免震要素の条件とした
    （`Model::node_in_use_excluding_elem` を新設し、`node_in_use` から要素参照チェック部分だけ
    差し替えられるようリファクタ）。
  - `RemoveSupportIsolator` は対象要素（＋ `isolator_attrs`）と接地節点を
    `DeleteMember`→`DeleteNode` の順（`node_in_use` が要素参照中の節点削除を拒否するため
    `PlaceSupportIsolator`の逆操作と同じ順序）で削除し、対象節点の `restraint` を戻す。
  - **拘束復元の仕様**: `PlaceSupportIsolator` は設置前の `restraint` を記録していないため、
    `RemoveSupportIsolator` の撤去後の拘束は常に `FIXED` に統一する仕様とした（設置前が
    ピン支点等だった場合でも `FIXED` に戻る。必要ならユーザが撤去後に境界条件パネルで
    再設定する）。undo（`UndoRemoveSupportIsolator`）は撤去直前の拘束（通常は
    `PlaceSupportIsolator` が解放した `FREE`）へ戻し、`DeleteMember`/`DeleteNode` が返す
    `InsertMember`/`InsertNode` を使って元の ID・位置・特性で完全復元する。redo は
    「復元後の状態から改めて `RemoveSupportIsolator` を発行し直す」実装とした（`PlaceSupportIsolator`
    の逆操作と同型の考え方）。
  - `tables/members.rs` の免震一覧（`isolators_table`）の削除ボタンは
    `Model::support_isolator_ends` で判定し、支点免震なら `RemoveSupportIsolator`、通常の
    免震要素なら従来どおり `DeleteMember` を使うよう分岐した。
  - 境界条件パネル（`tables/nodes.rs`）の「配置済み」表示に「撤去」ボタンを追加し、同じ
    `RemoveSupportIsolator` を呼ぶようにした。
  - `Model::support_isolator_ends` を使うよう `find_support_isolator`（`tables/nodes.rs`）も
    書き換えた（5-5 参照）。
  - テスト: `squid-n-edit/src/tests.rs::test_remove_support_isolator_roundtrip`
    （配置→撤去で `eq_ignoring_dofmap` が配置前と一致・撤去→undo で配置直後の状態に一致・
    さらに redo で撤去状態に戻る）、
    `test_remove_support_isolator_noop_when_not_support_isolator`（通常の免震要素・存在しない
    節点は Noop）。`tables/nodes.rs` にも「撤去」ボタン相当のコマンド呼び出しテストを追加。

### 5-4. 免震の入力単位不一致（N/mm・N vs kN/mm・kN）

- `tables/nodes.rs::isolator_props_fields`（境界条件パネルの配置フォーム・部材タブの
  免震支承材追加フォームで共用）の K1・K2・Kv 入力が N/mm 表記・生値のままで、免震一覧
  （`tables/members.rs::isolators_table`）の kN/mm 表記と単位が食い違っていた
  （Qd・N（長期軸力）は元々 kN 表記で換算済みだった）。
- 対応: K1・K2・Kv も kN/mm 表記へ統一し、表示のたびに 1000 で除算・確定時に 1000 を
  乗算する換算を追加した（`IsolatorProps` 自体の内部表現は従来どおり N/mm・N のまま）。
  境界条件パネルの「配置済み」要約表示（K1/K2/Kv の表示）も同じ換算に揃えた。

### 5-5. その他の低優先度指摘（まとめて対応）

- `SetNodeSupportSpring`（`node_member.rs`）: 負のばね剛性成分は 0 にクランプするよう変更
  （物理的に無意味なため）。
- `AddIsolator`（`node_member.rs`）: `elem.id` が `model.elements.len()`（追加すべき末尾
  インデックス）と一致しない場合は ID＝配列インデックス不変条件を壊すため Noop にするガードを
  追加（`AddDamper`・`AddMember` 等の既存コマンドは対象外、今回追加分のみ）。
- `tables/nodes.rs` の支点ばね DragValue、および `tables/members.rs::isolators_table` の
  免震諸元 DragValue（K1/K2/Qd/Kv/μ）: `changed()` のたびにコマンドを発行すると、ドラッグ中は
  毎フレーム undo スタックを消費してしまうため、`drag_stopped()`（またはフォーカス喪失
  `lost_focus()`）で確定するよう変更した。
- `find_support_isolator`（`tables/nodes.rs`）: 接地節点（FIXED側）を選択したときに
  「配置済み」と誤表示してしまうバグを修正。`Model::support_isolator_ends` に委譲し、対象節点が
  要素の**上部側**（接地でない側）である場合のみ `Some` を返すようにした。
- `tables/members.rs::SetIsolatorPropsLocal`: `retain`+`push` による更新は、undo 後に
  再適用すると当該エントリが `isolator_attrs` の末尾へ移動し並び順が変わってしまっていた。
  `props=Some` の場合は `iter_mut().find()` によるインプレース書換えに変更し（`None`
  ＝指定解除の場合のみ `retain` で除去）、並び順を維持するようにした。
