# 材料を断面へ移す 申し送り

作成日: 2026-08-07
対象コード:
`crates/squid-n-core/src/model/{section.rs,element.rs,secondary.rs,aggregate.rs}`、
`crates/squid-n-core/src/{material_grade.rs,section_shape/types.rs}`、
`crates/squid-n-element/src/{factory/input_check.rs,frame/fiber/mod.rs,frame/beam/construct.rs,wall/misc_wall.rs}`、
`crates/squid-n-solver/src/statics/analysis/precheck.rs`、
`crates/squid-n-solver/src/nonlinear/pushover/{hinge.rs,shear_yield.rs}`、
`crates/squid-n-design-jp/src/{material_strength/rebar.rs,rc/,srrc/,ultimate/,joint_wiring/}`、
`crates/squid-n-io/src/stbridge/{section_std.rs,import/{assemble.rs,rebar.rs,parser.rs}}`、
`crates/squid-n-edit/src/section_material/element_assign.rs`、
`crates/squid-n-app/src/{tables/{sections.rs,members.rs,materials.rs},section_editor.rs,viewer/th_detail.rs}`、
`docs/`（材料の指定場所・解析前チェック・ST-Bridge の材料）、
`dev_docs/specs/構造計算一貫プログラム_実装設計書.md`

モデル作成支援機能の第 2 弾。作成ウィザードと 3D グリッドの前提として、
材料の持ち主を部材から断面へ移した。作成ウィザード・階複製は本申し送りの範囲外。

## 変更前の問題

材料の持ち方が 3 つに割れていた。

1. **主材料は部材が持っていた**（`ElementData.material` / `SecondaryMember.material`）。
   同じ断面を使う部材どうしで別々の材料を割り当てられ、断面性能と材料強度が
   別の場所に散っていた。
2. **鉄筋・内蔵鉄骨は断面形状がグレード名の文字列で持っていた**
   （`RcRebar.main_grade` / `ShearBar.grade` / `SrcRect.steel_grade`）。
   `Material` を通らないため区分も物性も検証されず、降伏点は名称末尾の数字を
   パースして得ていた（`KH785` → 785）。
3. **どちらも無いときは部材材料の名前を鉄筋グレード名として読んでいた**。
   RC 部材の主材料はコンクリート（`Fc24` 等）なので、この経路に落ちると
   `rebar_allowable_shear("Fc24", …)` が既定枝へ流れ、根拠のない値が出ていた。

ST-Bridge は材料を断面に持つ。書き出し側はこの食い違いを埋めるため、
「その断面を最初に参照する部材の材料を柱用／梁用の役割別に代表とする」逆算
（`section_materials()`）を持っていた。内部の持ち方が規格と揃っていないことの
症状であり、断面を柱用・梁用へ分割するたびに代表が変わりうる不安定な実装だった。

## 対応

### 1. 材料は断面が持つ

`Section` へ 4 つの欄を置き、`ElementData.material`・`SecondaryMember.material`・
形状のグレード名文字列をすべて削除した。

| 欄 | 役割 | 対象断面 |
| --- | --- | --- |
| `material` | 主材料（コンクリート／鋼材） | すべて |
| `rebar_material` | 主筋 | RC 矩形・RC 円形・SRC 矩形・RC 壁 |
| `shear_rebar_material` | せん断補強筋 | 同上 |
| `steel_material` | 内蔵鉄骨 | SRC 矩形 |

**違う材料を割り当てるならそれは別の断面**とする。部材ごとに材料を変える経路が
無くなったので、「同一断面・別材料」を表現していた逆算はすべて不要になった。

解決は `Model::{element_material, element_rebar_material, element_shear_rebar_material,
element_steel_material, secondary_material}` に集約し、各クレートはこれだけを呼ぶ。

### 2. 降伏点は材料の `fy` だけで決める

`material_grade::{rebar_yield_strength, shear_rebar_yield_strength}` は
材料の `fy` を返すだけにした。材料名からの数値パースは廃止し、
`rebar_sigma_y`（名前の数字を σy とする関数）は削除した。

材料の**名前**は許容応力度表の引き当て（令90条表・高強度品の製品表）にのみ使う。
規格名が表の行を指すのは規準どおりの運用だが、降伏点を名前から推定するのは別物である。

グレード名から強度を推定する `material_grade::rebar_grade_f_value` は
**ST-Bridge 取り込みの境界専用**として残した（規格側が名前しか持たないため）。

### 3. 未割当は止める

材料が無いときに既定値で補う経路を断った。

| 場所 | 検査 |
| --- | --- |
| `squid_n_solver::…::model_issues`（全解析共通の前チェック・診断タブ） | 断面の主材料、配筋を持つ断面の主筋・せん断補強筋、SRC 断面の内蔵鉄骨 |
| `squid_n_element::factory::nonlinear_input_issues`（非線形解析） | 主筋の材料と `fy`、鋼材ファイバの降伏点 |
| `RcDesign::check` / `SrcDesign::check`（許容応力度検定） | 主筋・せん断補強筋（SRC はさらに内蔵鉄骨）。未割当は `Skipped` で理由を返す |

### 4. ST-Bridge は逆算をやめた

`section_materials()`（部材からの逆算・柱用／梁用の代表選択）を削除し、
書き出しは断面の材料をそのまま `strength_main` / `strength_concrete` /
`strength_steel` / 配筋の `strength_*` へ出す。

取り込みでは、部材の `id_material` を**参照先の断面へ移す**。
断面がグレード名を持たず部材だけが材料を指すファイル（実 ST-Bridge に多い）でも
材料が失われない。同じ断面を指す部材が別々の材料を指す場合は最初の 1 件を採り、
件数を取り込み報告へ警告として出す。

### 5. UI

材料の割り当てを部材テーブルから断面テーブルへ移した。断面テーブルに
「材料」「主筋」「せん断補強筋」「内蔵鉄骨」の 4 列を置き、断面形状から使わないと
わかる欄は淡色の `—` にして選べないようにしている。
部材テーブルの材料欄は断面から引いた表示のみになった。
断面作成パネルの配筋欄からは材質のコンボを外した（材料はテーブルで割り当てる）。

編集コマンドは `SetElementMaterial` を `SetSectionMaterial { section, role, material }`
へ置き換えた（`role` は `SectionMaterialRole::{Main, Rebar, ShearRebar, Steel}`）。

## 敵対的レビューで検出・修正した不具合

### 1. 時刻歴の断面検定が全 RC・SRC 部材で「検定不能」になる

`viewer/th_detail.rs` の `DesignCtx` が材料 3 欄を埋めていなかった。
本作業で `RcDesign::check` / `SrcDesign::check` に未割当ガードを入れたため、
断面に材料が正しく割り当てられていても、時刻歴の詳細パネルだけが
全 RC・SRC 部材を `Skipped` にして「検定不能」と表示する状態になっていた。
設計タブ（`actions.rs`）・MCP（`design_check.rs`）と同じく断面から解決して渡すよう修正した。

`checker_for` を呼ぶ 3 経路すべてが材料を渡していることを確認した。

### 2. 耐震壁の w_ft をコンクリート材料の名前から引いていた

`joint_wiring/wall.rs` が `rebar_allowable_shear(&mat.name, …)` を呼んでおり、
`mat` は壁・側柱の**主材料（コンクリート）**だった。`Fc24` のような名前は
どの鉄筋グレードにも一致しないため既定枝（長期 195・短期 295）へ落ち、
SD390 の壁筋でも SD295 相当で評価されていた。

この誤りは変更前から存在したが、当時は正しい材料が**どこにも無かった**ため
直しようがなかった。断面が `shear_rebar_material` を持つようになったので、
`MemberInfo` へ `shear_mat` を足して側柱・壁の両方をその材料から引くよう修正した。

### 3. 検定側に届かない死んだフォールバックが残っていた

`rc/column/mod.rs` の `.unwrap_or(mat.name.as_str())`、`srrc/{beam,column}.rs` の
「せん断補強筋の材質が無ければ主筋のグレード名を使う」経路は、
`RcDesign::check` / `SrcDesign::check` のガード導入後は到達しない。
到達しないフォールバックが残っていると、次に読む人が「未割当でも動く」と
誤解するため削除した。

## 2 巡目の敵対的レビューで検出・修正した不具合

### 4. 材料だけが違う断面が取り込みで統合され、片方の材料が消える

`Section::properties_eq` は断面性能と形状しか比べていなかった。材料が断面へ移った
ことでこの判定が不完全になり、ST-Bridge 取り込みで符号＋階と寸法が同じ・材料だけが
違う 2 定義が 1 断面へ統合され、**先に読んだ方の材料が無言で採用**されていた。

「違う材料を割り当てるならそれは別の断面」という本作業の前提そのものに反する。
`properties_eq` へ材料 4 欄を足し、材料が違う定義は統合せず符号へ連番を付けて
両方残すようにした（既存の改番経路がそのまま使える）。

### 5. 部材の `id_material` が食い違うときの取りこぼしが無言だった

断面側にグレード名が無く部材だけが `id_material` を持つファイルでは、
同じ断面を指す部材が別々の材料を指しうる。材料は断面が持つため後勝ちの材料は
行き場がなく、先勝ちで捨てられていた（しかも無言で）。
件数を数えて取り込み報告へ警告を出すようにした。

### 6. MCP の断面問い合わせから材料が見えない

`query_model` の断面出力は id・符号・A・Iy・Iz だけで、材料 4 欄も階も出していなかった。
材料が断面へ移り、未割当を解析前チェックが止めるようになったのに、
問い合わせ側から「どの断面のどの欄が空か」を追う手段が無い状態だった。
4 欄と `floor` を出力へ足した。

### 7. `SetSectionMaterial` にテストが無かった

本作業の中心となる新しい編集コマンドなのに、apply・undo の往復も Noop ガードも
検証していなかった。4 つの役割それぞれで往復すること、ほかの欄が動かないこと、
存在しない断面への割当が Noop であることのテストを追加した。

## 検証

- `cargo test --workspace --all-features` 緑（2175 テスト）
- `cargo clippy --workspace --all-targets --locked -- -D warnings`、gui・mcp フィーチャ版とも緑
- `cargo fmt --all -- --check` 緑
- `cargo run -p xtask -- check-deps` 緑（依存方向に変化なし）
- 追加・改訂したテスト
  - core: 材料の `fy` だけから σy を決めること（名前から推定しないこと）、
    断面 → 材料のダングリング参照を `validate` が弾くこと、
    `visit_material_ids` が 4 欄すべてを走査すること
  - element: 主筋の材料が未割当／`fy` 未設定の RC 部材を入力チェックが止めること、
    内蔵鉄骨の材料が未割当の SRC 断面を止めること
  - solver: 断面に割り当てた鉄筋の材料が Qy・My へ反映されること
  - io: 断面の 4 材料が往復すること、部材の `id_material` が断面へ移ること、
    柱と梁で材料が違うなら別断面としてそれぞれのグレード名が出ること
  - edit: 断面が参照する材料は削除できないこと、繰り上げが断面の参照へ追随すること、
    `SetSectionMaterial` が 4 役割それぞれで往復し undo で戻ること
  - core: 材料だけが違う断面が `properties_eq` で別物になること
  - io: 材料が違う定義を統合しないこと、部材の材料の食い違いを警告すること
  - mcp: 断面の問い合わせが材料 4 欄を出すこと

## 既知の挙動変更（利用者から見えるもの）

- **既存のプロジェクトファイルは材料が外れた状態で開く。**
  部材が持っていた材料は読み捨てられ、断面の材料欄は未設定になる。
  解析前チェックが未割当を名指しするので、断面テーブルで割り当て直す。
  後方互換性は維持しない方針（AGENTS.md）にしたがう。
- 配筋を持つ断面で主筋・せん断補強筋の材料が未割当だと、許容応力度検定が
  「検定不能」の理由を返し、解析前チェックが解析を止める。
  変更前は既定値（σy=345・σwy=295）で無言に検定していた。
- 耐震壁・側柱の w_ft が壁筋の材料から決まるようになった（上記の不具合 2）。
  SD295 以外の壁筋を使うモデルでは接合部・壁のせん断検定結果が変わる（**是正**）。

## 残課題

- **壁の \( Q_u \) の σwh は 295 N/mm² 固定のまま**。
  `wall_panel.rs` の `wall_shear_ultimate` は `sigma_wh: 295.0`・
  `high_strength_shear_rebar: false` をハードコードしており、断面の
  `shear_rebar_material` を見ていない。規格上の最小グレードなので安全側だが、
  正しい材料が引けるようになった以上は解消したい。
  終局耐力の数値が動くため本作業には含めず、既定値として docs へ明記した
  （`docs/calc_basis/04_要素剛性/05_壁エレメントモデル.md`）。
- **`SetSectionMaterial` は材料の存在を検証しない**。
  `SetElementSection` と同じく「呼び出し側が検証する」規約にしたがっているが、
  ダングリング参照を作ると `Model::validate` が落ちて他の診断が全部止まる。
  編集コマンド全体の規約として見直すのがよい。
