# 限界耐力計算（P12）と段階的耐力喪失解析を削除した件 申し送り

## 1. 方針

限界耐力計算（容量スペクトル法）と段階的耐力喪失解析は、いずれも製品機能として
使われていませんでした。
[AGENTS.md](../../AGENTS.md) の「現在の要件を完全に満たすもっともシンプルな実装を
選ぶ」に従い、実装・利用者向けドキュメント・仕様書をまとめて削除しました。

削除前の呼び出し関係は次のとおりです。

- 限界耐力計算（`capacity_spectrum.rs`）は `p12` フィーチャ配下の未実装スタブで、呼び出し元が 1 つもない
- 段階的耐力喪失解析（`staged_strength_loss`）は自身のテストからのみ呼ばれ、アプリ・MCP のどちらからも到達しない

## 2. 削除したもの

### 2.1 コード

| 対象 | パス |
|---|---|
| 容量スペクトル法のスタブ | `crates/squid-n-design-jp/src/capacity_spectrum.rs` |
| `p12` フィーチャ | `crates/squid-n-design-jp/Cargo.toml`、`CONTRIBUTING.md` の機能フラグ表 |
| 段階的耐力喪失解析 | `crates/squid-n-solver/src/nonlinear/strength_loss/`（`mod.rs`・`tests.rs`） |

`squid_n_solver::strength_loss` の再エクスポート（`lib.rs`）も外してあります。

### 2.2 増分解析からの節点変位記録

`PushoverStep::node_disp` と `record_node_disp` 引数を削除しました。
この 2 つは段階的耐力喪失解析の専用機能です。
あの解析は任意ステップの部材変形角を事後に再計算するため、生の全自由度変位
ベクトルを全ステップ分そのまま保持する必要がありました。

増分解析が使う節点変位由来の量は、すべて別のフィールドに算定済みで入っています。
そのため削除しても失われる情報はありません。

- 頂部変位・層間変位は `PushoverStep::top_disp` / `story_drifts` に算定済み
- ヒンジ詳細図の M-θ 応答経路は `PushoverResult::member_history`（材端回転を含む全確定ステップの履歴）
- 終局時の部材変形角 Rp は `PushoverResult::member_response`

削除前に `record_node_disp = true` を渡していたのは段階的耐力喪失解析だけでした。
アプリ・MCP・例題・V&V テストは、すべて `false` を渡していました。

## 3. 残したもの

### 3.1 せん断降伏イベント（`shear_yield.rs`）

`shear_yield.rs`・`ShearYieldEvent`・`PushoverResult::shear_yields` は残しています。
もともと段階的耐力喪失解析の判定用に作られた仕組みです。
ですが現在は P7 の **SRC 柱・SRC 耐震壁の部材ランク判定**が使っており
（`crates/squid-n-app/src/app/actions.rs`）、消すと二次設計が壊れます。

「破壊モードがせん断破壊か」を決めるのがその用途です。
削除にあわせて、モジュールコメントとフィールドコメントを現在の用途へ書き換えました。

### 3.2 部材変形角の算定（`member_response::member_rp_angle`）

部材別 Rp の算定に使うため残しています。
この関数のコメントには「弦回転角が塑性回転角に対して過大となる」という既知の近似が
書いてあります。
その安全側の説明が FEMA 356 の塑性回転角 a との比較を前提にしていたため、現在の
利用先である靭性保証型耐震設計指針の塑性理論式に沿って書き直しました。

Rp が大きいほど有効係数 ν とトラス機構の cotφ がともに小さくなります。
終局せん断強度が下がるので、検定は安全側に出ます。

## 4. 利用者ドキュメント（`docs/`）の章番号

削除した 2 つのページは次のとおりです。

- `docs/calc_basis/09_限界耐力計算/`（章ごと）
- `docs/calc_basis/05_構造解析/08_段階的耐力喪失解析.md`

空いた番号は繰り上げました。

| 変更前 | 変更後 |
|---|---|
| `calc_basis/10_免震制振/` | `calc_basis/09_免震制振/` |
| `calc_basis/11_数量積算/` | `calc_basis/10_数量積算/` |
| `calc_basis/05_構造解析/09_累積損傷度.md` | `calc_basis/05_構造解析/08_累積損傷度.md` |
| `calc_basis/05_構造解析/10_並列計算.md` | `calc_basis/05_構造解析/09_並列計算.md` |

番号を空けたまま残さなかったのには理由があります。
mdBook はサイドバーの章番号を `SUMMARY.md` の並び順から自動採番しますが、各ページの
見出しには番号が手書きで埋め込まれています。
9 章を抜いたまま放置すると、サイドバーが「9. 免震・制振」と表示するのに本文見出しは
「10. 免震・制振」のままになり、表示が食い違います。

そのため見出し番号（`10.1.1` のような 3 階層まで）、他章からのクロスリンク、
`book.toml` のリダイレクト表も追随させてあります。

旧 URL から新 URL へのリダイレクトは追加していません。
リダイレクト表の用途は「章ディレクトリごとに `README.html` を `index.html` で受ける」
ことに限定されており、別種のエントリを混ぜると規約が濁るためです。

`docs/calc_basis/README.md` の法令ツリーからは、`令82条の5` と `平12建告1457号` の
2 行も落としました。

なお章番号の繰り上げにより、過去の申し送りが持つ `docs/calc_basis/10_免震制振/` の
ようなパス表記は、現在の配置と一致しなくなりました。
これも過去の記録として意図的に残しています。

## 6. P12 を参照していた他フェーズの仕様書

限界耐力計算は**恒久的に実装しません**。
そのため他フェーズの仕様書に残っていた「v2 で実装」という記述は、果たされない
約束になります。
P12 はフェーズ番号の欠番として扱い、繰り上げはしません。
`P1.5`・`P5.5`・`P5.6` が併存しているとおり、フェーズ番号は順序ではなく識別子だからです。
同じ理由で `UI-17` も削除のみとし、`UI-18`・`UI-19` は繰り上げていません。

**`specs/構造計算一貫プログラム_実装設計書.md`**

| 箇所 | 対応 |
|---|---|
| R20 の判断（§主要な設計判断） | 「v1 対象外（v2）」→「対象外（実装しない）」へ書き換え |
| 機能一覧の「設計」行 | 「・限界耐力」を削除 |
| §11.1 対象 | 「v1 対象外（v2 で実装）」→「対象外（実装しない）」へ書き換え |
| フェーズ表 | 「P12 限界耐力計算」の行を削除 |
| 早期実証ポイント・担当表 | 「限界耐力」の言及を削除 |

R20 の行は**削除せず書き換えました**。
この行はリポジトリで唯一 `R20` を記録しており、しかも R21（GPU）の判断が同居して
います。
行ごと消すと、要件 R20 の存在と GPU の設計判断が同時に失われます。

付録 B 用語集の「限界耐力計算」は残しました。
本文に語が 2 箇所（R20・§11.1）残るため、読者が語義を引ける状態を保つほうが自然です。

**`specs/UI設計.md`**

「UI-17 限界耐力：容量スペクトル・性能点の表示」の行、設計タブの内容、レポートの
章立てから限界耐力を落としました。

§6 可視化一覧の性能曲線の行は、**消さずに書き換えています**。

```
変更前: - **性能曲線**（容量曲線・性能点、P12 §5）
変更後: - **性能曲線**（ベースシア–頂部変位、P5 §7.4）
```

`性能曲線` には 2 つの意味が重なっていました。
増分解析の性能曲線（ベースシア–頂部変位）は実装済みで `UI-10`（P5）の担当ですが、
括弧の中の容量曲線・性能点は限界耐力計算の語です。
可視化一覧で性能曲線を挙げているのはこの 1 行だけなので、行ごと消すと実装済みの
機能が目録から欠落します。

**各フェーズ仕様書**

`P9`・`P11` のナビゲーション文（「次は P12」「以降は v2.0（…P12 限界耐力）」）から
P12 を落としました。
スコープ表からは「限界耐力」の語だけを落とし、同じ行に同居する保有水平耐力・Ds・
応答スペクトル法・GPU・ML は残しています。
応答スペクトル法（`P6`）は限界耐力計算とは別の解析手法で、単独で実装しうるためです。

`P7_二次設計.md` のスコープ表だけは行を残し、次の形にしました。

```
| 限界耐力計算 | **含まない（恒久）** | 実装しない方針 |
```

`specs/数量積算.md` のスコープ表に「**含まない（恒久）**」の前例があるため、新しい
記法を持ち込まずに「なぜここに限界耐力の話がないのか」へ答えを残せます。

## 7. 今後

限界耐力計算（令 82 条の 5）は正規の計算ルートですが、本ソフトでは実装しません。
方針を変える場合は、削除した `specs/P12_限界耐力計算.md` を git 履歴から復元でき
ます。
ただし告示 1457 号の版・改正の確認からやり直してください。

増分解析のステップごとの変形図を作る場合は、`node_disp` を復活させないでください。
時刻歴応答解析の `ThRecording` と同じ設計判断（記録粒度・型・オプトインの要否）を
あらためて行うほうが素直です。
既定のステップ数は 50 なので、全自由度の `f64` を全ステップ分保持すると
プロジェクトファイルが大きく膨らみます。
