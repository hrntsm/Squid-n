# 実装レビューと重複統合 — 申し送り

作成日: 2026-08-03

ワークスペース全体（15 クレート・約 176k 行）を 4 領域（GUI／ソルバ・要素／設計・荷重系／
基盤・IO 系）に分けてコードレビューし、実害の大きい不整合の修正と重複統合を行った。
本書は「本ブランチで修正した内容」と「レビューで確認したが未着手の残課題（優先度付き）」を記録する。

## 1. 本ブランチで修正した内容

### 1.1 編集コマンドの ID 参照整合（データ破壊の修正）

ID＝配列添字の不変条件を保つ「削除時の ID 繰り上げ」から、以下の参照が漏れていた。
ST-Bridge を取り込んだモデル（二次部材あり）で節点・断面・材料を削除すると、二次部材が
別の対象へ張り付き、保存時の `validate()` まで発覚しなかった。

- `squid-n-edit::shift_node_ids` / `shift_section_ids` / `shift_material_ids` に
  `Model::secondary_members`（小梁・間柱）の参照を追加。
- `section_in_use`・`DeleteMaterial` の使用中ガードに二次部材の参照を追加
  （`material_in_use` を新設）。
- `Model::shift_elem_attr_refs`（core）に一本部材指定 `beam_groups` を追加し、
  `panel_gen.rs` 側の手動繰り上げを削除（単一情報源化）。従来は部材削除後に
  グループが**無関係な部材のモーメントを検定に合成**していた（validate も通らず
  サイレントに誤る、最悪の失敗様式）。
- `DeleteMember` が beam_groups から当該部材を連動削除し、undo で位置ごと復元
  するように変更（`InsertMember::beam_group_refs`）。
- `Model::validate()` に beam_groups のダングリング検査を追加。
- `Model::eq_ignoring_dofmap` に `secondary_members`・`axes` を追加
  （undo・SCZ 往復テストの検査対象から漏れていた）。
- 回帰テスト 5 件を `squid-n-edit/src/tests.rs` に追加。

### 1.2 整合質量行列の全体系変換漏れ（数値計算の修正）

`ElementBehavior::mass_matrix` の整合質量（Consistent）が要素局所系のまま全体自由度へ
散布されていた。整合質量は軸方向（m/3 系）と曲げ方向（156m/420 系）で係数が異なり
回転不変ではないため、**鉛直柱・斜材で質量が誤った全体軸へ配分**され、固有周期が
部材の向きに依存していた（片持ち梁の検証で水平材と鉛直材の固有周期が約 29% 乖離）。
固有値解析・全時刻歴解析は常に Consistent を使うため影響範囲が広い。

- `BeamElement`／`TrussElement`／`FiberBeam` の Consistent 分岐に
  `M_global = Rᵀ M_local R` の変換を追加（集中質量は並進 3 成分等価の対角行列で
  回転不変のため変換不要）。
- `FiberBeam::mass_matrix` は曲げブロックの DOF 添字も誤っていた（連番書き込みで
  ねじり Rx と連成・節点 j の並進質量欠落）ため、beam と同じインデックス配列方式へ
  修正（現状この実装は線形ファクトリ経由では到達不能だが、誤ったまま残すと危険）。
- トレイト doc に「質量行列は全体系で返す契約」を明記。
- 回帰テスト（水平材と鉛直柱の固有周期一致）を eigen テストへ追加。
- 利用者向け docs（固有値解析）に座標変換の記述を追記。

### 1.3 design-jp の RC/SRC/CFT 重複統合（非保守側の旧仕様残存の修正を含む）

RC 側で修正済みのバグが、コピーされた SRC 側に残っていた。重複の典型的な帰結のため、
修正と同時に単一情報源化した。

- **せん断スパン比 α の退化時規約**: RC の `shear_alpha` は「Q≈0 は下限 1.0
  （割増なし）」へ修正済みだったが、SRC の複製 `shear_alpha_src` は旧仕様の
  「上限 max_alpha（割増を最大化する非保守側）」のままだった。SRC 側の複製を
  削除し `crate::rc::shear_alpha` に統合（**設計結果が保守側へ変わる**）。
  docs（RC 断面検定・SRC/CFT 断面検定）に退化時規約を明記。
- 断面諸元ヘルパ 6 個（`one_bar_area`/`bar_set_area`/`tension_dt`/`pw_ratio`/
  `AxisProps`/`rect_axis_props`）の SRC 側複製を削除し、`crate::rc::section_props`
  へ統合（複製理由だった「rc 側が private」は既に解消済みだった）。
- N-M 相関曲線の補間 `interp_ma`（25 行、バイト単位で同一の複製）を rc 側へ統合。
- `ratio_or_large`（SRC・CFT に同一実装）を `crate::ratio_or_large` へ統合。
- QD 決定分岐（Qd1/Qd2/Min、RC と SRC で同一）を `QdMethod::resolve` へ統合。

### 1.4 GUI の解析結果表示の不整合修正

- `apply_pushover_result`／`apply_time_history_result` が `staleness.last_run` の
  更新のみで `mark_fresh()` を呼ばず、モデル編集後に増分解析・時刻歴だけを実行しても
  「⚠ モデルが編集されています」バナー・時刻歴アニメーション・部材クリックが
  無効のまま復帰しなかった。静的解析と同じく `mark_fresh()` へ統一。
- `apply_static_case_result`／`apply_combo_result`／`apply_static_all_result` が
  `last_static`・`bundle.member_forces` を新結果へ差し替える一方、`current_static` が
  優先する `nav.focus_result` を据え置いていたため、**変位図（旧結果）と応力図・
  断面検定（新結果）が食い違う**表示になっていた。apply 時に `focus_result` も
  新結果へ切り替えるよう修正。
- 回帰テスト 2 件を `squid-n-app/src/app/tests.rs` に追加。

## 2. レビューで確認した残課題（未着手、優先度順）

レビューは 4 領域の並列調査で行い、以下は指摘の要約（file:line は調査時点）。
着手時は現状を再確認すること。

### 2.1 High（誤った結果が正常な結果と区別できない類）

1. **材端集中ばね梁の部材応力が非線形経路で無音欠落**
   `ConcentratedSpringBeam` が `state_member_forces` 未実装（トレイト既定 `None`）。
   線形経路の `ensure_line_member_forces` 相当のガードが非線形経路
   （`timehistory/recording.rs::member_forces_nonlinear`）に無い。
2. **プッシュオーバー非収束のサイレント打ち切り**
   全フェーズが `break` で静かに終了し、`PushoverResult` に終了理由が無い。
   荷重制御が低 λ で非収束の場合、Qu がその時点の最大ベースシアとして
   「正常な結果」の顔で返る（保有水平耐力の過小評価）。終了理由
   （TargetReached/LambdaCap/NonConvergence/TangentSingular）の追加が必要。
3. **`invert_small`（beam/linalg.rs・fiber の複製）が特異時に pivot=1.0 で
   無音に押し通す**。部分ピボッティングも無い。機構化した部材の静縮約で
   もっともらしい剛性が全体 K に混入する。`Option`/`Result` 化と呼び出し側の
   エラー化が必要。
4. **断面/材料未割当チェックが Beam 限定**（`precheck.rs:31-38`）。
   Fiber/Shell 等は `unwrap_or(205000.0)`・`width 100/depth 200` 等の暗黙既定へ
   無音フォールバックする。precheck の対象拡大と暗黙既定の撤去が必要。
5. **ST-Bridge インポートが 1316 行の単一関数**（`import/mod.rs:340-1652`）。
   状態機械の変数表現が実際に状態漏れバグを生んでいる。パーサ構造体化と
   後処理の関数分割が必要（既存の往復テストが安全網になる）。
6. **`squid-n-gpu::PcgGpu::solve` が空行列を解いて誤答を返すスタブ**。
   現状どこからも依存されていないが、`Err` を返すか crate ごと削除すべき。
   `squid-n-ml` は 1 行の空クレートで workspace から外す判断も可。

### 2.2 Medium（構造的な負債・静かな失敗）

- **GUI**: `start_*_job` 7 本のコピペ（前処理・spawn・catch_unwind・ジョブ登録が
  同型）。増分解析・時刻歴・固有値だけ `ensure_preparation()` を通らず、
  仕口パネル生成（`apply_panel_zones_for_analysis`）も省かれるため、解析対象
  モデルが静的解析と食い違う。`spawn_job` への共通化で構造的に解決すべき
  （固有値の UI スレッド同期実行もここで解消）。
- **GUI**: CMQ 図表示中の毎フレーム床格子 FEM 求解（`refresh_beam_loads`）。
  既存の `compute_auto_load_sync_hash` によるキャッシュを適用すべき。
- **GUI**: `App` 構造体 110 フィールド（69 が `cfg(feature="gui")`）。
  `AppCore`/`UiState` の分離と `UiState::reset_for_new_model()`（`load_model` が
  `stick_response`・`time_history_data`・各種 draft を取りこぼす問題の解消）。
- **GUI**: `last_error` の単一スロット共有（荷重組合せ欄に無関係のエラーが出る）、
  読み取り専用テーブルの定型 32 箇所、`tables/*` の行高ハードコード
  （`theme::table_row_height` 未使用の 14 箇所）、enum 表示ラベルの二重定義
  （`LoadCaseKind`・`MemberKind` で訳語が食い違う）。
- **ソルバ**: Newton 反復 4 実装（収束条件・失敗時の扱いが不揃い、50/1e-6 が
  3 箇所にハードコード）、時刻歴セットアップ 4 重複（影響ベクトル構築は
  一字一句同一）、変位展開＋断面力復元 3 重複、`global_dofs` 8 重複、
  部材軸・鉛直判定の 3 規約混在（0.707 vs 0.8/0.2 vs dz>(dx+dy)/2）。
- **ソルバ**: `use_kg`（P-Δ）が線形時刻歴で `let _ = use_kg;` と黙って捨てられる。
  実装するか引数を削除すべき。
- **ソルバ**: `ElemState` が空構造体のまま全 API を貫通（削除で 40 箇所短縮）、
  `StatefulModel` が self 不使用で `&mut Model` を強制、`restore_state` の
  downcast 失敗が全 10 実装で無音、チェックポイントに免震・履歴ダンパーの
  状態が保存されない（レジュームで処女状態にリセット）。
- **要素**: 耐震壁の側柱走査が O(壁数×要素数) かつ非線形要素 1 枚につき
  壁エレメントを 2 回構築（`factory/mod.rs:311-322`）。
- **設計**: 鋼材せん断有効断面積が柱（`shear_area`: `tw·H`）と梁
  （`beam_shear_area`: `tw·(H−2tf)`）で別定義（同一 H 形断面で τ が変わる。
  規準上の意図か不整合か要判断）。`M2/M1` 算定 2 関数の丸写し
  （`steel_lateral_buckling_c`/`steel_p_lambda_b`）。
- **設計**: 鋼材単位重量が 4 表現に散在（`quantity` の 7.85 系 vs core の
  77.0 kN/m³ 由来 7.8518e-9、約 0.02% の系統差）。重力加速度・N/mm²→kgf/cm²
  変換係数も重複。core::units への集約が必要。
- **設計**: `member_rank.rs` の「要・原典照合」の仮値（s_wt_fa=9.0 等）が
  幅厚比表対象外形状のフォールバックとして本番の Ds 決定に効いている。
  原典照合または「未判定」を明示する変更が必要（実務判断を要する）。
- **設計**: M–φ エンジンが section と skeleton に 2 実装（塑性域の集約規則が
  異なり同じ部材で違う骨格が出る。適用範囲の明記が必要）。
- **IO/edit**: Delete/Insert/shift の三点セットが 6 エンティティでコピー
  （約 360 行。1.1 の漏れの根本原因。ジェネリック化で再発防止）。
  `EditCommand::apply` が失敗時 `Noop` を返し `UndoStack::run` が成否を
  区別しない（undo ラベルに "Noop" が出る・redo 履歴が消える）。
- **IO**: `ResultStore`/`ResultWriter` が `Result` を返さず panic
  （MCP のジョブが `Running` のまま永久に終端しない）。`persist_job_outcome` が
  書き込み失敗を握りつぶして `Done` を報告する。
- **IO**: ST-Bridge 往復で壁の未使用断面が 1 枚ずつ増殖、`BOX-HxWxT` の
  ライブラリ名が corner_r を含まず値が化ける、export の断面 id 採番が
  2 箇所で重複計算。
- **math**: `assemble_csc` の `expect("valid triplets")`（診断価値ゼロの panic）。

## 3. 着手順の推奨

1. 2.1-1〜4（無音の誤答系）: 影響が計算結果の信頼性に直結する。
2. GUI の `spawn_job` 共通化: 準備計算の通し忘れを構造的に解決（2.2 先頭）。
3. edit の Delete/Insert/shift ジェネリック化: 1.1 の再発防止。
4. `ResultStore` の Result 化: MCP ジョブの無限待ち解消。
5. 死んだコード削除（2.3): 以降のリファクタ対象面積を先に減らす。
