# 利用者ドキュメントへの実装参照の追記 — 申し送り

作成日: 2026-09-12

対象: `docs/`（mdBook）、`CONTRIBUTING.md`

## 背景と経緯

Squid-n は OSS であり、利用者向けドキュメント（`docs/`）の説明から実装へさかのぼれることが重要です。
しかし docs には「何をするか」の説明だけがあり、どのクレート・モジュール・関数が実装しているかに
触れていない節が多数ありました。計算根拠（`docs/calc_basis/`）には `**実装**` 行の記載が
一部ありましたが、書式（crate 修飾の有無、行番号の有無）も不統一でした。

## 変更内容

- docs 全体の説明節（計算・判定・表示・入出力・編集の仕様を述べている節）に、
  `**実装**：`squid_n_xxx::module::item`（`crates/...`）が…します。` の形式で実装参照を追記。
  目次・章導入・ライセンス・ビルド手順・クライアント設定例・利用者手順の案内は対象外。
- 既存の略記参照を crate 修飾へ統一（例: `section_shape::` → `squid_n_core::section_shape::`、
  `dynamic::` → `squid_n_solver::dynamic::`、`viewer::` → `squid_n_app::viewer::`）。
  行番号（`.rs:123`）・半角コロン（`**実装**:`）・ワイルドカード（`peak_*`）を除去。
- レビューで判明した既存の誤参照を修正。例:
  - スラブ自重の実装を `squid_n_load::self_weight` から `squid_n_core::model::Model::slab_self_weight_intensity` へ
  - `frame::factory` / `common::transform` / `common/behavior.rs` など存在しないパスを実体へ
  - `factory::flexural_alpha_y`・`concrete_class_factor`・`PlaceSupportIsolator` など非公開パスの解決
  - `rc_capacity` は `squid_n_core`、`build_seismic_load_case` は `squid_n_solver` であることを反映
- 本文とコードの不一致を修正（支点記号の描画位置、時刻歴の検定 `checker_for`、立体グリッドの
  トグルの定義位置、`squid-n-app` のようなハイフン crate 表記など）。
- `CONTRIBUTING.md`「ドキュメントサイト（mdBook）」に、節ごとに `**実装**` を記載する規約
  （書式・行番号を書かない・検証方法・重複回避）を追記。

## 今後の判断

- ページ末尾に `## 実装` を持つページ（`01_荷重/08`・`09`、`04_要素剛性/06`、`10_数量積算/01`）は、
  説明のある節に入口を追記する場合とページ末尾へ一本化する場合が混在しています
  （`10_数量積算/01` は一本化）。どちらへ統一するかは別途判断が必要です。
- 参照先には private / `pub(crate)` の項目を含みます。実装を追う目的では問題ありませんが、
  公開 API に限定する方針にする場合は再エクスポートの追加が必要です。
- レビュー中に見つかった実装側のギャップ: 数量積算の間柱は円形断面でも矩形として扱われます
  （`secondary_member_quantity` が `RcRect`/`SrcRect` 以外を幅・せいで処理）。円形柱は
  `compute_quantity_takeoff` が円形式で扱うため、間柱の扱いと不整合です。数量の精度に関する
  別課題として記録します。
