# 非線形時刻歴が地動ゼロ交差で収束しない不具合の修正 申し送り

作成日: 2026-08-11
対象コード: `crates/squid-n-solver/src/common/newton.rs`、
`crates/squid-n-solver/src/dynamic/timehistory/nonlinear.rs`、
`crates/squid-n-solver/src/dynamic/lumped_mass/time_history.rs`

## 1. 症状

実建物モデル（`crates/squid-n-app/tests/fixtures/model.stb`）の非線形時刻歴応答解析が、
既定設定（サンプル波 dt=0.01 s・継続時間 10 s・減衰 2%・Newmark-β・最大反復 50 回・
tol=1e-6）で次のエラーになり完走しなかった。

```text
非線形時刻歴解析エラー: nonlinear time history: step 50 did not converge
```

線形時刻歴は同じモデル・同じ波で完走し、手組みの小規模モデルなら非線形も通る。
統合テスト `time_history_nonlinear_runs` を `#[ignore]` にして残していた。

## 2. 切り分け

全ステップの Newton 反復の残差を記録した。

```text
step=24  r=2.82e-6  |p_dyn|=2.50e6   ratio=1.13e-12  → 1 反復で収束
step=25  r=1.90e-6  |p_dyn|=2.43e-9  ratio=1.90e-6   → 1 回目で落ち、2 回目でぎりぎり収束
step=49  r=1.49e-2  |p_dyn|=2.32e6   ratio=6.44e-9   → 1 反復で収束
step=50  r=1.13e-2  |p_dyn|=4.52e-9  ratio=1.13e-2   → 50 回反復しても収束せず
```

通常のステップは 1 反復で残差が 11 桁落ちて収束している。**落ちるのは入力加速度が
ゼロを横切るステップだけ**である。サンプル波は周期 0.5 s の正弦なので `t = 0.25, 0.50, …`
で 0 になり、dt=0.01 なので step 25 と step 50 がそこに当たる。

その時刻の各項を測ると次のとおり。

```text
step=50  |p_dyn|=4.5e-9  |M·a|=1.56e7  |C·v|=8.9e5  |f_int|=1.56e7
```

**材料の非線形性は無関係**である。このモデルは増分解析でも 1/150 の変形まで弾性で、
時刻歴でも塑性化していない（`du_total` は反復を重ねても一切変化しない＝解は動いていない）。

## 3. 原因

収束判定の基準ノルムに**動的外力 `p_dyn` だけ**を使っていた。

```rust
if cfg.newton.converged(r_norm, p_norm.max(1.0)) { ... }
```

`p_dyn` は外力から長期荷重 `f0` を除いたもので、これは「長期が卓越するモデルで判定が
緩まないように」という意図的な設計だった。ところが地動加速度がゼロを横切ると
`‖p_dyn‖ → 0` となり、基準が床の **1.0（N）** まで落ちる。判定は
「残差 < 1e-6 N」という**絶対値判定**に化ける。

実建物では内力・慣性力が 1e7 N 規模あり、悪条件な有効剛性 `K_eff` の線形解が持つ残差
（概ね `条件数 × ε × 力のスケール`）が 1e-1 N 規模になる。1e-6 N は**原理的に到達
できない閾値**だった。step 25 が通ったのは、その時点では応答が小さく残差もたまたま
小さかったからにすぎない。

残差 1.13e-2 N は実際の力のスケール 1.56e7 N に対して**相対 7e-10**であり、収束している。
判定の物差しだけが壊れていた。

## 4. 修正

基準ノルムを**動的釣り合いの各項のノルムの最大**に改める。

```rust
pub fn dynamic_reference_norm(p: &[f64], m_a: &[f64], c_v: &[f64]) -> f64 {
    let norm = |v: &[f64]| v.iter().map(|x| x * x).sum::<f64>().sqrt();
    norm(p).max(norm(m_a)).max(norm(c_v)).max(1.0)
}
```

地動が 0 でも構造は動いており慣性力・減衰力は大きいので、基準は消えない。長期荷重
`f0` を含めない点は従来どおりなので、当初の意図（長期が卓越するモデルで緩めない）も保つ。
最低値 1.0 は、応答が完全に静止していて 3 項とも 0 のときの 0 除算避けである。

質点系（串団子）時刻歴（`lumped_mass/time_history.rs`）も `1.0 + ‖p‖` という同じ構造
だったため、あわせて同じ関数を使うよう改めた。

## 4.1 敵対的レビューで判明した積み残しと、その根治

上の修正だけでは**問題を解消しきれていなかった**。継続時間を延ばすと同じ破綻が戻る。

| 継続時間 | 非収束ステップ |
|---|---|
| 10 s | 0 / 1001 |
| 60 s | 0 / 6001 |
| 120 s | **202 / 12001** |

末尾を計測すると原因は明らかだった。

```text
step=11999  r=1.02e-4  ref=1.000e0  |p|=6.2e-10  |Ma|=5.8e-4  |Cv|=7.9e-5  |fint|=6.0e-4
```

応答が減衰しきると 3 項すべてが 1 N を下回り、また床の 1.0 まで落ちる。**床の値 1.0 N が
モデルの力のスケールと無関係**という根本を残したままだったため、失敗の発生時刻を
t=0.5 s から t>60 s へ動かしただけだった。しかも「参考値として続行」に変えた後なので、
物理的に無意味な領域（力が 1e-4 N）に対する**偽の警告**として出る。前より悪い出方をする。

そこで、解析中に観測した力のスケールの最大値に対する下限を設けた。

```rust
const DECAYED_SCALE_FLOOR_RATIO: f64 = 1.0e-2;

pub fn dynamic_reference_norm(scale: f64, peak_scale: f64) -> f64 {
    scale.max(peak_scale * DECAYED_SCALE_FLOOR_RATIO).max(1.0)
}
```

比率 1% の根拠は実測である。最大 6.1e7 N の解析の末尾で、力が 6e-4 N まで落ちたところ
履歴則が微小振幅でチャタリングし、残差が 1e-4 N から下がらなくなった。これを収束と
認めるには `tol × 下限 > 1e-4` すなわち下限 > 1.6e2 が要り、
`6.1e7 × 1e-2 = 6.1e5` で十分な余裕がある。応答が大きい時刻は瞬間値のほうが
大きいので下限は効かない。

修正後は 300 秒でも非収束 0 件になった。10 秒の結果（最大変位 57.794 mm）は変わらない。

なお、この積み残しは**修正した本人が「押し出しただけではないか」と疑って継続時間を
延ばして試す**まで表に出なかった。既定の 10 秒では通ってしまうため、統合テストにも
現れない。実地震波は 30〜120 秒で静かな末尾を持つのが普通なので、既定以外の設定で
日常的に偽警告が出るところだった。

## 5. 検討して採らなかった案

- **ステップの自動細分**: 効かない。Newton は 1 反復で収束しており `du_total` も動いて
  いないので、刻みを細かくして解決する状況ではない。刻みを半分にしても正弦波の
  `t = 0.5` はサンプル点に残るので同じゼロ交差に当たる。そもそも「基準が 0 になる」
  ことが原因なので刻みを変えても基準は 0 のまま
- **ステップ初回残差 `r0` を基準にする**: 自己スケーリングで定番だが、初回残差が小さい
  ステップでは逆に判定が厳しくなりすぎる
- **絶対床 1.0 N をモデル規模に応じて引き上げる**: 値の根拠を説明できない

## 6. テストの構成と、再現できなかったこと

**ソルバー層の end-to-end テストではこの不具合を再現できなかった。**
`test_nonlinear_time_history_converges_when_ground_accel_is_zero`（自由振動区間を含む
SDOF）は修正前でも通る。残差の主因は丸め誤差ではなく**悪条件な `K_eff` の線形解の残差**
であり、1 自由度の良条件モデルでは残差が 1e-6 N を大きく下回るためである。再現には
多自由度の実規模モデルが要る。

そのため回帰ガードは次の 2 段構えとした。

- **判定そのものの単体テスト**（`common/newton.rs`）: 外力が 0 でも慣性力を基準に採ること、
  3 項の最大を採ること、静止時に床の 1.0 を返すこと
- **実建物での統合テスト**（`squid-n-app` の `time_history_nonlinear_runs`）: `#[ignore]` を
  解除した。スナップショットへ非線形時刻歴の代表値（`th_nl.*`）も追加した

SDOF のテストは「自由振動区間を含む解析が完走する」という API レベルの確認として残す。
不具合の再現テストではないことをテストのドキュメントコメントに明記してある。

## 7. 結果

| 項目 | 値 |
|------|-----|
| 非線形時刻歴 | 完走（1001 フレーム） |
| 最大水平変位 | 57.79 mm（線形 59.46 mm） |
| 層間変形角 | 4.454e-3 / 4.849e-3 / 3.150e-3 / 1.925e-3 |

線形とほぼ同じ応答で、弾性に留まるモデルとして妥当である。線形時刻歴の結果は変わらない
（線形経路は Newton 反復を使わない）。

## 8. 非収束時の扱いを質点系へ揃えた

反復が上限に達したときの扱いが 2 経路で食い違っていた。立体モデル（`nonlinear.rs`）は
`Err` で解析全体を止め、質点系（`lumped_mass`）はその時点の試行状態で確定して続行し
非収束ステップ数を警告表示していた。利用者から見ると「途中まで解けた結果を捨てるか、
参考値として見せるか」の違いになる。

**参考値として見せる側（質点系）へ揃えた。**立体モデルも不収束ステップを確定して続行し、
`ResponseResult::non_converged_steps` を返す。結果タブ「時刻歴」の先頭に、質点系と同じ
文言で注記を出す。

ただし**発散（変位が有限値でない）した場合だけは打ち切る**。以降のステップも結果も
すべて NaN に汚染され、参考値にすらならないためである。この場合はステップ開始状態へ
戻してから `Err` を返し、時間刻み・減衰・復元力特性の見直しを促すメッセージにした。

既存テスト `test_nonlinear_time_history_convergence` は旧挙動（`Err` になること）を
明示的に固定していたため、新しい契約（完走し非収束ステップ数が立つ）へ更新した。

## 9. 残課題

- 刻みの自動細分は、塑性化が急に進むモデルでは有用な機能でありうる。今回の不具合とは
  無関係なので入れていない
