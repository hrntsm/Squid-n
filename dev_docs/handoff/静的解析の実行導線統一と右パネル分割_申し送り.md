# 静的解析の実行導線統一（単体実行／一括解析）と右パネルの分割

作成日: 2026-07-30
対象ブランチ: `claude/analysis-settings-panel-refactor-dj86ny`
関連文書: `解析設定パネルのフロー整理_申し送り.md`、`準備計算_申し送り.md`、`../specs/UI設計.md`

## 1. 背景（変更前の問題）

### 1.1 荷重ケースと荷重組合せで実行導線が分かれていた

解析パネルには「荷重ケース（静的）」と「荷重組合せ」の 2 セクションがあり、
それぞれに独立した「▶ 実行」があった。加えて組合せ側には「▶▶ 全組合せ一括解析」があり、
静的解析の実行導線は合計 3 つだった。

一方で内部の解き方も分かれていた。荷重ケースは `Analysis::linear_static`、荷重組合せは
`Analysis::linear_combination` が**組合せ係数で重み付けした荷重ベクトル \\( F = \sum c_i F_i \\)
を組み立てて解き直す**実装で、同じ荷重ケースを参照する組合せが n 件あれば n 回求解していた。
線形解析では重ね合わせの原理が成り立つため、この求解は本来不要である。

### 1.2 右パネル「解析設定」の情報量が過大だった

1 枚のパネルに「① 準備計算」（実行・ステータス・地震力の条件・風圧力の条件・計算条件・
階の定義）と「② 解析」（荷重ケース・荷重組合せ・固有値・増分解析・時刻歴応答）を縦に積んで
いたため、スクロール量が大きく、いま一貫計算のどの段階にいるのかが読み取りにくかった。

## 2. 変更後の構成

```
右ドック（パネル切替: 🔍 インスペクタ / 🛠 ① 準備計算 / ⚙ ② 解析）

① 準備計算                              ② 解析
  [① 準備計算][② 解析]  ←切替行           [① 準備計算][② 解析]  ←切替行
  [🛠 準備計算 実行][📋 結果を表示]         最終実行 / 結果の陳腐化表示
  ステータス                              ▸ 静的解析
  ▸ 地震力の条件 (Ai 分布)                    対象: [荷重ケース＋荷重組合せの一覧]
  ▸ 風圧力の条件                              [▶ 単体実行]
  ▸ 計算条件                                  [▶▶ 一括解析]
  ▸ 階の定義                               ▸ 固有値
                                          ▸ 増分解析
                                          ▸ 時刻歴応答
```

静的解析の実行導線は **単体実行**（選択した 1 件）と **一括解析**（全荷重ケース＋
全荷重組合せ）の 2 つになった。「対象」ドロップダウンは荷重ケースと荷重組合せを
見出しで区切った 1 つの一覧で並べる。

## 3. 実装した変更

### 3.1 荷重組合せを荷重ケース単体結果の線形和で求める（squid-n-solver）

- `linear::superpose_static(terms: &[(&StaticOnce, f64)]) -> StaticOnce` を新設。
  節点変位と部材断面力（評価断面ごとの 6 成分）を係数倍して足し合わせる。
  評価断面位置 `xi` は先頭の項の値を採る。
- `analysis/combination.rs` を新設し、荷重組合せ関連を `analysis/mod.rs` から分離した。
  - `Analysis::linear_combination`: 参照する荷重ケースを重複なく `linear_static_batch` で
    解き、`superpose_static` で線形和する（荷重ベクトルの合成・再求解を廃止）。
  - `Analysis::linear_combination_batch`: 組合せ群が参照する荷重ケースの**和集合**を
    1 回ずつ解いてから各組合せを組み立てる。従来は組合せ単位に並列求解していたため、
    同じ荷重ケースを参照する組合せの数だけ重複求解していた。
  - `Analysis::linear_static_with_combinations(lcs, combos) -> StaticBatch`: 一括解析の入口。
    荷重ケース単体の結果と組合せの結果を両方返す。
- `scale_member_load`（組合せ用に部材荷重を係数倍するヘルパ）は不要になったため削除した。
  部材中間荷重によるスパン内力は各荷重ケースの結果に含まれており、結果ごと係数倍される。
- 参照する荷重ケースが存在しない、またはその荷重ケースの解析が失敗した組合せは
  `Err` にする。従来は存在しない荷重ケース ID を参照すると `assemble_global_f` が
  零ベクトルを返し、その項が黙って 0 になっていた。
- 項を持たない組合せ（縮退ケース）は、解けている荷重ケースの結果を 0 倍して零結果を作る
  （節点数・評価断面の構成を保つため。`zero_result` は `member_forces` が空になる）。

数値的には、荷重ベクトルを合成して 1 回解く従来方式と理論上一致する
（線形解析のため）。浮動小数点演算の順序が変わるため、ビット単位では従来結果と
一致しない場合がある。

### 3.2 静的解析の実行導線を 2 つに統一（squid-n-app）

- `StaticTarget { Case(LoadCaseId), Combo(usize) }` を新設（単体実行の対象）。
  `App::analysis_target: Option<StaticTarget>` が選択状態を持つ（旧 `analysis_combo_idx` を置換）。
- `App::{start_static_target_job, run_static_target}`（単体実行）が
  `start_load_case_job` / `start_combination_job` へ振り分ける。標準の水平力ケース
  （EX/EY・WX/WY）を方向別の結果キーへ振り分ける既存の規約は変更していない。
- `App::{run_all_combinations, start_all_combinations_job}` を
  `App::{run_static_all, start_static_all_job}` へ置換した。全荷重ケースを単体で解き
  （`linear_static_with_combinations`）、全荷重組合せをその線形和で求める。
  結果は荷重ケースが `bundle.statics`、組合せが `bundle.combos` へ入る。
  - 表示対象（`last_static`）は最後に成功した荷重組合せ、組合せがなければ最後に成功した
    荷重ケース。長期／短期区分は表示対象が組合せのときのみ組合せ名から再判定する。
  - 一括解析でも EX/EY・WX/WY は方向別キー（`StaticCaseKey::Seismic`/`Wind`）へ格納される
    ため、剛心の精算・保有水平耐力の判定が参照する結果が 1 回の一括解析で揃う。
  - **空の水平力ケース**（種別が地震・風なのに荷重が空）は解析対象から外し、エラー一覧へ回す
    （判定は `is_empty_lateral_case` に集約し、組合せ側のガード
    `empty_lateral_case_in_combo` と共用）。零の水平力を方向別キーへ格納すると、
    剛心の精算・保有水平耐力の判定がそれを正しい地震時応力として扱ってしまうため。
  - エラー時に既存結果を壊さないよう、`self.results.take()` した bundle を
    「1 件も解けなかった」経路で戻すようにした（旧 `apply_all_combinations_result` は
    「結果を壊さない」とコメントしながら take したまま return しており、
    直前の解析結果が失われていた）。
- `JobResult::AllCombos` を `JobResult::StaticAll { computed: Result<StaticAllComputed, _>, pre_errors }`
  へ置換（`StaticAllComputed` は荷重ケース結果と組合せ結果の両方を運ぶ）。
  ジョブラベルは「全組合せ一括解析」→「一括解析」。
- 実行対象の解決順（`resolved_analysis_target`）は
  「選択中の対象（モデル編集で失効していないもの）→ ナビゲータ／荷重表で選択中の荷重ケース →
  荷重ケースの先頭」。荷重ケースを選ぶと `nav.focus_load_case` にも反映し、
  従来の選択連動を保つ。

### 3.3 右パネルを ①/② の 2 枚に分割（squid-n-app）

- `RightPanel::AnalysisSettings` を `RightPanel::{Preparation, Analysis}` へ分割。
  描画は `App::analysis_settings_panel` → `App::{preparation_panel, analysis_panel}`。
- ステータスバー右端のアイコンは 🔍 インスペクタ・🛠 ① 準備計算・⚙ ② 解析の 3 つ。
  下ドックの 🛠（準備計算の**結果**タブ）と紛れないよう、hover を
  「準備計算の結果」／「① 準備計算（解析条件の入力・実行）」に書き分けた。
- 両パネルの先頭に「① 準備計算 / ② 解析」の切替行（`right_panel_switcher`）を置き、
  ステータスバーを経由せずに手順どおり行き来できるようにした。
- 工程タブ「解析」のドック配置プリセット（`apply_tab_preset`）は ① 準備計算を開く。
- 「最終実行／結果は再計算が必要」の表示は ② 解析へ移した（解析結果の陳腐化の話であるため）。
  ② には準備計算が古い場合の注意表示も置き、解析実行時に自動最新化される旨を添えた。

## 4. 影響と非互換

- **公開 API の削除・改名**（いずれも `squid-n-app` 内と GUI からのみ使われていた）:
  - `App::{run_all_combinations, start_all_combinations_job}` → `App::{run_static_all, start_static_all_job}`
    （意味も変わり、荷重ケース単体の解析も行う）
  - `JobResult::AllCombos` → `JobResult::StaticAll`
  - `RightPanel::AnalysisSettings` → `RightPanel::{Preparation, Analysis}`
  - `App::analysis_combo_idx` → `App::analysis_target`
  - `squid_n_solver::analysis` に `StaticBatch` を追加（`linear_combination` /
    `linear_combination_batch` のシグネチャは変更なし）。
- **一括解析のエラー条件が変わった**: 従来は荷重組合せが 0 件でエラーだったが、
  現在は荷重ケースが 0 件でエラー。組合せがなくても荷重ケース単体の解析は行う。
- **結果のビット一致**: 荷重組合せの結果は線形和で組み立てるため、従来（合成荷重を解く方式）と
  ビット単位では一致しない場合がある（値としては丸め誤差程度）。
- プロジェクトファイル（.scz）のスキーマは変更していない。

## 5. 残課題

- 単体実行で荷重組合せを選ぶと、その組合せが参照する荷重ケースを解くが、その**単体結果は
  保存していない**（`bundle.statics` へ入れていない）。組合せを続けて実行するときに
  同じ荷重ケースを解き直すことになる。荷重ケース結果のキャッシュを持てば省ける。
- 一括解析は「モデルの全荷重ケース」を対象にする。使っていない荷重ケースが多いモデルでは
  無駄が出るため、対象の絞り込み（組合せから参照されているものだけ、など）は検討の余地がある。
- `Analysis::linear_combination`（単発）は毎回 `linear_static_batch` を呼ぶため、
  参照ケース数が少ないと `run_batch` のスレッド配分（faer の並列度切替）のオーバーヘッドが
  相対的に大きい。単発経路では逐次に落とす最適化が可能。
