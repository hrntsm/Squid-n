# モデル化確認の3Dビュー 申し送り

作成日: 2026-07-25
対象コード: `crates/squid-n-app/src/viewer/modeling.rs`（新規）、
`viewer/mod.rs`、`crates/squid-n-app/src/app/mod.rs`、`docs/result_view.md`、
`crates/squid-n-element/src/wall/misc_wall.rs`（`wall_is_seismic` 公開）

## 1. 何を実装したか

3D ビューアの表示モードに「モデル化」を追加した（`ViewMode::Modeling`）。
各部材が**解析上どの要素モデルで扱われるか**を色と記号で可視化し、意図どおりの
モデル化になっているかを視覚的に確認できるようにした。ツールバーで解析種別
（静解析＝弾性／増分解析＝弾塑性、`ModelingAnalysis`）を切り替えると、同じ形状の
モデルでも部材の分類がどう変わるかを見比べられる。表示仕様は利用者向け
`docs/result_view.md`「モデル化の表示」節を参照。

背景（要望）:
- 静解析は断面の降伏を考えないため、部材は原則すべて弾性でモデル化されるはず。
- 増分解析は降伏を考慮するため、軸力変動する部材はファイバー要素、剛床上で軸力
  変動が小さい梁は材端集中塑性で十分なはず。
- 耐震壁の側柱が面内両端ピンになっているかなど、複数の確認事項を視覚的に検証
  したい。

### 高度化（第2版）で追加した表示

形状だけでは分からないモデル化の要素を、その設定位置に応じて描くよう拡張した。

- **剛域**: `ElementData::rigid_zone.length_i/j` の区間を材端の太い暗色バーで描き、
  部材色の基準線は可とう区間に描く。
- **材端塑性ヒンジ（●）**: 材端集中塑性の剛接端（剛域があればそのフェイス）に
  塗り円を描く。ピン・半剛端には描かない。
- **ファイバー塑性化域**: `plastic_zone`（Lp）指定時は端部 Lp 区間をファイバー色の
  太線で強調し中央を弾性（グレー基準線）で描く。未指定は可とう長全体を分布塑性。
- **壁エレメントの「エ」状表示**: 耐震壁は壁エレメント置換モデル（壁柱＝中央鉛直材、
  上下剛梁＝暗色太線、四隅＝ピン○）で描く。`wall_panel_geometry` から幾何を取得する。
- **雑壁の区別**: 耐震壁不成立（`wall_is_seismic == false`）の壁は `WallMisc` として
  破線輪郭の半透明ポリゴンで描き、周辺部材へ剛性算入されることを示す。
- **パネルゾーン**: `ElementKind::PanelZone` を接合部中心のひし形＋接続線で描く。

このため `squid_n_element::wall::misc_wall::wall_is_seismic` を `pub(crate)` から
`pub` へ変更した（ビューが耐震壁成立を判定するため。ロジックは変更なし）。

## 2. 設計判断

### 2.1 分類は要素生成と同じ判定関数へ委譲

`modeling::classify` は独自の判定を持たず、要素生成
（`squid_n_element::factory::build_behavior` / `build_nonlinear_behavior`）が使う
`resolve_force_regime`（フォースレジーム判定）と `wall_side_column_release`
（側柱判定）へそのまま委譲する。これにより「ビューの色」と「実際に解析へ渡る要素
種別」が原理的に一致し、分類ロジックの二重管理を避けた。

- 静解析（`ModelingAnalysis::Static`）: 梁は側柱を除き常に弾性
  （`build_behavior` が集中ばね／ファイバーいずれの regime でも弾性 `BeamElement`
  ベースで組むため）。
- 増分解析（`ModelingAnalysis::Incremental`）: 梁は `resolve_force_regime` で
  `ConcentratedSpring`→材端集中塑性、`Fiber`→ファイバーへ振り分ける
  （`build_nonlinear_behavior` と同じ）。
- 側柱（`wall_side_column_release` が `Some`）は解析種別に依らず側柱ピンとして
  扱う（トポロジ由来の面内解放のため。両パスとも `InPlaneReleasedColumn`）。

### 2.2 分類 `ModelClass` は描画から独立した純粋関数でテスト

`classify(data, model, analysis) -> ModelClass` を `egui::Painter` に依存しない
純粋関数として切り出し、静解析＝弾性／増分解析の regime 別振り分け／要素種別
（壁・ブレース・その他）／マルチスプリングの解析種別別分類をユニットテストした
（`viewer/modeling.rs` の `tests`）。既存の `check_ratio.rs` / `diagram.rs` が集計・
配色ロジックを描画から切り離してテストしている方針に倣っている。側柱ピンの検出
自体は `squid-n-element` 側（`wall/side_column`）で既にテスト済みのため、本ビュー側
では regime・種別マトリクスの網羅に絞った。

### 2.3 描画は既存モードの上へ重ねるオーバーレイ方式

`check_ratio::draw_check_ratio` と同様に、基本形状（節点・部材線・壁ポリゴン）を
描いた後で `modeling::draw_modeling` が分類色の線・壁ポリゴンと端部記号を上へ
重ねる。`viewer_panel` の共通投影・カメラ・ピック処理をそのまま流用でき、変位
（`disp`）は `Modeling` モードでは常に `None`（形状ベースの確認ビューのため変形は
扱わない）。

### 2.4 端部接合条件の記号

線材の端部に接合条件を記号で重ねる。○＝ピン（`EndCondition::Pinned`）、□＝半剛
（`EndCondition::SemiRigid`）。側柱は面内両端ピンのため両端に○を描く。記号は
節点から材軸方向へ 9px 内側に置いた白抜き（背景色塗り＋色付き輪郭）で、ピンの
慣用記号に合わせた。

### 2.5 凡例の配置

モデル化凡例はビュー**左上**に置く。支持条件凡例が左下を使うため衝突を避けた。
凡例にはモデルに実際に現れた分類のみを出現順で載せ、○/□の記号凡例は該当する
端条件が存在するときだけ表示する。

## 3. 色・記号規約

| 分類 | 色 | 意味 |
| --- | --- | --- |
| 弾性材 | グレー | 断面の降伏を考えない弾性材 |
| 材端集中塑性 | 緑 | 材端回転ばね。剛床上で軸力変動が小さい梁 |
| ファイバー(分布塑性) | オレンジ | 軸-曲げ連成の分布塑性。軸力変動する柱など |
| 側柱(面内両端ピン) | 紫 | 耐震壁の側柱。面内のみ両端ピン |
| 壁エレメント | 青 | 壁エレメント置換モデル（「エ」状。増分でせん断降伏考慮） |
| 雑壁 | 暖色 | 耐震壁不成立。周辺部材へ剛性算入（破線ポリゴン） |
| パネルゾーン | 藍 | 柱梁接合部パネル（中心にひし形） |
| トラス/軸材 | ティール | 軸剛性のみのブレースなど |
| その他 | 淡いグレー | バネ・免震・ダンパー・シェル |

- ○ 端部ピン（`Pinned`）／□ 端部半剛（`SemiRigid`）／● 材端塑性ヒンジ（材端集中塑性）。
- 剛域＝材端の暗色太バー／ファイバー塑性化域 Lp＝端部のファイバー色太線。

## 4. 既知の制約・残課題

- **`ElementKind` の分類粒度**: マルチスプリング梁（`MultiSpring`）は静解析で
  弾性・増分解析で材端集中塑性としているが、要素実体は常に端部軸ばね群を持つ。
  一般的な架構では `MultiSpring` 種別を明示指定する場面は稀なため簡便化した。厳密な
  区別が必要になれば分類を追加する。
- **ファイバーと材端集中塑性の実装現状**: `build_nonlinear_behavior` の
  `ConcentratedSpring` 経路は端バネ骨格が必要で、Model への降伏応力供給が未整備の
  範囲では実挙動がファイバーへフォールバックする場合がある（`factory/mod.rs` の
  注記参照）。本ビューは**モデル化の意図（regime 判定の結果）**を示すものであり、
  当該フォールバックが解消されれば表示と実挙動が完全一致する。
- **二次部材（小梁・間柱）**: 解析対象外のため本ビューの分類対象に含めず、従来モード
  と同じ暖色で描く（`show_floor_secondary` トグルに従う）。
- **剛域の表示は保持値ベース**: 剛域長は `app.model` に保持された値を描く。自動剛域は
  解析実行時に `apply_auto_rigid_zones` で `app.model` へ反映されるため、解析前は
  0（未表示）、手動指定はそのまま表示される。描画のためにモデルを毎フレーム変更する
  副作用は持たせていない。
- **壁エレメントの幾何**: 「エ」状表示は `wall_panel_geometry`（4 節点・下辺/上辺の
  対応付け）に依存する。4 節点未満や退化幾何ではポリゴンへフォールバックする。
