# 時刻歴応答解析: 詳細記録（ThRecording）と長期荷重初期化 — 申し送り

## 実装範囲

`crates/squid-n-solver/src/dynamic/timehistory/` を対象に、以下を実装した。

1. **詳細記録 `ThRecording`**（`result.rs`）を新設し、線形（Newmark-β、`linear.rs`）・
   線形（HHT-α、`hht.rs`）・非線形（`nonlinear.rs`）の 3 経路すべてで記録するようにした。
   - `ResponseResult::recording: Option<ThRecording>` を `#[serde(default)]` で追加（.scz 後方互換）。
   - 記録の組立ロジックは新モジュール `recording.rs`（`ThRecorder`）に集約し、3 経路で共有している。
2. **非線形時刻歴の長期荷重初期化**（`nonlinear.rs`）。
   - `NonlinearThCfg { max_iter, tol, use_kg, apply_long_term, record_every }` を新設し、
     `nonlinear_time_history_analysis` の末尾引数（旧: `use_kg, max_iter, tol` の 3 引数）を
     このフィールドを持つ 1 構造体に置き換えた（破壊的変更。呼び出し元は本モジュールの
     `tests.rs` のみ）。
   - `apply_long_term=true`（既定）で、プッシュオーバーの長期載荷フェーズ（`pushover::driver.rs`）
     と同じ経路・同じ漸増規約（5 分割＋収束失敗時の増分半減）で長期荷重を静的 Newton 反復で
     載荷し、要素状態を commit してから時刻歴を開始する。長期荷重ベクトル `f0` は時刻歴を
     通じて一定の外力として毎ステップ加算する（プッシュオーバーの `f0+λ·q` と同じ扱い）。
   - `initial_disp`/`initial_vel` は「長期解からの増分」として扱う。時刻歴の初期変位 `u0` は
     長期解の変位＋`initial_disp` であり、以降の応答（`peak_disp`・`recording` の全量）は
     この全変位を含む。
3. **バグ修正**: 非線形時刻歴の初期剛性組立（Rayleigh/初期剛性比例減衰の参照剛性）が
   `use_kg` を無視していた（`let _ = use_kg;`）。`crate::pushover::assemble_k`
   （Newton 反復内で使う関数と同一）に置き換え、`use_kg` を反映するようにした。
   あわせて、この初期剛性の組立を長期荷重載荷**後**（かつ動的初期変位 `initial_disp`
   反映**前**）に行うよう順序を変更した。減衰行列の参照剛性は「長期荷重下の構造」を
   基準とするのが物理的に妥当なため。

## `ThRecording` の最終形と設計判断

```rust
pub struct ThRecording {
    pub record_every: usize,
    pub frame_time: Vec<f64>,
    pub node_disp: Vec<Vec<[f64; 6]>>,      // [frame][node_idx]
    pub story_x: StoryResponse,
    pub story_y: StoryResponse,
    pub member_forces: Vec<Vec<Option<squid_n_element::beam::MemberForces>>>, // [frame][elem_idx]
    pub peak_member_forces: Vec<Option<squid_n_element::beam::MemberForces>>, // [elem_idx]
}

pub struct StoryResponse {
    pub stories: Vec<squid_n_core::ids::StoryId>,
    pub story_weight: Vec<f64>,
    pub story_shear: Vec<Vec<f64>>,   // [frame][story]
    pub floor_accel: Vec<Vec<f64>>,
    pub floor_vel: Vec<Vec<f64>>,
    pub floor_disp: Vec<Vec<f64>>,
    pub peak_shear_coeff: Vec<f64>,
}
```

- **方向の扱い**: 加振方向（X/Y）を自動選択せず、`story_x`/`story_y` として**常に両方向**を
  記録する設計にした（`ResponseHistory` の記録方向自動選択とは独立）。UI が方向別に
  階応答グラフを描けるようにするための判断。加振されていない方向（例: `accel_y` 未入力）
  でも、その方向の自由度に生じる応答（ねじれ・偏心による連成等）をそのまま記録する。
- **階の並び**: `model.stories` と同じ並び（下層→上層）をそのまま採用した。既存の
  `update_story_drift`/`pushover::response::compute_story_shear` も同じ前提（`model.stories`
  は既に下→上に整列済み）に依っており、独自の再整列はしていない。
- **階の重量 `story_weight`**: `Story::seismic_weight`（設計用地震用重量）をそのまま使う。
  慣性力ベースの層せん断力係数 `Ci = max|Qi| / Σ(j≧i) Wj` の分母に使う値として、
  プッシュオーバー等の他解析と定義を揃えるため。ノード質量から再計算する方式は採らなかった。
- **階の応答（floor_accel/vel/disp）**: 階に属する節点（`Story::node_ids`）の質量加重平均
  （`Node::mass` の当該方向成分を重みとする）。質量が全節点ゼロの階は単純平均にフォールバック。
- **層せん断力**: 慣性力ベース（内力ベースの `pushover::compute_story_shear` とは別実装）。
  `Σ_(dof∈階) M·r[dof]·(相対加速度+地動加速度)` の符号反転で、既存 `history::record_history_step`
  のベースシア算定の層別版になっている（1 層のみのモデルでは両者が厳密に一致することを
  テストで確認済み、`test_story_shear_matches_base_shear`）。
- **記録の間引き**: `record_every` ステップごとに 1 フレーム。既定は自動決定
  （`(n_steps/1000).max(1)`、`recording.rs::auto_record_every`）。線形（Newmark-β）・
  HHT-α の 2 経路は間引き量を指定する公開 API を追加しておらず、常に自動決定のみを使う
  （呼び出し元を増やさないための判断）。非線形経路のみ `NonlinearThCfg::record_every` で
  明示指定できる。**UI 側で間引き量を選ばせたい場合は、線形/HHT-α にも同様のオプション
  引数を追加する必要がある**（既存呼び出し元は `statics::analysis::Model::time_history`/
  `time_history_hht`（`statics/analysis/mod.rs`）の 2 箇所のみで、影響範囲は小さい）。
- **`peak_disp`・`peak_member_forces`・`peak_shear_coeff`**: 全ステップで更新し、間引かない
  （メモリを圧迫する時系列本体だけを間引く方針）。
- **部材内力 `member_forces`**: 線形経路は `ElementBehavior::recover_forces`（弾性 behavior を
  ループ前に 1 回構築し使い回す）、非線形経路は `ElementBehavior::state_member_forces`
  （現在の committed 状態から復元）。内力分布を持たない要素は `None`。

## 追記4: コードレビュー指摘対応（ソルバ数値部分）

コードレビューで確定した以下の指摘を修正した。対象は `crates/squid-n-solver/**`・
`crates/squid-n-element/src/springs/damper/maxwell.rs`。

### 高-1: 非線形時刻歴で支点ばね内力が残差に入らない（修正）

`nonlinear.rs` の残差計算 3 箇所（初期加速度・Newton ループ・長期荷重
`newton_static_converge`）で `compute_f_int`（要素の内力のみ）を使っており、
支点ばね（`Node::support_spring`）の内力寄与 `k_i・u_i` が残差に反映されていなかった。
プッシュオーバー（`nonlinear::pushover::driver.rs`）は `add_support_spring_f_int` で
別途加算していたが、時刻歴側は未対応だった。

- `nonlinear::pushover::assembly::add_support_spring_f_int` を
  `nonlinear::pushover::mod.rs` から `pub(crate) use` で再エクスポートし
  （従来は `assemble_k`・`compute_f_int` のみ再エクスポート）、`timehistory::nonlinear`
  から `crate::pushover::add_support_spring_f_int` として参照できるようにした。
- 3 箇所すべてで、`compute_f_int` の結果に対し「縮約前の全体試行変位」
  （`reducer.expand_u(...)`）を渡して `add_support_spring_f_int` を追加適用する形に統一した
  （プッシュオーバー `driver.rs` の `newton_converge` と同じ経路）。
- `newton_static_converge` は「呼び出し開始時点の全体変位（縮約空間）」
  `u_base_red: &[f64]` を新規引数に追加し、`u_base_red + du_total`（ステップ内累積修正量）を
  展開して支点ばね内力の評価に用いる。
- **影響**: 支点ばねのみで支持される部材（要素の剛性を持たない、または支点ばね依存度が
  高いモデル）で、非線形時刻歴の長期荷重初期化・Newton 反復が原理的に収束しなかった
  （要素が無い/少ないモデルでは `f_int` が常に一定になり、残差が外力そのままで不変になるため）。
  一般の（要素剛性が主体の）モデルでは、支点ばねの剛性は元々 `assemble_k`（接線剛性）には
  正しく含まれていたため、収束はするが不要な反復や、支点ばねに変位が生じても内力に反映
  されない誤差が生じ得た。
- テスト: `crates/squid-n-solver/src/dynamic/timehistory/tests.rs` に
  `test_support_spring_long_term_static_matches_analytical`（支点ばねのみの SDOF で
  長期荷重の静的解が `u=F/k` と一致）・`test_support_spring_free_vibration_matches_linear`
  （同モデルの自由振動応答が線形時刻歴と一致）を追加。

### 高-2: 層せん断力の地動項 xg が回転連成成分に乗算される（修正）

`recording.rs::compute_story_dir` が、階に属する節点の**全 6 自由度**について
`m_r[dof]・(a_free[dof]+xg)` を集計していた。一貫質量行列では `M·r` が回転自由度にも
非零成分を持つため、回転自由度の相対加速度に地動加速度 `xg`（本来は並進量）を直接加算する
という次元的に誤った演算を行っていた。

- **修正後の定義**: 毎ステップ 1 回、`common::mass_accel_free`（新設）で
  疎行列ベクトル積 `ma_free = M・a_free`（自由 DOF 空間、方向に依存しない）を計算し、
  方向別に `f_abs_d[dof] = ma_free[dof] + xg_d・m_r_d[dof]` を作る。層集計は
  **当該方向の並進自由度のみ**（`StoryDofGroup::force` を全 6DOF 収集から並進 DOF のみに戻した）。
  一貫質量の並進-回転連成は `M・a_free` という正しい行列ベクトル積の中に既に反映されるため、
  回転 DOF 自体を集計に含める必要が無い。
- **無所属節点の再配分**: どの階にも属さない節点（基礎レベルの自由節点等）の並進 DOF は、
  従来「最下層固定」だったのを、Z 座標が最も近い階（階の代表 Z＝所属節点の平均 Z）へ
  計上するよう改善した（階が無ければ従来通り何もしない）。
- **`history.rs::record_history_step` も同じ定義に統一**: ベースシアは
  `−Σ_{当該方向の並進DOF} f_abs_d` として、`ma_free`（呼び出し側で 1 回だけ計算し共有）を
  受け取る形に変更した。従来の実装（`Σ_dof m_r[dof]・a_free[dof]` を全 DOF で集計）は、
  対称性より**総和としては**数学的に同じ値を与えていたため、**ベースシアの数値そのものは
  変わらない**（既存テスト `test_story_shear_matches_base_shear`・app 側
  `test_story_shear_layer0_matches_history_base_shear` は変更なしで通過）。変わるのは
  **階別の内訳**（`StoryResponse::story_shear` の各階の値）で、回転連成の誤混入が無くなった
  ぶん、一貫質量モデルの上層階の値が変化し得る（物理的に正しい方に修正）。
- `ThRecorder::record_step`・`ThRecorder::compute_story_dir` は `ma_free: &[f64]` を
  引数に追加。呼び出し元（`linear.rs`/`hht.rs`/`nonlinear.rs`）は各ステップ 1 回
  `common::mass_accel_free(&m_free, reducer, &a)` を計算し、`record_history_step`・
  `recorder.record_step` の両方へ共有する（線形経路は `run_steps`/`run_steps_hht` に
  `m_free: &SparseColMat<usize,f64>` 引数を追加）。

### 中-1: 長期漸増載荷の早期終了（修正）

`apply_long_term_static` は、5 分割の固定スケジュール（20%,40%,...,100%）で、
各ステップ内の増分半減リトライが縮小した載荷率で成功した場合、**そのステップの残増分を
再挑戦せず**次の固定スケジュール値へ進んでいた。最終ステップ（目標 100%）でこれが起きると、
100% 未満の載荷率のまま `Ok(())` を返し、長期荷重が完全には載荷されないまま時刻歴を開始する
不具合があった。

- 載荷率追跡ロジックを `LoadFractionState`（`nonlinear.rs`、FEM に依存しない純粋な状態機械）
  に切り出し、`apply_long_term_static` は `while let Some(mu_target) = state.next_target()`
  で載荷率が 100% に達するまで継続するよう書き換えた。半減リトライで成功した場合も、
  次回は基準増分（1/5）から再開して残増分を追いかける。連続失敗が最大試行回数（5 回）を
  超えたら従来どおり `Err`。
- テスト: `nonlinear.rs` 内 `load_fraction_tests` モジュールに
  `all_success_reaches_full_load_in_five_steps`・
  `half_step_success_still_reaches_full_load`（半減成功パスでも最終的に 100% へ到達）・
  `repeated_failure_exceeds_max_attempts` を追加（FEM を介さない単体テスト）。

### 中-2: Maxwell ダンパーの記録軸力が commit 後評価で過小（修正）

`crates/squid-n-element/src/springs/damper/maxwell.rs`: `commit_state()`/
`update_state(commit=true)` は、`committed_ud` を更新した**後**の状態から
`state_member_forces` が軸力を再評価する構造だった。`solve_ud` の初期値（後退 Euler の
`Ud` 反復の起点）に更新後の `committed_ud` を使うため、ダッシュポットが「既にこの伸びに
対する解へ到達済み」とみなされ、速度 V≈0・軸力が過小に評価される不具合があった。

- `committed_ud` 更新**前**（＝現在の後退 Euler 履歴に基づく）に評価した軸力を
  `committed_force: f64` フィールドへキャッシュするよう変更（`commit_state`・
  `update_state(commit=true)` の両方）。
- `state_member_forces` は `trial_elong == committed_elong`（commit 直後）なら
  `committed_force` を返し、それ以外（Newton 反復中の trial 状態）は従来どおり
  `axial_force(trial_elong)` を再評価する。
- `snapshot_state`/`restore_state`（タプルに `committed_force` を追加）・
  `serialize_checkpoint`/`deserialize_checkpoint`（従来デフォルト実装＝状態非永続化だったのを、
  `springs/spring.rs` と同じ bincode シリアライズ実装を新規追加）にも反映した。
  空バイト列（旧チェックポイント）は「状態なし」として許容する。
- テスト: `test_maxwell_state_member_forces_after_commit_matches_pre_commit_axial_force`
  （commit 直後の `state_member_forces` が「commit 直前（`committed_ud` 更新前）の
  `axial_force`」と一致し、素朴な post-commit 再評価とは異なることを確認）。

### 中-3: 層応答ピークが間引きフレーム基準（修正）

`StoryResponse` に `peak_story_shear`・`peak_floor_accel`・`peak_floor_vel`・
`peak_floor_disp`（`Vec<f64>`、階数長、`#[serde(default)]`）を追加した。
`ThRecorder::record_step` は、フレーム間引きに関わらず毎ステップこれらを更新する
（`peak_shear_coeff` と同じ扱い）。フレーム時系列本体（間引きあり）だけを見て
極大値を求めていた従来仕様では、間引きフレームの合間に生じるピークを取り逃していた。

- テスト: `test_story_response_peaks_match_full_resolution_regardless_of_thinning`
  （`record_every=7` と `record_every=1` で同一解析を実行し、間引きあり側のピークが、
  間引きなし側の全フレームから独立に求めた絶対値最大と一致することを確認）。

### 中-4: 部材内力のフレーム記録のメモリ削減（修正）

`ThRecorder::record_step` のフレーム記録（`ThRecording::member_forces`）は、各要素の
`MemberForces.at` を両端 2 点（最小ξ・最大ξ）のみに間引いて保持するよう変更した
（`trim_member_forces_to_endpoints`、新設）。3D アニメーション・部材内力ヒストリパネル
（履歴ループ表示）は元々端部値のみを使用しており、中間評価断面（既定 3 点）は不要だった。
包絡 `peak_member_forces`（`merge_peak_member_forces`）は従来どおり全評価断面を保持する
（トリミング前の `member_forces_now` に対して行うため影響なし）。

- テスト: `test_frame_member_forces_trimmed_to_endpoints_envelope_keeps_all_sections`。
