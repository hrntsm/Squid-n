# 準備計算（解析前の前処理）の実装 — 申し送り

## 背景と経緯

従来、解析前の前処理（剛域の自動算定・床荷重/自重/積載の集計・地震力 Ai 分布の算定と
EX/EY への同期）は、各解析エントリの内部（`sync_auto_load_cases_action`）で
**暗黙に**実行されており、利用者が単独で実行して内容を確認する手段が無かった。

このため「解析前に階の分布・剛域・Ai 分布を確認したい」という運用上の要求に応えられず、
たとえば階の自動生成が意図した階数になっているか、剛域が過大でないか、Ai 分布の
ベースシアが妥当かを、解析を回して結果から逆算するしかなかった。

本変更で、これらを **「準備計算」という明示的な実行単位**として切り出し、実行結果を
確認用のデータ構造（`PreparationResult`）として保持・表示できるようにした。

## 実装の要点

### 実行単位（`crates/squid-n-app/src/app/preparation.rs`）

- `App::run_preparation()` — 利用者が明示的に実行する入口。階が未定義なら
  `generate_stories_action()` で自動生成してから集計する。
- `App::ensure_preparation()` — 各解析エントリの先頭で呼ぶ内部入口。
  **階の自動生成は行わない**（解析の実行が暗黙にモデルの階構成を書き換えるのを
  避けるため）。従来 `sync_auto_load_cases_action()` を直接呼んでいた箇所を
  すべてこれに置き換えた。
- `App::refresh_preparation()`（private）— 共通処理。
  `apply_parallelism_setting` → `sync_auto_load_cases_action`（剛域＋荷重同期）→
  `run_diagnostics`（stale のときのみ）→ 集計 → `preparation_stale = false`。
  荷重同期が `mark_edited()`（= `preparation_stale = true`）を呼びうるため、
  **フラグのクリアは必ず集計の後**に行う（順序を入れ替えると常に stale になる）。

### 状態管理

- `Staleness::preparation_stale` を追加（`Default` は true = 未実行）。
  `mark_edited()` で true に戻る。`mark_fresh()` では触らない。
- `App::preparation: Option<PreparationResult>`。`load_model` でリセットする
  （併せて `diagnostics` もクリアするようにした。従来は前モデルの診断が残っていた）。

### ソルバ側の切り出し（重複実装を作らないため）

準備計算の表示のために算定ロジックを app 側へ再実装するのは二重実装になるため、
ソルバの荷重ケース構築関数から**算定部分を単独の公開関数として切り出し**、
構築側がそれに委譲する形にした。

- `analysis::seismic_distribution_for_model(model, cfg, t) -> AiDistribution`
  （`build_seismic_load_case_from_model` が委譲）
- `analysis::wind_precalc_for_model(model, cfg) -> WindPrecalc`
  （`Analysis::wind_static` が委譲）

これにより、表示される Ai 分布・風圧力は解析入力そのものと同一の算定結果になる
（テスト `test_preparation_ai_matches_synced_seismic_case` で ΣPi = ΣFx を担保）。

### 表示（`crates/squid-n-app/src/prep_view.rs`）

下ドックに `BottomTab::Preparation`（「準備計算」）を追加。横長の表が多いため、
既存方針どおり左右ドックではなく下ドックへ収容した。サブビューは
階の分布／地震力（Ai 分布）／風圧力／剛域／断面性能／幅厚比／部材剛性／荷重集計。
`summary::build_preparation_csv` で CSV コピーにも対応。

解析設定パネル（右ドック）の先頭に「🛠 準備計算 実行」と状態表示を置き、
実行後は下ドックの準備計算タブへ自動で切り替える。

## 設計判断（なぜそうしたか）

- **解析側から準備計算をゲートしない**（未実行ならエラーで止める、とはしない）。
  各解析は `ensure_preparation()` で自動的に最新化する。準備計算の価値は
  「事前に確認できること」であり、実行を強制することではないため。
  結果として既存の解析エントリの挙動は従来と等価（剛域反映＋荷重同期）に保たれる。
- **`run_preparation` は階が既に定義済みなら再生成しない**。`ApplyStories` は
  階を丸ごと置き換えるため、手入力した地震用重量・階種別・PH/地下の設定が
  失われる。再生成は従来どおり「🏢 階の自動生成」ボタンで明示的に行う。
- **`run_eigen` は `ensure_preparation()` に置き換えていない**。精算周期
  （`AiMode::SemiPrecise`）では固有値解析が準備計算（Ai 分布）の**前提**であり、
  固有値解析の直前に「固有値解析が未実行です」という注意を出すのは不合理なため、
  従来どおり `apply_rigid_zones_for_analysis()` のみを呼ぶ。
- **プッシュオーバー・時刻歴は据え置き**。これらは DL/EX 等の荷重ケースを
  消費せず、剛域は `compute_pushover` 内で複製モデルへ適用している。
- **剛域一覧は λ = 0 でもフェース距離があれば載せる**。λ（剛性計算用）と
  フェース距離（危険断面位置用）は別概念で、S 造の仕口では λ = 0 になる
  （直交 S 材は λ の算定対象外）。λ > 0 のみで絞ると S 造モデルで表が空になり、
  危険断面位置が確認できない。
- **支点数から剛床代表節点を除外**。`generated_masters` は面外拘束を持つ仮想節点で
  あり、これを支点として数えると利用者の想定と食い違う。

## 追補: 断面性能・幅厚比の取り込みと結果の永続化

### 断面性能（`PrepSectionRow`）

`model.sections` と同順で、断面諸量（A・Iy・Iz・J・Asy・Asz・D・B）と使用部材数・
材料・E を一覧する。**値はモデルが持つ解析入力そのもの**であり、表示側で再計算は
しない（表示と解析入力が食い違わないようにするため）。断面二次半径 i=√(I/A) のみ
表示のために算出する。

### 幅厚比・部材ランク（`PrepWidthThicknessRow`）

ランクは断面形状・部材用途（柱／梁）・鋼種でのみ決まるため、**(SectionId,
SteelMemberUse, MaterialId) でグルーピング**して行数を抑えた（部材数に比例して
行が増えるのを避ける）。

判定ロジックは `compute_holding_capacity` にインラインで書かれていたものを
`app::steel_width_thickness_rank`（構造規定の幅厚比表 → 単一幅厚比法へフォール
バック）として切り出し、**Ds 算定と準備計算の表示が同一関数を通る**ようにした。
部材用途の選択も `app::steel_member_use_of` に共通化している。

筋かい（有効細長比で BA〜BC を定める）は本表の対象外。Ds 算定側は従来どおり
`steel_brace_type` で別扱いする。

### 結果の永続化（.scz）

- `PreparationResult` とその下位型に `serde` を導出。foreign 型のうち
  `SoilClass`・`TerrainRoughness`（load）、`MemberKind`・`MemberRank`・
  `SteelMemberUse`（design-jp）、`AiMode`・`SeismicDir`（solver）へ
  `Serialize`/`Deserialize` を追加した（load・design-jp には serde 依存を新規追加）。
- io 層は準備計算の型を知らないので、**バイト列として受け渡す**設計にした
  （エントリ名 `preparation.msgpack`）。直列化はアプリ層（rmp-serde）が行う。
  エントリは manifest に列挙されハッシュ検証の対象になる。
- API は `save_scz(path, model, preparation: Option<&[u8]>)` /
  `load_scz(path) -> (Model, Option<Vec<u8>>)` の 1 組に統一した
  （未リリースのため後方互換のラッパは置かない。本書「後方互換なしの方針」）。
- **保存するのは最新（`!preparation_stale`）のときだけ**。これにより読込側は
  「同梱されている＝そのモデルに対して最新」と扱え、復元時に
  `preparation_stale = false` にできる。古い結果を最新と誤認させない。
  準備計算エントリが無いファイルは「準備計算を保存していないプロジェクト」で
  あり（旧形式ではない）、読込側は未実行状態から始める。

### 後方互換なしの方針

本プロジェクトは未リリースであり、`.scz` のスキーマ版は 1 のまま据え置く方針
（`scz::CURRENT_SCHEMA_VERSION` のコメント参照）。したがって旧 API を残す・
旧形式を読めるようにする、といった互換のための分岐は入れない。API 変更時は
呼び出し側（app・mcp・テスト）をすべて追従させる。

## 追補: 部材単位の剛性一覧と解析結果の永続化

### 部材剛性（`PrepMemberStiffnessRow`）

断面単位の表では表せない、部材ごとに決まる剛性の割増しと SRC/CFT 等価断面を
一覧する。表示値が要素構築（`BeamElement::new`）の適用値と乖離しないよう、
判定・算定を squid-n-element 側の公開関数へ切り出して**双方から同じ関数を通す**。

- `beam::stiffness_breakdown(model, data) -> StiffnessBreakdown{slab, wall_girder}`
- `beam::composite_props_of(model, data) -> Option<CompositeProps>`

`construct.rs` は内部版（`breakdown_with` / `composite_props_with`）へ委譲する形に
変更した。断面形状ごとの分岐（RC 矩形→スラブ協力幅、H 形鋼→合成梁）も
`breakdown_with` 側へ移したため、分岐の二重管理は無い。

フレーム内雑壁の断面性能算入は部材ごとの断面合成（平行軸の定理）であり単一の
倍率で表せないため、この内訳には含めない（実効 Iy にも含めない旨を doc に明記）。

**性能**: 部材ごとの判定はモデル全走査を含む（`is_wall_top_bottom_girder` は
O(部材数)、`slab_cooperating_width` は O(スラブ数×部材数)）。準備計算は解析の
たびに走るため、割増しも等価換算も生じ得ないモデル（スラブ厚 0・壁なし・
SRC/CFT なし）では**事前判定で丸ごとスキップ**する。既定のモデルは無コスト。

### 解析結果の永続化（`SavedResults`）

`ResultsBundle` 全体（静的解析・荷重組合せ・固有値・プッシュオーバー・時刻歴・
断面検定・床/小梁設計）に加え、復元後の表示状態（`last_static`）と
`last_run` を `SavedResults` にまとめて `.scz` の `results.msgpack` へ保存する。

serde 導出を追加した型:

- squid-n-element: `MemberForces`
- squid-n-solver: `StaticOnce`・`ModalResult`・`ResponseResult`・`ResponseHistory`・
  `PushoverResult` と配下（`PushoverStep`・`CapacityPoint`・`HingeEvent`・
  `HingeLevel`・`MechanismType`・`ShearYieldEvent`・`PushoverMemberResponse`）
- squid-n-design-jp: `CheckKind`・`CheckComponent`・`CheckResult`・`CheckOutcome`・
  `JoistDesignResult`・`SlabDesignResult`
- squid-n-app: `ResultsBundle`・`StaticCaseKey`・`StaticKey`・`MemberChecks`・
  `PositionCheck`・`JointCheck`

時刻歴応答（`ResponseResult`）はステップ全体の節点変位を持たず、代表応答の
`Vec<f64>` 数本とピーク値のみのため、そのまま同梱してもファイルは肥大しない
（全ステップの応答が要る用途には `squid_n_io::results` の Parquet ストアがある）。

準備計算と同じく**最新（`!results_stale`）のときだけ同梱**し、復元時は
`results_stale`・`design_stale` をクリアする。断面検定の結果も同梱されるため、
復元後に `run_design_check` を再実行する必要はない。

### .scz の派生データ受け渡し

エントリが 2 つになったため、引数・返り値を構造体へまとめた。

- `save_scz(path, model, SczExtras{preparation, results})`
- `load_scz(path) -> SczContents{model, preparation, results}`

io 層はどちらの中身も解釈しない（型はアプリ層。直列化は rmp-serde）。

## 残課題

- **柱の積載荷重低減**（`live_load::column_live_load_reduction`）は断面検定側で
  適用しているが、準備計算の表には出していない。柱ごとの支持階数と低減率を
  一覧できると入力確認に有用。
- **フレーム内雑壁の断面性能算入**は部材剛性の表の「実効 Iy」に含めていない
  （単一倍率で表せないため）。合成後の断面性能そのものを列挙する形なら
  一覧化できる。
- 風圧力の**内圧係数 Cpi は 0 固定**（`WindStaticCfg::cpi`）。風上・風下の合算では
  相殺されるため合成 Cf に影響しないが、片面評価に拡張する際は入力が必要。
- 解析結果の同梱により `.scz` が大きくなる（節点変位・部材内力はケース数に比例）。
  zip エントリの上限は 512 MiB（`MAX_ENTRY_UNCOMPRESSED`）で、超える規模では
  保存に失敗する。大規模モデルでは Parquet ストア（`squid_n_io::results`）への
  振り分けを検討する。
