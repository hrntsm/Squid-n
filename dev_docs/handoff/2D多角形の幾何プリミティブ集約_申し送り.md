# 2D 多角形の幾何プリミティブの集約 — 申し送り

作成日: 2026-09-03
対象コード: `crates/squid-n-core/src/geom/polygon.rs`、`squid-n-load`、`squid-n-app`

この申し送りでは、多角形の面積・重心・点と辺の距離・内包判定が 3 クレート 7 モジュールへ複製されていたのを `squid_n_core::geom::polygon` へ集約した経緯と、その過程で見つかった縮退判定の欠陥を記録します。

## 背景 — 幾何の式が散らばっていた

床領域・壁領域の検出とリビルド、床の荷重分配、断面輪郭の重心補正は、いずれも同じ多角形の式を必要とします。
ですがこれらは別々の時期に別々のモジュールへ実装されたため、同じ式が何度も書き写されていました。

コード自身が複製を自認している箇所もありました。
`wall_region_rebuild::project_onto` のコメントは「`region_gen::wall` 内部の `project` と同じ計算だが `pub(crate)` ではないため同じ式をここに持つ」と書いています。
`squid_n_load::floor::polygon::ON_BOUNDARY_TOL_MM` のコメントも「床レベルの公差と同じ 1 mm」と書いており、`region_gen::BOUNDARY_TOL_MM` と値も意味も同じ定数が二重に定義されていました。

見つかった重複は次の 5 種です。

| 重複していたプリミティブ | 箇所 | 性格 |
|---|---|---|
| 符号付き面積（シューレース公式） | `region_gen::signed_area`・`region_rebuild::shoelace_area`・`wall_region_rebuild::shoelace_area`・`load::floor::geometry::polygon_area` | 4 実装。ループの書き方だけが違う |
| 面積重心 | `region_rebuild::shoelace_centroid`・`wall_region_rebuild::shoelace_centroid`・`app::viewer::hinge::polygon_centroid` | 3 実装。縮退判定のしきい値だけが違う |
| 点と線分の距離 | `region_gen::point_segment_dist`・`region_rebuild::point_segment_dist`・`load::floor::polygon::point_segment_dist2` | **前 2 者はバイト単位で一致**。3 番目は二乗版 |
| レイキャストによる内包判定 | `region_gen::polygon_contains_strict`・`load::floor::polygon::point_in_polygon`・`app::viewer::pick::point_in_polygon` | 辺上の扱いだけが違う |
| 構面への射影 | `region_gen::wall::project`・`wall_region_rebuild::project_onto` | コメントで重複を自認 |

`region_gen::signed_area_abs` は `pub` で、`model::wall_plate` が純粋な幾何計算のために `region_gen` を参照していました。
領域検出のモジュールへモデル層が依存する形になっており、層の向きとしても逆でした。

## 決めたこと

着手前に dig で 5 問を確認し、次の形に決めました。

| 問い | 決定 |
|---|---|
| スコープ | `squid-n-core` と `squid-n-load`。`app::viewer::pick` は対象外 |
| 縮退（面積 0）の判定 | 絶対値ではなく境界ボックス相対 |
| 置き場所 | `geom/polygon.rs` を新設し、既存の `polygon_area_3d` も移す |
| 内包判定の API | 辺上の扱いを名前に出した 2 関数へ分ける |
| 構面への射影 | `WallRegionBoundary` のメソッドへ |

`app::viewer::pick` を外したのは、そこだけ `egui::Pos2` の f32 スクリーン座標を扱う UI のヒットテストだからです。
式は同じでも単位系も型も目的も別で、寄せると実寸（mm）と描画座標を同じ関数へ通すことになり、変換コードが増えるだけになります。

置き場所を `geom` にしたのは、そのモジュールの doc が「複数のクレートが同じ判定規則を必要とするものだけを置く」と宣言しており、3 次元の `polygon_area_3d` がすでにそこにあったためです。
純粋な演算をサブモジュールへ分ける先例は `geom::vec3` にあります。
2 次元版だけを別の場所へ置くと多角形の面積が 2 か所に分かれてしまうため、3 次元版もあわせて `geom::polygon` へ移しました。

## 見つかった欠陥 — 縮退判定が機能していなかった

集約の過程で、既存の面積重心が**縮退した多角形を検出できていない**ことがわかりました。

面積重心はシューレースの符号付き面積 `A` を用いて `6A` で除算するため、`A` が 0 に近いと発散します。
これを防ぐガードが 2 系統ありました。

- `region_rebuild`・`wall_region_rebuild`: `A.abs() <= f64::EPSILON`（約 2.2e-16）
- `app::viewer::hinge`: `a.abs() < 1e-9`

どちらも面積の**絶対値**をしきい値と比べています。
ですが建物座標は ~1e4 mm なので、シューレース和の各項は ~1e8 になります。
一直線に並んだ頂点の符号付き面積は厳密には 0 ですが、この大きさの項を足し引きすると丸め誤差が ~1e-8 mm² 残るため、**残差は両方のしきい値をすり抜けて除算へ入ります**。
つまり縮退した境界を与えたとき、頂点の単純平均へ落ちるはずの処理が、実際には巨大な座標を返していました。

加えて断面輪郭の座標は ~1e2 mm と 3 桁小さく、面積も ~1e4 mm² 程度です。
尺度の違う 2 つの用途を単一の絶対値で正しく覆うことは、そもそもできません。

そこで面積を**境界ボックスの最大辺長の 2 乗**と比べる形にしました。
比は無次元になるため、建物の平面でも断面の輪郭でも同じ判定が使えます。
基準に境界ボックスの「面積」を採らないのは、縮退した多角形ではそれ自体が 0 へ潰れて基準にならないためです。
しきい値 1e-12 は、シューレース和の相対丸め誤差（頂点数 n に対し概ね `n · f64::EPSILON` ≒ 1e-15）に 3 桁の余裕を持たせた値です。

この欠陥が実害を出していなかったのは、縮退した境界が実モデルに現れないためです。
床領域の重心照合は旧領域の名前の引き継ぎに使い、壁領域の重心照合は壁版の帰属判定に使い、断面輪郭の重心は描画にしか使いません。
いずれも応力・重量へ直結しないため危険側の欠陥ではありませんが、**すり抜ける形のガードを 3 か所に増やしたまま残すのは避けたい**と判断し、集約とあわせて直しました。

## 内包判定を 2 つに分けた理由

辺上の点をどう扱うかは、集約前の 2 つの実装で正反対でした。
そしてどちらにも理由がありました。

- `region_gen::polygon_contains_strict` は辺上を**除外**します。辺上の点は隣接する両方の領域に該当するため、含めると版や二次部材の帰属を一意に決められません
- `load::floor` の `point_in_polygon || point_on_polygon_boundary` は辺上を**包含**します。床板の縁に載る小梁を検定の対象から落とさないためです

この判断の違いこそが実装が 2 か所へ分かれた原因なので、集約先では `contains_excluding_boundary` と `contains_including_boundary` という名前で区別しました。
呼び出し側のコードを読んだだけで、辺上をどちらへ倒したのかがわかります。

さらに 3 つ目として `contains_by_ray_crossing` を置きました。
床の荷重分配は 200×200 の格子でセル中心が多角形の中か外かを数え上げますが、この走査は点に帰属先を与えるのではなく面積を積んでいます。
ここへ公差の帯を持ち込むと、辺から 1 mm 以内に中心を持つセルが内外どちらの判定でも数から漏れ、**荷重面積が落ちる危険側**になります。
そのため帯を見ないレイキャストを別の名前で用意し、doc に「帰属を決める用途に使ってはならない」と明記しました。

## 面積の 3 種を名前で区別した

集約前の `load::floor::geometry::polygon_area` は 3 次元座標を受け取って XY へ投影した面積を返し、`geom::polygon_area_3d` はニューエルの公式による真の面積を返していました。
名前からはこの違いが読み取れません。

投影面積と真の面積の取り違えは危険側になりえます。
傾いた壁の自重に投影面積を用いると、傾きのぶんだけ重量を過小評価するためです。
そこで `area_xy` と `area_3d` へ改名し、どちらを使っているかが呼び出し側で見えるようにしました。

## 検証

計算根拠を変えていないことを、次の順で確認しました。

- ワークスペース全体のテスト（スナップショットを含む）が全数成功する
- `gui`・`mcp` フィーチャ付きのテストも成功する
- clippy 3 条件（ワークスペース `--all-targets`、`gui`、`mcp`）と `cargo fmt --check` が通る
- `cargo doc -p squid-n-core` の警告数が集約前の 194 件から 193 件へ減る（新規の警告を出していない）

集約先には性質テストを 13 件新設しました。
とくに `centroid_of_collinear_points_falls_back_to_vertex_mean` は、建物座標の尺度で一直線に並んだ頂点を与えて重心が発散しないことを確かめるもので、上記の欠陥に対する回帰テストにあたります。
`the_three_containment_rules_differ_only_on_the_boundary_band` は、3 つの内包判定が内部と外部では一致し、辺上の帯でのみ分かれることを 1 つのテストで示します。

コードの差分は 19 ファイルで、追加 504 行・削除 367 行です。
このうち新設した `geom/polygon.rs` が 417 行（doc とテスト 13 件を含み、実装本体は 252 行）を占めるため、**既存のモジュールからは差し引き 280 行が消えました**。

## 残課題

- `app::viewer::pick::point_in_polygon` は集約していません。f32 のスクリーン座標を扱う UI のヒットテストで、実寸の幾何とは別物として残しました。式そのものは `contains_by_ray_crossing` と同じなので、将来スクリーン座標も f64 で扱う方針になれば寄せられます
- `point_segment_dist_sq` の縮退した線分に対するガードが、集約前の `load` 側（`len2 > 1e-12`）から `core` 側（`len2 <= f64::EPSILON`）へ揃いました。差が出るのは長さが 1.5e-8〜1e-6 mm の線分だけで、そのときも返る点は始端から 1e-6 mm 以内に収まるため実害はありません。**片方へ揃えた事実だけを記録しておきます**
- `region_gen::wall` には境界を作る前の面走査が使う private な `project` が残っています。`WallRegionBoundary::project` はこれへ委譲する形にしたため式は 1 つですが、入口は 2 つあります。面走査が構面ごとの型を先に作る設計へ変われば 1 つにできます
