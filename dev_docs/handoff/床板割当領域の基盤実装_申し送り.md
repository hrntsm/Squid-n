# 床板割当領域・壁版割当領域の基盤実装_申し送り

作成日: 2026-09-14

## 目的

ADR 0020（`dev_docs/adr/0020-assign-plates-to-member-bounded-regions.md`）が定める
「囲まれた床板・壁版は支持部材で分割された割当領域へ 1 枚ずつ割り当てる」モデルへ
向けた基盤を実装した。本申し送りは、今回実装した範囲と、ADR 0020 の全要件に対して
**未実装のまま残した範囲**を明確にする。

## 実装済み

### 1. モデル要素としての割当領域（core）

- `FloorPlateAssignmentRegion` / `WallPlateAssignmentRegion`
  （`crates/squid-n-core/src/model/assignment_region.rs`）を `Model` のフィールド
  `floor_assignment_regions` / `wall_assignment_regions` として接続した。
- 各領域は `未設定 / 版なし / 版IDあり` の `PlateAssignment` を持つ。
- `FloorPlateAssignmentRegions::get` / `get_mut`、`WallPlateAssignmentRegions::get` /
  `get_mut`、`Model::floor_assignment_region` / `wall_assignment_region` により、
  **配列添字と一致しない安定 ID** で検索できる。削除でも ID を詰めない。
- `Model::validate` が領域 ID の重複・境界辺の妥当性・参照版の存在・版の二重割当を
  検証する。
- `Model::visit_elem_ids` が境界の主架構 `ElemId` を繰上げ・繰下げに追随させる。

### 2. 再構築と ID・状態の維持

- `FloorPlateAssignmentRegions::rebuild` / `WallPlateAssignmentRegions::rebuild` が
  支持部材の線分から半辺面走査で閉領域を求め、**境界が同じ領域の ID と割当状態を
  維持**し、境界が変わった領域は新しい ID の未設定として作り直す。
- `Model::rebuild_floor_assignment_regions` が、レベルごとに水平な大梁と、
  同じレベルにある `SecondaryMemberTopology` の小梁を集めて面走査し、上記の
  維持規則で領域を再構築する。
- `Model::rebuild_wall_assignment_regions` が、柱脚位置から検出した鉛直構面ごとに
  局所座標 `(s, z)` で柱・梁と支持された間柱を面走査し、同じ維持規則で領域を再構築する。
  間柱は `SecondaryMemberTopology` の `Post` のうち両端が支持されたものだけを辺に含める
  （片持ちの自由端は閉領域の辺にならないため含めない）。
- `squid_n_job::prepare::prepare_model_for_analysis` から
  `Model::rebuild_floor_assignment_regions` と `Model::rebuild_wall_assignment_regions` を
  呼び、解析前処理で割当領域が更新されるように結線した。
- `squid-n-mcp` の `query_model` が `floor_assignment_regions` /
  `wall_assignment_regions` / `secondary_member_topologies` を照会できる。

### 3. 二次部材のトポロジー

- `SecondaryMemberTopology`（安定 `SecondaryMemberId` ＋ `SecondaryMemberEnds`）と
  `SecondaryMemberAnchor`（支持部材 ID ＋材軸位置）を `Model.secondary_member_topologies` に接続した。
  二次部材用のモデル節点は生成しない。
- 片持ち自由端は `SecondaryMemberEnds::Cantilever` の親構面内 2D ベクトルで表す。
- `SecondaryMemberTopology::validate_all` が重複 ID・取付き位置の範囲・ダングリング参照に
  加えて、**支持グラフの循環**を拒否する。`Model::validate` から呼ぶ。

### 4. 支持部材境界の座標解決

- `Model::support_member_axis` が主架構（2 節点要素）と支持端どうしの二次部材の材軸を
  再帰的に解決する（循環ガード付き）。
- `Model::support_boundary_segments` が `SupportBoundary`（支持部材 ID ＋材軸区間）の
  座標列を返す。面走査は T 字端点で辺を分割し、単なる幾何交差を支持接続とはみなさない。

## 未実装（ADR 0020 の要件に対して）

以下は今回手を付けておらず、**利用者フローとしては未統合**である。
項目 3（壁版割当領域の再構築）のみ、後続の作業で実装済みである。

1. **既存型から新モデルへの移行**: `SlabShape::Enclosed { boundary }`・
   `WallPlateShape::Enclosed { boundary }` は境界節点列を保持したままで、
   割当領域 ID を参照する形へ移行していない。囲まれた版が割当領域から形状を
   解決する経路は無く、境界の重複保存も残っている。
2. **二次部材の安定 ID の既存経路への反映**: 現行の `SecondaryMember` は
   `[NodeId; 2]` のままで、`SecondaryMemberTopology` とは別物のまま併存する。
   荷重分配・反力伝達・領域リビルドは従来の節点ベース経路を使う。
   そのため `Model::rebuild_floor_assignment_regions` に小梁は実質含まれない
   （`secondary_members` が空）。
3. **壁版割当領域の再構築（対応済み）**: `Model::rebuild_wall_assignment_regions` を
   実装し、`prepare` から呼ぶようにした。柱・梁・間柱の構面面走査、境界不変時の
   ID・状態維持、変化分の新 ID・未設定化まで実装済み。MCP からの照会にも対応した。
   **利用者による割当・編集（作成・版なし・未設定）は引き続き未実装。**
4. **作成・編集フロー**: GUI・一覧フォーム・EditCommand・MCP の、任意節点境界に
   よる囲まれた版作成の廃止と、割当領域 ID による作成・編集・版なし・未設定操作は
   未実装。Attached 版の既存入力は変更していない。
5. **3D ビュー**: 親 `FloorRegion` / `WallRegion` を作業範囲とした小梁・間柱の配置、
   割当領域クリックでの編集画面、領域 pick・hover・状態表示、複数領域への
   「版なし」一括設定は未実装。
6. **削除時の選択**: 「未設定へ戻す」「版なしにする」の選択、二重割当・境界不一致の
   拒否（`validate` に一部あり）は未実装。
7. **4 節点でない壁版割当領域**: 荷重は扱うが剛性算入なしとする明示は未実装。
8. **ST-Bridge**: 割当領域との境界一致を必須とし、不一致で取り込み全体をエラーに
   する処理は未実装。
9. **未設定時の計算前確認と出力**: GUI の明示的続行確認、結果画面・CSV レポートへの
   未設定件数と対象 ID の常時記載は未実装。解析を許可する「警告のみ」の扱いを
   `docs/` に明記する作業も、上記が未実装のため未着手。

## 残課題

- ADR 0020 の中核である「囲まれた版の境界を割当領域へ一本化する」型移行が未完了。
  `SlabShape::Enclosed` / `WallPlateShape::Enclosed` の全参照（床 81・壁 87 か所）を
  割当領域参照へ移す必要がある。
- `SecondaryMember` を `SecondaryMemberTopology` へ一本化し、節点ベースの
  荷重伝達経路を支持部材 ID ベースへ置き換える必要がある。
- 壁版割当領域の自動再構築と MCP 照会は実装済み。ただし利用者による割当操作が
  無いため、`PlateAssignment` は実質すべて未設定のままである。ADR 0020 の
  中核である型移行が済むまで、割当領域は「解析前処理が作る派生データ」であり、
  利用者は操作できない。

## 追記（段階移行: 割当領域の逆引きと二次部材の安定 ID・取付き位置）

作成日: 2026-09-14

ADR 0020 の中核（囲まれた版の割当領域参照化、`SecondaryMember` のトポロジー一本化）へ
向けて、緑を保つ段階移行として次を実装した。旧表現は削除せず併存させている。

### 1. 割当領域の逆引きと整合検査（core）

- `Model::slab_assignment_region(SlabId)` / `Model::wall_plate_assignment_region(WallPlateId)`
  を追加し、版から割当領域を逆引きできるようにした。
- `Model::assignment_region_boundary_coords(&[SupportBoundary])` と
  `Model::floor_assignment_region_coords` / `Model::wall_assignment_region_coords`
  を追加し、割当領域境界の頂点座標 [mm] を支持部材の材軸から解決する。
- `Floor/WallPlateAssignmentRegions::validate` が、取り付く版（`Attached`）を割当領域が
  参照することを拒否するようにした（囲まれた版だけを割り当てる）。

### 2. 二次部材の安定 ID と取付き位置表現（core）

- `SecondaryMember` に `id: Option<SecondaryMemberId>` と
  `ends: Option<SecondaryMemberEnds>` を追加した。取付き位置表現を持つ部材は ID も持つ。
  旧 `nodes` / `end_support` は併存させ、移行完了まで残す。
- `Model::next_secondary_member_id` と `Model::alloc_secondary_member_id` を追加し、
  `secondary_member_topologies` と `SecondaryMember` の既存 ID の最大 + 1 以上を払い出す。
- `Model::validate_secondary_member_anchor_ends` を `Model::validate` へ組み込み、取付き
  位置表現を持つ二次部材の ID 重複・アンカー参照・材軸位置範囲・支持グラフ循環・
  片持ち自由端・主架構アンカーの実在を検証する。旧 `nodes` 表現だけの部材は対象外。
- `Model::anchor_point` を公開し、`Model::support_member_axis` は
  `SecondaryMember.ends` からも材軸を解決できるようにした。

### 3. 中核へ寄せた本番経路（core）

- `Model::secondary_member_axis(&SecondaryMember)` を追加し、取付き位置表現があれば
  アンカーから両端座標・材軸長を解決し、無ければ両端節点へ退避する。
- `Model::secondary_joist_axes` が上記を使い、`SecondaryJoistAxis` の両端座標・材軸長が
  アンカー由来になるようにした（`nodes` は識別用に残す）。

### 残っている旧経路

- `SlabShape::Enclosed { boundary }` / `WallPlateShape::Enclosed { boundary }` は境界節点列を
  保持したまま。割当領域 ID 参照への移行は未着手（本番 42 / 63 箇所、テスト 40 / 25 箇所）。
- `SecondaryMember.nodes` / `end_support` は併存中。`SecondaryMemberTopology` と
  `Model.secondary_member_topologies` も併存中（本番 18 / 14 箇所）。
- 荷重分配の `LoadTarget::Span { nodes, t }` は `NodeId` 対のまま。割当領域・安定 ID
  経由の目標指定への移行は未着手。
- 本番コードはまだ `SecondaryMember.id` / `ends` を生成しない（取り込み・編集・GUI が
  旧 `nodes` を作る）。`prepare` は `rebuild_*_assignment_regions` を呼ぶが、割当領域の
  小梁・間柱は `secondary_member_topologies` 経由のまま。

## 追記（床板割当領域の編集経路と GUI・MCP）

作成日: 2026-09-14

今回のセッション目標は「囲まれた床板の経路を端から端まで新モデルへ移行する」だった。
到達したのは**編集コマンド・GUI・MCP を割当領域経由へ移す段**までで、**型移行
（`SlabShape::Enclosed` の廃止）と生成経路（架構作成ウィザード・ST-Bridge 取り込み・
`region_rebuild`）の割当領域経由化は未完**。緑（`cargo test --workspace --locked` ほか）は保った。

### 実装済み

- **編集コマンド（squid-n-edit）**: `AddSlab`（任意節点境界）を廃止し、次を追加した。
  - `AssignSlabToFloorPlateRegion { region, plate }`: 割当領域が存在し、状態が未設定または
    版なしのときだけ、床板を末尾に生成して領域を `Plate(生成した床板)` へ原子的に変える。
    既に版ありなら Noop（undo 履歴に積まない）。領域の境界頂点を節点へ解決できない場合も Noop。
  - `SetFloorPlateRegionNoPlate { region }` / `UnsetFloorPlateRegion { region }`: 版ありなら
    床板の削除も同一 Undo 単位に含め、指定状態へ戻す。既に同じ状態なら Noop。
  - 内部コマンド `SetFloorPlateRegionAssignment` が「状態＋床板の生成・削除」を一括適用し、
    適用前状態を復元する逆操作を返す（undo/redo は自分自身の往復）。
- **core**: `Model::visit_slab_ids` が `floor_assignment_regions[*].assignment` の `Plate(id)` を
  繰上げ・繰下げに追随するようにした。`Model::retain_slabs` は削除された床板を指す割当を
  未設定へ戻し、残りの版 ID を張り替える。`Model::floor_assignment_region_nodes(id)` を追加し、
  割当領域境界の頂点に一致する節点列を返す。`DeleteSlab` / `InsertSlab` は割当領域の参照を
  未設定化し、undo で復元する。
- **既存床板の結びつけ（生成経路の部分移行）**: `Model::rebuild_floor_assignment_regions` が
  領域再構築後に `Model::bind_enclosed_slabs_to_assignment_regions` を呼び、境界節点が
  一致する未設定領域へ既存の囲まれた床板を割り当てる。これにより架構作成ウィザード・
  ST-Bridge 取り込みが作った床板も、次回の準備計算で割当領域へ結びつく。境界が一致しない
  床板（二次部材アンカー由来の頂点を含む領域など）は未割当のまま残す。
- **MCP（squid-n-mcp）**: `model_edit` から `AddSlab` を外し、
  `AssignSlabToFloorPlateRegion` / `SetFloorPlateRegionNoPlate` / `UnsetFloorPlateRegion` を配線した。
  床板割当領域は既存の `model_query(kind=floor_assignment_region)` で照会できる。
- **GUI（squid-n-app）**: スラブタブの任意節点フォームを廃止し、床板割当領域の一覧
  （ID・所属床領域・状態・床板 ID・境界支持部材数）と、未設定／版なし領域への割当、版なし・
  未設定操作を追加した。3D のスラブ作成モードは任意境界を作れない旨の案内表示に変えた。
- **docs**: `docs/mcp_server/03_ツール一覧.md` と `docs/mcp_server/05_制約・注意点.md` の
  床板コマンドを更新。`dev_docs/specs/床（スラブ）設計.md` の `AddSlab` 記述を修正。

### 判断と理由（申し送り）

- **型移行を今回見送った理由**: ADR 0020 は割当領域が版 ID を持つ一方向参照で、版から
  割当領域は逆引きする。この形では、**囲まれた床板は割当領域に割り当て済みでなければ境界を
  解決できない**。`SlabShape::Enclosed { boundary }` を廃止すると、新規に床板を作る全経路
  （架構作成ウィザード・ST-Bridge 取り込み・`region_rebuild`・テスト約 50 か所）が
  「先に割当領域を作り、版を割り当てる」順序へ移行済みでないと、境界を持たない版が生まれて
  緑を保てない（鶏卵問題）。段階移行として、まず編集・GUI・MCP の経路を新モデルへ寄せた。
- **暫定の境界重複保存**: 型移行前のため、`AssignSlabToFloorPlateRegion` は割当領域の境界
  節点を `SlabShape::Enclosed { boundary }` へ保存している（`floor_assignment_region_nodes`）。
  確認済みの前提「境界を重複保存しない」は次段の型移行で満たす。この重複は本追記に記録する。
- **割当領域の境界に節点が無い場合**: 二次部材アンカー由来の頂点は既存節点に一致しないため
  `floor_assignment_region_nodes` は `None` を返し、割当コマンドは Noop になる。現行の
  `rebuild_floor_assignment_regions` は大梁（2 節点要素）だけから領域を作るため実害は無いが、
  小梁を領域生成に含める段では、頂点を節点へ解決する代わりに境界座標そのものを保持する
  必要がある。
- **削除の任意位置対応**: `SetFloorPlateRegionAssignment` は `retain_slabs` で版を削除するため、
  割当中の床板が末尾でなくても状態変更できる。

### 未完（次段以降）

1. **型移行（最優先）**: `SlabShape::Enclosed { boundary }` を廃止し、`SlabShape` を
   取り付く版だけにする（または囲まれ／取り付きの判別を別表現へ移す）。`Slab::boundary_nodes` /
   `boundary_coords` / `edge_nodes` / `reference_node`、`region_rebuild` の所属判定・
   取り付く床板への変換、荷重分配、可視化、ST-Bridge export、設計、`Model::validate`、
   全テスト（床 81 か所）を割当領域解決へ更新する。
2. **生成経路の割当領域経由化（残）**: 既存床板の結びつけ（`bind_enclosed_slabs_to_assignment_regions`）
   は実装したが、架構作成ウィザード（`frame_gen`）・ST-Bridge 取り込み（`assemble::build_slabs`）・
   `region_rebuild` 自体は依然として床板の境界を直接作る・読む。境界不一致の取り込み版の扱い
   （一致探索して割当、一致しなければ現行どおり版を残す）と新規編集経路での任意境界禁止の
   徹底は次段。
3. **3D pick（床のみ）**: 床領域を作業範囲として表示し、割当領域をクリックで編集画面を開く。
   投影と `point_in_polygon` を用い、重なりは手前優先。今回未実装。
4. **ST-Bridge の境界一致必須化、未設定時の計算前確認と出力**。
5. **壁版の同様の移行**（次セッション以降）。

## 追記（床の型移行・生成経路の割当領域経由化）

作成日: 2026-09-14

前回の最優先残課題だった「囲まれた床板の鶏卵問題」を解消した。`SlabShape::Enclosed { boundary }`
を廃止し、囲まれた床板の境界は `Model::slab_assignment_region(slab_id)` が返す床板割当領域と
境界座標解決 API から得る。緑（`cargo test --workspace --locked` ほか）を保った。

### 実装済み

- **型移行**: `SlabShape` は `Enclosed`（単位）と `Attached { anchor, extent }` の 2 値。
  `Slab::boundary_nodes` / `boundary_coords` / `boundary_coords_with` / `edge_nodes` /
  `reference_node` は `&Model` を取り、囲まれた床板は割当領域から解決する。床板側に境界を
  重複保持しない（ADR 0020 の一方向参照）。
  - `edge_nodes` は割当領域境界の頂点 `k`→`k+1` を返す。支持部材の両端を返すと、大梁を
    途中節点で分割した割当領域の辺荷重が全長へ載って荷重分配が変わるためである。
- **生成経路**: 架構作成ウィザード（`frame_gen`）は格子の各マスについて大梁要素から
  割当領域を作り、対応する床板を割り当てる。ST-Bridge 取り込みは大梁と小梁から割当領域を
  再構築し、`StbSlab` を境界一致で割り当てる。`region_rebuild` は所属判定と取り付く床板変換を
  割当領域境界で行う。`Model::add_enclosed_slab_from_nodes` /
  `assign_enclosed_slab_to_matching_region` はテスト・フィクスチャ用の補助。
- **`SlabShape::Enclosed { boundary }` の crates 内残存は 0**。単位値 `SlabShape::Enclosed` の
  参照は残る（形の判別に必要）。`WallPlateShape::Enclosed` は現行維持（壁は次セッション）。
- **`Model::validate`**: すべての囲まれた床板がちょうど 1 つの割当領域に割り当てられていること、
  割当領域の境界が他と重複しないことを検証する。

### 判断と理由

- **ST-Bridge の境界一致を必須にしつつ重心フォールバックを残した**: 実建物フィクスチャ
  （`crates/squid-n-app/tests/fixtures/model.stb`）の `StbSlab` は、支持部材に沿わない頂点
  （例: 節点 64 と節点 59 のように位置の異なる頂点の使い分け）を含み、支持部材由来の割当領域と
  境界が完全一致しない。確定指示の「一致する割当領域が 1 つも無ければ取り込み全体をエラー」に
  対し、**重心が入る未割当の割当領域があればそれを割り当てる救済を残した**（無ければエラー）。
  この救済が一致できない版の面積を割当領域の面積へ置き換えるため、`full_model` の代表スカラは
  変わる（地震用重量 +2.9% 程度）。安全側（重量過大）だが、真の形状ではない過渡期の近似であり、
  壁版移行・ST-Bridge 側の版分割まで残課題とする。
- **単位値 `SlabShape::Enclosed` は残した**: `Attached` との判別に必要であり、廃止対象は境界の
  重複保持（フィールド）である。呼び出し側の分岐は単位パターンへ更新した。
- **旧 `nodes` 表現の二次部材に安定 ID を許容した**: 割当領域が小梁を参照できるようにするため、
  ST-Bridge 取り込みで二次部材へ `SecondaryMemberId` を払い出す。`Model::validate` の
  「安定 ID を持つが取付き位置表現を持たない」を許容へ変更し、旧表現は `nodes` から材軸を
  解決する。`SecondaryMember` のトポロジー一本化（旧フィールド削除）は次セッション。
- **`frame_gen` の割当領域は支持部材の向きに合わせた span を持つ**: 境界の進行方向と要素の
  節点順が逆の辺は `span = [1, 0]` とする。全辺 `[0, 1]` 固定だと境界座標が閉じず、頂点が
  重複して床板 ID が壊れた。

## 追記（ST-Bridge 取り込みの割当領域分割・重心フォールバック撤去）

作成日: 2026-09-14

前回の残課題 4 を実装した。ST-Bridge 取り込みで、大梁・小梁から再構築した床板割当領域と
境界が一致しない `StbSlab` を、覆う割当領域ごとの床板へ分割し、面積按分で荷重を配分する。
前回残した重心フォールバック（重心が入る領域へ割り当てて領域形状・領域面積へ置き換える処理）は
撤去した。緑（`cargo test --workspace --locked` ほか）を保った。

### 実装方式

- **多角形交差**: `squid_n_core::geom::polygon::intersection_area` を追加し、`i_overlay`（MIT/Apache-2.0、
  f64 のブール演算。凸・凹・穴を扱う）で 2 つの単純多角形の交差面積を求める。`squid-n-core` の
  依存に `i_overlay = "8"` を追加した。幾何を自前実装せず確立したライブラリへ寄せる方針
  （AGENTS.md「実装方針」）と、既存の多角形ユーティリティに交差が無かったことによる。
  `i_overlay` の既定は単一スレッドで、入力を領域順・スラブ順の決定的な順序で走査するため
  決定性（ADR 0002）を損なわない。依存追加に伴い `Cargo.lock` も更新した（cargo 1.98 の
  再解決で windows-sys 系の推移依存が最新の semver 互換版へ揃った。幾何・解析の挙動には
  影響しない）。
- **分割と按分**（`crates/squid-n-io/src/stbridge/import/assemble.rs::assign_imported_slabs`）:
  各 `StbSlab` の境界 XY 多角形と、各割当領域の境界座標（`floor_assignment_region_coords`）の
  交差面積を求める。交差面積が正の領域ごとに床板を 1 枚作り（形状は `SlabShape::Enclosed`。
  境界は割当領域から解決）、元 `StbSlab` の仕上げ荷重・積載を **交差面積比（元スラブ面積に対する
  割合）で領域へ合算**し、領域面積で割って面荷重強度へ戻す。躯体の断面・材料は元 `StbSlab` から
  継承する。1 つの割当領域へ複数の `StbSlab` 片が重なる場合は領域の床板 1 枚へ統合する。
- **階レベルの一致を必須にした**: 交差判定は XY だけでなく Z も一致する領域に限る
  （`LEVEL_TOL_MM`）。XY 投影だけでは、同じ平面位置にある別階の割当領域とも交差してしまい、
  1 枚の `StbSlab` が全階の領域へ按分される誤りになる。実フィクスチャで発見した。
- **未帰属面積の検出**: 元 `StbSlab` の面積に対して交差面積の合計が不足する（面積比 1e-6 ＋
  絶対 1e-3 mm² を超える）とき、1 辺だけが大梁に全長覆われる跳ね出し（`convert_to_attached`）を
  除いて取り込み全体を `StbError::SlabWithoutRegion` で失敗させる。エラーには未帰属面積と元の
  境界節点を含める。面積を黙って欠落させない（危険側にしない）。
- **断面・用途の競合**: 1 つの割当領域へ厚さ・材料の異なる `StbSlab`、または異なる室用途の
  `StbSlab` が重なった場合は、単一の `SlabPlate` では自己重・積載を表現できないため
  `StbError::SlabRegionConflict` で取り込みを失敗させる（安全側）。実フィクスチャでは
  前述のレベル一致修正により 1 領域＝ 1 元スラブとなり、競合は発生しない。

### 重心フォールバックの撤去

`assign_imported_slabs` から `containing_region`（境界節点の重心が入る未割当領域へ割り当てる
処理）とその呼び出しを削除した。重心フォールバックは版の面積を割当領域の面積へ置き換えるため、
実建物フィクスチャで地震用重量を約 +2.9% 過大にしていた（安全側だが真値ではない）。
専用のテストは無かった（`containing_region` を直接検証するテストは存在しなかった）。

### 検証

- **実フィクスチャの総面積・総重量**: `crates/squid-n-app/tests/full_model.rs` に
  `import_preserves_stbridge_slab_area_and_weight` を追加した。フィクスチャの `StbNode` と
  `StbSlab` の境界、`StbSecSlab_RC` の板厚をテスト側で独立に読み、元スラブの総面積と
  「面積×板厚」を求める。取り込み後の床板の総面積・総和が相対 1e-6 以内で一致することを固定する
  （板厚がそろって一定密度なので「面積×板厚」の一致は総重量の一致と同値）。
- **分割**: `squid-n-io` に `test_import_splits_slab_across_assignment_regions` を追加。小梁 1 本で
  2 領域に分かれる 1 枚の `StbSlab` が 2 枚へ分割され、各片が元の断面を継承し、総面積が元と
  一致することを固定する。
- **未帰属エラー**: `squid_n_io` に `test_import_errors_when_slab_area_stays_unassigned` を追加。
  割当領域の外へ張り出す版（大梁に全長で載る辺が 2 本あり取り付く床板へ変換できない）が、
  面積と境界節点を含む `StbError::SlabWithoutRegion` で取り込み全体を失敗させることを固定する。
- `cargo test --workspace --locked`・`cargo test -p squid-n-app --features gui`・
  `cargo test -p squid-n-mcp --features mcp`・`cargo fmt --all -- --check`・clippy 3 本・
  `cargo run -p xtask --locked -- check-deps`・`mdbook build` はすべて成功。

## 追記（壁版の割当領域方式への移行）

作成日: 2026-09-14

前セッションの最優先残課題だった「壁版の同様の移行」を実装した。`WallPlateShape::Enclosed { boundary }`
を廃止し、囲まれた壁版の境界は `Model::wall_plate_assignment_region(plate_id)` が返す壁版割当領域と
`Model::wall_assignment_region_nodes` / `assignment_region_boundary_coords` から解決する。
緑（`cargo test --workspace --locked` ほか）を保った。

### 実装済み

- **型移行**: `WallPlateShape` は `Enclosed`（単位）と `Attached { anchor, extent }` の 2 値。
  `WallPlate::boundary_nodes` / `boundary_coords` / `column_face_nodes` / `has_quad_boundary` /
  `area` は `&Model` を取り、囲まれた壁版は割当領域から解決する。壁版側に境界を重複保持しない
  （ADR 0020 の一方向参照）。`boundary_coords_with`（変形図用）は割当領域境界の頂点を
  `coord_of` へ通す。
- **編集コマンド（squid-n-edit）**: `AddEnclosedWallPlate`（任意節点境界）を廃止し、床板と同じ形の
  `AssignWallPlateToRegion { region, section, opening_area, opening_weight }` /
  `SetWallPlateRegionNoPlate { region }` / `UnsetWallPlateRegion { region }` を追加した。
  内部コマンド `SetWallPlateRegionAssignment` が状態＋壁版の生成・削除を一括適用し、
  適用前状態を復元する逆操作を返す。削除は `Model::retain_wall_plates` が `WallRegion.wall_plate_ids`
  と割当領域の参照を張り替える。`DeleteWallPlate` / `InsertWallPlate` も割当領域の参照を
  未設定化・復元する。`Model::visit_wall_plate_ids` が割当領域の版 ID を繰上げ・繰下げに追随する。
- **生成経路**: ST-Bridge 取り込みは `build_walls` が `PendingWall`（境界節点＋断面）を返し、
  柱・梁・間柱から `rebuild_wall_assignment_regions` で割当領域を再構築したうえで
  `assign_imported_walls` が境界一致で割り当てる。一致しない壁は `wall_attached_shape_from_boundary`
  でパラペット等の取り付く壁版へ変換できるときだけ取り込み、できなければ
  `StbError::WallWithoutRegion` で取り込み全体を失敗させる。
- **`wall_region_rebuild`**: 所属判定・取り付く壁版への変換は割当領域から解決した境界を使う。
  変換した壁版の割当領域は未設定へ戻す。
- **GUI（テーブル）**: 壁版タブの任意節点フォームを廃止し、壁版割当領域の一覧（ID・状態・境界節点数）と、
  未設定／版なし領域への断面を選んでの割当、版なし・未設定操作を追加した。3D の壁作成モードは
  ピックした 4 節点に一致する未設定の割当領域へ割り当てる形へ変更した。
- **MCP**: `model_edit` から `AddEnclosedWallPlate` を外し、`AssignWallPlateToRegion` /
  `SetWallPlateRegionNoPlate` / `UnsetWallPlateRegion` を配線した。壁版割当領域は既存の
  `model_query(kind=wall_assignment_region)` で照会できる。
- **`Model::validate`**: すべての囲まれた壁版がちょうど 1 つの壁版割当領域に割り当てられて
  いることを検証する。境界の重複は割当領域側で拒否する。
- **4 節点でない壁版**: 割当領域の境界が 4 節点でない囲まれた壁版は、壁エレメントにも
  周辺部材への剛性算入（`misc_wall` の `enclosed_geometry` は 4 節点前提）にも載せず、
  自重のみを境界辺へ配る。モデルタブ「壁版」の「解析要素」列と
  [床板・壁版の表示](../../docs/result_view/15_床板・壁版の表示.md) に明記した。

### 判断と理由（申し送り）

- **ST-Bridge の壁は境界一致を必須にし、不一致は取り込み全体エラーとした**: 床は水平面なので
  交差面積の按分ができるが、壁は任意の鉛直構面にあり、間柱で分割された割当領域への面積按分は
  未実装である。境界が一致しない壁を黙って落とすと壁の面積・重量を欠落させるため、安全側に
  エラーにして気づかせる。実データで必要になった時点で、床と同様の「覆う領域ごとの分割・
  面積按分」を実装する。
- **`Model::add_enclosed_wall_plate_from_nodes` はテスト・フィクスチャ用**: 境界辺ごとに既存の
  2 節点梁・二次部材を支持部材として使い、無ければ 2 節点梁を追加する。取り込みの本番経路は
  `rebuild_wall_assignment_regions` と境界一致（`assign_imported_walls`）を使う。
- **`rebuild_wall_assignment_regions` の防御的修正**: 実フィクスチャ（壁 0 枚）で
  `rebuild_wall_assignment_regions` を呼ぶと、退化した往復辺（span `[1,1]`）と同一境界の
  重複領域が発生し `validate` に落ちた。`normalize_boundary` が退化するマージを行わないようにし、
  面走査結果から同一境界を除去した。また `resolve_boundary_support` の新規要素 ID を
  `elements.len()` ではなく既存 ID の最大 + 1 に改め、要素 ID が添字と一致しないモデルでの
  衝突を防いだ。
- **4 節点でない壁版の剛性算入なしは危険側**: 壁の面内剛性を過小評価する。従来挙動の維持であり
  今回新たに導入した近似ではないが、割当領域境界が 4 節点でない壁版は剛性が解析に入らない。
  該当壁版はモデルタブの「解析要素」列で「解析要素」にならないことが確認できる。将来
  `misc_wall` を含めて一般化するかは別課題とする。
- **壁の要素 ID を index 前提から外した**: `Model::elements` の ID が添字と一致しない
  テスト（`add_surrounding_frame` が連番でない ID を作る）で仮の支持部材 ID が衝突していた。

## 追記（別型 `SecondaryMemberTopology` の廃止と片持ち自由端の解決）

作成日: 2026-09-14

`SecondaryMember` と別に存在した `SecondaryMemberTopology`（`Model.secondary_member_topologies`）を
廃止し、二次部材の取付き位置表現を `SecondaryMember.ends`（`Option<SecondaryMemberEnds>`）へ一本化した。
あわせて、取付き位置表現の片持ち自由端を 3 次元座標へ解決できるようにした。緑
（`cargo test --workspace --locked`・gui・mcp・clippy 3 本・`check-deps`・`mdbook build`）は保った。

### 実装済み

- **別型の廃止**: `SecondaryMemberTopology` と `Model.secondary_member_topologies` を削除した。
  検証は `validate_secondary_members(&[&SecondaryMember])` へ移し、`Model::validate` から呼ぶ。
  割当領域の再構築（`rebuild_floor_assignment_regions` / `rebuild_wall_assignment_regions`）は
  `joists()` / `posts()` を走査し、`ends` を持つ部材はアンカーから材軸を解決する（1 本の経路）。
- **片持ち自由端の解決**: `Model::secondary_member_end_points` を追加した。片持ちは支持端を
  アンカーから解決し、自由端を親構面の 2D ベクトルから 3 次元へ解決する。従来
  `secondary_member_axis` は片持ちを `None` としており、`ends` を持つ片持ちは荷重分配から
  落ちていた。解決規則は次のとおり。
  - 小梁: 水平面（全体 XY）。`自由端 = 支持端 + [vx, vy, 0]`。
  - 間柱: 鉛直構面の局所座標 `(s, z)`。`自由端 = 支持端 + [s·方向, 0, vz]`。
    間柱は鉛直で `s` は 0 のため、通常は `[0, 0, vz]` の加算になる。`s ≠ 0` の場合は
    支持端を通る構面が `region_gen::wall::wall_planes` から一意に取れるときに限り解決する。
- **実部材化判定の追随**: `secondary_member_materialized` は、`ends` を持つ部材では両端座標に
  一致する節点を結ぶ 2 節点 `Beam` 要素の有無で判定する（節点 ID の完全一致は取付き位置表現が
  持たないため）。
- **ID 検索・払い出し**: `Model::secondary_member(id)`・`alloc_secondary_member_id` は
  `joists()` / `posts()` の安定 ID を用いる。`support_member_axis` の二次部材解決も同経路。
- **`Model::validate`**: 安定 ID（`Some` のみ）の重複と、旧 `nodes` 表現の種別＋端点重複を検証する。
  取付き位置表現のアンカー参照・材軸位置範囲・支持グラフ循環・片持ち自由端は
  `validate_secondary_members` が検証する。
- **MCP**: `model_query` の kind を `secondary_member_end` / `secondary_member_ends` へ改め、
  `ends` を持つ二次部材を返す（旧 `secondary_member_topologies` 別名は削除）。

### 判断と理由

- **片持ちの自由端ベクトルの基底を種別で分けた**: 小梁は常に水平、間柱は常に鉛直であり、
  親領域を検索しなくても種別だけで基底が決まる。壁の `s` 成分が非零のときは構面が一意に
  定まらないため `None` とし、荷重を黙って欠落させない（片持ちの `ends` は生成経路が
  正しい基底で作る責務を持つ。生成経路のアンカー化は次段）。
- **`SecondaryMember.ends` を `Option` のまま残した**: 取付き位置表現を持たない旧 `nodes` 表現の
  部材が本番（ST-Bridge 取り込み）に残るため。両表現の併存は本追記の範囲では解消しない。

## 追記（二次部材の支持部材アンカー生成）

作成日: 2026-09-14

ST-Bridge 取り込みと解析前処理で、二次部材（小梁・間柱）の両端節点から
「どの支持部材（大梁・柱・他の二次部材）の材軸上のどこ（0..1）に載るか」を解決し、
`SecondaryMember.ends`（`SecondaryMemberAnchor`）を設定するようにした。緑
（`cargo test --workspace --locked`・gui・mcp・clippy 3 本・`check-deps`・`mdbook build`）は保った。

### 実装済み

- **節点 → 支持部材アンカー**: `Model::resolve_node_anchor(node, exclude)` を追加した。
  主架構の 2 節点 `Beam` を要素 ID 昇順で調べ、材軸上（端点を含む）にあれば最も近い要素を
  優先する。無ければ他の二次部材の**内法**に載るものを安定 ID 昇順で調べる。いずれも距離
  `MEMBER_AXIS_TOL_MM` [mm] 以内で最も近い候補を採り、入力順に依存しない。
- **両端節点 → `ends`**: `Model::secondary_ends_from_nodes(id, kind, nodes, end_support)` を
  追加した。両端支持は `Supported([a, b])`、片端自由は支持端を基準とした親構面内ベクトルの
  `Cantilever` へ変換する。小梁は水平面（XY）、間柱は鉛直構面の局所座標 `(s, z)`。
- **一括変換**: `Model::anchorize_secondary_members()` を追加した。全二次部材の
  `(id, kind, nodes, end_support)` を不変のまま集め、アンカーを解決してから `ends` を
  設定する。解決できた部材数と、解決できなかった節点対を返す。
- **取り込み**: `assemble` が `infer_secondary_end_supports` の直後に一括変換を呼ぶ。
  自由端の推定結果をそのまま片持ちへ写す。解決できなかった部材は件数を `notes` に出し、
  旧 `nodes` 表現のまま残す（荷重・重量は従来どおり節点経由で扱い、欠落させない）。
- **解析前処理・GUI**: `squid_n_job::prepare::prepare_model_for_analysis` と GUI の
  `refresh_preparation` が、割当領域の再構築の前に一括変換を呼ぶ。モデルの編集
  （端部支持条件の変更・節点の移動）の後も、割当領域・検定・解析が同じアンカーを見る。

### 判断と理由

- **支持部材の選択は主架構優先・距離最小**: 節点が大梁の材軸上にあるならその大梁が直接
  支持するため、10 mm 以内に並走する二次部材へ支持を奪わせない。既存の逐次伝達
  （`squid_n_load::cascade`）と同じ規則にそろえ、荷重経路とアンカーが食い違わないようにした。
- **不明端点は「未所属（旧表現）として残す」を選んだ**: 支持が見つからない支持端を
  片持ちへ読み替えると、本来支持されるはずの荷重の行き先を奪い危険側になり得る。
  解決できた部材だけをアンカー表現へ移し、できない部材は旧 `nodes` 経路のまま残す。
  取り込み報告に件数を出す（黙って落とさない）。実フィクスチャ（`model.stb`）の
  二次部材は 56/56 本すべて解決できている。

### 完了しなかった理由（旧フィールド削除）

`SecondaryMember` の `nodes`・`end_support` の削除（セッション目標 2）は**未完**である。
`nodes` を消すと、荷重分配の `LoadTarget::Span { nodes: [NodeId; 2], t }` と逐次伝達の
`SecondaryKey = (NodeId, NodeId)` が端点節点を参照できなくなる。これらは材軸途中の取付きを
表せる安定 ID への移行が前提であり、次段の `LoadTarget::Span` 安定 ID 化と同じ作業になる。
先に旧フィールドだけを消すと、端点節点を持たない（材軸途中に取り付く）二次部材の荷重が
行き先を失う危険側の状態になるため、生成側のアンカー化（本追記）までで止めた。
フィールド名を一時的に退避して数えた素の参照エラーは core だけで 56 件、下流を含めると
さらに増える。次段は `SecondaryKey` / `LoadTarget::Span` の安定 ID 化と一体で行う。

  片持ち小梁を境界に使える。
- `EndSupport` 型は編集コマンド `SetSecondaryMemberEndSupport` の入力（支持／自由の 2 要素）と
  GUI の候補表示、`SecondaryJoistAxis` の作業用フィールドとして残した（公開 API が使うため
  意図的な残置。`SecondaryMember` のフィールドではない）。

### 2. 荷重分配の安定 ID 化（load/job）

- `cascade::SecondaryKey = SecondaryMemberId`。`Axis`・`TransferredMember` の `nodes` を
  安定 ID と端点座標に置き換えた。`primary_node_loads` は端点座標から節点を引いて主架構へ渡す
  （従来と同じ経路・同じ総和）。
- `LoadTarget` に `Secondary { member: SecondaryMemberId, t }` を追加した。取り付く床板の支持辺が
  二次部材小梁のとき、節点対ではなく安定 ID で対象を指す。`Span { nodes, t }` は節点対で表す
  実部材・床板境界辺の幾何解決用に残した（床板境界はモデル節点のまま）。
- `SecondaryJoistAxis` は `member` を持ち、`nodes` 依存を 0 にした。
  `secondary_joist_distribution_split`・`SecondaryJoistLoads` は安定 ID をキーにする。
- `wall_plate_load` の間柱キー、`joist_design` の分配欠落判定、`job` の自動荷重も安定 ID に
  追随させた。実 `Beam` が存在する小梁へ分布荷重を載せる二重計上回避の既存挙動は維持した。

### 3. アンカー未解決時の扱い（安全側の判定）

- 支持端のアンカーを解決できない二次部材は `SecondaryMemberEnds::Detached`（端点座標）で保持する。
  **重量・材軸長を欠落させない**。
- 荷重は伝達せず、解析前チェックが「支持部材アンカーへ解決できない二次部材」を**エラー**にして
  解析を止める。片持ちへの読み替えはしない（**危険側**のため行わない）。
- 旧実装は `nodes` のまま残して節点経由で扱っていた。新実装は安定 ID と生座標のみで、この状態は
  利用者に見える（ST-Bridge 取り込み報告の notes・解析前チェック・`CONTEXT.md`）。
- この判定を `docs/calc_basis/01_荷重/03_床荷重の分配.md`・
  `docs/model_io/03_ST-Bridge_要素別変換状況.md`・`CONTEXT.md` に記載した。

## 追記（独立レビュー指摘の修正: 材軸中間アンカーの欠落防止）

作成日: 2026-09-15

安定 ID＋支持部材 ID＋材軸位置（`SecondaryMemberEnds::Supported { position }`）で材軸中間を
指せるようになった一方、各所に「端＝モデル節点」という旧前提が残り、新しいアンカーを無言で
捨てる経路があった。独立レビューの指摘 1〜6 のうち、以下を修正した。緑
（`cargo test --workspace --locked`・gui・mcp・clippy 3 本・`check-deps`・`mdbook build`）は保った。

### 1. 密度直接算入での二次部材自重の欠落（危険側）

- `story_gen::self_weight_calc::enumerate_self_weight` が、二次部材の端座標に一致する節点が
  無いと `continue` して自重を捨てていた。`secondary_end_weight_node` を追加し、一致節点が
  無ければ**最も近い構造節点**（剛床代表節点を除く。Z 優先 → 3 次元距離 → 添字で決定的）へ
  配って欠落させない。
- **二重計上の確認**: 標準構成（DL あり）では `generate_stories_with_opts` が
  `include_density_self_weight = false` で呼ばれ、`SelfWeightItem::SecondaryLine` は
  `node_weight` へ入らない（`self_weight_case_content` も `SecondaryLine` を扱わない）。
  二次部材の自重は逐次伝達（`cascade::solve` の `include_self_weight`）だけが運ぶ。修正は
  `include_density_self_weight = true`（DL なし）の経路にのみ効くため、DL 経路との二重計上は
  無い。
- 回帰テスト: `story_gen::tests::test_secondary_member_on_midspan_is_seismic_weight_in_density_path`
  （大梁の材軸位置 0.5 にアンカーした小梁の自重が、密度直接算入で階の地震用重量に含まれる）。
- 仕様は `docs/calc_basis/01_荷重/05_地震用重量_層データの生成.md` に追記した。

### 2. ST-Bridge 書き出しでの二次部材の無言消失

- 端に一致する節点が無い二次部材を黙って `continue` していたのを、`members_body` が
  未出力 ID を集計し `StbError::SecondaryWithoutNode`（件数と対象 ID）で書き出し全体を
  失敗させるようにした。ST-Bridge は材端を節点 ID で表すため材軸中間の取付きを表現できず、
  ADR 0020 の「二次部材用のモデル節点を作らない」と両立させる最小の安全側対応として、
  節点合成ではなくエラーで可視化する方を採った。
- 回帰テスト: `stbridge::tests::test_export_errors_when_secondary_has_no_end_node`。
- 仕様は `docs/model_io/03_ST-Bridge_要素別変換状況.md` に追記した。

### 3. `Detached` からの端部支持条件変更が無言 Noop

- `squid_n_edit::secondary::ends_supported` が `Detached` を `[true, true]` と返していたため、
  表で「支持-支持」を選んでも同条件と判定して Noop になり、アンカー再解決が走らなかった。
  `Detached` は `None` とし、「支持-支持」指定時に `secondary_ends_from_coords` で再解決する。
- 回帰テスト: `tests::set_secondary_member_end_support_recovers_detached`。

  外れていた。端に一致する節点が無い場合は材端と同じレベルの節点から階を引き、`copy_secondary`
