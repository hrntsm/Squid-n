# 剛域長の算定を技術基準へ揃える 申し送り

作成日: 2026-08-11
対象コード: `crates/squid-n-element/src/frame/beam/rigid_zone.rs`、
`crates/squid-n-element/src/wall/misc_wall.rs`、
`crates/squid-n-core/src/model/stress_cfg.rs`、
`crates/squid-n-app/src/app/{actions.rs,panels.rs}`

## 1. 背景

利用者から、剛域長の算定が技術基準と食い違っているとの指摘があった。資料の規定は
次のとおり。

- ある節点に集合する**柱と大梁がすべて RC/SRC 造**のとき、その節点に集合する柱・
  大梁の端部に剛域を設ける（初期設定値）
- 剛域長 `Lg = Lf − D/4`（`Lf` = 節点から部材フェースまでの距離、`D` = 部材せい）
- 「部材フェース」「部材せい」には、部材の原断面を用いるか**取り付く壁を考慮した値**
  を用いるかを選択できる（初期設定値は「壁を考慮する」）。両側に取り付く壁の長さが
  異なる場合は長い方の壁を基準にする。ここでいう「壁」は現場打ちコンクリート壁で
  厚さ 100 mm 以上のもの
- 両端の剛域長の合計が部材長を超える場合は、**部材長の中点から部材せいの 1/4**
  の距離までを剛域とする

## 2. 実装との差分（修正前）

| 項目 | 資料 | 修正前の実装 | 判定 |
|------|------|--------------|------|
| 基本式 | `Lg = Lf − D/4` | RC/SRC: `λ = reduction·(D_直交/2 − D_自身/4)` | 一致（`reduction` は資料にない追加係数。既定 1.0） |
| 適用条件 | 節点の柱・大梁がすべて RC/SRC のときのみ | 自部材が S/CFT でも `λ = D_直交RC/2` を与える（`D_自身/4` の控除なし） | **相違** |
| 部材フェース・部材せい | 既定で壁を考慮 | 原断面 `sec.depth` のみ | **相違**（未実装） |
| 両端の剛域長が重なる場合 | 中点から部材せい 1/4 | `rigid_arm::resolve_lengths` が剛域なし `(0,0)` に落とす | **相違** |

`λ = D_直交RC/2` という S 部材向けの式は意図的に書かれたコードで、docs
（`04_要素剛性/01_ティモシェンコ梁要素.md` §4.1.4）にも明記され、
`test_auto_rigid_zone_steel_beam_rc_column` が「S梁+RC柱: λ = 柱せい/2 = 300」を
期待値として固定していた。S 造の仕口は剛域ではなく仕口パネル
（`RigidZone::panel_offset_i/j`）でモデル化するため、剛域も与えると接合部を二重に
剛く評価することになる。

## 3. 修正内容

### 3.1 適用条件

`all_rc_src_at`（新設）で、節点に集合する `ElementKind::Beam` がすべて RC/SRC 系か
判定し、1 本でも S 系があればその端の剛域長を 0 にする。対象部材自身も判定に含める。
ブレース・壁・仕口パネルと、解析要素ではない二次部材（小梁・間柱）は判定の対象外。

これに伴い、`max_orth_depth` の `only_rc_src` 引数（λ 用に RC/SRC の直交材だけを
見る分岐）は不要になった。適用条件が成り立つ節点では直交材は定義上すべて RC/SRC に
なるためで、λ と face が同じ幾何量 `Lf` を共有する形に整理した
（`max_orth_depth` → `max_orth_face`。せいの 2 倍ではなくフェース距離そのものを返す）。

### 3.2 壁の考慮

`wall_protrusion`（新設）が、部材に取り付く壁の「部材フェースからの張り出し」
（壁の長さ − 部材せい/2）を返す。壁の長さは既存の `MiscWall::wing_length`（袖壁）・
`strip_height`（腰壁・垂壁）をそのまま使う。

- **部材せい D は向きを持たない**ため、取り付く壁のうち張り出しが最大のものを採る
  （「両側で長さが異なる場合は長い方」）。
- **部材フェース Lf は向きを持つ**。柱の片側だけに袖壁がある場合、フェースが外側へ
  移るのは袖壁が張り出している側に取り付く梁だけで、反対側の梁は移らない。
  `wall_protrusion` の `toward` 引数でこれを表す。この点は資料に明示がなく、
  幾何的に自然な解釈として実装した（利用者と合意済み）。
- 対象の壁は `collect_rigid_zone_walls`（新設）で集める。**耐震壁も含む**点が
  `collect_misc_walls`（耐震壁不成立の壁だけ）との違い。判定は「RC 壁かつ厚さ
  `RIGID_ZONE_WALL_MIN_THICKNESS_MM` = 100 mm 以上」。耐震壁の板厚条件 120 mm とは
  別の閾値であることに注意。三方スリット壁はいずれの用途でも周辺部材と縁が切れて
  いるため除く。
- 収集の重複を避けるため、`collect_misc_walls` と共通の走査を `collect_walls_where`
  へ切り出し、受け入れ条件だけを差し替える形にした。

### 3.3 重なりのクランプ

両端の剛域長の合計が材長以上になる場合、`λi = λj = max(0, L/2 − D/4)` へ丸める。
自動算定（`rigid_zone_with_adjacency`）の中で行う。手入力で上書きした結果として
重なった場合は従来どおり `rigid_arm::resolve_lengths` が剛域なしへ落とす
（そちらは部材せいを知らないため。設計上の役割分担として docs に明記した）。

### 3.4 設定

`StressAnalysisCfg::rigid_zone_consider_walls`（既定 `true`）を追加し、
`RigidZoneRule::consider_walls` へ渡す。GUI は解析タブの準備計算セクションに
チェックボックス「剛域の算定で壁を考慮する」を追加した。既存プロジェクトファイル
（.scz）は `#[serde(default = ...)]` により既定 `true` で読める。

## 4. 結果への影響

添付の実建物モデル（`crates/squid-n-app/tests/fixtures/model.stb`）で、修正前は
剛域長が 0 でない部材 29 本のうち **12 本が S 系**だった（S 大梁が RC 柱に取り付く
仕口）。修正後はこれらが 0 になる。本モデルに壁要素はないため、壁考慮による変化は
ない（壁の効果はユニットテストで検証している）。

| 項目 | 修正前 | 修正後 |
|------|--------|--------|
| T₁ | 0.4676 s | 0.5266 s |
| T₂ / T₃ | 0.4246 / 0.3810 s | 0.4811 / 0.4312 s |
| EX 最上階変位 | 16.54 mm | 19.62 mm |
| 1FL 層間変形角 | 1/1121 | 1/673 |
| 最大検定比 | 0.5552 | 0.6092 |

本来存在しないはずの剛域が取れたことで建物が柔らかくなり、周期が伸びて変形・検定比が
増える方向に動いた。修正後が正しい。

## 5. 残課題

- **`reduction`（剛域長の低減率）は資料に規定がない**。既定 1.0 で式に影響しないが、
  UI からも設定できない死んだパラメータになっている。残すか外すか未決。
- 壁を考慮した寸法は**剛域の算定にのみ**反映している。断面算定の危険断面位置は
  同じ `face_i/face_j` を使うため連動するが、部材の自重（`enumerate_self_weight` が
  `face_i/face_j` で内法長を求める）にも連動する点は意図的か未確認。壁付き RC 梁の
  自重が内法長の短縮分だけ減ることになる。
- 統合テストの `full_model` は壁のないモデルのため、壁考慮の経路は
  `squid-n-element` のユニットテストでしか守られていない。壁付きの実モデルを
  フィクスチャに追加できると望ましい。
