# 実モデル（ST-Bridge）による統合テストの追加 申し送り

作成日: 2026-08-11
対象コード: `crates/squid-n-app/tests/full_model.rs`、
`crates/squid-n-app/tests/fixtures/model.stb`、
`crates/squid-n-app/tests/snapshots/full_model__snapshot_key_scalars.snap`

## 1. 背景と目的

機能を追加するたびに、既存の解析経路がどこかで動作しなくなる事象が繰り返し
発生していた。原因は、テストがすべて**手組みの小規模モデル**（門型ラーメン・
1 層立体フレーム）を対象にしていたことにある。実建物のモデルは

- 剛床（各階のダイアフラム）
- 二次部材（小梁）と、その支持点で区切られたパネルスラブ
- S 造と RC の混構造
- 多数のスラブ（82 面）と自動生成される仕口パネル

といった構成を同時に含み、これらが組み合わさったときだけ現れる不具合が
`dev_docs/handoff/` の申し送りに繰り返し記録されている（`剛床上の梁の応力欠落`、
`基部の剛床に小梁支持点`、`階と剛床の分離` など）。

そこで、実際の設計モデルを 1 つフィクスチャとして固定し、**GUI のボタンが呼ぶのと
同じ入口**（`App` の `run_*` / `compute_*`）で全解析を通す統合テストを追加した。

## 3. テストの構成

### 3.1 対象範囲

`App` の実行系エントリを解析ごとに 1 テストへ分割し、共通の「取り込み＋準備計算」は
ヘルパー（`imported()` / `prepared()` / `analyzed()`）で共有する。分割したのは、
1 本にまとめると最初の失敗以降が未検証になり、切り分けに毎回時間がかかるため。

| # | 解析 | テスト |
|---|------|--------|
| 1 | ST-Bridge 取り込み | `import_builds_expected_model` |
| 2 | 準備計算 | `preparation_computes_stories_and_seismic_forces`、`preparation_is_idempotent` |
| 3 | 診断 | `diagnostics_are_clean` |
| 4 | 静的（全ケース・全組合せ） | `static_all_solves_every_case_and_combination`、`dead_load_transfers_to_column_bases`、`combination_is_linear_sum_of_load_cases` |
| 5 | 固有値 | `eigen_returns_descending_positive_periods` |
| 6 | 地震静的 X/Y | `seismic_static_produces_monotonic_story_displacement` |
| 7 | 一次設計（断面検定） | `design_check_covers_every_member` |
| 8 | 二次設計（層指標） | `story_metrics_computed_for_every_layer` |
| 9 | 保有水平耐力・Ds・終局検定 | `holding_capacity_and_ultimate_checks` |
| 10 | 増分解析 | `pushover_reaches_ultimate_state` |
| 11 | 時刻歴（線形／非線形） | `time_history_linear_runs` / `time_history_nonlinear_runs` |
| 12 | SCZ 往復・ST-Bridge 往復 | `scz_roundtrip_preserves_model_and_results`、`stbridge_roundtrip_is_reanalyzable` |
| — | 代表スカラの固定 | `snapshot_key_scalars` |

全テストの実行時間は dev プロファイルで **数秒**。重量テストの分離
（`#[ignore]` による除外・`--release` 限定）は不要と判断した。

### 3.2 検証の三層構造

煙テスト（エラーなく完走し結果が空でない）だけでは、過去に実際に起きた
「エラーは出ないが応力が欠落する」「サイレントにゼロ変位を返す」類を検出できない。
そのため次の 3 層で検証する。

1. **煙テスト** — `last_error` が空、結果が空でない
2. **構造的不変量** — 全部材に断面力がある／固定荷重で全柱脚が圧縮／固定荷重で
   上向きに動く節点がない／固有周期が正で降順／モード形状が全ゼロでない／
   地震時の水平変位が上階ほど大きい／層せん断が上階ほど小さい／
   最終ステップのベースシアが Qu と一致する／組合せが荷重ケースの線形和に一致する
3. **代表スカラのスナップショット** — 値そのものの変化を差分として見せる

### 3.3 判定上の注意

- **`App::last_error` は注意（Notice）でも埋まる。** ST-Bridge 取り込みは
  「欠落属性の要約」「支点の自動設定」といった注意も `report_error` 経由で
  `last_error` に載せる（`app/actions.rs` の `import_stbridge_from`。ステータスバーで
  見落とされないようにするための仕様）。テストは「先頭が ⚠ 以外ならエラー」と判定し、
  各ステップの前に `clear_error` でクリアする。
- **`threads = 1` を全テストで指定する。** 既定の 0（全コア）では並列リダクションの
  加算順が実行ごとに変わりうるため、スナップショットが安定しない。
- **スナップショットは有効数字 4 桁の指数表記に丸める**（`sig4`）。スナップショットは
  手元（Windows）で生成して CI（Linux）で照合されるため、浮動小数の環境差
  （ベクトル化の差・`faer` の並べ替え・libm の実装差。通常 1e-12 オーダー）で
  偽陽性にならない桁まで落とす。4 桁あれば設計上意味のある変化は確実に捕まる。
  もし CI で不一致が出た項目があれば、その項目だけ許容誤差付きアサート
  （`assert_relative_eq!` 相当）へ逃がす。
- **準備計算の階の表（`PrepStoryRow`）は「層」を並べる**ため、行数は
  `Model::stories` の階数より 1 少ない（5 階 → 4 行）。
- **ST-Bridge 往復は準備計算の前に行う。** 準備計算は仕口パネル要素を
  `Model::elements` へ追加するが（115 → 157）、これは解析用の生成物であり
  ST-Bridge には書き出されない。準備計算後のモデルと突き合わせると要素数が
  一致せず、往復の検証にならない。

## 4. 発見した不具合

統合テストの追加とバグ修正を切り分けるため、発見時点ではいずれも修正せず
`#[ignore]` で残した。4.1・4.2 はその後修正済み。残る 4.3 は
`cargo test -p squid-n-app --test full_model -- --ignored` で再現できる。

### 4.1 準備計算が 1 回目と 2 回目で固定荷重を変える（影響度: 高）— **修正済み**

テスト: `preparation_is_idempotent`（`#[ignore]` を解除して常時実行）

**症状**: 実建物モデルで準備計算を 2 回実行すると、固定荷重 DL の内容が変わる。

- 部材荷重 702 件のうち **17 件の強度が下がる**（例: 材長 4000 mm の梁で
  w = 21.6 → 11.88 N/mm、材長 8800 mm の梁で 21.6 → 17.18 N/mm）
- DL の総鉛直外力が **6,889,465 N → 6,228,505 N**（−660,960 N、約 9.6%）へ減る
- 階の地震用重量もこれに追随し、最下階（1FL）が 3,702,394 N → 3,041,434 N へ減る
- 3 回目以降は 2 回目と同値で安定する

準備計算は各解析の実行前にも自動で走るため、「準備計算を実行した回数」で
柱脚軸力・断面検定の結果が変わる状態だった。

**原因**: `App::generate_stories_action`（`app/actions.rs`）が

1. `sync_gravity_load_cases_action()`（自重を DL へ同期）
2. 階の生成
3. `apply_rigid_zones_for_analysis()`

の順で実行していた。RC/SRC 梁の自重は**柱面間の内法長**
`L_eff = L - face_i - face_j` で算定する
（`squid_n_load::story_gen::self_weight_calc` の `enumerate_self_weight`）が、
`RigidZone::face_i/face_j`（柱フェース距離）を埋めるのは 3 の
`apply_auto_rigid_zones` である。したがって 1 回目は face が**未算定（0）**の
まま自重が同期され、節点間距離で算定した過大な値が DL に入っていた。2 回目は
face が入った状態で同期が走るため正しい値になり、そこで安定していた。

`refresh_preparation` → `sync_auto_load_cases_action` は同期のハッシュ一致で
早期 return するため、1 回目の実行中に取り違えが自己修復されることもなかった。

**「剛域の有無で自重が変わる」わけではない**（当初そう記述していたが誤り）。
自重が参照するのは柱フェース距離 `face_i/face_j` だけで、剛域長 `length_i/j` は
一切参照しない。face は接合関係と直交部材のせいから一意に決まる幾何量であり、
`recompute_auto_zones` は剛域長の Manual/Auto フラグとは独立に**常に**再算定する
（`squid-n-element/src/frame/beam/rigid_zone.rs`）。つまり剛域長を手入力で
上書きしても自重は変わらない。問題は「剛域が無効だった」ことではなく、
「幾何量である face がまだ算定されていなかった」ことである。

**修正**: `generate_stories_action` の先頭で `apply_rigid_zones_for_analysis()` を
呼び、自重の同期より前に face を算定するようにした。算定は部材の幾何と断面のみに
依存し、階の生成結果には依存しないため、先に呼んで差し支えない。

**残る設計上の弱さ**: `face_i/face_j` は幾何から一意に決まるにもかかわらず、
`ElementData::rigid_zone` にキャッシュとして持たれ、名前が剛域を指す関数
`apply_auto_rigid_zones` が副次的に埋めている。今回のように「呼ぶ前に読む」
経路が新設されれば同じ事故が再発する。face を必要な箇所で幾何から都度求めるか、
少なくとも剛域長とは別の関数で算定するのが本来の姿である。統合テストの
`preparation_is_idempotent` が同種の再発を検出する。

**結果への影響**: 過大だった自重は 1FL の RC 基礎梁のもので、支点へ直接流れる
経路にあるため柱脚軸力（`static.DL.sum_base_axial`）と最大鉛直変位は変わらない。
変わったのはその基礎梁自身の断面検定（`design.max_ratio` 6.019e-1 → 5.552e-1）と、
そこから波及する増分解析の Qu（2.427e6 → 2.426e6 N）・偏心率の末尾桁のみ。
地震力算定に使う ΣW は最下階を含まないため、地震静的解析・保有水平耐力の
主要値は変わらない。

**関連するドキュメント更新**: 柱面間距離が何を指すのか（＝柱フェース距離であり
剛域長ではないこと）が利用者向けドキュメントに書かれていなかったため、
`docs/calc_basis/01_荷重/05_地震用重量_層データの生成.md` に明記した。

### 4.2 非線形時刻歴応答解析が実建物モデルで収束しない（影響度: 中）— **修正済み**

テスト: `time_history_nonlinear_runs`（`#[ignore]` を解除して常時実行）

既定設定で `step 50 did not converge` となり完走しなかった。原因は収束判定の基準
ノルムで、動的外力 `p_dyn` だけを基準にしていたため、**地動加速度がゼロを横切る時刻**
（サンプル波は周期 0.5 秒なので t=0.25・0.50…）で基準が消えて床の 1.0 N まで落ち、
判定が到達不能な絶対値判定に化けていた。材料の非線形性は無関係で、このモデルは
時刻歴でも塑性化していない。

基準ノルムを動的釣り合いの各項（外力・慣性力・減衰力）の最大へ改めて解消した。
詳細は [非線形時刻歴の収束_申し送り.md](./非線形時刻歴の収束_申し送り.md) を参照。

### 4.3 ST-Bridge から取り込んだ小梁が断面検定されない（影響度: 中）— **修正済み**

テスト: `joist_design_checks_cover_imported_secondary_members`

ST-Bridge 取り込みは小梁を `Model::secondary_members` へ入れるが、床の
`Slab::joists` は空のまま（床荷重の二重計上を避ける）。`floor_design_checks` が
`secondary_members` の小梁も見て、中点のスラブ帰属・負担幅から単純支持梁として
断面検定するよう修正した。

## 5. 観測しているが不具合ではない事項

- **増分解析でヒンジが 1 つも発生しない**（`pushover.hinges = 0`、
  `mechanism = Partial`）。既定の終了条件が「目標最大層間変形角 1/150」
  （`push_use_drift_angle = true`・`push_drift_denom = 150`）であり、本モデルは
  その変形に達するまで弾性に留まるため。38 ステップで目標に到達して正常終了して
  いる。したがってスナップショットの `pushover.Qu = 2.427e6` は「1/150 の変形時の
  水平力」であって、部材の塑性化を伴う耐力ではない。
- **`design.slab_checks = 81`**（スラブは 82 面）。1 面は一方向版として設計スパンを
  決められない形状のため対象外になる。

## 6. 今後

- 残る `#[ignore]` は 4.3 の 1 件。
- `App` に解析エントリを追加したら `full_model.rs` にもテストを追加する
  （CONTRIBUTING.md「実モデルの統合テスト」に明記済み）。ソースを走査して
  追加漏れを機械的に検出する仕組みは、リネームやファイル分割で壊れるため
  今回は入れていない。
- フィクスチャを増やす場合は `crates/squid-n-app/tests/fixtures/` に置き、
  本ファイルにモデルの諸元を追記する。RC 造・SRC 造・耐震壁付きなど、
  構造種別の異なるモデルを 1 つずつ足すのが費用対効果が高い。
