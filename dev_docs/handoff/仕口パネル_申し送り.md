# 仕口パネル（柱梁接合部パネル）の導入 申し送り

関連文書: [仕口パネル_定式化と検証_2026-07.md](../v_and_v/仕口パネル_定式化と検証_2026-07.md)、
`docs/calc_basis/04_要素剛性/06_パネルゾーン.md`、`docs/preparation/06_仕口パネル.md`

## 1. 何が問題だったか

「パネルの設定はあるがモデル化を有効にできない」という指摘から着手した。調査の結果、
次の 2 つが別の問題として存在していた。

### 1.1 モデル化が存在しなかった

`ElementKind::PanelZone` と `PanelZone` 要素の定義はあったが、**生成する経路が無く実モデル
には現れなかった**。剛性方式も `RigidZoneApprox`（剛性ゼロ）固定で、`ElasticShearPanel` は
到達不能なうえ、中心節点の並進自由度へ対地ばねを与える誤った定式化だった。

### 1.2 検定はあったが「見えて」いなかった

S/SRC パネルゾーンの断面検定は `joint_wiring` から**無条件に実行**され、設計タブの表には
出ていた。一方で次が欠けており、利用者からは「検定が無い」ように見えていた。

- 3D 検定比図の節点マーカーが半径 5px の点のみ（数値ラベルもホバー詳細も無し）
- レポート CSV に `[部材検定]` しか無く、接合部・パネル・耐震壁の検定が 1 行も出ない

## 2. どう直したか

### 2.1 モデル化（力学中核）

利用者から提供された資料「仕口パネル」§2.10 に従い、接合部の節点へせん断変形角
\\( \gamma_X \\)・\\( \gamma_Y \\) の 2 自由度を追加する方式で実装した。式と既定値は
利用者向けドキュメントに記載してある。実装上の判断（追加自由度の置き方、`[B]` 変換を
剛域変換へ帰着させた根拠、\\( \zeta \\) の解釈、体積 \\( V_e \\) の扱い）は V&V レポートに
まとめた。

主要なファイルは次のとおり。

| ファイル | 役割 |
|---|---|
| `squid-n-core/src/panel_zone.rs` | 柱断面 → パネル諸元（dc・tp・κ・Ve）と梁の db。**要素側と検定側の唯一の出所** |
| `squid-n-core/src/dof.rs` | パネル自由度の払い出し（`panel_dof` / `has_panel_dof` / `panel_dof_ref`） |
| `squid-n-element/src/springs/panel.rs` | 仕口パネル要素（弾性・弾塑性） |
| `squid-n-element/src/springs/panel_gen.rs` | パネル要素の自動生成（準備計算の前処理） |
| `squid-n-element/src/frame/panel_offset.rs` | パネルへ接合する部材のデコレータ |

### 2.2 検定の可視化・出力

- 3D 検定比図: 節点マーカーをひし形へ変更し NG は拡大。ホバーで種別・検定比・判定・根拠を
  表示し、NG または「全ラベル表示」ON で検定比を数値描画。凡例にも件数を追加
- レポート CSV: `[接合部検定]`（節点・種別・検定比・判定・根拠）を追加
- 検定の \\( {}_p M \\): パネルをモデル化した節点は解析出力の \\( M_{SX} \\)・\\( M_{SY} \\)、
  していない節点は従来の手組み式。**検定の実施自体はモデル化の有無に依らない**

## 3. 既存挙動への影響（重要）

### 3.1 既定オンのため既存モデルの結果が変わる

`Model::panel_zone` は既定が `Model`（モデル化する）で、`#[serde(default)]` により旧 `.scz`
も既定値で補完される。したがって **S 造モデルは再解析すると結果が変わる**。後方互換は
考慮不要との判断（利用者確認済み）。

変化の向きは 2 つの効果の合成になるので注意。

- パネルのせん断変形 → 柔らかくなる
- パネル分オフセットが剛域として働く → 硬くなる

接合部を無視した従来モデルとの比較では後者が勝ち、**全体としては硬くなる**のが普通。
「パネルを入れたのに硬くなった」は不具合ではない。

### 3.2 準備計算がモデルの要素配列を変更する

パネルは準備計算（`apply_rigid_zones_for_analysis` の末尾）で再生成される。`Model` は
「配列添字 == `ElemId`」を不変条件とするため、生成・削除では要素 ID を詰め直し、部材荷重・
部材グループ・側テーブル属性の参照も同時に付け替えている（`panel_gen::remove_existing_panels`）。

**新しく `ElemId` を参照する側テーブルを追加する場合は、この詰め直しの対象へ加えること。**
現状は `Model::shift_elem_attr_refs` に載っているものと、`load_cases[].member[].elem`、
`beam_groups` を処理している。

### 3.3 ねじり解放の判定からパネルを除外した

`beam/torsion.rs` はパネルを「材軸まわり回転を拘束する要素」とみなしていたが、新しい
パネルは節点の標準 6 自由度へ剛性を与えないため、拘束ありとみなすと材軸まわり回転が
浮いた節点を見逃して全体剛性行列が特異になる。判定から除外した。

### 3.4 呼び出し規約の変更

- `joint_wiring::collect_joint_checks_with_long` に `panel_moments` 引数が増えた
  （`collect_joint_checks` は空スライスを渡すラッパのまま）
- `StaticOnce` に `panel_moments` フィールドが増えた
- `ElementBehavior` に `panel_moments_from` が増えた（既定 `None`）
- `steel::panel_zone::SPanelInput` に `design_moment: Option<f64>` が増えた
- `springs::panel` の `PanelZone::evaluate` は自由関数 `face_moments(dc, db, tp, &conn)` へ
  移した（原典照合済みのテストはそのまま維持）

## 4. 残課題

V&V レポート §4 に列挙した。設計判断に直結するものを再掲する。

- **\\( \theta \\)（パネル部材座標系の回転角）とパネル中心オフセットは 0 固定**。変換は
  一般の \\( \theta \\) で実装済みなので、斜交フレーム対応は入力の追加で足りる
- **表 2.10.1 の 4 ケース**は「接合位置＝柱フェース距離」に相当する整合のみ実装
- **斜材はパネル自由度と連成しない**（資料が接合位置・\\( \zeta \\) を定めていない）
- **`Section::panel_thickness` の入力 UI は未追加**。解決順（断面形状から算定し、
  `panel_thickness` があれば優先）は実装済みだが、GUI から入力する手段がまだ無い。
  ダイアフラム補強・ダブラープレートの明示指定を使うには断面編集への欄追加が要る
- **パネル節点の判定が要素走査**。側柱判定と同じ計算量の posture だが、大規模モデルでは
  隣接マップの事前構築へ寄せる余地がある
- **`SteelBuiltH`（組立 H 形）柱は対象外**。κ の標準式が適用できないため。断面検定側も
  従来から対象外で、挙動は変えていない

## 5. テストの入口

| 対象 | 場所 |
|---|---|
| パネル諸元の解決 | `squid-n-core/src/panel_zone.rs` の `tests` |
| 追加自由度の払い出し | `squid-n-core/src/dof.rs` の `test_panel_node_gets_two_extra_dofs` 他 |
| パネル要素（弾性・弾塑性） | `squid-n-element/src/springs/panel.rs` の `tests` |
| パネル生成（冪等性・ID 整合） | `squid-n-element/src/springs/panel_gen.rs` の `tests` |
| `[B]` 変換 | `squid-n-element/src/frame/panel_offset.rs` の `tests` |
| 系レベル（解析解照合・釣り合い） | `squid-n-solver/tests/panel_zone.rs` |
| 準備計算での生成とトグル | `squid-n-app/src/app/tests.rs` の `test_preparation_generates_panel_zones` |
| 3D 節点検定のホバー判定 | `squid-n-app/src/viewer/check_ratio.rs` の `tests`（`--features gui`） |
| レポート CSV | `squid-n-app/src/summary.rs` の `test_report_and_metrics_from_sample_flow` |

GUI 側のテストは `cargo test -p squid-n-app --features gui` でないと走らない
（`viewer` モジュールが `gui` フィーチャ配下のため）。`cargo test --workspace` だけでは
検定比図のテストが素通りするので注意。
