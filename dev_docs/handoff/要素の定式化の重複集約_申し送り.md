# 要素の定式化の重複集約 — 申し送り

作成日: 2026-09-03
対象コード: `crates/squid-n-element/`

この申し送りでは、線材要素のあいだで複製されていた**定式化**を集約した経緯と、その過程で見つかった要素間の食い違いを記録します。

## 背景 — 前回が残したもの

同日の [要素振る舞いの定型集約とクレート階層の整理](要素振る舞いの定型集約とクレート階層の整理_申し送り.md) では、`ElementBehavior` の実装 14 個に集中していた**定型**の重複を集約しました。
塊は、節点自由度の収集・変位だけを状態に持つ弾性要素の状態機械・委譲ラッパの転送の 3 つです。

今回は前回と同じく、テストコードを除いた本体を対象にクローン検出をやり直しました。
すると `squid-n-element` になお重複が残っており、しかもその性格が前回とは違うことがわかりました。
前回集約したのは、要素の種別に関係なく同じ形になる**手続き**の重複です。
今回残っていたのは、複数の要素が同じ物理を扱うために結果として同じ式を書いている**定式化**の重複でした。

この違いは重要です。
定型の重複は、書き忘れたメソッドが既定値へ静かに落ちるという形で表面化します。
ですが定式化の重複は、片方だけを直したときに**解析結果が要素種別によって食い違う**という形で出ます。
そして食い違いが起きたとき、どちらの数値が正しいかはコードを読んだだけでは判断できません。

見つかった重複は次の 6 件です。

| 重複していた定式化 | 箇所 | 性格 |
|---|---|---|
| 静縮約 K\* = Kaa − Kab·Kbb⁻¹·Kba | `beam/stiffness.rs`・`fiber/mod.rs`・`concentrated/mod.rs` | 写像・ばね結線・特異時フォールバックまで逐語一致 |
| 小行列の逆行列 | `beam/linalg.rs`・`fiber/mod.rs` | 同一アルゴリズム。ヒープ版とスタック版 |
| 幾何剛性 Kg | `beam/behavior.rs`・`fiber/mod.rs` | 係数 20 行が一致 |
| 整合質量の Hermite ブロック | `beam/behavior.rs`・`fiber/mod.rs` | 逐語一致 |
| 断面・材料の引き当て | `frame/truss.rs`・`frame/beam/construct.rs` | バイト一致 |
| 端部幾何の取り出し | 線材 6 要素 | 2 通りの書き方に割れていた |

複製であることをコード自身が自認している箇所もありました。
`concentrated` の特異時フォールバックのコメントは「`beam::stiffness::condense_end_springs` と同じ扱い」と書き、`fiber` の逆行列は「`super::beam::invert_small` と同一アルゴリズム」と書いています。
[クレート横断の重複統合](クレート横断の重複統合_申し送り.md) は、この形について「解は複製してコメントで断ることではなく、共通部分を出すことである」と結論づけています。
今回もその方針に従いました。

## 決めたこと

着手前に dig で 6 問を確認し、次の形に決めました。

| 問い | 決定 |
|---|---|
| スコープ | `squid-n-element` 内で完結させ、見つかった 6 件すべてを対象とする |
| 静縮約を切る層 | 解放自由度のリストを受け取る高さ。3 箇所を寄せる |
| `side_column` を含めるか | 含めない。同値の可能性は残課題へ回す |
| 逆行列の一本化 | スタック版へ統一し、ヒープ版を削除する |
| 置き場所 | 利用者の広がりに合わせ、またぐものはクレート直下、`frame` 内で閉じるものは `frame` 直下 |
| 検証の水準 | 既存テストとスナップショットに加え、共有関数へ性質テストを新設する |

`side_column` を外したのは、そこだけ**コードの一致ではなく数学的な同値**だからです。
ほかの 3 箇所は内部自由度を作って縮約しますが、`side_column` は解放行・列を 0 にする別の形で書かれています。
ばね剛性 0 を与えれば一致するはずとはいえ、それは等価性の証明を要する主張です。
逐語一致した重複を消すという今回の目的に証明を要する変更を混ぜると、差分のどこまでが機械的な移設なのかが読めなくなるため、残課題へ回しました。

置き場所の基準は、前回と同じ「そのくくりに説明力があるか」です。
今回はそれを利用者の広がりで判断しました。
`frame` と `wall` の両方から使われるものを `frame/beam/` の下に置いたままにはできません。

## 変更内容

### 小行列の逆行列を 1 実装へ

`invert_small` を `frame/beam/linalg.rs` からクレート直下の `linalg.rs` へ移し、`fiber` が持っていた `invert_small_stack` を削除しました。

一本化の方向はスタック版です。
全呼び出し箇所が n≤6 に収まることは先に確かめました。
弾性梁とファイバー梁の解放自由度は両端の回転 3 成分ずつ、材端集中ばね梁と側柱要素は 2、ファイバー梁のヤコビアンは 6 です。
可変長を扱えるヒープ版を残す理由がないうえ、弾性梁と材端集中ばね梁の側では反復のたびの小さなヒープ確保も落ちます。

移動先をクレート直下にしたのは、`wall::side_column` から使われているためです。
`frame/beam/linalg.rs` は自身のモジュール doc に「梁固有ロジックを持たない汎用数値ヘルパ」と書きながら梁の下に置かれており、位置が実態と合っていませんでした。

n が 6 を超えると作業配列の範囲外になり、添字パニックで落ちます。
`debug_assert` に頼らず release ビルドでも止まるため、誤った値を黙って返すことはありません。
上限付近が範囲外にならないことを確かめる n=6 のテストも足しています。

### 直線材の定式化を `frame::prismatic` へ

弾性梁・ファイバー梁・材端集中ばね梁が共有する 3 つを集約しました。

- `condense_end_releases` — 材端解放の静縮約。3 箇所が写像からフォールバックまで一致していた
- `geometric_stiffness` — P-δ の幾何剛性。剛体アーム変換まで含めて返す
- `lumped_mass` / `consistent_mass` — 質量行列

静縮約は `(自由度, ばね剛性)` の組を渡す形へ揃えました。
材端集中ばね梁は `[5, 11]` 固定、ファイバー梁は `EndRelease`、弾性梁は端条件から組み立てたリストを渡します。
解放できるのは 3 箇所とも両端の回転 3 成分ずつで系の大きさが n≤18 に収まるため、作業配列をスタックへ置けます。

幾何剛性で可撓長が一致することは、実地に確かめました。
弾性梁は `self.length - li - lj` をその場で求め、ファイバー梁は構築時の `flex_length` を読みます。
ですが、どちらも同じ `rigid_arm::resolve_lengths` を通した剛域長を使っており、同一の式に同一の入力を与えています。

質量は、質量スカラの出どころだけが要素ごとに違います。
弾性梁は ρ·A·L、ファイバー梁はファイバー面積の総和から求めるためそこは引数で受け、Hermite の一貫質量を配る 4×4 ブロックは共通にしました。

### 断面・材料の引き当てを `frame::section_lookup` へ

`get_section` と `get_material` がトラス要素と弾性梁にバイト一致で複製されていました。
`construct.rs` はすでに `sec_material` だけをトラス要素から import しており、同じファイルの中で「共有するもの」と「複製するもの」が混在していたことになります。

3 つとも `frame/section_lookup.rs` へ移し、あわせて `sec_material` の置き場所も是正しました。
トラス要素に置いてあるものを弾性梁が参照する形は、両者が対等な線材要素であることと合っていません。

フォールバックの意味はモジュール doc へ書きました。
ID が範囲外・世代違い・未割当のいずれも物性ゼロへ落とし、検出は解析前チェックへ委ねるという方針です。
ここで架空のもっともらしい断面を与えると、チェックを通らない経路から来たモデルが無音のまま解析されてしまいます。

### 端部幾何の取り出しを `EndGeometry` へ

線材要素の構築は例外なく「2 節点を引く → 座標を得る → 節点間距離を測る → 局所座標系を組む」で始まります。
その前半 3 つが 6 要素に書き写されており、しかも `if index < len` 版と `.get().map().unwrap_or()` 版という 2 通りの書き方に割れていました。
両者が返す結果は同じです。

`transform::EndGeometry` を新設して 6 要素を寄せました。
`LocalFrame` を組む直前の材料になるため、`LocalFrame` と同じモジュールに置いています。

**局所座標系の組み方そのものは集約していません。**
零長要素の扱いが要素ごとに違い、節点バネは単位回転（全体系＝局所系）、免震支承は鉛直（局所 x ＝全体 z）を既定とするためです。
これをまとめると分岐を持ち込むだけで、くくりの説明力がむしろ落ちます。
零長を特別扱いしない 4 要素（トラス・弾性梁・Maxwell ダンパー・履歴ダンパー）は `EndGeometry::local_frame` を呼ぶ形に揃えました。

## 数値への影響

大半はビット一致します。
幾何剛性と質量は係数も演算順序も同一で、逆行列は確保先がヒープからスタックへ変わるだけであり、断面・材料の引き当てと端部幾何にいたっては関数を移しただけで式を変えていません。

**ただし静縮約は、ファイバー梁だけ丸めが変わりえます。**
従来、弾性梁と材端集中ばね梁は Kab·Kbb⁻¹ をいったん中間変数に持ってから Kba を掛けていたのに対し、ファイバー梁は 3 重ループで一度に掛けており、浮動小数の結合が違っていました。
どちらが正しいというものではなく、集約するなら片方に揃えるしかありません。

演算量の少ない前者へ揃えました。
3 箇所のうち 2 箇所がすでに採用していた形であることと、中間変数を持つほうが O(na·nb² + na²·nb) で 3 重ループの O(na²·nb²) より少ないことが理由です。

実モデル（`full_model.rs`）と壁モデル（`wall_model.rs`）のスナップショットに差分は出ておらず、ワークスペース全体のテストもすべて通っています。

## 見つかった食い違い — ファイバー梁の整合質量にねじれ項がない

集約の過程で、弾性梁とファイバー梁の整合質量が違うことがわかりました。
弾性梁は部材軸まわりの回転慣性 ρ·J·l/6 をねじれ自由度（rx）へ入れていますが、ファイバー梁はこれを持たず、当該自由度の質量が 0 のままになっています。

意図的な省略かどうかは判断できませんでした。
ファイバー梁は断面をファイバーへ分割する定式化上ねじり定数 J を保持していないため、「持てないから持っていない」とも「入れ忘れ」とも読めます。

本ブランチでは挙動を変えず、`torsion_term` に 0 を渡して従来どおりとしました。
前回の申し送りが書いているとおり、リファクタと挙動変更を同じ差分に同居させると、どちらが数値を動かしたのかを後から追えなくなるためです。
是非の判断は残課題へ回します。

なお影響が出るのは整合質量を選んだ固有値解析と時刻歴応答だけで、既定の集中質量では両要素とも並進 3 成分しか持たないため差は出ません。

あわせて、弾性梁が使っている回転慣性そのものにも検討の余地が見つかりました。
`ρ·J·l/6` の `J` はねじり剛性 `GJ/L` に用いるねじり定数であり、回転慣性が本来必要とする極二次モーメント `Ip = Iy + Iz` ではありません。
開断面では `J` が `Ip` よりはるかに小さいため、ねじれの回転慣性を小さめに見ることになります。
安全側か危険側かはねじれ卓越モードの周期がどちらへ動くかで決まり、入力スペクトルとの関係で変わるため、この場では判定していません。

利用者向けの計算根拠（`docs/`）には、これらの現状を追記しました。
4.1.7 にはねじれ自由度の回転慣性と `J` を使っている旨を、4.9.2 にはファイバー梁がねじれの回転慣性を持たない旨を明記しています。
どちらもコードに埋め込まれた既定でありながら、利用者が結果の根拠を追える形になっていませんでした。

## 残課題

| 状態 | 項目 |
|------|------|
| ☐ | ファイバー梁の整合質量がねじれ質量を持たない。弾性梁は ρ·J·l/6 を持つ。ファイバー梁は J を保持しないため、入れるなら断面から J を求める経路が要る。意図的な省略か入れ忘れかは判断できていない。**整合質量を選んだ固有値・時刻歴にのみ影響**し、既定の集中質量では差は出ない |
| ☐ | 弾性梁の整合質量のねじれ項が `ρ·J·l/6` で、`J` はねじり定数（`GJ/L` と同じ値）であり極二次モーメント `Ip = Iy + Iz` ではない。開断面では `J ≪ Ip` のため回転慣性を小さめに見る。安全側か危険側かはねじれ卓越モードの周期の動く向きで決まるため未判定 |
| ☐ | `wall::side_column` の `released_local_stiffness` を `prismatic::condense_end_releases` へ寄せられるか。ばね剛性 0 で数学的には一致するはずだが未検証。寄せる場合は、`inner.local_stiffness()` が剛域変換済みである点が前提と合うかも確かめる |
| ☐ | `frame/section_lookup.rs` の物性ゼロ断面と、`squid-n-io` の `zero_section` が同じ形をしている。統合するには `Section` の既定値を `squid-n-core` へ持ち上げることになり、クレート横断の判断が要るため今回は対象外とした |
| ☐ | `springs/spring.rs` と `frame/truss.rs` の `recover_forces` に、局所変位から局所力を作る部分（`rotate_to_local` → K·u）の重複が残る。返す断面力の形が違う（節点バネは 6 成分 2 点、トラスは軸力のみ）ため、共有できるのは前半だけ |
| ☐ | `frame/fiber/mod.rs` の中に同一ファイル内の重複が残る（ガウス点まわり）。今回は要素をまたぐ重複に絞ったため触っていない |
