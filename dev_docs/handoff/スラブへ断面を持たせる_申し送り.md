作成日: 2026-08-07
対象コード:
`crates/squid-n-core/src/{section_shape/{types.rs,builder.rs,properties.rs,label.rs},model/{slab.rs,aggregate.rs},structure_kind.rs}`、
`crates/squid-n-section/src/mn_surface/fibers.rs`、
`crates/squid-n-load/src/floor/mod.rs`、
`crates/squid-n-solver/src/statics/analysis/precheck.rs`、
`crates/squid-n-design-jp/src/{quantity/mod.rs,steel/mod.rs,material_strength/steel.rs,secondary/width_thickness/}`、
`crates/squid-n-io/src/stbridge/{export.rs,import/{parser.rs,assemble.rs}}`、

`docs/`（床の断面と自重・数量積算・診断・ST-Bridge）

モデル作成支援機能の第 3 弾。作成ウィザード・3D グリッド・階複製は本申し送りの範囲外
（後続 PR）。本 PR は**その前提として、床が断面を持つ形へ寄せる**ことだけを扱う。

## 変更前の問題

床の板厚が 2 か所に散っていた。

1. `Slab.thickness`（床ごと。`Option<f64>`）— ST-Bridge の書き出しと床配筋の設計が読む
2. `Model::slab_thickness`（建物一律）— 梁剛性増大・自重の梁断面控除・数量積算が読む

床ごとの厚さが未設定なら建物一律値へ退く形（`slab.thickness.unwrap_or(model.slab_thickness)`）
だったが、この 2 つは意味が違う。`Model::slab_thickness` は「**剛性計算に見込む**スラブ厚」で、
既定の 0 は「スラブ協力幅による梁剛性増大を見込まない」を意味する。実際の板厚の代わりに
使うと、協力幅を見込まないモデルで床厚 0 の自重・数量が黙って出る。

さらに床の自重は、ST-Bridge の取り込み時に `板厚 × 24 kN/m³` を計算して
`AreaLoad { kind: "自重(自動)" }` へ**焼き込んで**いた。板厚を変えても材料を変えても
自重が追随せず、24 kN/m³ の決め打ちが根拠なく残る。アプリ内で作った床は自重が
そもそも載らなかった。

書き出し側も、スラブ断面の符号を `S{スラブID}`、コンクリートを `Fc21` と決め打ちしていた
（壁断面も同じ）。

## 対応

### 1. 床は断面を持つ

`Slab` へ `section: Option<SectionId>` を置き、`Slab.thickness` を削除した。
**床ごとの板厚と自重は、この断面から解決する**。

| 解決するもの | 情報源 |
| --- | --- |
| 板厚 | `Model::slab_thickness_of` ＝ 断面の `thickness` |
| 自重 | `Model::slab_self_weight_intensity` ＝ 板厚 × 主材料の単位体積重量 |
| 固定荷重 DL | `Model::slab_dead_intensity` ＝ 自重 ＋ 仕上げ等（`Slab.loads`） |
| 合成面荷重 | `Model::slab_intensity` ＝ DL ＋ 用途別の積載 |

`Slab::dead_intensity` は `Slab::finish_intensity`（仕上げ等だけ）へ改名した。
自重を含む値はモデルを見ないと出せないため、`Model` 側のメソッドへ移している。

**建物一律の `Model::slab_thickness` へは退かない。** 意味の違う値を混ぜないためである。

### 2. スラブ断面の形状 `RcSlab`

`SectionShape::RcSlab { thickness }` を新設した。断面一覧の断面形状は `S-t150` と表示する。
断面諸量は幅 1 m の帯としての名目値で、`RcWall` と同じ扱いになる。

配筋は持たない。床配筋の設計は板厚とかぶり厚から算定しており（`design_slab_oneway`）、
断面にも配筋を置くと入力の持ち主が二重になるためである。断面テーブルの材料欄も
主材料（コンクリート）だけが有効になる。

断面作成パネルの形状に「RC スラブ」を追加し、板厚を入れて作れるようにした。

### 3. 未割当は止める

| 場所 | 検査 |
| --- | --- |
| `model_issues`（解析前チェック・診断タブ） | 断面が未割当の床、断面の材料または板厚が定まらない床 |

床の自重が算定できないまま解析へ進むと、長期荷重が過小なまま応力が出る（危険側）。
既定の板厚・材料で補わずにエラーで止める。

### 4. ST-Bridge は断面を往復する

取り込みは `StbSecSlab_RC` / `StbSecSlabDeck` から**符号・階・板厚・`strength_concrete`**を
読み、内部の `Section`（形状 `RcSlab`）として組み立てて床へ割り当てる。同じ断面を指す床は
1 つの断面を共有する。符号が既存断面と衝突する場合は空いた符号まで連番を送る。
自重の焼き込み（`AreaLoad { "自重(自動)" }`）は廃止した。

書き出しは床の断面の符号・階・板厚・材料名を出す。**壁断面の `Fc21` 決め打ちも
断面の材料から解決するよう直した**（同じファイルの隣り合う関数で規則が食い違うのを避ける）。

### 5. 数量積算

床のコンクリート体積を、建物一律値ではなく**床ごとの断面の板厚**から算定するようにした。
梁の型枠のスラブ厚控除・自重の梁断面控除・スラブ協力幅は、梁ごとに隣接スラブを探す
別の話なので変えていない（下記の残課題）。

## 敵対的レビューで検出・修正した不具合

### 1. 断面を共有する床が往復で増殖する

書き出しが `StbSecSlab_RC` を**スラブ 1 枚ごと**に出していた。断面が床へ移ったことで
同じ断面を共有する床が普通に生じるようになり、N 枚の床が同名の断面 N 個として
書き出されて、再取り込みのたびに符号が `S15`・`S15#2`… と増えていく。

`slab_section_ids` を置いて**内部断面ごと**に 1 つの ST-Bridge 断面を割り当て、
断面定義側（`slab_sections`）と部材の参照側（`StbSlab` の `id_section`）が
同じ採番を共有するようにした。断面が未割当の床にはそのスラブ専用の id を後ろへ振る。

### 2. スラブ断面が `StbSecRaw` としても二重に出る

床だけが参照する断面が、`StbSecSlab_RC` と `StbSecRaw` の両方で書き出されていた。
再取り込みで「Raw 由来の断面＋スラブ断面」が 1 組ずつ増殖する。壁の厚さ専用断面には
同じ除外がすでに入っていたが（`wall_only_sections`）、スラブは新設のため漏れていた。
`slab_only_sections` を足して Raw 側の出力から外した。

どちらも 2 往復して断面が 1 つのままであることを確かめる回帰テストを追加した。

## 2 巡目の敵対的レビューで検出・修正した不具合

### 3. 床だけが使う断面で削除ボタンが無反応になる

断面テーブルの「部材数」は部材・小梁・二次部材しか数えておらず、床を数えていなかった。
一方で削除ガード（`section_in_use`）には床を足していたため、床だけが使う断面は
**部材数 0 と表示されて削除ボタンが押せるのに、コマンドは Noop** という状態だった。
数え漏らすとこうなることは、当該コードのコメント自身が警告していた。
テーブル側と準備計算側の両方で床を数えるようにし、回帰テストを追加した。

### 4. 3D のスラブ作成モードが必ず断面未割当の床を作る

床タブの追加フォームには断面の選択欄を置いたが、3D ビューのスラブ作成モードは
`section: None` 固定のままだった。3D から作った床は必ず解析前チェックで止まる。
追加フォームと同じ下書き（`slab_draft`）を使うようにした。

### 5. 消えた断面を指した下書きで「追加」が無反応になる

断面を削除したあと下書き（`slab_draft.section`）が古い ID を指したままだと、
`AddSlab` が参照検証で Noop になり、ボタンを押しても何も起きない。
下書きが解決できない場合は未割当として扱うようにした。

## 既知の挙動変更（利用者から見えるもの）

- **既存のプロジェクトファイルは床の断面が未割当で開く。** `Slab.thickness` は読み捨てられる。
  解析前チェックが未割当を名指しするので、断面を作って床タブで割り当て直す。
  後方互換性は維持しない方針（AGENTS.md）にしたがう。
- 床の自重が断面から算定されるようになった。ST-Bridge から取り込んだモデルでは、
  従来の焼き込み値（24 kN/m³ 固定）ではなく断面の材料の密度で決まる。
- 床の数量（コンクリート体積）が、建物一律の床厚ではなく床ごとの板厚から出るようになった。
- ST-Bridge の書き出しで、スラブ・壁のコンクリートが `Fc21` 固定でなくなった（**是正**）。

## 残課題

- **`Model::slab_thickness` の廃止**: 梁剛性増大（スラブ協力幅・合成梁）・自重の梁断面控除・
  梁の型枠のスラブ厚控除は、いまも建物一律値を読む。本来はその梁に隣接する床の断面から
  板厚を引くべきだが、梁ごとに隣接床を探す実装が要り、剛性・自重・数量のすべてで結果が
  変わる。独立した PR に値する規模のため分けた。

### 後続 PR の確定済み設計

**架構作成ウィザード**
- 新規モデル専用。`ファイル > 新規（架構ウィザード）…` から呼び、現在のモデルを置き換える
- 生成するのは節点・柱・大梁・柱脚支点・通り芯・階・床。**材料と部材断面は作らない**
  （材料はプリセットがあり、断面の寸法は設計判断のため）
- 床は既定 ON のチェックボックスで外せる。分配方法は三角形・台形分布
- 床には階なしの断面 `S15`（板厚 150 mm）を 1 枚だけ作って全階へ割り当てる
- `Model::slab_thickness` は 0 のままにする（協力幅を見込むかは設計者の判断）
- スパン入力は個別スパンの表 ＋「等スパン一括入力」の補助欄。床用途の既定は事務室

**3D グリッドとスナップ**
- 格子点にスナップし、節点が無ければその場で作る（節点追加＋部材追加の複合コマンド）
- 既存節点と格子点が両方近いときは既存節点を優先する
- 描画は全レベルの平面格子のみ。鉛直線は描かず、通り名は最下レベルの端に添える。
  トグルは既定 ON（通り芯と階が両方あるときだけ出す）

**階への複製**
- 対応付けは平面位置（柱は 1 点、梁・小梁は両端の 2 点、壁・床は頂点の並び）
- 断面は複製先の階名で断面を複製してから割り当てる。同じ符号＋階が既にあればそれを使い、
  寸法が違っても上書きしない。`floor` が `None` の断面はそのまま共有する
- 部材・節点は作らない。床・二次部材は必要な節点がそろっていれば作り、すでにあれば
  属性を上書きする。足りない分は件数を報告する
- 複製対象は「断面」「荷重」「スラブ」「二次部材」。**床の面荷重・用途は「荷重」に含め、
  「スラブ」は境界の形だけを写す**
- 既存の荷重は消さずに足す。複製先は複数選択できる
