# 質点系モデル生成バグと解析タブ設定の永続化 — 申し送り

## 経緯

ユーザーから「同じモデルで時刻歴応答解析を行うと質点系（串団子）モデルと立体モデルで
結果が全然違う」との報告を受け、以下を順に調査・修正した。

1. 質点系（串団子）モデル生成のバグ修正（層剛性 K1 が 0 に縮退する）
2. 質点系モデルの固有値解析機能の追加
3. 解析タブの設定値（`AnalysisSettings`）の `.scz` への永続化

いずれも `fix/lumped-mass-long-term-origin` ブランチに3コミットで積んでいる（本稿作成時点で
`main` へ未マージ・未push）。

## 1. 質点系モデル生成バグ

### 症状と原因

`build_lumped_mass_model`（`crates/squid-n-solver/src/dynamic/lumped_mass/model.rs`）は、
プッシュオーバー結果の `capacity_curve` をそのまま層 Q-δ 曲線として使い、変位絶対値が最小の
点を「原点直後の弾性剛性点」として `K1 = Q1/δ1` を計算していた。

長期荷重初期載荷（`push_apply_long_term`、既定 ON）を使うモデルでは、`capacity_curve` の
先頭に「長期荷重のみを載荷した状態」（水平力ゼロ、`load_factor=0.0`）が記録される。この状態
でも、非対称な長期荷重により層にわずかな残留水平変形（丸め誤差ではなくミリメートル級）が
生じることがある。この点の絶対変位が、以降の水平力載荷ステップの変位より小さいと、変位最小点
として誤って拾われ、その点の水平力がほぼゼロであるため `K1 ≈ 0`（層がほぼ無抵抗）に縮退して
いた。

ユーザー提供の実モデル（4層）で実際に再現した。修正前は全4層で K1=0.0 kN/mm、Q1=0 だった。

### 修正

長期荷重のみを載荷した点（`steps[].load_factor == 0.0`）の (δ, Q) を層 Q-δ 曲線の**原点**として
各点から差し引いてから `fit_story_trilinear` へ渡すようにした（単純な除外ではなく原点補正。
除外だけだと、以降の点にも残留変形がオフセットとして乗ったままになり、層剛性の相対分布が歪む）。

修正後、同じ実モデルで K1=81.6/68.6/65.3/15.2 kN/mm（下層→上層）となった。

## 2. 質点系モデルの固有値解析

立体モデルとの周期比較検証のため、`crates/squid-n-solver/src/dynamic/lumped_mass/eigen.rs`
を新設した。M（対角）・K（せん断型三重対角、K1 ベース）から標準固有値問題
`A = M^{-1/2} K M^{-1/2}` へ帰着し、faer の `self_adjoint_eigen`（対称行列固有値分解）で解く。
串団子パネルに周期・モード形状（最上階=1.0正規化）の一覧を追加表示した。

減衰算定（`lumped_mass_time_history`）の ω1 も、従来の自作の逆反復法（power iteration、1次
モードのみを概算する `fundamental_omega`）から、この新しい固有値解析の1次モードへ差し替えた。

### 質量 0 以下の層への対応（レビューで発見）

当初、質量 0 以下の層があると `stick_omega1` が `.max(1e-9)` で丸めた質量をそのまま
`fundamental_omega` へフォールバックする実装にしていた。これだと ω1=√(k/1e-9) が桁違いに
大きくなり、`a1=2h/ω1` が実質ゼロへ潰れて**無音で無減衰**になる（非安全側の破綻。初期剛性比例
ではなく接線剛性比例になっていた過去の減衰バグと同じ失敗形）。

減衰算定専用の内部処理として、質量 0 以下の層は他層の正の質量の平均で置き換えてから固有値分解
するよう修正した（`stick_omega1`）。表示用の `lumped_mass_eigen` はこの補正をせず、質量 0 以下
をそのままエラーとして利用者へ見せる（減衰算定と表示で目的が異なるため、意図的に処理を分けて
いる）。

## 3. 解析タブの設定値の永続化

### 背景

調査の過程で、解析タブの設定値（`AnalysisSettings`。時刻歴の波形パラメータ・減衰モデル、
固有値解析のモード数など）が `.scz` に一切保存されていないことが判明した。

- `AnalysisSettings` 自体が `Serialize`/`Deserialize` を derive していなかった。
- `save_project_to_opts`（`squid-n-app/src/app/actions/io.rs`）は `preparation`・`results`
  のみを直列化しており、`analysis_cfg` には触れていなかった。
- `.scz` 内の `settings.json` は中身が `{"code": "JIS B 0001", "created_at": ""}` という
  無関係な固定値だった。
- `eframe::App` の実装も `save`/`load` を持たず、OS レベルの永続化も経由しない。

このため、`.scz` を保存して開き直すと解析タブの設定値がすべて既定値に戻っていた。同梱されて
いる解析結果（例えば串団子パネルで実行した時刻歴応答）がどの条件で得られたものか、保存後は
再現できなくなっていた。これはユーザーが実際に「質点系と立体モデルの時刻歴を比較した際、
両方とも同じ設定（サンプル波・非線形ON・初期剛性比例減衰）で実行したはず」と申告した内容の
裏付けを取ろうとした際に発覚した（設定が保存されていないため、`.scz` を読み込むだけでは
本当に同じ条件だったか確認できなかった）。

### 対応

- `AnalysisSettings` と、その全フィールドの型（`ThDir`・`ThDampingModel`・`ThIntegrator`・
  `DuctilityMethod`・`LumpedMassType`・`QdMethod`・`BondMethod`。他は既に対応済み）に
  `Serialize`/`Deserialize` を追加した。
- `squid_n_io::scz::SczExtras`/`SczContents` に `analysis_settings` フィールドを追加し、
  `analysis_settings.msgpack` という任意エントリとして `.scz` に同梱するようにした
  （`preparation.msgpack`・`results.msgpack` と同じ仕組み）。
- 保存時は、モデルの新陳（staleness）と無関係に常に現在の `analysis_cfg` を同梱する
  （結果を生成した条件そのものであり、結果が古くても・結果がなくても保存する意味がある）。
- 読込時は、同梱されていれば `self.analysis_cfg` をまるごと復元する。ただし
  `mass_method` は `Model::mass_method` を単一情報源とする既存の設計（`squid-n-core`
  `story.rs` のコメント参照）があるため、読込後は常にモデル側の値で上書きする
  （そうしないと、設定を変えた後に「階の自動生成」を再実行せずに保存した場合、パネル表示と
  モデルが実際に使う方式が食い違ったまま気づけなくなる）。

### 既知の残課題: 波形（CSV読込波）は依然として保存されない

`AnalysisSettings` には波形の**パラメータ**（サンプル波の周期・振幅・継続時間・dt）は含まれるが、
**CSV 読込波の中身そのもの**（`run_time_history_from_csv` が `rfd::FileDialog` で読み込み、
`GroundMotion` へパースして即座に使い捨てる加速度配列）はどこにも保存されない。

このため、CSV波形で実行した時刻歴応答の結果を `.scz` に保存して開き直しても、th_period・
th_amp 等の「サンプル波用パラメータ」だけがもっともらしく復元される一方、実際に使われた波形は
再現できない。今回の対応は「解析条件が保存されるようになった」ことを意味するが、CSV波を使った
解析の**完全な再現性**はまだ確保できていない。

対応するなら、`GroundMotion`（またはその元になった波形ファイルのパス＋ハッシュ）を
`analysis_settings.msgpack` 相当のエントリ、または新規の任意エントリとして `.scz` に同梱する
実装が必要。次に着手する場合の候補箇所:

- `crates/squid-n-app/src/app/panels.rs::run_time_history_from_csv`（波形読込・使い捨て箇所）
- `squid_n_solver::timehistory::GroundMotion`（`Serialize`/`Deserialize` の有無を要確認）
- `squid_n_io::scz::SczExtras`（新規フィールド追加、または `analysis_settings` に含める）
