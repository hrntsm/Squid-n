## 0. 方針（第1・2波から継続）

すべての施策は「**同じ演算を同じ順序で行い、確保・生成・再計算の回数だけを減らす**」
ものに限定し、数値結果のビット一致を維持する。検証は各ベンチの数値出力
（変位・ベースシア・周期・有効質量比等）の完全一致と、決定性テスト
（`cargo test --workspace deterministic`、9件）で担保した。

## 1. 実施内容

### 1.1 squid-n-math（全解析に効く基盤）

- **`AutoSolver::factorize` の直接法分岐でインスタンス再利用**: 従来は factorize の
  たびに内部 `CholeskySolver` を新規生成しており、呼び出し側が `AutoSolver` を
  持ち回っても symbolic 分解キャッシュが効かなかった（第2波申し送り 1.1 の残課題）。
  既存の `State::Direct` があればそれへ factorize するよう修正。
- **`AutoSolver::solve_into` を実装**（直接法時は `CholeskySolver` の内部スクラッチ
  再利用へ委譲）。
- **`CholeskySolver`/`LuSolver` の symbolic キャッシュ判定を軽量化**:
  ヒット判定のためだけに毎回 `SparsityPattern`（Vec 2本）を複製していたのを、
  アロケーションなしのスライス比較（`SparsityPattern::matches`）に変更。
  ヒット時（Newton 反復・時刻歴ステップの圧倒的多数）の毎回の Vec 確保を排除。
- 再利用のビット一致テスト・solve_into 一致テストを追加。

### 1.2 増分解析（プッシュオーバー、効果大）

第2波申し送りには「driver.rs は毎ステップ1回の組立てで反復しないためキャッシュの
恩恵が小さい」とあったが、**これは誤りだった**。実際は長期荷重初期載荷・荷重制御・
変位制御・弧長法の各フェーズに最大50回の Newton 反復（変位制御は反復あたり2回
ソルブ）があり、毎反復でソルバ新規生成（`SolverBackend::Auto` — 当時は factorize の
たびに内部ソルバを作り直すため symbolic キャッシュが原理的に無効）・非キャッシュ版
CSC 組立（毎回ソート）・非 `_into` 版 API（毎回 Vec 確保）を実行していた。

- `SolverState`（`DirectSparseCholesky` ソルバ1個＋`CscCache` 2個＋作業バッファ一式）
  を解析冒頭で1回だけ生成し、全フェーズ＋`elastic_roof_slope` で `&mut` 持ち回り。
- `assemble_k`→`assemble_k_cached`、`reduce_k`→`reduce_k_cached`、
  `solve`→`solve_into`、`reduce_f`→`reduce_f_into`、`expand_u`→`expand_u_into`。
- 弧長法の修正子反復（`arc_length.rs`）の `scale`/`add` を作業バッファへの書き込み
  （`scale_into`/`add_into`）に変更。
- 段階的耐力喪失解析（`strength_loss`）は `pushover_analysis_recording` を最大10回
  程度呼ぶため、本改善はそのまま倍加して効く。

### 1.3 集中ばね梁要素（非線形解析の要素側）

- **`UniaxialMaterial::probe(&self, strain) -> (応力, 接線剛性)` を追加**:
  `trial()` と数学的に同一の応答を状態を書き換えずに返す非破壊評価。全7実装
  （Bilinear / MenegottoPinto / Concrete / ConcreteNewRc / SteelBuckling /
  TsujiYamada / HysteresisMaterial）の `trial()` が committed 状態と入力ひずみのみに
  依存する（trial 状態を読まない）ことを実装ごとに確認した上で、計算本体を共通の
  内部関数へ切り出して trial/probe 双方から呼ぶ（乖離防止）。probe=trial の
  一致・非破壊性の検証テストを全実装に追加。
- `ConcentratedSpringBeam` の `solve_internal_equilibrium`（要素内 Newton、最大50回）・
  `tangent_stiffness`・`internal_force` の `clone_box()+trial()`（Box 複製の
  ヒープ確保）を probe へ置換。
- 可撓部局所剛性 `local_stiffness_flex()`（`BeamElement::clone()` を含む 12×12 組立）
  を `OnceLock` でキャッシュ（幾何・断面・材端条件は要素生成後不変。派生値のため
  snapshot/restore の対象外）。

### 1.3b FiberBeam（プロファイル結果を受けた追加ラウンド、§3 参照）

- **断面応答のガウス点キャッシュ**: `GaussPoint` に断面応答（軸力・両軸曲げと接線）の
  キャッシュを追加。`trial_stress`/`trial_et` を書き換える全経路
  （`update_section_trial`/`update_hinge_section_trial`）の直後に同一のファイバー順・
  同一式で1回だけ総和を計算し、`elem_tangent`/`elem_internal_force`/`solve_hinges`/
  `hinge_tangent` 等の読み出し側は再総和せずキャッシュを参照。commit/revert/restore は
  従来から trial 配列に触れず「読み出し前に必ず `update_state` が再導出する」不変条件が
  あり、キャッシュは同じ不変条件に相乗りする（新たな失効経路なし）。
- **B 行列のキャッシュ**: ひずみ－変位行列は `xi`（ガウス点固定）・可撓長・φ のみに
  依存し要素生成後不変のため、生成時に1回だけ計算して保持。
- **小規模ヒープ確保の排除**: `solve_internal_dofs`/`condense_releases`/`solve_hinges`/
  `hinge_tangent` の反復内 `vec!` を固定長スタック配列へ置換（逆行列も同一の
  Gauss-Jordan 手順のスタック版）。

### 1.4 固有値解析

- 部分空間反復ループの `y`/`x_new`（n×q）・列抽出・spmv 結果・射影行列の各バッファを
  ループ外確保に変更（`x`/`x_new` は swap）。`solve`→`solve_into`、
  `spmv`→`sparse_matvec_into`。
- `compute_participation`: 方向（X/Y/Z）に依存しない `phi_free`・`m_phi`・`φᵀMφ` を
  3方向ループの内側からモードごと1回の計算へ巻き上げ（演算列は不変、同一値の
  再計算を1回にしただけ）。節点モード形状の展開が別途行っていた `expand_u` の
  二重計算も解消。
- **大規模モデルで PCG が固有値解析へ流用される問題の修正**（性能と頑健性の両方）:
  `Analysis::prepare` は `SolverBackend::Auto` を使うため、縮約後自由度数が
  `AUTO_ITERATIVE_MIN_DOF`（5万）以上では f32 精度の PCG が選ばれる。従来の
  `Analysis::eigen`/`seismic_period(SemiPrecise)` はこれをそのまま部分空間反復へ
  渡しており、求解のたびに数千回規模の PCG 反復が走る／固有値反復の収束判定
  （相対誤差 1e-10）に達せず `NonConvergence` になり得た。PCG 規模では固有値解析
  専用に直接法で分解し直す `solve_eigen` へ振り分ける
  （`Analysis::eigen_solver_dispatch`）。しきい値未満は従来どおり分解を再利用。

### 1.5 静解析

- **引張専用ブレースの active-set 反復（最大50回）の全面再設計**: 従来は反復ごとに
  `model.clone()`＋DofMap/Reducer/K組立/ソルバ生成のフル再実行。要素接続・拘束・
  自由度構成は反復間で不変のため、DofMap・Reducer・荷重ベクトル・ソルバ
  （symbolic キャッシュ有効）・`CscCache` をループ外で1回だけ構築。新設
  `BraceIterAssembly` が全要素の局所剛性（有効時/無効時）と内力回収用 behavior を
  事前構築し、各反復は active 集合に応じた triplet 化のみ。無効化断面のモデル複製も
  全体で1回。
- **部材荷重の重ね合わせのグルーピング化**: `superpose_member_loads` が要素ごとに
  全部材荷重を総当りスキャンしていたのを、`ElemId` での事前グルーピング参照へ
  （要素内の荷重出現順は維持）。`solve_once_inner`・`Analysis::recover_member_forces`
  の両経路に適用。
- **`Analysis` の荷重ベクトルメモ化**: `prepare` 時に全荷重ケースの
  `assemble_global_f` を事前計算して保持。`linear_static`/`linear_combination` が
  参照する。同じ荷重ケースが複数の組合せへ登場する典型パターンで再計算を排除。

## 3. 非線形時刻歴が横ばいだった理由（プロファイル調査）

要素側の `clone_box` 排除（1.3）で非線形時刻歴も改善すると仮説を立てたが、
th_bench(c) は有意差が出なかった。callgrind（命令数、th_bench 相当モデルの
非線形 256 步、総命令数 34.5G）で実測した結果、**th_bench の柱は集中ばね梁では
なく FiberBeam（塑性増分ヒンジモデル）であり、支配コストはそちら側**だった:

| 関数 | 命令数比 |
| --- | --- |
| `FiberBeam::update_trial_state`（solve_hinges 含むインライン） | 23.2% |
| `FiberBeam::section_response_from_cache`（全ファイバー総和） | 18.1% |
| `Bilinear::trial`（ファイバー単位の呼び出し） | 16.9% |
| `FiberBeam::update_hinge_section_trial` | 5.1% |
| `FiberBeam::elem_tangent` | 3.6% |
| `LocalFrame::to_global` / `ductility_probe` / `invert_small` | 各 2.2〜2.6% |
| malloc / memset / memcpy 合計 | 約 6.5% |

つまり第2波で疎行列側（分解・組立）を削った後の非線形時刻歴は、要素内の
ファイバー評価（ヒンジ内部 Newton の反復ごとの全ファイバー再 trial・断面総和の
繰り返し・B 行列の再計算）が支配的になっている。1.3 で最適化した集中ばね梁
（梁 120 本）は同モデルに含まれるが、柱のファイバー評価に比べ相対的に軽く、
全体では差が出なかった。この結果を受け、第3波の追加ラウンドとして FiberBeam の
断面応答キャッシュ・B 行列キャッシュ・小規模ヒープ確保排除を実施した
（実施内容は §1.3b、結果は §2: 非線形時刻歴 約18%減）。

## 5. 残課題・申し送り

1. **非線形時刻歴の次のボトルネック**: §3 のプロファイルで `Bilinear::trial` が
   ファイバー単位の `Box<dyn UniaxialMaterial>` 仮想呼び出しになっており（16.9%）、
   材料種別ごとの devirtualization（enum 化）や fibers の SoA 化が残る大きな候補。
   設計変更を伴うため今回は見送った。
2. **要素ループの並列化（rayon）は引き続き未実施**（第2波 4.1 から継続）。要素番号順
   を保った collect なら決定性を維持できる設計方針も第2波申し送りのとおり。
   `update_state` の要素ループは共有状態が無く最も安全に並列化できる。
3. **`CscCache`/`WeightedSumGuard` の clone 返し**（第2波 4.2 から継続）: 参照返し
   バリアントの追加と `nonlinear.rs` の借用整理。O(nnz) のコピーが Newton 反復ごとに
   残っている。
4. **faer 低レベル API による数値分解バッファの再利用**: symbolic 再利用でも
   `Llt::try_new_with_symbolic` は数値因子配列とスクラッチを毎回確保する。
   `SymbolicCholesky::factorize_numeric_llt`（faer 0.24）を直接使えば Newton 反復の
   数値分解をアロケーションフリーにできるが、実装難易度が高い（unsafe/MemStack）。
5. **`Analysis` の部材ビヘイビアキャッシュ**: `recover_member_forces` がケースごとに
   全要素 `build_behavior` を再実行している。`ElementBehavior` トレイトに
   `Send + Sync` 境界を追加すれば `prepare` で1回構築して共有できる（バッチ解析で
   効果大）。トレイト変更を伴うため今回は見送り。
6. **施工段階解析の `model.clone()`**: ステージごとに部材・拘束構成そのものが変わる
   ため DofMap/ソルバの再利用は成立せず、clone コストも各ステージのフル分解に比べ
   小さいと判断して見送った（再検討時はこの前提を確認すること）。
7. **`ArcLengthSolver::step` の solve クロージャ**が所有 `Vec` を返す契約のため、
   弧長法では反復ごとに1本の Vec 確保が残っている。
