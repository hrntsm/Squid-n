# ナビゲータ断面材料一覧 申し送り

作成日: 2026-08-22

## 1. 背景

左ドック・ナビゲータに「断面一覧」「材料一覧」ツリーを実装した。断面一覧は階を親ノードにして断面をまとめ、上階から下階へ表示する。一方、材料一覧は材料区分ごとにグループ化し、表示順は鋼材→コンクリート→鉄筋の固定順で集約する。

今回の改修では、断面と材料の一覧がモデル編集の直前導線として機能するように整え、部材一覧の直後にツリーを配置した。発見要素の選択時には、下ドックを開いてモデルタブを断面または材料へ切り替え、対応する focus を設定する。これにより、一覧から直接対象の要素へ遷移できるようになった。

利用者向けの計算根拠は以下に記録している。

- [docs/model_edit/02_断面の符号と階.md](../../docs/model_edit/02_断面の符号と階.md)
- [docs/calc_basis/02_材料/04_標準材料一覧.md](../../docs/calc_basis/02_材料/04_標準材料一覧.md)

## 2. 実装概要

### データモデル（`squid-n-app`）

- `crates/squid-n-app/src/app/nav_model.rs`
  - 純粋関数 `section_floor_groups`
  - 純粋関数 `material_category_groups`
  - `stories` と一致する `floor` は上階→下階順でグループ化
  - `stories` に存在しない `floor` は、その階名ごとに独立グループとして後続に並ぶ
  - `floor=None` の断面だけを末尾の「（階なし）」グループへ集約
  - 空グループは省略
  - 表示順は上階→下階順
- `crates/squid-n-app/src/app/mod.rs`
  - `Navigator.focus_material: Option<MaterialId>` を新設
  - `#[cfg(any(test, feature = "gui"))]` で純粋関数のテストを GUI 無しでも実行可能

### UI

- `crates/squid-n-app/src/app/panels/navigator.rs`
  - 「部材一覧」の直後に断面一覧と材料一覧を配置
- `crates/squid-n-app/src/tables/materials.rs`
  - 材料テーブルの ID セルを選択可能セル化
  - `focus_material` をハイライト表示
  - `DeleteMaterial` の際、対象の `focus_material` をクリア
  - 削除後の ID 再採番に合わせて、対象より小さい ID の削除時には focus のずれが起こる既存挙動と同じ扱いとする

### 構造とテスト

- 純粋関数の実装は `#[cfg(feature = "gui")]` の UI メソッドから切り離している
- `nav_sections` / `nav_materials` は GUI 機能でのみ利用可能
- `nav_model.rs` にユニットテストを追加し、以下の 6 件を通してグループ化の仕様を固定する
  - 階グループ化の集約挙動
  - 階定義の上階→下階順
  - 未定義階名の初出順
  - 空階グループ省略
  - 材料区分固定順（入力順に依存しない）
  - 材料区分 UI 順位の全バリアント網羅

## 3. 確定設計（2026-08-22）

| 項目 | 集約場所 |
|------|----------|
| 階グループ化 | `section_floor_groups` |
| 「（階なし）」集約 | `section_floor_groups` |
| 空グループ省略 | `section_floor_groups` |
| 材料区分グループ化 | `material_category_groups` |
| 材料表示順 | `material_category_ui_rank`（鋼材→コンクリート→鉄筋。列挙追加時は match が fail-loud） |
| 断面・材料の focus | `Navigator.focus_section` / `Navigator.focus_material` |
| クリック導線 | `leaf click` → `active_tab = Tab::Model` → `bottom_dock_open = true` → `bottom_tab = BottomTab::Model` → `model_tab = ModelTab::Sections/Materials` → `focus` 設定 |
| 下ドックの開閉フラグ | `preparation.rs` のパターンを採用（`design_view.rs` は採らない） |
| UI ガード | `#[cfg(feature = "gui")]`, `#[cfg(any(test, feature = "gui"))]` |

断面一覧と材料一覧は、一覧の親ノードである階および材料区分によってツリー構造を明確化した。材料区分については、`MaterialCategory` の列挙順とは独立に、UI 表示だけを固定順で統一する設計とした。これは利用者にとっての見え方を一貫させるためであり、内部列挙順に依存しない。

## 4. 残課題

| 状態 | 項目 |
|------|------|
| ☐ | 対象より小さい ID の要素削除時のフォーカスずれ。`DeleteMaterial` / `DeleteSection` は後続 ID を繰り上げるため、フォーカス中より小さい ID を削除すると `nav.focus_*` が別要素を指す（影響はハイライトのずれ表示のみ）。`focus_section` にも同型の既存挙動があり、恒久対処は編集コマンド側での focus 再マップ |

対応済み（2026-08-22 フォロー）:

- ナビゲータ断面一覧の階グループ化を、階定義と完全一致しない階名でも独立グループで表示する方式へ変更（自由文字列である Section.floor の仕様に合わせた。従来は（階なし）へ集約され下パネル表示と不整合だった）
- レビュー指摘: 複数階の上階→下階順をテストで固定。材料区分の表示順を `match` による順位へ切り替え、バリアント追加時にコンパイルで気づけるようにした。テストフィクスチャをヘルパー化。申し送りのテスト件数を実装に合わせた

対応不要と判断済み:

- 同名階や「（階なし）」という名称の実階がある場合の CollapsingHeader `id_salt` 衝突 — 準備計算が階を一意生成する運用では事実上発生しないため過剰防御と判断
