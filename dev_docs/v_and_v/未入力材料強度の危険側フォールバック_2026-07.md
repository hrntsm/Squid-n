# 未入力の材料強度に対する危険側フォールバックの是正（2026-07）

**監査日:** 2026-07-28
**対象:** 非線形解析（保有水平耐力計算＝プッシュオーバー、非線形時刻歴応答解析）に
おける、**入力不足時のフォールバック**。
**契機:** 利用者ドキュメント（5.7 増分解析）に「\( Q_u \) を算定できない壁
（コンクリート強度が未設定など）は線形弾性として扱います」と明記されていたこと。
弾性のまま解析することは**危険側**であり、仕様として容認してはならない。

---

## 1. 問題の構造

非線形解析は、部材の終局耐力で応力を頭打ちにすることで崩壊機構を形成する。
耐力を算定できない部材は「弾性のまま／降伏しないまま」扱われ、押し込むほど
際限なく応力を負担する。結果として崩壊機構が形成されず、保有水平耐力を
**過大評価**する（＝危険側）。

すなわち「入力不足 → 既定値・弾性へ無音フォールバック」は、単なる利便性では
なく**安全性に直結する欠陥**である。入力不足は代替値で埋めず、解析を停止して
利用者へ是正内容を示すのが正しい扱いとなる。

## 2. 是正前に存在した危険側フォールバック

| # | 箇所 | 未入力の内容 | 従来の挙動 | 危険側である理由 |
|---|------|--------------|------------|------------------|
| 2.1 | `factory/mod.rs` `build_nonlinear_behavior`（Wall） | 材料の Fc | Qu=0 → 弾性の壁として解析続行 | 壁が Qu を超える水平力を無制限に負担 |
| 2.2 | `wall_panel.rs` `wall_shear_capacity_issue` | 断面未設定・材料未設定・Fc≤0・4 節点未満 | いずれも `None`（不備なし）を返し、`shear_capacity_of` は 0 → 弾性 | 2.1 と同じ。個別診断の網羅漏れが無音の弾性化に直結していた |
| 2.3 | `dynamic/timehistory/nonlinear.rs` | 同上 | 耐震壁の不備チェックを一切行っていなかった（プッシュオーバーのみ実装） | 非線形時刻歴で壁が降伏せず、応答を過小評価 |

だった。いずれも「未入力なのに解析が最後まで通り、結果が出てしまう」点で共通する。

## 3. 是正内容

### 3.1 解析前の入力チェックを新設し、両方の非線形解析から呼ぶ

`squid_n_element::factory::{nonlinear_input_issues, ensure_nonlinear_input}`
（`factory/input_check.rs`）を新設した。要素種別ごとに次を判定する。

- 耐震壁（`Wall`）: `WallPanelElement::wall_shear_capacity_issue`
- 線材（`Beam` / `Fiber` / `MultiSpring`）:
  - 材料が割り当てられていない
  - コンクリート系断面（`SectionShape::is_concrete_like`＝RC/SRC/CFT）で Fc 未設定または Fc ≤ 0
  - 上記以外の断面で fy も Fc も未設定
- 弾性としてモデル化することが仕様の要素（`Shell` / `PanelZone` / `NodalSpring`）と、
  特性を専用属性で持つ要素（`Isolator` / `Damper` / `Brace`）は対象外

呼び出し箇所は `pushover/driver.rs`（従来のインライン実装を置換）と
`dynamic/timehistory/nonlinear.rs`（新規、2.3 の是正）。エラーは是正内容を示す
日本語文を先頭 5 件まで列挙し、残りは件数で示す。

### 3.2 耐震壁の不備判定を網羅的にした

`wall_shear_capacity_issue` に、断面未設定・壁厚 ≤ 0・材料未設定・Fc ≤ 0・
壁エレメント構築不可（4 節点未満／退化）の各診断を追加した。さらに末尾へ
**総括判定**を置き、耐震壁として成立する壁で `shear_capacity_of` が 0 以下なら、
個別診断に当てはまらなくても不備として扱う。個別診断の追加漏れが無音の
弾性化に戻らないための不変条件（2.2 の再発防止）。

### 3.3 残るフォールバックには到達不能である旨を明記

2.4〜2.6 の各フォールバックは、3.1 のチェックにより非線形解析では到達しない。
削除はせず（線形解析・単体テストからの呼び出しがあるため）、到達しない根拠を
コメントで明記した。

## 5. 残課題（未修正）

### 5.1 RC 主筋の σy 既定値 345 N/mm²

`hinge.rs` / `shear_yield.rs` / `factory/springs.rs` は、RC 部材の主筋降伏強度を
`mat.fy.unwrap_or(345.0)` としている。SD295 の部材では耐力を過大評価する
（危険側）。ただしコンクリート材料のプリセット（`material_grade.rs`）は
`fy: None` であり、現状のデータモデルでは主筋強度の入力経路が実質存在しない。
チェック対象に加えると RC モデルが一律に解析不能となるため、今回は据え置いた。
**主筋強度を材料または断面の属性として独立に持たせる設計変更**が前提となる。

### 5.2 鋼材 σy 既定値 235 N/mm²（断面形状未設定の部材）

`hinge.rs` の複合断面・形状不明の分岐は `mat.fy.unwrap_or(235.0)` を用いる。
3.1 のチェックにより「fy も Fc も無い」ケースは停止するが、「Fc のみ設定された
形状未設定の部材」では 235 が使われる。5.1 と同じく入力経路の設計課題。

### 5.3 有効せん断断面積 as = 0 の方向

`build_dir_threshold` は as ≤ 0 の方向を \( Q_y = +\infty \)（判定対象外）とする。
直接入力断面で as を 0 とするのは「せん断変形を考慮しない」モデル化の意思表示
とも解釈できるため、入力不足とは断定できずチェック対象から外した。せん断降伏を
判定しない旨は利用者ドキュメント（5.7.3）に明記した。
