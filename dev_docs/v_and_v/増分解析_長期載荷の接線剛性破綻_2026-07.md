# 増分解析が長期荷重の初期載荷で解けない不具合の原因調査（2026-07）

利用者報告「増分解析でエラーになる（長期荷重の静解析は問題なく流れる）」の原因調査と
修正の記録。あわせて、同時に報告された「ねじりをピンにしているのに地震荷重時に
ねじり応力が出る」も同じ調査の中で切り分けた（結論は別件・表示側の問題）。

再現に用いたモデルは利用者提供の `.scz`（RC ラーメン 4 層＋塔屋、節点 170・要素 115、
剛床 4、Fc21、基礎梁 500×1800、柱脚ピン）。

## 1. 報告されたエラーメッセージは偽陽性だった

```
増分解析エラー: 長期荷重の初期載荷が収束しません（長期荷重に対して構造が不安定な可能性）。
長期荷重の初期載荷における接線剛性が特異です。次の自由度に剛性がありません:
節点 166 の Ux、節点 166 の Uy、節点 166 の Rz、節点 167 の Ux、節点 167 の Uy 他 7 件。
```

名指しされた 12 自由度は、**剛床の代表節点 4 つ（節点 166〜169）× 面内 3 成分**そのもの
だった。代表節点は階自動生成（`squid_n_load::story_gen::generate`）が重心に置く仮想節点で、

- 要素は 1 つも接続しない
- `Uz`・`Rx`・`Ry` のみを「零剛性自由度による特異行列を避けるための数値上のダミー拘束」とする
- 面内 3 成分（`Ux`・`Uy`・`Rz`）は自由のまま、剛床拘束のマスターとして働く

ため、**縮約前の接線剛性 \( K \) では必ず対角がちょうど 0** になる。診断
（`pushover/diagnosis.rs`）はこの `k_free` を走査していたので、**階を定義したモデルでは
例外なくこの偽陽性が出る**（健全なモデルでも出る）。実際、本モデルの縮約後 \( K_r \) には
初期状態で対角ゼロも負も 1 つもなく、解析冒頭の初期接線剛性チェックは通っていた。

**修正**: `diagonal_defects` の走査対象を縮約後 \( K_r = T^\top K T \) に変え、
`Reducer::free_dof_of`（縮約空間 → 自由 DOF 空間の逆写像。`indep_free` を
`Reducer::build` で保持）で節点・成分へ翻訳する。`t_rows` からの復元では不十分で、
剛リンクのスレーブ行が `[(master, 1.0)]` の形になるため一意に逆写像できない。
回帰テスト `test_diagnosis_ignores_rigid_diaphragm_master`。

## 2. 真因: NewRC コンクリートの「ひずみ 0 での接線」が 0 だった

`NewRcEnvelope::compression(x)` は、有理式の応力が非正になる終局域を
`if stress <= 0.0 { (0.0, 0.0) }` でクランプしていた。有理式は
\( \sigma_c(0) = 0 \) なので、**原点（x=0）もこのクランプに入り接線 0 を返していた**。

増分解析のファイバー用コンクリート既定は逆行型（`Retrace`、
`default_fiber_concrete_hysteresis(Incremental)`）で、圧縮側は除荷・再載荷も
`envelope_compression` を辿る。よってひずみちょうど 0 の評価がそのまま原点クランプに
掛かる（原点指向型 `OriginOriented` は別分岐で `(ec*strain, ec)` を返すため無傷、
`uniaxial::Concrete`・`ConcreteCyclic` も無傷）。

### 波及の経路

1. `GaussPoint::new` はファイバー接線キャッシュを `m.trial(0.0).1` で初期化する
   → RC 断面のコンクリート繊維がすべて **et = 0**。実測値: 500×1800 の基礎梁で
   コンクリート 80 繊維が et=0、主筋 16 本のみ et=205000。
2. `FiberBeam::build_plastic_zone` は、そのキャッシュから
   `sec_ei`（＝ヒンジ回転 γ の基準になる断面の弾性曲げ剛性）を採る
   → **主筋分だけ**の 6.98e14 になる（正しくは 6.38e15。約 1/9.1）。
3. 塑性増分ヒンジは
   \( \gamma = s L_p (\kappa - m_{sec}/EI_{sec}) \) を「弾性線を超える塑性超過分」と
   定義しており、弾性状態では \( dm = EI_{sec} \) すなわち γ=0 で要素剛性が
   \( K_{el} \) に厳密一致することを前提にしている。`sec_ei` が 9 倍小さいと
   `hinge_tangent` の \( G = -sL_p(\delta - dm/EI_{sec}) \) が 0 にならず、
   静縮約 \( K^* = K_{el} - f_x J^{-1} (DB) \) が巨大な負値を引く。

### 観測された挙動（修正前）

- 解析冒頭の初期接線剛性チェックは**通る**（未変形では `dm` も `sec_ei` も同じ
  ゼロ接線キャッシュから来るので G=0 になり、\( K^* = K_{el} \) のため）。
- 長期載荷の Newton 1 回目（\( |du|_\infty = 0.17\,\mathrm{mm} \) の微小変形）で
  ファイバーに実接線が入った瞬間に `dm/sec_ei ≈ 9.1` となり、17/115 要素
  （1 階の基礎梁・全ファイバー要素）の接線剛性の対角が −1.5e12 級の負値になる。
  残差は 1.95e8 → 2.71e8 と増大し、以降どれだけ増分を刻んでも回復しない。
- 線形静解析はファイバー要素を使わない（弾性 `BeamElement`）ため無傷。
  **「長期の静解析は通るのに増分解析だけ落ちる」という報告と完全に一致する。**

**修正**: `NewRcEnvelope::compression` は \( x \le 0 \) で \( (\,0,\ E_c\,) \) を返す。
原点の接線は解析的にも \( E_c \) に一致する（\( d(\text{ratio})/dX|_{X=0} = A \)、
\( A = E_c \varepsilon_{c0}/\sigma_{cB} \) より
\( (f_c/\varepsilon_{c0})\cdot A = E_c \)）。

**修正後**: 長期載荷は 5 分割各 2〜3 反復で収束し、増分解析は X 方向 Qu=3246 kN、
Y 方向 Qu=2528 kN（目標層間変形角 1/100、16 ステップ）で完走する。

### 既存テストがすり抜けた理由

`test_newrc_initial_tangent_is_ec` は `envelope_compression(-1e-9)` を評価しており、
**ひずみちょうど 0 を確かめていなかった**。ε=0 は「材料としてはどうでもよい点」に
見えるが、ファイバー断面の初期接線キャッシュに直結する実運用上の要所である。

回帰テスト:

- `newrc.rs::test_newrc_tangent_at_exactly_zero_strain_is_ec`（逆行型・原点指向型とも）
- `newrc.rs::test_newrc_envelope_compression_at_origin`
- `fiber/tests.rs::test_rc_plastic_zone_fiber_tangent_stays_positive_in_elastic_range`
  （RC 塑性化域ファイバー梁が弾性域で正定値を保つ。修正前は失敗することを確認済み）
- `fiber/tests.rs::test_all_fiber_materials_return_initial_tangent_at_zero_strain`
  （下記の共通要件を、実際に使う全材料を通しで確かめる。修正前は失敗することを確認済み）

### 材料実装の共通要件（`UniaxialMaterial`）

`sec_ei` は要素生成時のキャッシュをそのまま基準にするため、**どの材料であれ
「ひずみ 0 の接線 = 初期弾性接線」が成り立たないと同じ破綻が起きる**。これを
`UniaxialMaterial::trial` の doc コメントに実装要件として明記し、
`concrete_fiber_material`（除荷則 3 種 × fc≤60 / fc>60 の全分岐）と
`steel_fiber_material` を通しで確かめるテストで担保した。新しい材料モデルを
追加する際は同テストへ 1 行足すこと。

骨格式が原点で応力 0 になること自体は正しいので、**終局域のゼロクランプ条件と
見分けがつかない**のがこの種の不具合の温床である。調査時に他モデルも確認した結果は
次のとおりで、いずれも無傷だった。

| モデル | ε=0 の接線 | 備考 |
| --- | --- | --- |
| `ConcreteNewRc`（逆行型） | **0（不具合）→ Ec** | 圧縮側が常に包絡線を辿るため原点クランプに掛かる |
| `ConcreteNewRc`（原点指向型） | Ec | 別分岐（`(ec*strain, ec)`）で包絡線を呼ばない |
| `ConcreteCyclic`（Karsan–Jirsa） | Ec | `ConcreteEnvelope::initial_tangent` が `envelope.ec` を直接返す |
| `uniaxial::Concrete`（放物線、fc>60） | 2fc/\|εc0\| | 別分岐 |
| `mander::popovics_envelope` | Ec | x=0 で `e_sec·r/(r−1) = Ec` に解析的に一致 |
| `MenegottoPinto`（鋼材・主筋） | E | — |

## 3. 「ねじりピンなのに地震時に Mx が出る」は表示側の問題

同モデルでねじり解放の対象外部材は **0 本**（全 115 部材で i 端ねじれを解放済み）。
線形静解析の全荷重ケースで \( M_x \) の最大は次のとおりで、**理論どおり厳密にゼロ**だった。

| ケース | max \|Mx\| [N·mm] | 参考: max \|Mz\| [N·mm] |
| --- | --- | --- |
| EX | 3.5e-14 | 2.3e8 |
| EY | 2.7e-12 | 2.0e8 |

原因は応力図の描画側にあった。応力図は成分ごとに独立正規化する（60 px ＝ その成分の
モデル全体最大）ため、**全部材ゼロの成分では丸め誤差が最大値になり、誤差が画面一杯の
図として描かれる**。描画可否の判定が `max_abs >= 1e-12`（N·mm の絶対値）だったため、
EY の 2.7e-12 N·mm がこれを超えて描画に回っていた。凡例は kN·m 小数 1 桁なので
`max=0.0` と表示され、「値は 0 なのに図がある」という見え方になる。

**修正**: `viewer/diagram.rs::is_significant` を追加し、**同じ次元の成分の最大値**
（力 `[N,Qy,Qz]` ／ モーメント `[Mx,My,Mz]`）に対する相対値 \( 10^{-9} \) で判定する。
丸め誤差は基準に対して \( 10^{-12} \) 以下、実応力は最小でも \( 10^{-6} \) 程度の比を
持つため両者を安全に分離できる。実質ゼロの成分は凡例に
「全部材ゼロ（図なし）」と表示し、選択中であることは分かるようにする。

回帰テスト: `diagram.rs::{negligible_component_is_not_drawn,
small_but_real_component_is_still_drawn, all_zero_group_is_not_drawn}`。

## 4. 調査に使った一時コード

`crates/squid-n-app/examples/` に `repro_pushover.rs`・`repro_gravity.rs`・
`repro_torsion.rs` を一時作成し、`.scz` を読んで
（a）縮約前後の対角ゼロ／負の自由度、（b）長期載荷の Newton 反復を driver と同じ手順で
再現して発散箇所を特定、（c）全荷重ケースの成分別最大値、を出力した。調査後に削除済み。
同種の報告があれば同じ 3 本を書き直すのが早い（`squid-n-app` は `squid-n-io` と
`squid-n-solver` の両方に依存するので、`.scz` を読んでソルバを直接叩ける唯一のクレート）。
