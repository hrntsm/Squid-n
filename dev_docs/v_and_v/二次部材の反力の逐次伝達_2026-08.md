# 二次部材の反力の逐次伝達（2026-08）

**対象**: `squid_n_load::cascade`（二次部材の荷重伝達）、`squid-n-job::auto_loads`（荷重同期）、`squid-n-app::check::design_secondary_joist_checks`（断面検定）
**区分**: 申し送り「床領域・壁領域の再設計」§3.4・§5.44（Step 5 の完遂）
**判定**: ☑（小梁を二次部材へ一本化。二次部材に支持された二次部材の荷重が解析から消える危険側の穴を塞いだ）

---

## 対象

同じ物理的な小梁を手入力小梁ライン（`JoistLine`）と二次部材（`SecondaryMember`）の
2 つの型で登録できる状態を解消し、荷重の基準を一本化した。あわせて、二次部材が
他の二次部材に支持されている場合に反力が黙って解析から消える不具合を是正した。

設計決定の経緯は申し送り §3.4（dig による合意 10 問）、実装内容は §5.44 を参照。

## 発見: 実データが現に荷重を失っていた

**着手前の見立ては誤りだった。** 「実フィクスチャの小梁 56 本は全本とも両端が大梁の
材軸上にあり、小梁どうしの内部交点も 0 件だから、代表スカラは不変であるべき」と
記録していたが、実装中の実測でこれが覆った。

見落としていたのは、**床板の境界が小梁の材軸上で途中節点により分割されている**ことである。

| 計測 | 値 |
|---|---|
| 二次部材小梁 | 56 本 |
| 床板境界が材軸上で分割されている小梁 | **15 本** |
| その分割点（小梁の内法に載る床板境界節点） | **20 か所** |
| そのうち大梁の材軸上に無いもの | **20 か所（全部）** |

分割点は、いずれも別の小梁が取り付く T 字の交点である。そこへ載った辺荷重の反力は
`resolve_nodal_to_primary` が主架構の梁へ変換できず、`NodalLoad` のまま残り、
`DofMap::build` が非構造節点として無視していた。

**実測した欠落**:

| | 値 [N] |
|---|---|
| 床板の固定荷重の総和（面荷重 × XY 投影面積） | 3,356,237 |
| 非構造節点で捨てられていた荷重 | **240,373（7.2%）** |

荷重タブには見えるため、総和を眺めても気づけない。`precheck` の孤立節点チェックは
二次部材の参照節点を意図的に除外しているため警告も出ない。§5.28 で自立壁について
見つけたのとまったく同じパターンである。

## 是正

二次部材が受け持った荷重を単純梁の両端反力に変えて支持相手へ渡し、**支持相手が別の
二次部材のときはその集中荷重として渡して、主架構へ行き着くまで繰り返す**（逐次伝達）。

交点は常にピン受け・架けとするため（§3.4 F2）各段が静定に決まり、逐次伝達は近似ではなく
厳密解である。受け側・架け側は幾何から決まる（端点が相手の内法に載るほうが架け側）。

反力は材軸に対して分解し、直交成分は単純梁反力、材軸方向成分は両端 1/2 ずつとする。
水平な小梁に鉛直荷重なら全部が直交成分、鉛直な間柱に自重なら全部が軸方向成分になり、
どちらも従来の扱いと一致する。**小梁と間柱を同じ骨格で扱えるのはこの分解による。**

## 代表スカラの変化（`snapshot_key_scalars`）

実 ST-Bridge フィクスチャ（`model.stb`）。**変化は「これまで失われていた荷重が主架構へ
載る」＝需要が増える向き**であり、安全側への是正である。

| キー | 是正前 | 是正後 | 変化 |
|---|---|---|---|
| `static.DL.sum_base_axial` | -2.895e6 | **-3.143e6** | +8.6%。回収した床荷重 240 kN と二次部材自重の経路変更に対応する |
| `static.DL.min_uz` | -8.685e-1 | **-9.427e-1** | +8.5%。荷重が増えたぶんたわむ |
| `design.joist_max_ratio` | 2.975e-1 | **3.125e-1** | +5.0%。受け梁が架け梁の反力を集中荷重として受けるようになった |
| `eigen.T[0]` | 4.849e-1 | 4.851e-1 | +0.04%（並進モード） |
| `eigen.T[2]` | 4.042e-1 | 4.096e-1 | +1.3%（ねじれモード） |
| `metrics[2FL].Re`（偏心率） | 1.593e-4 | 9.211e-3 | 絶対値は小さいまま |
| `pushover.Qu` | 2.509e6 | 2.515e6 | +0.2% |
| `design.max_ratio` | 6.352e-1 | **6.336e-1** | **−0.25%。増加ではない** |

`design.max_ratio` だけが微減した。荷重の総量は増えているが、**帰属先が変わった**ためである。
是正前は分割された床板境界ごとに単純梁反力を出し、その一部を（大梁の材軸上に無い）分割点へ
載せていた。是正後は小梁 1 本を通しの単純梁として扱い、反力は両端（＝大梁の上）へ集まる。
このため個々の大梁が受ける集中荷重の位置と大きさが入れ替わり、最大検定比を与える部材が
わずかに軽くなった。**総量が増えているのに一部の部材が軽くなること自体は矛盾しない**
（荷重の再配分であり、他の部材は重くなっている）。

固有周期と偏心率が動いた理由は、**階の重量は変わらず、階の中での荷重の位置が変わった**
ためである。`prep.total_seismic_weight` と `prep.story[*].seismic_weight` は是正前後で
まったく変化していない（地震用重量の階配分は従来どおり両端 1/2 ずつのままで、§3.4 F8 の
残課題としてあえて触っていない）。一方で、荷重の作用点は「小梁の端部節点（一部は
非構造節点で捨てられていた）」から「大梁上の集中荷重」へ移った。床内での重量の偏りが
変わるため、並進モード（`T[0]`・`T[1]`）はほとんど動かず、**ねじれモード（`T[2]`）と
偏心率が相対的に大きく動く**。この動き方は説明と整合する。

`model.nodes` は 166 → 171、`model.elements` は 115 → 157 と記録されているが、これは
準備計算が生成する仕口パネル要素等を含む値であり、本変更とは無関係である（是正前後で同じ）。

床分配を混ぜると期待値が分配則に依存するため、面荷重を 0 にして**自重だけ**で骨格を確かめる。

| テスト | 内容 |
|---|---|
| `joist_on_girders_terminates_at_primary` | 両端が大梁に載る小梁は自重の半分ずつを主架構へ渡して終端する |
| `joist_on_joist_cascades_to_primary` | 架け側の端が受け側に載ることを支持判定で確認し、主架構へ渡る総和が 2 本の自重の合計に一致する |
| `vertical_post_splits_axial_load_in_half` | 鉛直な間柱の自重は材軸方向成分なので両端へ 1/2 ずつ（従来の扱いを保つ） |
| `floating_joist_is_unresolved` | どこにも載らない二次部材を検出する |
| `cyclic_support_is_reported` | 支持関係が一巡する 3 本を検出し、逐次伝達の対象から外す |
| `crossing_without_shared_node_is_reported` | 節点を共有しない交差を検出する |
| `materialized_joist_is_skipped` | 実部材化済みの二次部材は対象外 |

**直線 2 本では相互支持は幾何的に成立しない**（互いの端点が相手の内法にある配置が作れない）
ため、循環のテストは 3 本で一巡させている。

## 実装レビューで見つけて直した 2 件

コミット前の自己レビューで、逐次伝達本体に 2 件の問題を見つけて直した。

1. **主架構より二次部材を優先していた。** 端部が大梁の材軸上にあり、かつ 10 mm 以内に
   並走する別の二次部材の内法にも載る場合、二次部材を受け側に選んでいた。大梁が直接
   支持しているのだから、そこで終端するのが正しい。`joist_design` が既に持っていた
   「並走する小梁が外周大梁の荷重を奪わない」規則（§5.42）と同じ考えである。
   **主架構を先に判定し、届かないときだけ二次部材を探す**形へ直した。
2. **部材数に対して超線形だった。** 端部ごとに `beam_span_position` を呼んでいたため、
   呼び出しのたびに全要素を走査し直していた（`O(二次部材数 × 要素数)`）。自重の引き当ても
   キーごとに全二次部材を線形探索していた。大梁候補列と二次部材の索引を 1 回だけ構築して
   使い回す形へ直した。`region_gen::wall` で同じ罠が残課題になっている（900 本で 1.8 秒）
   ため、新しく作らないようにした。

## 既知の近似・未対応

- **材軸方向成分（軸力）は両端へ 1/2 ずつ**。長期の鉛直荷重としては下側の支点へ全量が
  流れるのが自然で、現行は下の梁を半分だけ軽く見る**危険側の可能性がある**。今回は従来の
  扱いを引き継ぐにとどめ、是正は残課題とした（申し送り §3.4 F8）。地震用重量の階配分では
  「上下階へ半分ずつ」が慣行であり、変えるとしても長期側だけになる。
- **壁版から間柱への辺荷重の分配は未実装**。間柱はいまも自重しか持たない。骨格には通して
  あるため、分配を実装すれば同じ経路に乗る。
- **間柱の断面検定は存在しない**。
- **段差床・傾斜小梁の検定そのものは未対応**。荷重の行き先は逐次伝達の分解則で定義された
  （材軸直交成分と軸方向成分に分ける）が、検定は「未」のままである。
- 逐次伝達が荷重を流せない形（循環）に含まれる二次部材は、荷重が主架構へ渡らない。
  これは解析前チェックのエラーで止めるため、黙って消えることはない。
