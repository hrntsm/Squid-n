# V&V: フレーム外雑壁（`OutOfFrameMiscWall`）の壁版への移行（2026-09）

## 対象

床領域・壁領域の再設計 §3.2 E4「自由座標の雑壁は節点参照へ完全移行し、自由座標入力は
廃止する」の実装。あわせて次の 3 件を扱う。

1. **壁の仕上げ・増打ちの面荷重**（`WallPlate.loads`）の新設
2. **立ち上がり高さの未指定（＝階高いっぱい）**（`WallPlateShape::Attached.extent` の `Option` 化）
3. **偏心率の n 倍法の対象を自立壁だけへ限定**

設計決定の経緯と dig の回答は
[`handoff/床領域・壁領域の再設計_申し送り.md` §5.48](../handoff/床領域・壁領域の再設計_申し送り.md)
を参照。

## 何を検証したか

### 1. 移行前の経路が持っていた危険側の欠陥（実測）

移行の合格条件を「代表スカラの一致」に置かなかったのは、**旧経路が重量を失っていたため**で
ある。一致させにいくと、失っていた状態を正解として固定することになる。

壁フィクスチャ（`squid-n-app/tests/wall_model.rs`）のパラペット（Y=3000 面の梁 6-7 に沿う、
長さ 4000・高さ 900・面重量 1.2e-3 N/mm²、総重量 4320 N、`MiscWallTransfer::Column`）について、
`prep.summary.total_seismic_weight` を 3 つの状態で実測した。

| 状態 | 総地震用重量 [N] | パラペットの寄与 [N] | 総重量に対する割合 |
|---|---|---|---|
| パラペットなし | 41452.78 | — | — |
| **旧経路（記録されていた代表スカラ）** | **43610** | **2157.2** | **49.9%** |
| 新経路・総重量を 4320 N に揃えた場合 | 45772.78 | 4320.0 | 100% |

**旧 `MiscWallTransfer::Column` は、壁の重量の半分を階の地震用重量から落としていた。**
最も近い柱要素の**上下 2 節点**へ 1/2 ずつ配る規則のため、下端側（基部の節点）へ回った分は
どの階にも属さず集計から外れる。上階の地震力を過小に見る危険側の挙動である。

後継の `LoadTransfer::Columns` は取付き線の両端へ集中するので、全量がその階に残る。
上表の 3 行目がこれを示す（寄与 4320.0 N ＝ 総重量そのもの）。

もう 1 つの欠陥は `misc_wall_weight_shares` の `nearest_node` にあった。モデルの全節点から
最近接を選ぶため非構造節点に当たりうるが、`DofMap` は非構造節点への節点荷重を無視する。
地震用重量には残るのに長期 DL からは黙って消える。§5.28 で自立壁について削除した
フォールバックと同型で、後継の経路（取付き線・床領域のアンカー）はどちらも構造節点または
床板を経由するため、この穴自体が生じない。

### 2. 代表スカラの変化

フィクスチャのパラペットを、取り付く壁版（線アンカー・`LoadTransfer::Columns`・立ち上がり
900・板厚 120 の RC・仕上げ 0.3 kN/m²）へ置き換えた。総重量は 4320 N → 11247.5 N になる。

`squid-n-app/tests/wall_model.rs` のスナップショット差分は次のとおり。

| 項目 | 旧 | 新 | 変化 |
|---|---|---|---|
| `prep.total_seismic_weight` | 4.361e4 | 5.270e4 | +20.8% |
| `eigen.T[0]` | 7.208e-2 | 7.898e-2 | +9.6% |
| `eigen.T[1]` | 5.270e-2 | 6.196e-2 | +17.6% |
| `static.DL.wall_forces_abs_sum` | 1.126e5 | 1.070e5 | −5.0% |
| `static.EX.wall_forces_abs_sum` | 2.951e7 | 3.322e7 | +12.6% |
| `static.EX.top_disp_x[node4]` | 8.584e-3 | 9.435e-3 | +9.9% |
| `holding.qu` | 9.529e5 | 8.747e5 | −8.2% |
| `holding.qun` | 2.290e4 | 2.767e4 | +20.8% |

### 3. 変化の要因を、重量と剛性へ切り分けた実測

代表スカラの変化が何によるものかを確かめるため、パラペットの状態を 4 通りに変えて実測した。
2 行目は断面を外して面荷重だけで総重量 4320 N を作った状態で、板厚が引けないため雑壁の剛性
算入の対象にならない。3 行目は断面を持たせたまま板厚を調整して総重量を 4320 N に合わせた
状態で、剛性算入の対象になる。この 2 行の差が剛性の寄与にあたる。

| 状態 | 総重量 [N] | `DL.wall_forces_abs_sum` | `holding.qu` | `holding.qun` |
|---|---|---|---|---|
| パラペットなし | 41452.8 | 1.2691e5 | 9.2570e5 | 2.1763e4 |
| 重量 4320 N のみ（剛性算入なし） | 45772.8 | 9.8237e4 | 8.0583e5 | 2.4031e4 |
| 重量 4320 N ＋ 剛性算入あり | 45772.8 | 9.8237e4 | 8.0583e5 | 2.4031e4 |
| 現行（板厚 120 ＋ 仕上げ） | 52700.3 | 1.0701e5 | 8.7471e5 | 2.7668e4 |

読み取れることは 3 つある。

**パラペットを雑壁の剛性算入へ含めた効果は、このフィクスチャでは 0 である。**
2 行目と 3 行目が全項目で一致した。雑壁の断面性能算入はコンクリート系部材にしか適用せず、
このパラペットが取り付く頂部梁は鋼であるためである。§5.45 の残課題「取り付く壁版を雑壁の
剛性算入へ含めた効果が未測定」は、フィクスチャの型が旧型だったことが理由ではなく、
**取付き先の部材種別が理由だった**。残課題は引き続き残る。

**`holding.qun` は算入された地震用重量に比例して動く。** 41452.8 → 2.1763e4、43610（旧経路の
記録値）→ 2.290e4、45772.8 → 2.4031e4、52700.3 → 2.7668e4 と単調である。必要保有水平耐力が
重量に追随することの確認になる。

**`static.DL.wall_forces_abs_sum` と `holding.qu` は、重量に対して単調ではない。**
どちらもパラペット重量 4320 N 付近を谷として、増やすと戻る。このフィクスチャは対称な架構で、
長期では壁と柱の負担差が小さく壁の材端力がほぼ打ち消し合う位置にある（`wall_model.rs` の
`static.DL.wall_forces_abs_sum` の行に付したコメント参照）。**絶対値の総和がこの打ち消しの
近傍を通るため、これら 2 項目は本フィクスチャでは変化の向きを解釈できる指標ではない。**
壁の面内せん断を実際に動かすのは地震荷重で、変化を追う代表値は `static.EX` 側に置いてある。

`eigen.T`・`static.EX`・`holding.qun` の増加は、いずれも重量の増加（+9090 N）で説明がつく。
その内訳は、旧経路が落としていた分の回復が +2162.8 N、フィクスチャの入力をパラペットの実寸
（板厚 120 の RC ＋ 仕上げ 0.3 kN/m²）へ改めた分が +6927.5 N である。

実 ST-Bridge フィクスチャ（`squid-n-app/tests/full_model.rs`）は**全項目不変**である。
`OutOfFrameMiscWall` を 0 件しか含まないため、この移行が当たらない。

### 5. 危険側の穴を新設していないこと

立ち上がり高さの未指定（`extent = None`）を線アンカーでも許すと、
`squid_n_element::misc_wall::attached_geometry` が `top_pair = None` の壁として扱い、
`strip_height` の `other_missing` 経路で階高分の腰壁せいを取付き先の梁 1 本へ丸ごと算入する。
梁の剛性を過大に、変形を過小に見る。

これを 3 か所で同じ規約により弾く。

| 場所 | 弾き方 |
|---|---|
| `Model::validate` | `CoreError::DanglingRef` |
| `squid-n-edit::wall_extent_ok` | `AddAttachedWallPlate`・`SetAttachedWallPlateExtent` が Noop |
| `squid-n-app` の壁版タブ | 自立壁のときだけ「階高」チェックボックスを出す |

加えて `plate_geometry` は `extent` が `None` の壁版を `attached_geometry` へ渡す前に落とす。
規約が破られたモデルを読み込んでも、剛性を過大に見る経路へは入らない。

n 倍法の二重計上も避けている。腰壁・垂れ壁・パラペット（線アンカー）は
`squid_n_element::misc_wall::collect_misc_walls` が周辺柱梁の断面性能へ既に算入しており、
等価剛性要素としても数えると剛性の過大評価＝偏心率の過小評価になる。
`self_standing_stiffness` が `RegionAnchor::FloorRegion` 以外を返さないことで防ぐ。

## 未検証・残る近似

- **仕上げ・増打ちの面荷重を持つ実モデルでの検証**。壁フィクスチャのパラペット 1 枚だけが
  `loads` を持つ状態で、実 ST-Bridge フィクスチャには 1 枚も無い。ST-Bridge に仕上げ荷重の
  情報源が無いため、取り込み経路では常に空になる。
- **複数層にまたがる自立壁の n 倍法**。下端が載る床の直上の層 1 つにだけ寄与させ、上の層には
  算入しない。旧 `OutOfFrameMiscWall` の中間高さによる単一帰属と同じ扱いだが、剛性の寄与を
  落とす側なので偏心率がどちらへ振れるかは形状による。
- **取り付く壁版を雑壁の剛性算入へ含めた効果**（§5.45 の残課題）。上表の 2 行目と 3 行目が
  一致したとおり、このフィクスチャでは効果が 0 である。雑壁の断面性能算入はコンクリート系
  部材にしか適用せず、パラペットが取り付く頂部梁が鋼であるためで、測定には RC 梁へ取り付く
  壁版を持つフィクスチャが要る。
