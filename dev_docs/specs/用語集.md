# 用語集

実装に登場する概念とその呼び名を集約する。**新しい概念に名前を付ける前にここを見る**。
既存の用語で表現できるなら、新しい言い換えを作らずそれを使う。

新しく実装した概念には、その都度この用語集へ追記する。「誤用に気づいたら直す」だけでは
気づくまで誤用したままになる。用語集を常に現状の全用語を映した状態に保つことで、次に
同じ概念へ名前を付けようとしたときに既存の用語が見つかり、重複や混同を防げる。

## 床

| 用語 | 意味 |
|---|---|
| 床領域／区画 | 大梁が囲む 1 スパンの区画そのもの。名前・境界・所属小梁・所属床板一覧・手入力小梁ラインを持つ。`FloorRegion` |
| 床板 | 区画内の版。大梁または小梁で囲まれる、または主架構に取り付く。断面・仕上荷重・室用途・分配方法を持つ。`Slab` |
| 取り付く床板 | 片持ち・バルコニー・出隅。主架構に囲まれず、取付き線または点と張り出し量で決まる。`SlabShape::Attached` |
| 取付き先 | 取り付き領域（床・壁とも）が取り付く相手。線（節点対＋区間）／点（節点）／床領域（節点対＋所属先の床領域 ID）の 3 つを取る。床板（`Slab`）は線・点のみを使う（床領域アンカーは床板では常に不正）。壁の取り付き領域（`WallPlate` の `Attached` 形）は自立壁で床領域アンカーを使う。床領域アンカーの節点対は壁自体の長さ（自重の算定）に使い、荷重は節点ではなく所属先の床領域へ渡して等価な面荷重へならす（D17: 壁が床領域内のどこにあるかという位置情報だけを捨てる。長さは捨てない）。`RegionAnchor` |
| 伝達規則 | 取付き先が「線」の取り付き領域（床板・取り付く壁版）が、自らの荷重（面荷重・自重）を主架構のどちらへ渡すかの2択（D16。取付き先が「点」「床領域」は渡し方が一意なので選べない）。`Anchor`（**分布**、既定）は取付き線の区間 `span`（全長なら `[0, 1]`）へ等分布荷重として載せ、梁の曲げを生じさせる（片持ちスラブ・梁に載るパラペットの実際の伝わり方。部分区間を梁全長へ薄めない）。`Columns`（**集中**）は梁の曲げを無視し、取付き線の区間中点（`t_mid`）による単純梁反力按分で両端の柱2本へ集中荷重として渡す（出隅・雑壁の柱伝達と同じ操作）。`squid_n_core::model::LoadTransfer` |
| 版 | 床板の仕様（断面・仕上荷重・室用途・分配方法・一方向）そのもの。`SlabPlate` |
| 二次部材 | 小梁・間柱。解析要素ではなく、床荷重・自重は主架構への集中荷重（CMQ）として伝わる。`SecondaryMember` |
| 交差小梁の格子解析 | 手入力の小梁ライン（`FloorRegion.joists`）による二方向の床格子サブモデル。`JoistLine`、`squid_n_job::floor_grillage` |
| 負担幅（トリビュタリ幅） | 小梁 1 本が受け持つ面荷重の幅（`spacing`）。実荷重は `w × spacing` の等分布荷重として小梁の支持点へ伝わる。二次部材の小梁検定では、境界に載る小梁は床板境界の幾何（`squid_n_load::secondary::joist_edge_tributary_width`）、床板内部を通る小梁は平行小梁の間隔から求める |

## 壁

| 用語 | 意味 |
|---|---|
| 壁領域 | 柱・梁が囲む鉛直構面内の閉領域そのもの（D1）。版の仕様は持たない（壁版〔`WallPlate`〕が持つ）。`id`・`name`・`boundary`・`wall_plate_ids`・`post_ids` を持つ（床領域 `FloorRegion` と同型）。主架構から再構成される派生的な入力の持ち主（D10）で、利用者は表示名（`SetWallRegionName`）と間柱コマンド（`SetWallRegionPostIds`）を持つが、間柱所属は準備計算の D7 で入れ直される。`region_gen::wall` の境界から組み立てる `wall_region_rebuild` は結線済み。壁版の ST-Bridge 取り込み・要素生成・参照張り替え（自重算定・保有水平耐力・ST-Bridge 出力）も結線済み（§5.14）。利用者による領域の追加削除はできない。`squid_n_core::model::WallRegion` |
| 構面 | 柱・梁のうち、XY 平面上の同一直線の真上（`MEMBER_AXIS_TOL_MM` の許容差以内）に乗るものの集合。壁領域の境界検出は構面ごとに面走査を行う（床の「同じレベル」に相当する絞り込み単位）。通り芯（`AxisGroup`。表示専用）には依存しない新規の幾何判定。`squid_n_core::region_gen::wall` |
| 壁領域の境界 | 構面内で柱・梁が囲む閉領域そのもの（面走査の結果）。`WallRegion` 本体（版・二次部材を持つ利用者向けの型）とは別で、`wall_region_rebuild` がこれを入力に `WallRegion` を組み立てる。面積はニューエルの公式による 3 次元面積（理想平面への投影を経由しない）。`squid_n_core::region_gen::wall::WallRegionBoundary` |
| 壁版 | 版の仕様（断面・開口）を持つ実体。1 つの壁領域は間柱で分割されていれば複数の壁版を持ちうる（E5。床側の `Slab` と同じ関係）。パラペット・構面外の腰壁・垂れ壁・自立壁はどの壁領域からも参照されない独立した壁版として存在する（`OutOfFrameMiscWall` の後継）。層の構面内に重心が入る腰壁・垂れ壁は `Enclosed` のまま壁領域へ帰属する。自重は必ず断面（厚さ・主材料）参照から求め、`OutOfFrameMiscWall` が持っていた直接入力（面重量・厚さ）の経路は持たない。柱・梁が囲む壁版（`Enclosed` 形）は `wall_region_rebuild` が所属先の `WallRegion` へ自動で割り当てる。どの壁領域にも収まらず、水平な辺がちょうど 1 つ大梁に全長載り自由端が 1〜2 点の壁版は、`wall_region_rebuild` が取り付く壁版（`Attached`／`Line` アンカー）へ自動変換する（床側 D20 相当。§5.18。自由端は取付き辺上にない頂点。同じ高さでも辺から外れた頂点は数える。§5.22）。取り付く壁版は解析要素にしない。自重の自動分配（取り付く壁版の自重配分）と数量拾いへの算入は行う。ST-Bridge 取り込みは `RawWall`（`StbWall`）を `WallPlate` として組み立てる（§5.14。旧版は `ElementKind::Wall` を直接生成していた）。利用者による取り付く壁版の追加削除は `squid-n-edit` の `AddAttachedWallPlate`/`DeleteWallPlate`/`InsertWallPlate`（床板の `AddAttachedSlab`/`DeleteSlab`/`InsertSlab` 相当。§5.18）で可能（`squid-n-app` の GUI・MCP 配線は未着手）。`Enclosed` の境界がちょうど4節点かは `WallPlate::has_quad_boundary` で判定する（Q6=C。5節点以上や3節点以下は解析要素を生成しない。壁エレメントの4節点24自由度の定式化を崩す一般化は行わない。§5.19）。`squid_n_core::model::WallPlate` |
| 取り付く壁版の自重配分 | 取り付く壁版（`WallPlate` の `Attached` 形）の自重を、伝達規則（`LoadTransfer`）に沿って地震用重量・長期応力解析のDL・数量拾いへ算入する仕組み。「線」アンカーは取付き線（`LoadTarget::Span`。区間 `span` を梁全長へ薄めず正確に扱う）または取付き線両端の柱（`LoadTarget::Node`）へ、「床領域」アンカー（自立壁）は所属先の床領域の床板へ等価面荷重（D17）として上乗せする（強度の分母は床の分配と同じ XY 投影面積。床板を1枚も持たない、または XY 面積が 0 の床領域では総重量保存のため取付き線の両端節点への集中荷重にフォールバックする）。床の取り付く床板と同じ幾何解決パイプライン（`squid-n-job::auto_loads::slab_load_case_content`）へ合流させることで、部分区間の精度を床側と揃える（危険側の近似を避ける。`AGENTS.md`「実装方針」参照）。DL が無く密度から地震用重量を直接算入する経路では、総重量を取付き線両端の節点へ集中させて算入する（`accumulate_attached_wall_seismic_weight`）。数量拾いにはフレーム外雑壁と同じカテゴリ（`MemberCategory::MiscWall`）で算入する。`squid_n_load::wall_attached` |
| 壁展開・壁展開モデル・壁展開インデックス | 壁の解析要素（`ElementKind::Wall`）は入力の正である `Model` には存在しない生成物（D4・D5）であり、`WallRegion`/`WallPlate` から都度組み立てる。**壁展開**はこの組み立て操作、**壁展開モデル**はその結果（生成要素を追加した `Model` の一時的な複製。呼び出し元のモデルへは書き戻さない）、**壁展開インデックス**は壁展開モデル中の生成要素 `ElemId` から由来する `WallPlateId` を逆引きする対応表を指す。壁展開モデルには由来する壁版の開口・三方スリットを写した `WallAttr` も合成して積む（既存の壁消費者を無改修で動かすための移行期の内部表現。`Model.wall_attrs` そのものの恒久存続を意味しない）。都度計算でキャッシュしない（生成は決定的なため複数回呼んでも同じ `ElemId` になる）。二重展開（壁展開モデルへさらに壁展開を適用すること）は自重・剛性の二重計上を招くため禁止で、`debug_assert!` で検査する。`squid_n_load::wall_expand::expand_wall_elements` |
| 壁エレメント | 耐震壁の要素モデル（RC規準の耐震壁）。壁柱を上下の剛梁で挟む 4 節点 24 自由度要素。`ElementKind::Wall`、実装は `squid_n_element::wall::wall_element::WallElement`。剛域算定・自重・解析・診断の直前に壁展開モデルとしてのみ現れ、`Model.elements` には保存されない。ST-Bridge の書き出しは壁版から行い、壁エレメントは出さない |
| フレーム内雑壁 | 腰壁・垂壁・袖壁。壁エレメントとしてではなく、周辺の柱・梁の断面性能へ合成する（独立した解析要素ではない）。`squid_n_element::wall::misc_wall::InFrameMiscWallGeometry`（`pub(crate)`） |
| フレーム外雑壁 | 部材としてモデル化しない壁。始点・終点の絶対座標に高さ・面重量を持ち、0.5m 分割規則で近傍の節点へ重量を集計する（フレーム内雑壁とは異なり、周辺部材への剛性合成はしない）。`squid_n_core::model::OutOfFrameMiscWall`（公開型）。Step 7+8 で節点参照（線／点／床領域のアンカー）へ作り替え予定 |
| 側柱 | 耐震壁の左右の鉛直辺。面内両端ピン化して壁エレメントとのせん断二重計上を避ける。`side_column` |

「雑壁」は構造計算上、フレーム内雑壁・フレーム外雑壁のどちらも指しうる語である。**「雑壁を直して」
のように型名を伴わずに話すときは、上表の 2 行のどちらを指すか（既存の壁エレメントが降格した
ものか、最初からモデル化しない壁か）を先に確認すること。** 2026-08-26 以前は両者の Rust 型名が
`MiscWall` で衝突していたため（`squid_n_element` 側を `InFrameMiscWallGeometry` へ、
`squid_n_core` 側を `OutOfFrameMiscWall` へ改名して解消）、このすれ違いはコード上でも
起こりやすかった。

## 柱梁接合部

| 用語 | 意味 |
|---|---|
| 仕口パネル | 柱梁接合部。S造（CFTを除く）にせん断変形角の自由度を持つ要素として設ける。`ElementKind::PanelZone` |
| 剛域 | 部材端の剛体アーム長。柱・梁のフェース距離（取り付く壁の張り出しを含む）から算定する。`RigidZone` |

## 禁止語

| 用語 | 意味 |
|---|---|
| パネル | **禁止**。建築構造では柱梁接合部（仕口パネル）を指す確立した語のため、床の区画・床板・構面の意味では使わない。UI のドックパネル等、画面部品の意味でのみ許可する |
