# 床領域と壁領域

本書では、床版と小梁をまとめる「床領域」と、壁版と間柱をまとめる「壁領域」のデータモデルを紹介します。

二次部材（小梁・間柱）は解析対象の部材ではなく、荷重を大梁や柱へ渡すための部材です。
そのため、どの床を支えている小梁なのか、どの壁に付いている間柱なのかがわからないと、荷重を渡す先を決められません。
この所属関係を持たせるための仕組みが、床領域と壁領域です。

## 現在の実装状況

**このデータ構造を編集する UI はまだありません。**
`squid-n-edit` の編集コマンドと `Model::validate` の検証までを実装した段階です。

そのため利用者向けの `docs/` には節を置いていません。
UI からの入力経路ができ、荷重分配が所属関係を実際に使うようになった時点で、利用者向けの計算根拠として `docs/` に書き起こしてください。

現時点で領域へ所属を登録できるのは、編集コマンドを直接呼ぶ場合だけです。

- ST-Bridge の取り込みでは所属を作らない。元の XML に床と小梁、壁と間柱の親子関係を表す要素がないため
- 架構作成ウィザードでも所属を作らない
- そのため、実運用のモデルでは所属リストは空のまま

## 型の構成

所属は、二次部材の側ではなく**領域の側が子の ID を持つ**形で表します。

| 型 | フィールド | 内容 |
|---|---|---|
| `Slab` | `secondary_joist_ids: Vec<SecondaryMemberId>` | その床領域に属する小梁の ID |
| `WallRegion` | `wall: Option<ElemId>` | 壁版の要素 ID。`None` は版なし |
| `WallRegion` | `post_ids: Vec<SecondaryMemberId>` | その壁領域に属する間柱の ID |

二次部材の側に「所属する領域」を持たせなかったのは、1 枚の床に何本もの小梁が付くという関係が素直に表せるためです。
逆向きに持たせると、領域を消したときに全二次部材を走査して所属を外す必要があり、参照の整合を保つ手間が増えます。

### 床版は常に存在する

床領域は `Slab` そのものであり、床版のない床領域はモデルに持ちません。
床版がなければ床荷重も発生せず、小梁をまとめる意味がないためです。

一方で壁領域は `wall` が `None` になれます。
壁版としては扱わない補助的な間柱束のように、版を持たない間柱のグループを表す必要があるためです。

## `SecondaryMemberId` の不変条件

`SecondaryMember.id` は、**`Model::secondary_members` の配列添字と一致していなければなりません**。
領域側は ID で子を指すため、添字とずれると別の部材を指してしまいます。

この不変条件は `Model::validate` が確認し、破れていれば `IndexMismatch` を返します。

二次部材をまとめて間引くときは、必ず `Model::retain_secondary_members` を通してください。
素の `Vec::retain` で消すと後続の `id` が添字とずれ、領域側の参照が黙って別の部材を指します。
`retain_secondary_members` は間引きと同時に ID を振り直し、`secondary_joist_ids` と `post_ids` の参照を新しい ID へ張り替えます。

## 検証の内容

`Model::validate` は、領域の参照について次を確認します。

- `SecondaryMember.id` が配列添字と一致する
- `secondary_joist_ids` の参照先が実在し、種別が `Joist` である
- `post_ids` の参照先が実在し、種別が `Post` である
- `WallRegion.wall` の参照先が実在し、種別が `ElementKind::Wall` である
- ひとつの領域のリスト内で ID が重複しない

種別まで見ているのは、小梁を壁領域に登録するような取り違えを早い段階で弾くためです。

**なお、床をまたいだ重複は検証していません。**
同じ小梁が 2 枚の床の `secondary_joist_ids` に入っていても、現状では通ります。
荷重分配が所属関係を使うようになると、この状態は床荷重の二重計上になりますので、そのときに検証を追加してください。

## 参照整合の追随先

`SecondaryMemberId` を持つフィールドを `Model` へ追加したら、`Model::visit_secondary_member_ids` へ必ず追随してください。
二次部材の削除・挿入にともなう ID の繰り上げと繰り下げは、この走査を単一の情報源としています。

同じく、要素を削除する `DeleteMember` は `WallRegion.wall` を「版なし」へ戻します。
残したまま ID を繰り上げると、削除した壁の次にあった要素を指すことになるためです。
繰り上がった先がたまたま別の壁だと検証も通ってしまい、壁領域が黙って別の壁に付け替わります。

## 既定値

- `Slab.secondary_joist_ids`: 空（`#[serde(default)]`）
- `Model.wall_regions`: 空（`#[serde(default)]`）

`SecondaryMember.id` には `#[serde(default)]` を付けていません。
既定値で補うと不変条件が破れたモデルを黙って受け入れることになり、`validate` で検出したい状態がそのまま読み込まれてしまうためです。
未リリースのため旧スキーマの互換は取らず、読めない古いファイルは読込時にエラーとします。
